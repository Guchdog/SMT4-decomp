# H2 Draw and Secondary real-helper audit

## Proven Draw interworking defect

The pinned original Draw invokes the formatter in **Thumb state**, while the production final image invokes it in **ARM state**. At `0x002CB358`, original bytes `27 cd ff fa` decode as ARM `blx #0x002BE7FC`, which switches instruction sets. The target begins `0f b4 1c b5 08 4b 06 aa`, decoding as Thumb `push {r0,r1,r2,r3}; push {r2,r3,r4,lr}; ldr r3,...; add r2,...`. Treating these bytes as ARM does not yield that prologue.

In the run-013 production image, `0x002CB24C` loads the literal at `0x002CB574` (`0x002BE77C`), `0x002CB258` adds `0x80` to it, and `0x002CB25C` executes `blx r3`. The resulting register is **even** `0x002BE7FC`, and register BLX uses bit 0 to select ARM state. Source `src/engine/leaf_batch43_a.cpp` calls the same even address through `draw_call<void>`; this is a confirmed call-mode error in that production image. `0x002BE7FD` is the Thumb-tagged function pointer for the same entry. It is a strong hypothesis for an entry-time failure, not a captured guest PC or proof that the observed host exception arose there. The callback-only image and manual package provenance should be verified before applying this finding to a particular runtime image.

Original formatter gets `r0=sp+8`, `r1=0x002CB410` pointing to `%s\0`, `r2=payload + 0x96 * absolute_index`. Production passes its stack buffer, the relocated format `0x003FEED0` (also bytes `25 73 00`), and the same source-level descriptor formula. The final-image review established the relocated literal and pointer; the formatter HLE does **not** actually read either the format or descriptor bytes. It synthesizes `OptionN` from the descriptor address. Its final-address wrapper normalizes away the differing format pointer in traces. Thus prior trace passes do not verify real formatting, string length or call mode. The downstream font mock records r0–r2, resulting text and s0–s4; panel/sprite mocks record r0–r3 plus two stack words. These compare the exercised argument values/order, not real renderer side effects or all live input domains.

## Other helper state and ABI coverage

A linear Capstone scan of original `0x002CAEF0..0x002CB75C` (including a data-bearing region, so direct instruction boundaries were checked against context) found the formatter above as the only statically addressed original BLX-immediate in Draw/Secondary. Original Draw's other named calls are ARM BL to `0x002BEF7C`, `0x002BEF70`, `0x002BF558`, `0x0029F260`, `0x0029F248`, `0x0029D8E4`, `0x002BF6D0`, `0x002C5FA4`, `0x002BF460`, `0x002C0EC4`, `0x002C0E9C`, `0x002BE77C`, and `0x0029D8FC`. Production source uses their even addresses; ARM register BLX to those constants selects ARM as original BL does. This is an instruction-set audit, not a proof that every compiled dataflow or ABI argument is correct. The seven outlined-cache helper calls are ARM BL to `0x003FEE54`; that helper's `0x002C5FA4` call uses even target. The original's cache indirect `blx r1` and production indirect callback preserve the dynamically loaded target; without runtime contents, its actual address/state is unknown. Draw's HLE hardcodes one even callback and records only r0; it omits the real callback's mutation, reentrancy and clobbers. The cache uses `root+0x12AC`, indexed slot, flag and callback; the fixture initializes a valid root, index zero and callback, so malformed or concurrently changed real cache state is outside it.

The original Secondary direct calls use ARM BL to `0x002B9008`, `0x002A755C`, `0x002C4360`, `0x002BF41C`, and `0x002C45B8`; production source uses those even addresses. No additional statically selected Thumb target was found. Original call order is counter loop twice, optional script cleanup, two optional resource releases, registration predicate, optional task transition, reload global and optional final release. Existing directed differential compares declared r0/r1 values, ordering, selected writes and preserved GPR/SP/d8–d15; it models `0x002B9008`'s manager-halfword decrement but stubs the other four. The pinned helper at `0x002BF41C` traverses a bucket/list, `0x002A755C` frees nested resources and unlinks list fields, and `0x002C4360` examines allocator manager ranges and calls allocator machinery; none of these effects are exercised by trace-only models. `0x002C45B8` begins with an ARM null check and continues beyond its first eight-byte ledger fragment, so do not infer complete state effects from that fragment. Global-work mutation or resource reuse during helper calls remains an untested interaction.

## Why the differential missed it

`tools/h2_draw_experiment.py` installs an instruction hook keyed by the even numeric entry `0x002BE7FC`. Both control transfers reach that instruction address with different CPSR T state; the hook records the same helper name and synthesizes a return before the real instruction executes. It never records/asserts CPSR T at helper entry. `tools/h2_combined_offline_validation.py` additionally replaces the recorded format pointer with zero for both traces. Consequently an HLE pass can match even though original enters Thumb and production enters ARM. Return-state behavior of the real formatter is also bypassed. Its indirect callback fixture similarly covers only one synthetic target; this is not a blanket claim that every other helper is safely covered.

## Evidence and follow-up

This audit read `extracted/exefs/code.bin` SHA-256 `1f98884fe997af22e032a14c51a46c872b05b0e079a0f29e307b0e059cfaa558` and run-013 final image SHA-256 `7b2bc2983a890e1c4cf1ae71beca9f574260d98d6cfcdffb3bbb34bd3eb2b291`; the latter is an intermediate image, not the manual standalone IPS identity. Capstone ARM/Thumb disassembly and byte inspection were read-only. No emulator, live input, socket, profile, or binary mutation was used.

Before another runtime test, update the production formatter pointer to select Thumb, rebuild and redo placement/IPS integrity and independent review. Improve the harness to assert expected CPSR T at each hook entry, test both modes as a negative control, and record/read the actual `%s` bytes and descriptor content; add a bounded real formatter call and preserved ABI checks where feasible. Recheck actual generated body size, relocations and all final images; the cave has only eight spare bytes. Then use a controlled baseline/patch comparison and guest PC or real-helper boundary capture if separately authorized. A corrected formatter does not prove other helpers or full H2 behavior.
