# Navi delta producers and divisor trigger state

## Scope and evidence boundary

This report combines pinned ARM inspection of `code.bin` (SHA-256 `1f98884fe997af22e032a14c51a46c872b05b0e079a0f29e307b0e059cfaa558`), bounded aligned B/BL scans over executable text `[0x00100000,0x003FE624)`, the accepted run-004 callback trace, and the separately captured run-005 paired no-hit probe. Static control flow and runtime samples are kept separate below. Static object-relative offsets refer to the incoming callback object (`r4` in the callback and helper) only when the same pointer is passed through; they do not establish object ownership or identify it as player work.

## `0x0039C944`: exact guards for the accessor/divides

The helper is ARM and retains its object in `r4`. It has two direct calls to `0x0039FA68`, which reads `*[0x0044CDF0]+0x34` into VFP `s0` and returns. The helper's incoming `r0` argument is not used by that accessor. The global byte gate at `0x0049F91C+0x18` is distinct from the multiplier float loaded from `0x0044CDC8`.

1. **Delta path, call at `0x0039CA38`.** Entry word `[r4+0x10]` bit `0x20000` set selects the `0x002C01B0` query. A zero result branches to the delta recomputation block at `0x0039C99C`; a nonzero result reaches that block only if byte `[0x0049F91C+0x18]` is nonzero. A clear entry bit instead branches directly to the threshold block at `0x0039C9E8`, skipping the query, gate read, flag clearing, `+0x54` check, and recomputation of `+0x3C/+0x40`; this route compares the existing delta fields as stored. In the recomputation block, the code clears bits `0x30000` in `[r4+0x10]`; signed byte `[r4+0x54] > 2` forces `+0x3C/+0x40` to zero, otherwise it stores `(+0x44 - +0x4C)` and `(+0x48 - +0x50)`. It then reloads `[r4+0x10]` and tests bit `0x20000` at `0x0039C9E0`; the preceding same-thread `BIC #0x30000` and store have cleared that bit, so the branch to `0x0039CA90` is redundant on the shown sequential path absent an external/concurrent write. Both the clear-entry-bit route and the recomputation route reach the threshold comparisons. The code compares the bit patterns of `abs(+0x3C)` and `abs(+0x40)` to `0x3F000000` (float `0.5`). It zeros both fields and exits when both compare at most `0.5`; it proceeds when either compares greater. It then multiplies each delta by the float at `0x0044CDC8`, calls the accessor, and divides each scaled delta by the returned `s0` at `0x0039CA64` and `0x0039CA7C`. There is no zero, NaN, infinity, or sign guard on the divisor before either divide.
2. **Coordinate path, call at `0x0039CAA0`.** This call is separate from the `0.5` delta trigger. It is reached from the bit-set query branch when `0x002C01B0` returns nonzero and byte `[0x0049F91C+0x18]` is zero. The accessor result is used to divide coordinate differences derived from the two query output words and object fields `+0x2C/+0x30/+0x34/+0x38`, then passed with a coordinate pair to `0x00231B38`. It does not require the `+0x3C/+0x40` threshold.

The accessor body itself is only `LDR r0,[pc,#8]`, `LDR r0,[r0]`, `VLDR s0,[r0,#0x34]`, `BX lr`. It dereferences slot `0x0044CDF0`, replaces/clobbers input `r0` with the host pointer and returns the loaded 32-bit float representation in `s0`; it has no validation or normalization. Static inspection does not establish the runtime pointer lifetime or a finite/nonzero divisor domain.

## Direct producers and same-object paths

Within `0x0039C944`, direct writes to callback-object `+0x3C/+0x40` are at `0x0039C9B0/0x0039C9B4` (zero both when signed `+0x54 > 2`) and `0x0039C9D4/0x0039C9D8` (write coordinate differences otherwise), but these stores occur only on the entry-bit-set recomputation route. A clear entry bit skips them and compares the previously stored deltas. Other stores are at `0x0039CA0C/0x0039CA10` (zero both on the small-delta exit) and `0x0039CA28/0x0039CA34` (scale each by the multiplier before the accessor/divides). The coordinate branch at `0x0039CA9C` updates coordinate history and the repeat byte but does not itself store `+0x3C/+0x40`.

Other statically visible writers with caller paths in the Navi callback lineage are:

- **`0x0039B58C`, callback branch `0x00399E10`.** The callback passes its saved `r4` object to this helper only on the branch where unsigned byte `[r4+0x0C]` is zero and the two flag queries return nonzero. Inside it, nonzero `0x0039B864(r4)` exits immediately. With object flag `0x20000` set, it queries `0x002C01B0`; depending on that result and global gate `[0x0049F91C+0x18]`, it may use the mode-3 reader `0x003C303C`. A successful release condition clears bit `0x20000`, then either zeros `+0x3C/+0x40` if signed `+0x54 > 2`, or stores the coordinate differences from `+0x44/+0x48` and `+0x4C/+0x50`. When flag `0x20000` is clear, the `0x002315C8`/`0x002315B4` predicate and zero global gate can select mode-1 reader `0x003C3034`; this updates position/history fields and sets bit `0x20000`, but the reviewed report does not show that branch directly writing `+0x3C/+0x40`. Later in this helper, after the flag is clear, the same absolute-delta threshold logic may zero small deltas or scale/apply larger ones. Run-004 has callback byte `+0x0C=1`, so its observed branch does not call `0x0039B58C`.
- **`0x0039D758`, nested under `0x0039AF30`.** The callback passes its saved object to `0x0039AF30` when the reloaded unsigned byte `[r4+0x0C]` is nonzero. That helper can reach `0x0039D758` at `0x0039B03C` after its own flag/substate and helper checks; this is a same-register object flow, not proof that every callback reaches it. In `0x0039D758`, bit `0x02000000` causes an early zero return. Otherwise, nonzero `0x002315B4` predicate plus zero `[0x0049F91C+0x18]` selects the mode-1 reader `0x003C3034`; its output is used to write position/history `+0x44/+0x48` and `+0x4C/+0x50`, state pair `+0x2C..+0x38`, and zeros to `+0x3C/+0x40`, `+0x54`, and `+0x55`. This path initializes/clears the deltas, it does not by itself establish a later delta above threshold.
- **Host initializer `0x00291CAC`.** The straight-line allocation/initialization path stores `1.0f` at host `+0x34` and zero at host `+0x3C`; it also installs the allocated pointer at `0x0044CDF0`. This is not callback-object `+0x3C`: if a runtime callback object is host `+0x40`, its `+0x3C/+0x40` are host `+0x7C/+0x80`, while the accessor divisor is host `+0x34`. The initializer does not prove that the observed runtime host completed initialization or that no later alias writer changes the divisor. The bounded source scan's confirmed direct host `+0x34` accesses were the accessor load and this initializer store; the scan is not exhaustive for alias/indirect writers.

These sites establish a static path where query-derived position/history differences can feed the threshold. They do not establish what the reader outputs mean or their natural range. Thus the code can reach the greater-than-`0.5` branch if its guards permit and the resulting signed/float coordinate differences exceed the threshold, but available evidence does not show an ordinary in-game call producing that state. It also does not prove player, movement, or interaction semantics.

## Run-004 and run-005 kept separate

**Run-004, accepted callback trace.** The callback entry object was `0x086EB3C0`, with host slot `*[0x0044CDF0]=0x086EB380`, so this sample's callback pointer equals host `+0x40`. The captured `+0x10` word was zero; `+0x3C` and `+0x40` float words were both zero. The range-validated 0x60-byte object prefix was identical at each reached callback event and between original/patched profiles. The trace reached helper return PC `0x00399DAC` with `r0=0` in this one invocation. It did not stop at `0x0039FA68`, the divide instructions, or the internal threshold branch. Because the entry bit was clear in this sample, static control flow selects the route that compares the existing zero delta fields without recomputation; this is consistent with an early threshold exit, but that branch was not observed. The host snapshots were at host `+0x30` and `+0x38`, not `+0x34`, so they do not reveal the divisor.

**Run-005, paired no-hit accessor probes.** The runner reports `hit=false` for both `0x0039FA70` and `0x0039FA74` in original and patched runs. The bounded probe timed out and was interrupted at `PC=0x002A88A8` on thread 1; no accessor-entry registers or target memory were captured. It therefore gives no divisor bits and does not establish that the callback or either accessor path ran. The run-004 object values must not be transferred to run-005; the run-005 no-hit cannot be explained by run-004's zero fields. Its independent title/field checkpoint and cleanup results do not validate divisor reachability.
