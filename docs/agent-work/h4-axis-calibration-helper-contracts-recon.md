# H4 axis calibration helper contracts — static ARM

Pinned `code.bin` SHA-256 `1f98884fe997af22e032a14c51a46c872b05b0e079a0f29e307b0e059cfaa558`; all 20 packet input hashes verified. ARM disassembly of ledger spans: 0x0011C5EC (304 B), 0x00128610 (148 B), 0x0013B9FC (228 B), 0x0013B8F8 (260 B), 0x0013BAE0 (460 B, four trailing constants), 0x0013BCAC (212 B). These are original instruction observations, not compiled-C++ or runtime equivalence. The direct B/BL scan below covers aligned ARM text only; indirect, Thumb and computed calls remain open. No build/test/emulator/GDB/profile/save access or guest writes occurred.

## Parent and dispatch ABI

0x0011C5EC receives root r0 and output record r1, saves r4-r6/lr and allocates 0x18 bytes. It calls 0x00128C2C; nonzero returns r0=0. Otherwise calls 0x001285C4(root+0xC), then 0x0012A758 with r0=`*(*(root)+4)`, r1=record, r2=1, r3=&local count, two local cursor pointers on stack. Count <=0 returns 0. Successful copy reaches 0x0011C650..68: signed halfword record+0xE is stored as 32-bit fifth argument at `[sp]`; r0=root+0xC; r1=record+0xC pointer; r2=record+0xE pointer; r3=sign-extended halfword at +0xC. BL 0x00128610. Thus x/y inputs are values already loaded, not pointers or live rereads, while output pointers remain separately writable. All valid mapping/alignment and alias domains need testing.

0x00128610 preserves r4/lr and reserves 8 bytes; the original fifth argument is read from `[sp+0x10]` after this prologue. It reads selector byte `[calibration+0xC]`; selectors 0/1/2 sign-extend two halfwords from +0/+6, +2/+8, +4/+0xA respectively, writes them as 32-bit stack arguments 5/6, and calls 0x0013B9FC/0x0013B8F8/0x0013BAE0 respectively. Child register ABI: r0=out-x halfword pointer, r1=out-y halfword pointer, r2=x signed value, r3=y signed value; stack words A/B are the selected signed halfwords. Selector >=3 skips child and output writes, returning with residual r0 equal to calibration pointer; no general boolean return. Child return is passed through as residual r0 but parent 0x0011C5EC ignores it. BL sites are 0x0011C668→0x00128610, and 0x00128678/698/658→selectors 0/1/2 respectively; 0x001078E8 calls 0x0011C5EC. Scan does not establish dynamic execution or all possible callers.

## Selector 0: 0x0013B9FC

Let x=r2, y=r3, A=stack word 5, B=stack word 6. At 0x0013BA14..24 it computes `R = x*x + y*y` and `A2=A*A` with ARM low-32-bit `MUL/MLA`; comparison is signed. If `R <= A2`, it writes zero to out-y **first** then out-x, returns residual r0=0. Otherwise it computes `N = R << 14` in 32 bits. If signed N<=0, working root `Q=0`; else it uses an integer iterative divide/average loop (0x0013BA50..8C) with original helper 0x002C615C to derive Q. It tests signed `B*B <= R`: true sets `D=B-A`, `P=D<<7`; false sets `P=Q-(A<<7)`, `D=(Q arithmetic>>7)-A`. It calls 0x002C615C with low-32-bit `x*P` and Q, stores low halfword result to out-x, then calls it with `y*P` and Q and stores low halfword to out-y; r0 returns signed-extended low halfword of D. This resembles fixed-point radial scaling but only the exact operations are established. Overflow/wrap, zero divisor Q, helper rounding and termination under abnormal signed inputs are not proven; do not replace this with a mathematical sqrt/division without differential evidence. Alias ordering differs between the zero branch (y then x) and scaling branch (x then y).

## Selector 1: 0x0013B8F8

For each x/y, 0x0013B90C..60 applies signed comparisons against A: for a negative value, if `-value > A` the intermediate is `value+A`, otherwise 0; for nonnegative, if `A < value` it is `value-A`, otherwise 0. Negation and all adds, multiplies and shifts use ARM 32-bit results. Let these u,v and `F=B-A`, `R=u*u+v*v`. It compares signed `F*F` with R. If `F*F > R`, it stores u then v as halfwords without radial scaling. Otherwise it computes Q via the same positive `R<<14` iterative division/average pattern; signed nonpositive shifted value leaves Q=0, then calls 0x002C615C on low-32-bit `u*(F<<7)` and Q and on `v*(F<<7)` and Q, sign-extends each quotient's low halfword, stores x then y. Both paths return signed-extended low halfword of F. There is no guard against `F=0`, shifted overflow or Q=0, and 0x002C615C's zero-divisor behavior/rounding is a dependency. Negative A/B and out-of-normal-range values cannot be dismissed without caller-domain proof.

## Selector 2: 0x0013BAE0

The ARM body uses low-32-bit integer x²+y² before signed-to-float conversion, plus VFPv2 float arithmetic. Literal constants are 0.0, -36.0, +36.0, 1600.0. If the converted squared sum compares equal to zero it stores zero to out-x then out-y. Otherwise it forms a direction-dependent boundary pair from ±36 and a ratio of x/y or y/x (branch on signed wrapped x²/y² and input sign); it computes boundary squared length and clamps it to 1600.0 on VFP `HS`. If input squared sum compares `HS` boundary length, it proceeds; otherwise zeroes x then y. It computes sqrt(boundary length), sqrt(input length), converts B and B-40 to float. If input squared length >= float of wrapped B², it writes `(x*(B-40))/sqrt(R)` and `(y*(B-40))/sqrt(R)` after `VCVT.S32.F32` and low-halfword stores x then y. Otherwise it writes the corresponding interpolation `x*(B-40)*(sqrt(R)-sqrt(boundary))/( (B-sqrt(boundary))*sqrt(R))` and same for y, preserving the original VFP instruction grouping. The ARM `VCVT.S32.F32` is the round-toward-zero form; exact FPSCR exception flags/default-NaN/flush behavior, division by zero, NaN/unordered comparison, integer overflow and nonfinite conversions remain unverified. A is passed but this body does not read it. r0 remains the out-x pointer at return; no numeric return contract should be assumed beyond that static observation. No fast-math algebraic rewrite is justified.

## Parent post-processing and optional 0x0013BCAC

After calibration, if byte root+0x30 is nonzero, parent copies record word +0 to root+8 then clears root+0x30. It clears bit 0x2000 of record word +0, writes word +4=`new & ~previous` and +8=`previous & ~new`, where previous is root+8. If 0x002BB978()!=0 and 0x002BC9C8()==0 it zeros words +0/+8/+4 and halfwords +0xC/+0xE (in that store order). It then writes record word +0 to root+8. Finally it reads byte at absolute 0x00471AD8; if zero calls 0x0013BCAC(record), otherwise skips it. Parent returns 1 on this positive-copy path, 0 on earlier failures; helper effects are not a complete parent write set.

0x0013BCAC saves r4, reads word +4 and transforms bit 0x8: set it if both bits 0x4/0x8 were set, or bit 0x4 was set while record word +0 bit 0x8 was clear, or bit 0x8 was set while word +0 bit 0x4 was clear; otherwise clear bit 0x8. It stores updated +4. It applies the analogous test independently to word +8 using current word +0 and stores updated +8. Then if current word +0 bit 0x4 is set it clears bit 0x4 and sets bit 0x8 in +0; finally clears bit 0x4 in +4 and +8, in that order. Other bits are preserved. The tests are sequential and actual memory alias/fault domains matter. It leaves r0 as the final loaded/cleared word +8 on the normal return, which parent discards. It is conditional bit remapping; names/physical control mapping are not established.

## Independent review clarifications

The independent ARM review is recorded in `h4-axis-calibration-helper-contracts-review.md`. It confirmed the selector dispatch, stack arguments, low-word arithmetic, VCVT toward-zero conversion and write order. It clarified that selector 1's `RSB #0` wraps `x=-32768` to `0x80000000`, so the signed comparison against any signed-halfword A fails and that component becomes zero; mathematical negation would be incorrect. It also checked that VFP `HS`/`BHS` and `BLT` conditions take architectural routes on unordered comparisons. The parent-supplied halfword path produces finite, ordered operands before those tests; preserve the instruction conditions for any broader domain. The ordered interpolation guards imply its `B-sqrt(boundary)` denominator is nonzero. These clarifications do not resolve the integer divider, overflow domains, exceptional FPSCR behavior, or producer identity.

## Limits and next action

These are consumer-side transforms of one record, not proof of source-object writer, physical input API, refresh cadence, camera response or player movement. Strict scope leaves 0x002C615C divide semantics, valid calibrated A/B ranges, initialization, concurrent sample coherence, alignment/alias and all faults unresolved. The independent ARM review checked signed predicates and VFP branches, including the selector-1 INT16_MIN wrap and selector-2 unordered condition behavior; low-word overflow and exceptional domains remain unvalidated. Before C++ implementation, execute original dependencies in a dedicated offline harness and differentially test signed extremes, A/B ordering, exact deadzone and clamp boundaries, zero/negative denominators and overflow, selector outside range, output alias/faults, parent mask branches and same-input mutation; capture FPSCR and all writes.
