## Branch guards and both accessor routes

Independent Capstone ARM inspection of `0x0039C944` confirms `r4` retains the callback-object input and `r6=r4+0x162`. At `0x0039C968`, `TST r0,#0x20000` controls the first split. If clear, `BEQ 0x0039C9E8` enters the threshold comparison immediately; no query, global gate read, bit clearing, `+0x54` check, or recomputation of `+0x3C/+0x40` occurs on this entry route. The existing delta fields are compared as-is. If either absolute delta is greater than float `0.5`, control reaches the delta accessor at `0x0039CA38`; if both are at most `0.5`, the fields are zeroed and the helper exits.

If the entry bit is set, the helper calls `0x002C01B0` with two stack output pointers. A zero result branches to `0x0039C99C`. A nonzero result reads `[0x0049F91C+0x18]`: zero branches to the separate coordinate route at `0x0039CA9C`, while nonzero falls through to `0x0039C99C`. In this `0x0039C99C` update route the code clears `0x30000` in `[r4+0x10]`, then either zeros callback-object `+0x3C/+0x40` when signed byte `+0x54 > 2`, or computes `(object+0x44)-(object+0x4C)` and `(object+0x48)-(object+0x50)` into those delta fields. It then reloads `+0x10` and tests `0x20000` at `0x0039C9DC`. Since the preceding `BIC #0x30000` and store cleared that bit, the branch to `0x0039CA90` cannot be taken absent an intervening external/concurrent mutation. The report should call out that dataflow rather than presenting it as an ordinary reachable guard. The route then reaches the same `0.5` threshold test.

The delta route at `0x0039CA38` scales callback-object `+0x3C/+0x40` by the multiplier loaded from `0x0044CDC8`, passes `r6` in `r0` to `0x0039FA68`, saves its `s0` result, and divides the two scaled deltas by it at `0x0039CA64` and `0x0039CA7C`. The global gate byte at `0x0049F91C+0x18` is not this multiplier or the divisor. The separate coordinate route at `0x0039CA9C` calls the accessor at `0x0039CAA0` without the delta threshold; it divides query-output differences against callback-object fields `+0x2C/+0x30` and `+0x34/+0x38`. Those object-relative fields are also distinct from the accessor's global-host `+0x34` divisor source. Neither route adds a zero/finite divisor guard in the inspected code.

## Same-object producers and offset identity

The listed lineage is consistent in the pinned ARM image. Callback `0x00399D60` saves its input object in `r4`; at `0x00399DA4` it conditionally moves that `r4` to `r0` and calls `0x0039C944` at `0x00399DA8`. On the alternate callback branch, `0x00399E0C` moves the same `r4` to `r0` before calling `0x0039B58C`; that helper sets its own `r4=r0` and the guarded stores at `0x0039B614/618` or `0x0039B638/63C` target that object. In the nonzero `+0x0C` route, callback `0x00399DC4..0x00399DC8` passes its `r4` to `0x0039AF30`, which retains it in `r4` and later passes it at `0x0039B034..0x0039B03C` to `0x0039D758`. The listed position/history and delta stores in `0x0039D758` are therefore relative to the same callback object on that call chain, subject to that helper's branch guards. This is static lineage, not proof those producer branches ran naturally in either captured scenario.

The offset names must remain base-qualified. `0x0039FA68` loads `[*(u32*)0x0044CDF0 + 0x34]` into `s0`: this is **global-host `+0x34`**. The helper's `+0x3C/+0x40` delta fields and its coordinate fields `+0x34/+0x38` are relative to `r4`, the callback object. Initializer `0x00291D14` writes 1.0f to the host's `+0x34`; it also zeros host `+0x3C`. In the run-004 sample only, the callback object pointer is host+`0x40`; under that sampled relation host+`0x34` is callback-object-`0x0C`, while callback-object `+0x3C/+0x40` are host+`0x7C/+0x80`. This arithmetic demonstrates distinct addresses in that sample, not a universal ownership/layout contract. The host slot snapshots in run-004 cover host+`0x30` and `+0x38`, not host+`0x34`.

## Runtime artifacts kept separate

**Run-004:** The pinned original/patched callback trace captures callback entry `0x00399D60`, callback object `0x086EB3C0`, and global host pointer `0x086EB380`; the callback object's entry word `+0x10` and float words `+0x3C/+0x40` are zero, and its sampled prefix remains unchanged through the captured stops. It observes the `0x0039C944` return at `0x00399DAC` with `r0=0` in this one call. It does not stop at the helper's threshold branch, either accessor call, or either divide site, and it does not read host+`0x34`. The zero delta snapshot is consistent with an early threshold exit when the clear-bit route reads current fields, but the internal branch is not directly observed.

**Run-005:** The separate paired sample records 250 field-tick snapshots in each profile and no hit at either requested probe address, `0x0039FA70` or `0x0039FA74`. All four raw probe records (two addresses per profile) have `hit=false`, `interrupted=true`, stop PC `0x002A88A8`, and thread 1; no target-entry registers, host+`0x34` bits, or accessor return are captured. It supplies no current-run callback-object delta values. Do not transfer run-004's zero fields or callback return into run-005; the no-hit is not explained by a measurement in run-005. Both runs remain partial checkpoint evidence, not proof of natural divisor-path reachability, player/movement/interaction semantics, or H4 completion.

## Recommendation and next capture
