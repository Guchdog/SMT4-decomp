# H4 repeat-state consumer contexts

Static ARM disassembly of pinned `code.bin` SHA-256 `1f98884fe997af22e032a14c51a46c872b05b0e079a0f29e307b0e059cfaa558`, using ledger boundaries and aligned ARM B/BL scan of text 0x00100000..0x003FE624. A raw scan may include data; the sites below were checked in instruction context. Thumb, indirect/computed calls, callback registration and dynamic reachability remain unresolved. No build, test, runtime or save access was performed.

## Common caller and object

Ledger `0x0039B58C` is 728 bytes including literal tail, `0x0039D758` is 352 bytes including tail; both start in ARM state. Aligned direct call 0x00399E10→0x0039B58C occurs inside `0x00399D60`; 0x0039B03C→0x0039D758 occurs inside `0x0039AF30`. The latter has direct caller 0x00399DC8 inside `0x00399D60`. At entry 0x00399D60 saves incoming r0 as r4; both calls pass that r4 through r0, but occur on different branches: byte `[r4+0xC]` nonzero leads to 0x0039AF30, zero can lead to 0x0039B58C after 0x002C0BA8(0x400) and 0x002931CC(0x76) return nonzero. Signed byte +0xC == -1 and word +0x10 bit 0x1000 can short-circuit. No instruction here identifies r4 as player work. The later 0x0039AF30 call can skip/return based on bit 0x1000, global state and substate; after helper 0x0039B864 it calls 0x0039D758 with the same r4 at 0x0039B03C.

Both routines load literal 0x0049F91C and test byte +0x18 as a gate. The literal and test are directly observed, but this report does not establish the global's type; describe it only as a shared global gate. This is not proof that the r4 object is player work or that these branches perform in-world interaction. Pointers returned by 0x00231F58 and accepted by 0x00231B38 at r4+0x162 are not independently typed here.

## 0x0039B58C

At 0x0039B59C it calls 0x0039B864(r4), exiting on nonzero. Otherwise reads flags word `[r4+0x10]` and tests 0x20000. With that bit set, 0x0039B5CC calls 0x002C01B0 with r0=SP+0xC, r1=SP+8 (that entry sets mode r2=0 before reaching reader 0x002C01B8). If it returns nonzero and global 0x0049F934 byte is zero, control goes to 0x0039B708; otherwise 0x0039B5EC calls **0x003C303C**, whose instruction at 0x003C3040 tail-branches to reader after setting mode 3. Same output pointers SP+0xC and SP+8. Return is tested; if zero and global byte +0x18 is zero it skips the release path. Otherwise 0x0039B600..08 clears bit 0x20000; signed byte r4+0x54 >2 sets floats +0x3C/+0x40 to zero, else stores differences of prior floats (+0x44 minus +0x4C, +0x48 minus +0x50).

When bit 0x20000 is clear, 0x0039B66C calls 0x002315C8(0x1C, 0xFA4, SP+8, SP+0xC, SP+0x10, SP+0x14), then calls 0x002315B4 on the four resulting words. Nonzero return and global byte +0x18 ==0 reach 0x0039B69C **0x003C3034** (tail branch at 0x003C3038; mode 1), with r0=SP, r1=SP+4. Its return is not checked locally. 0x0039B6A0..F4 converts those two signed 32-bit output words to floats and stores +0x2C/+0x30, +0x44/+0x48 and +0x4C/+0x50; copies two words returned by 0x00231F58(r4+0x162) into +0x34/+0x38, clears byte +0x54, and sets bit 0x20000 in +0x10. If the mode-1 reader returns 0 and leaves outputs untouched, the caller still consumes prior stack contents; that path needs caller-state evidence, not an assumed zero initialization.

At 0x0039B708..48 mode-0 outputs are converted to floats, offset against +0x2C/+0x30 and +0x34/+0x38 and passed through a stack pair to 0x00231B38(r4+0x162, SP). Equal current values increment signed byte +0x54 up to 0x63; different values shift +0x44/+0x48 to +0x4C/+0x50 and store new values. Once flag 0x20000 is clear, 0x0039B7B4..840 tests absolute floats +0x3C/+0x40 against 0.5; small values are zeroed, otherwise each is multiplied by a literal-referenced float and applied via 0x00231F58/0x00231B38. This looks like a drag/inertia-style two-dimensional transform by inference only; the affected object and real interaction are unverified.

## 0x0039D758

Entry saves r0 as r4. If word +0x10 bit 0x02000000 is set, it returns 0. Otherwise 0x0039D78C/98 invokes 0x002315C8 with 0x1C, 0xFA4 and four stack output addresses, then 0x002315B4 with their values. Nonzero result and global 0x0049F934 byte ==0 branch to 0x0039D7F4. There 0x0039D7FC BLs **0x003C3034** (entry; its instruction at 0x003C3038 is the tail B) with r0=SP+0x18, r1=SP+0x1C, hence mode 1. It does not test reader return before consuming outputs. It sets object +0x10 bit 0x10000; converts the outputs to floats and stores +0x44/+0x48 and +0x4C/+0x50, fetches two words from 0x00231F58(r4+0x162), writes +0x2C/+0x30 and +0x34/+0x38, zeros floats +0x3C/+0x40 and bytes +0x54/+0x55. It returns 0 at 0x0039D7E8..F0.

On the alternate branch, if +0x10 bit 0x10000 is set, 0x0039D7C0 calls 0x00231B54; a nonzero result with global byte +0x18 ==0 reaches 0x0039D87C, where signed byte +0x55 is incremented and compared against literal 0x0000FFFF. Since every signed-byte value is less than that positive limit, the comparison is not an effective cap; the byte store can wrap. A positive resulting byte sets bit 0x20000. Otherwise 0x0039D7DC..E4 clears that bit. The register outputs and flags are concrete; animation, input identity and destination semantics are not established. 0x0039D758 has no direct call to mode-3 wrapper 0x003C303C in its inspected body.

## Conclusion and narrow next evidence

These are global-gated, coordinate-like two-dimensional state transforms, with local reader mode 0/1/3 paths. The mode-1 readers' boolean returns are not checked before their stack outputs are consumed; on failure, the reader leaves those buffers untouched, so values used by the callers are not established as fresh or zero. The routines are plausible UI/map-view interaction code, but there is no proven field-player pointer, active H4 execution, player movement, or specific interaction. A useful next static step is to trace initialization and callers of 0x00399D60 and the object at r4+0x162/0x00231F58/0x00231B38, establishing allocation, ownership and any link to observed field work. A separate authorized passive runtime task could capture entry r0 identity, flags and mode/return at these callsites against the settled H4 checkpoint; do not infer active behavior from a hit alone, and do not use unverified guest writes or watchpoints.
