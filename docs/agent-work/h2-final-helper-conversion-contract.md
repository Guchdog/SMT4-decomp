Existing H2 caller 0x00221168 passes r3=6, stack words 1,0; r0/r1/r2 come from prior calls. For r3=6 the selector picks `obj = *(uint32_t*)0x0043e18c` (0x00286954, 0x00286980-98); the first two writes do not null-check it. Restrict the proposed experimental slice to ordinary mapped RAM, r3=6, r2!=0, valid writable obj for at least offsets +0x2d and +0x5e and readable obj+8. Object lifetime/alignment must satisfy target storage accesses. This domain is a fixture precondition, not a claim that other selectors or cases are invalid in the game.

At 0x0028699c and 0x002869b4, respectively, store byte zero at obj+0x2d and obj+0x5e. Then:

- `obj[8]==4`: branch 0x002869c4-cc to 0x00286c38, return raw r0=1; no further local writes/calls in this path.
- `obj[8]==5`: comparisons 0x002869d4-e4 lead to 0x00286c40; load word obj+0x18 and call ARM 0x0028df54 with that value, then return 1. Require readable obj+0x18 and valid callee memory. The callee loads its literal 0x0044de98, then pointer `[0x0044de98+0x20]`, writes byte zero to pointer+0x3b and the input word to pointer+0xa8, and returns. Memory aliasing can affect final bytes and write order; fixture should cover any supported alias explicitly or restrict it.
- `obj[8]==0` and `obj[0x2e]==0`: 0x002869d0-dc branches to 0x00286b9c; 0x00286b9c-a4 then branches 0x00286bf8, where r6=6 bypasses the special 11/19 path and reaches 0x00286c38: return 1, no call. Require readable obj+0x2e.

These paths read r2 only for zero/nonzero and ignore r0/r1 and both stack arguments locally, aside from saving/loading the sixth word with VFP. Variation of those inputs is useful for checking accidental dependencies. The sixth argument's exact VFP/stack ABI and FPEXC requirements must be modeled in the ARM runner. Do not replace the whole original helper with a function valid only for these cases; leave original installed until all reachable branches are handled, or use a separately reviewed dispatcher/fallback preserving original body, its state and all call paths.
