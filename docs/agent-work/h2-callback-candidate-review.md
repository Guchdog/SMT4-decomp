# Independent review: H2 callback 0x00221168 candidate

Scope: read-only comparison of the pinned original, candidate `experiments/semantic_equivalence/h2_callback_00221168_candidate.cpp` (SHA-256 5c8ecc5c3b0a7eb4a20314e41d2a8877190f0e374e026e0c4534b81b7e315f77), runner `tools/h2_callback_00221168_experiment.py` (SHA-256 e122c28c701f4413aa893c16690d3da943d8ff1f66a3d7b4346be999a45b951c), and existing object `build/h2-callback-00221168/h2_callback_candidate.o` via llvm-objdump/readelf. No compile, runner, emulator, or guest execution performed by this reviewer; object provenance and any previous printed result are not independently confirmed.

## Findings

1. **Promotion not yet supported:** The runner hooks 0x00296f60 and 0x00286928 with synthetic results. It therefore cannot show behavior of those dependencies or integrated H2 scenario, and only exercises caller composition with the final helper stubbed. It does execute original 0x0028df3c, 0x00289640 and 0x0028686c. The actual helper and selector remain original dependencies. A first getter result and selector result can only take two and one values respectively; the getter result cannot change between the two getter calls in this fixture.
2. **The negative control is not enforced:** the runner increments `detected` but does not assert that any mutant differs. If the source replacement stops matching or the mutation ceases to affect this fixture, a zero-detection run still prints PASS. Assert the mutation was applied exactly once and require detection, recording which cases distinguish it. One inverted-branch mutant alone does not cover raw return propagation, the unconditional +0xa11 write, stack argument order or call side effects.
3. **Bounds and fault behavior:** +8 object is always 0x802000, so its null path and original fault are not tested. C++ `object[0x31]` when null is undefined behavior, even though the observed object currently emits the unconditional store. Restrict accepted source contract to valid non-null pointers on the zero branch; do not assert source-level null-fault equivalence without a justified defined target-specific approach. The +4 pointer is set null in half of cases, but the actual final helper stub avoids its own required dereference; such cases are wrapper-only fixtures, not valid full-composition inputs.
4. **Interworking and ABI:** the inspected object is ARM code with an even symbol, `.text` has no relocations, uses BLX to pinned even ARM addresses, and preserves r4-r8 and SP with an 8-byte aligned call frame assuming aligned entry. The caller runner patches an even table pointer and executes the ARM handler BLX, a useful bounded check. It does not explicitly inspect CPSR T bit, validate each call-site SP alignment, or validate a final-address patched branch/cave. Check those in the final integrated image; fixed 0x700000 candidate address and direct raw `.text` extraction do not validate production placement.
5. **Coverage accounting and aliasing:** 64 cases vary the low three case bits for eight branch combinations and randomize initial object bytes with seed=case; they are not 64 independent control-flow cases. The two object buffers and global pointer slots are always disjoint. Byte stores may alias pointer slots or other observed memory on a broader domain; valid alias combinations, all relevant globals and mutation by callees need explicit testing or a stated narrower proven contract. The harness compares 0x800000..0x803fff, 0x43e0bc and 0x806000..0x8060ff, not all mapped memory, and does not capture writes outside those windows.
6. **Caller limitations:** The fixture has task index 0 and row cost 1; zero/nonzero helper return tests both handler branches, but no helper or callback modifies task+0x18. Thus the handler branch where task+0x18 changes during callback is untested. Only one table entry and ARM target state are represented.

## Positive findings and next steps

The reviewed compiled body preserves the key instruction order: setter; first getter; zero-only +0x30/+0x31 writes; +0xa11 write independent of that branch; context getter; selector; second getter; six-argument final helper and raw return. Actual assembly forwards the register and stack values as expected for this pinned ABI. This is preliminary evidence for a wrapper with original dependencies, not proof of those dependencies or runtime parity.

Freeze the candidate and runner, fix and rerun the required negative-control assertion and broaden or explicitly bound domain coverage, preserve results and identity, then have the integrator check final-address code and interworking. Exercise caller composition and the same integrated H2 scenario after offline gates. Review source and compiled code again if either changes.

## Review run-002: direct ARM relocation and revised runner

Frozen candidate SHA-256 `7ac9194bb3e99c432f46a24999ffeda081d9784970beab4373be0b3f1efedf4f`; runner SHA-256 `78877cf3a356c41ea2c8dfe38eef4beb65201af973a4ba081eec366f18d7f5db`. This section supersedes the run-001 observations where the implementation or harness changed. Inspected the existing object via llvm-objdump and llvm-readelf, without rebuilding or executing a runner; its current source/object provenance has not been independently established.

The observed object contains a 140-byte ARM function including its literal and six `.rel.text` R_ARM_CALL relocations at offsets 0x0c, 0x10, 0x48, 0x58, 0x60 and 0x7c. Each original instruction is `0xebfffffe`; all target addresses in this harness are word-aligned ARM entries. The runner checks instruction form, type 28, target, range and word alignment and encodes `BL` with `target - (0x00221168 + offset + 8)`, which is the correct PC-relative calculation for these ARM calls. It installs the relocated bytes at the original even VMA and the caller BLX reads an even table entry. Hooks enforce ARM CPSR and eight-byte SP alignment at selected call entries. This is sound for the inspected relocation forms and selected targets, conditional on the object actually being the one produced from the frozen inputs; it is not yet verification of an integrated production patch.

The revised runner asserts the branch mutant is applied once and detected, records non-stack guest writes, verifies sentinel return, varies selector output and second getter state through hooks, covers overlapping object buffers, and exercises caller task-index mutation. These changes address several run-001 findings, but synthetic mutation occurs in a hook and does not show that the original selector or actual helper performs it. The 64 cases vary selected bits and seeded initial bytes; they are not exhaustive. The test has only one mutant and does not explicitly assert each intended path/event was reached.

The real-helper fixture still stubs selector 0x00296f60 and helper dependency 0x002c1f28 to return zero. Thus it compares a restricted helper path only and does not establish full helper or title behavior. This reviewer did not execute that fixture and cannot assert its run result. The always-valid +8 pointer leaves the null fault path untested, and a null dereference remains undefined in C++. +4 pointer null tests apply only to stubbed-helper wrapper cases. Object-object overlap is covered, but aliases to global slots and other objects, arbitrary layouts and concurrent changes are not. Non-stack Unicorn guest write hooks exclude writes made by Python hooks and stack contents; returned values, callee-saved registers, events and selected snapshots are compared separately.

Replacing only 140 bytes of a 148-byte original span leaves eight original bytes at the end. Control reaches the new return in tested entry paths, but potential external entries into the old body and any relocation/metadata associated with production placement require audit. The source still calls declared external names, so the reproducible production build/patch must resolve those symbols to the intended ARM destinations and verify the final patched image and interworking. Independent review of any changed inputs, bounded differential and caller evidence, and the requested original-versus-patched runtime scenario remain necessary before promotion; no claim of whole-H2 equivalence follows from this runner.
