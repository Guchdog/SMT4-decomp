## C++ recovery boundary

The orchestration is structurally recoverable into readable C++: an explicit context, callback/helper interfaces, temporary 0x60-byte output, staged failure propagation preserving returned status words, two output-producing subcalls, cleanup, and the final field/global updates. However, this report does **not** support a complete behaviorally faithful standalone conversion yet. Important helper semantics, context field types, buffer format, global flag lifecycle, ownership/aliasing of passed pointers, and error-value domains are unknown. In particular, `0x002e0dd0` only observes the sign bit and maps all high-bit outputs to 5, whereas `0x00310448` distinguishes exact high-bit values; a C++ implementation must preserve the original 32-bit returned word and let each caller apply its own interpretation.

Check helper order, cleanup paths, all forwarded pointers/stack constants, object/global writes, exact output copies and return bits. Caller-composition tests must retain exact-value checks for `0xc8810bea` and `0xc8810bef` at `0x00310448`, and test `0x002e0dd0`'s sign-bit-to-5 mapping. Negative controls should collapse return values to bool or change a cleanup call/field offset and be detected.
