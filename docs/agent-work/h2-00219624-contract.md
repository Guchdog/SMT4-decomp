## ABI and return contract

The entry is a two-pointer comparator:

- `r0`: pointer A to a record beginning with a readable 16-bit key.
- `r1`: pointer B to a record beginning with a readable 16-bit key.
- Return: raw signed ordering value in `r0` (`-1`, `0`, `+1`, or a signed difference from the final field comparisons).
- No stack arguments. Prologue saves `r4-r6,lr`; epilogue restores them and SP. There are no direct stores to either input record.

The function assumes both pointers are valid and at least two-byte aligned. It has no null, length, or mapped-range check. If the two first-stage classification values compare equal, it calls the record lookup helper and dereferences returned pointers without a null check.

## Branches and ordered helper behavior

1. Load `u16 keyA = *A` and call `0x0029ED08(keyA)`; save its return in `r6`.
2. Load `u16 keyB = *B` and call `0x0029ED08(keyB)`.
3. Compare the helper results as bit sets:
   - If `(valueB & ~valueA) != 0`, return `-1` immediately.
   - Else if `(valueA & ~valueB) != 0`, return `+1` immediately.
   - Otherwise continue. The pinned `0x0029ED08` helper returns only 0 or 1, so this orders unequal values as `0 < 1`; helper equality is required for the rest of the comparator. The two early returns skip `0x002B9364` entirely.
4. Call `0x002B9364(keyA)`, keep its returned record pointer in `r4`; then call `0x002B9364(keyB)`, keep its pointer in `r1`.
5. Compare `u8 recordA[2] - u8 recordB[2]`; if nonzero, return that raw 32-bit subtraction result.
6. If equal, compare `u8 recordB[3] - u8 recordA[3]` (the order is intentionally reversed relative to offset 2); if nonzero, return it.
7. If both byte fields are equal, return `u16 keyA - u16 keyB` as a 32-bit subtraction. Equal keys return zero.

Exact helper call order is therefore `29ED08(A key)`, `29ED08(B key)`, and only on equal helper results, `2B9364(A key)`, `2B9364(B key)`. Each helper receives its key in `r0`; no other arguments are supplied. Caller-saved registers and condition flags are scratch.

## Helper contracts and remaining limits

`0x0029ED08` is a 60-byte leaf. It compares the unsigned key to `0x500`; keys above that return zero. Otherwise it loads a pointer from literal `0x0043E2A8`, follows the word at global/object `+4`, computes a 56-byte row stride (`14 * key`), reads a halfword at row `+0x2E`, and returns `(halfword & 2) >> 1`. This establishes the returned 0/1 bit and memory access shape, but not the producer, full table extent, or semantic meaning of the bit.

`0x002B9364` is a 140-byte lookup routine. It first queries the object from literal-backed global `0x00433158` (`+0x35C` data pointer, `+0x360` count) through `0x002B48DC` using a 16-bit key and `0x94` record stride; on miss/empty it obtains a fallback table through `0x002C0EC4`, `0x002C0E9C`, and `0x002C0E4C` and performs another `0x002B48DC` search. It returns the selected record pointer in `r0`. The comparator reads only offsets `+0`, `+2`, and `+3` of each returned record. Search ordering, fallback table producer/lifetime, null-return conditions, and all transitive side effects remain helper boundaries; this task did not execute those helpers.

The comparator itself performs no writes, but its helpers read global/table state and may have additional effects. Valid key range for `0x002B9364`, record lifetime, aliasing, concurrency, invalid-pointer faults, and whether lookup results can be null are not bounded by this static slice.
