The title `00040000000e5c00` save directory in `%APPDATA%/Azahar/sdmc/Nintendo 3DS/00000000000000000000000000000000/00000000000000000000000000000000/title/00040000/000e5c00/data/00000001` is empty, including hidden entries. Its sibling `00000001.metadata` is 16 bytes, SHA-256 `b04a29a681dab6e6c33991eb1402cfe2fc488ebd768c54c55378cd36f1b1cf20`. The H2 `build/h2-runtime/profile-pristine-user` copy has the same metadata and no title save file. Inspected H2 autonomous original and patched profiles have no title save files. This is a bounded inventory, not proof that no other private save exists.

La captura runtime posterior confirmó que el juego reconoce el slot 0 y muestra el nombre `Flynn`.

The runtime comparison staged independent byte-identical copies under isolated original and patched `app/user` roots with adjacent private Azahar executables and required system data, never the live profile. The source and both copies had identical starting and ending hashes. Offline interworking, differential, caller-composition, and independent final-image review gates passed before Azahar launched.

The original and patched profiles loaded slot 0, showed `Flynn`, displayed `Load complete`, and reached `Map_Field3DManager` for 250 matched callbacks. Final captures show the Shinjuku Station — Underground 3D entrance and lower-screen map in both profiles. The paired empty-slot run rejected slot 1 without starting the save process; the cancel run returned to the title menu. Independent edge review accepted those results and confirmed that the current failure probes do not produce a real read error. The machine-readable evidence and limits are documented in [`h3-runtime-comparison.md`](h3-runtime-comparison.md). The emulator's GDB stub rejected a read of the field-context argument, so player coordinates/orientation were not recovered. H3 stays open until a real read-error response is observed.
