# 0x002C0EFC — experimental APT utility entry

Status: experimental isolated candidate, not integrated and not promoted. The entry calls the original wrapper 0x002B5A1C with six words (4, 0, 0, 0, 0, 0) and returns its unmodified 32-bit result. The wrapper and service remain original dependencies; see docs/agent-work/h2-apt-utility4-entry-contract.md.

The focused ARMv6K compilation and Unicorn comparison used the pinned original image against a controlled wrapper. Seeds 1 and 2 each passed 64 cases, including returned words 0, 1, 0x7fffffff, 0x80000000 and 0xffffffff, randomized incoming registers, flags and stack/data sentinels. The harness asserts the six words and ARM state at the wrapper, 8-byte wrapper stack alignment, restored stack, r4-r11 preservation, returned word, and unchanged caller-visible data and live stack. It independently detects wrong command, nonzero stack argument and discarded return. Reports, exact compiler invocations and SHA-256 values are in build/agent-work/H2-semantic/h2-apt-utility4-entry-candidate/run-001/seed-1a/report.json and seed-2/report.json. The first seed-1 attempt failed due to the harness initializing CPSR after banked SP; it was corrected and repeated as seed-1a.

This does not test Thumb callers, real service or wrapper side effects, the fallthrough entry, caller composition, runtime, or integration at the original address. A controlled wrapper is a stub and supplies return values without emulating service effects. Fixed direct wrapper address and ABI/linking must be independently reviewed before integration. No ledger status changes or whole-game equivalence are implied.
