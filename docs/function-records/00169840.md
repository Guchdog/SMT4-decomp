## Behaviour

1. **Top copy** (`0x00169854..0x001698A0`): four rows starting at `src`/`dst`,
   `0x200` bytes apart. Each row is copied in `0x20`-byte chunks (four
   `ldrd`/four `strd`); the loop is a do/while, so a non-positive width still
   copies one `0x20`-byte chunk. The pointer fix-up always yields the next row
   at `+0x200`.
2. **Bottom copy** (`0x001698A4..0x00169910`): the same four-row copy starting
   at `src + ((height - 4) << 9)` and `dst + ((height - 4) << 9)` (32-bit wrap).
3. **Band filter** (`0x00169914..0x0016A688`): starts at `src + 0x1000` /
   `dst + 0x1000` (row pitch `0x200`, band pitch `0x1000`). Each 4-byte lane
   loads eight source rows relative to the band base:
   `+0x600, +0x400, +0x200, 0, -0x800, -0x600, -0x400, -0x200` in that order.
   Rows `+0x600/+0x400` are copied to the destination *before* the
   `-0x800/-0x600/-0x400/-0x200` side is read and stored; rows `-0x400..+0x200`
   are rewritten by the shared four-centre-row kernel.
   - Per lane (`A/B/C/D/E/F` = outer_above, inner_above, centre_low,
     centre_high, inner_below, outer_below): `pair = uhadd8(C, D)`;
     `B_out = uhadd8(pair, A)`, `E_out = uhadd8(pair, F)`; each is replaced by
     the original `B`/`E` when `|A-C|` / `|F-D|` reaches `threshold_b` per byte.
     The centre outputs start from `pair` sharpened by
     `m = uhadd8(uhadd8(uhadd8(~E, B), 1), 1)`:
     `C_out = uqadd8(pair, uqsub8(m, 0x20))` then
     `uqsub8(..., uqsub8(0x20, m))`, `D_out = uqsub8(pair, uqsub8(m, 0x20))`
     then `uqadd8(..., uqsub8(0x20, m))`. Finally, for each byte where
     `|B-C| >= threshold_b`, `|D-E| >= threshold_b` or `|C-D| >= threshold_a`,
     all four outputs are replaced by their original row values; `B_out` also
     uses the `|A-C|` mask and `E_out` the `|F-D|` mask. The four selects are
     per-byte and compose to an OR of the masks. This is the same kernel as
     `0x001602DC`/`0x00167DCC` (reused as `filter_four_centre_rows`), not the
     signed `ssub8` variants `0x0015F7BC`/`0x0015FBA4`.
   - Per-byte arithmetic: `uhadd8 -> (a+b)>>1`, `uqsub8 -> max(a-b,0)`,
     `uqadd8 -> min(a+b,255)`, `uadd8 -> (a+b)&0xFF`,
     `usub8 -> (a-b)&0xFF` with GE = unsigned `a >= b`, `mvn`, `sel`.
     Every `sel` consumes the flags of the immediately preceding `usub8`.
4. **Loop control**: horizontal counter = `width_bytes - 0x10`, loaded from the
   stack each chunk. One `0x20`-byte chunk is always processed; it repeats while
   the signed counter stays `> 0` (`bgt`), filters four trailing lanes (`0x10`
   bytes) when it lands exactly on zero, and skips them when it goes negative
   (`blt`). The vertical counter starts at `height_bytes - 8`, is reduced by 8
   per band and loops while non-zero (`subs`/`bne`). Per band the source and
   destination advance by a net `0x1000` for aligned widths; heights not
   divisible by 8 and heights below 8 wrap for ~2^29 bands and are out of
   domain.
5. **ABI**: the original pushes only `{r0, lr}` and therefore clobbers
   callee-saved `r4-r11` (the same ABI violation as the sibling filters). The
   C++ candidate is a normal AAPCS function and preserves them.
