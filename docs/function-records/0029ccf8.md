# Function Record: script_vm_func_0029ccf8 (0x0029ccf8)

## Summary
- **Address:** `0x0029ccf8`
- **Original size:** 484 bytes (117 ARM instructions through the unconditional
  `pop`, then 16 bytes of literal data)
- **File:** `src/engine/leaf_batch41_c.cpp`
- **Role:** Status-menu model teardown plus status-widget reset, driven by the
  status work area and the field-view workspace. It is the status counterpart
  of the camp-menu close path and is called while leaving the status screen.
- **Status:** Semantically equivalent C++ (`non_matching`). The generated body
  is 796 bytes versus the 484-byte original, so the ledger row records
  `non_matching` with this semantic record. The historical `matching` label
  applied only to the previous raw-word block.

## Contract and Behavior
- **Signature:** `extern "C" u32 script_vm_func_0029ccf8(void)`
- **Arguments:** none (`r0`-`r3` are not read).
- **Return value:** `r0` is `3` on the state-3 early return and `2` on every
  path that reaches the widget reset. Callers in this tree declare the symbol
  `void` and ignore the result; the value is retained because it is the
  machine-visible contract.
- **Manager:** `g_StatusManager` at `0x0044e140`. Its work pointer is read from
  `+0x04` and dereferenced without a null check, so a live status work area is
  required.
- **Callee-saved registers:** `r4`-`r7` are preserved by the original; `r8`-`r11`
  are untouched. SP is balanced.

2. `sub_menu_state = *(u8*)(work + 0x1E67)`. Unless it is `3` or `9`, skip
   directly to the widget reset.
3. Model teardown:
   - `0x002A0DD4()` returns `*(u32*)(*(u32*)0x00447E88 + 0x194)`, the field
     view workspace subobject pointer.

     - otherwise the 12-byte stack record
       `{ u32 work+0x1E84, f32 work+0x1E88 + 1000.0f, f32 work+0x1E8C }` is
       passed by pointer to `0x0029411C(work+0x1E80, &record)`;

       `*(u32*)0x00447E88 + 0x134`.

     - a zero `work + 0x1E80` skips the shared disposal;

   - `0x002BDAC0(work + 0x038C, 5, 0)`

   - `0x002BF030(work + 0x04A4, 3)`

## Limits
- The helper bodies are replaced by deterministic stubs; their internal memory
  effects, real return values beyond the modelled ones, and the vtable slot 1
  implementation are not exercised here. Their contracts above come from their
  own pinned disassembly.
- The entity at `work + 0x1E80` is used only as `model[0] -> vtable[1]`; its
  type, the full vtable layout, and lifetime are not established.
- `work + 0x1E84` is copied as a raw word; no signedness or meaning is proven.
- `g_StatusManager+0x02` has no established name or producer in the existing
  `StatusManager` layout.
- Unaligned or unmapped work/entity memory, concurrent mutation, and natural
  game scheduling are outside the tested domain. The original dereferences the
  work pointer without a null check, so a null work area is not supported.
- Runtime equivalence, caller composition, and emulator validation were not
  performed; this record covers offline differential evidence only.
