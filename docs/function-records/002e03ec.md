- `r0..r3`: not read. The differential test seeds them with sentinels.

### Stack layout
The original copies a palette to its private frame before anything else:
`sub sp, sp, #0x30`, then
`ldm [0x004049E4]` (8 words) -> `sp+0x00..0x1C`,
`ldm [0x00404A04]` (3 words) -> `sp+0x20..0x28`, and
`ldr [0x00404A10]` -> `sp+0x2C`.
Those are the twelve contiguous words `[0x004049E4, 0x00404A14)`, i.e. the
copy of the 12-entry color table at `0x004049B4 + 0x30`. The loop reads this
copy, so a helper that rewrites the global table cannot affect the invocation.
`sp+0x2C` holds the twelfth entry, not a separate variable.

### Control flow
1. Copy the twelve palette words from `0x004049E4` to the frame.
2. `count = *(s32*)0x004C149C`; `count == 0` returns `0` without touching any
   helper or the render stack. Negative counts still push/pop (loop uses `bgt`).
3. Push: `pushed = ui_func_002c5f7c(5, 1)`; `previous = slots[count]`;
   `count += 1`; `slots[count] = pushed`; if `dirty != 0 || previous != pushed`
   call `flush_cb(pushed)` and clear `dirty`.
4. `ui_func_002c1d3c(*0x0044EA00, 0)`.
5. Loop `i = 0; i < *(s32*)0x004C149C; ++i` (re-read every iteration):
   `color = palette[i % 12] | 0x70`; call
   `func_0029705c(color, color, color, color, ...)` with the four vec3 corners
   `(rec+0x00, y, rec+0x08)`, `(rec+0x00, y, rec+0x14)`,
   `(rec+0x0C, y, rec+0x08)`, `(rec+0x0C, y, rec+0x14)` and
   `y = vertical_offset + 100.0f`. The 12 floats occupy `s0..s11` in that order.
6. Pop (re-reading `*0x0044EA00`): `previous = slots[n]`; `n -= 1`;

   `flush_cb(new_top)` and clear `dirty`; return the callback result or
   `new_top`.

Because the push stores `slots[n+1]` while comparing `slots[n]`, the pop sees
exactly the pushed value as its previous top; the only way to get a pop-only
callback is a helper that sets `dirty` again between push and pop (covered by
the test's draw-dirty case).

## Verification
`python tools/test_leaf_002e03ec.py` compiles the translation unit, relocates
the candidate body to `0x002E03EC`, and runs the pinned original against it in
separate Unicorn ARM machines with deterministic stubs at the original call
targets. It compares return `r0`, PC, final SP, `r4-r11`, `d8`, the ordered
call log (including all twelve `s0..s11` floats), full node/record/palette/
global pages, and the sorted non-stack write set.

33 differential cases cover: record count 0 (early return, null render base),
negative and `INT_MIN` counts, 1/2/12/13 records (palette wrap), NaN/Inf/-0.0/
subnormal record payloads, zero and `0xFFFFFFFF` helper results, render-stack
counts 0/1/8/12 (indexing past the four visible slots), dirty-only push,
previous-top mismatch, pop-only callback forced by a draw helper, draw-helper
count shrink/grow/negative updates (re-read loop bound), draw-helper rebasing of
`0x0044EA00` before the pop, and incoming offsets `0`, `+-100`, `+-1.5`,
`+-1e9`, NaN. Four negative controls (palette command bits, vertical step,
record stride, palette address) are each detected.

**Result:** `All 33/33 differential cases PASSED.`

## Unresolved / domain limits
- The three direct callees are modelled only by their observable register
  contract (`0x002C5F7C` returns the pushed command; `0x002C1D3C` is
  side-effect-only; `0x0029705C` consumes r0..r3 and s0..s11). Their internal
  behavior is out of scope for this record.
- The flush callback at `node+0x1C` is an indirect target with no static
  resolution; the test drives it with two deterministic stubs and verifies the
  exact target word is loaded from the node. Real callbacks may mutate any
  state the function does not re-read.
- The slot array length is unknown (the node exposes four slots but the flat
  indexing is unbounded); the reconstruction reproduces the original's
  unchecked `slots[count]` / `slots[count+1]` accesses exactly.
- The record payload floats are treated as opaque bit patterns; non-float
  bytes of the `0x1C`-byte record are not read here.
- No emulator/runtime session was run; equivalence is offline differential
  evidence only.
