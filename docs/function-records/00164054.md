## Behaviour

- This is the `0x001602dc` byte-wise edge filter with a 0x100-byte row stride:
  it starts at `base + 0x800` and each pass filters 0x20 bytes. Every 4-byte
  lane reads six rows at `centre{-0x300,-0x200,-0x100,0,+0x100,+0x200}` and
  rewrites only the four middle rows (`-0x200, -0x100, 0, +0x100`), in that
  store order.
- Per lane: `pair = uhadd8(C, D)`; `B_out` starts as `uhadd8(pair, A)` and
  `E_out` as `uhadd8(pair, F)`; each is replaced by the original `B`/`E` when
  `|A-C|` / `|F-D|` reaches `threshold_b` per byte. The two centre outputs start
  from `pair` sharpened by `m = uhadd8(uhadd8(uhadd8(~E, B), 0x01010101),
  0x01010101)`: `C_out = uqadd8(pair, uqsub8(m, 0x20202020))` then
  `uqsub8(..., uqsub8(0x20202020, m))`, `D_out = uqsub8(pair, uqsub8(m,
  0x20202020))` then `uqadd8(..., uqsub8(0x20202020, m))`. Finally, for each
  byte where `|B-C| >= threshold_b`, `|D-E| >= threshold_b` or `|C-D| >=
  threshold_a`, all four outputs are replaced by their original row values
  (`B`, `C`, `D`, `E` respectively) — the four selects are per-byte and compose
  to an OR of the masks.
- Packed arithmetic: `uhadd8`, `uqsub8`, `uqadd8`, `uadd8`, unsigned `usub8`
  (GE = unsigned `a >= b`, not `ssub8`), `mvn` and `sel`.
- Loop control: horizontal counter = `width_bytes - 0x10`, decremented by 0x20
  per chunk with a signed `> 0` branch. Exactly zero filters four trailing lanes
  (0x10 bytes, the block at `0x0016482c`..`0x00164bdc`); negative skips them
  after the unconditional first chunk. Each sweep advances one 0x800-byte band
  and the vertical counter (`height_bytes - 8`) is decremented by 8 per band,
  looping while non-zero (`subs`/`bne`); values of `height_bytes` that are not
  congruent to 8 modulo 8 never terminate and are treated as out of domain.
- ABI: the original pushes only `{r0, lr}` and therefore clobbers callee-saved
  `r4-r11` (shared ABI violation with `0x001602dc`). The C++ candidate is a
  normal AAPCS function and preserves them.
- Implementation note: the per-lane arithmetic is shared with the already
  reconstructed `0x001602dc` kernel (`filter_four_centre_rows`); only a
  stride-0x100 accessor (`filter_centre_row_100_at`) and the two band constants
  are new. The `pld` hints of the original are omitted (non-semantic).
