# Function Record: script_vm_func_001a8ffc (0x001a8ffc)

## Summary
- **Address:** `0x001a8ffc`
- **Size:** 1036 bytes (original span `[0x001a8ffc, 0x001a9408)`)
- **File:** `src/engine/leaf_batch34_c.cpp`
- **Role:** Script-VM inventory selection scheduler. On a pending-entry flag it
  resolves one entry id to a row and stores/plays its selected id. Otherwise it
  walks inventory indices `0x64..0x18F`, classifies each occupied index through
  the six-slot reader, and reports at most one selection per index through
  `0x002E8558` (kind-1 indices) or `0x002E876C` (kind-0 indices). The four
  selection counters in the root state are then cleared and a status word is
  returned.
- **Status:** Semantically equivalent C++ (`non_matching`). The compiled body is
  1584 B versus the 1036 B original: the two six-iteration slot loops are
  unrolled by the compiler and the branch chains are laid out differently. The
  ledger row is classified `non_matching` with this semantic record.

## Contract corrections found during implementation
- **The pending flag is a byte, the stored selection a word.** The block is read
  with `ldrb`/`strb` at `+0xAC` but read/written with `ldr`/`str` at `+0xB0`.
- **The state counters are signed 16-bit values, not bytes or words.** The
  original uses `ldrsh` for reads and `strh` for the exit clears; the
  comparisons against slot ids therefore compare a zero-extended `u16` with a
  sign-extended `s16`, so negative targets can never match.
- **The suppression slot at `[sp+0x30]` is persistent.** It is initialised once
  before the index walk and only written by the two self-reporting kind-1
  branches; it is not a per-index temporary. The per-index `[sp+0x28]` word is
  always `0` in both branches, so the `bic`/`bics` masks reduce to the
  `found`/suppression flags.
- **Kind-1 `other_id` stores the id and `other_amount` the amount.** The
  `strne`/`streq` pair after `cmp id, high_target` stores different fields, not
  the same word twice.
- **Kind-0 `sb` (`last_id`) holds a slot id, not a boolean.** `mov sb, r0` uses
  the zero-extended id; it also guards whether a later positive slot overwrites
  `last_id`/`other_amount`. The guard is not observable in the reported modes
  (modes that read `last_id` require fewer than two positive slots), but it is
  preserved.
- **`0x0028F460` runs only on kind-0 indices and after `0x00287ADC`.**
- **Kind values other than 0/1 are not consumed.** They skip both the slot walk
  and the `0x00287AB4` call.

## Limits
- Fixtures are synthetic: the root object, the four selection counters, the
  global pending/stored fields, the `0x00287B10` row and all slot records are
  scripted data, not captured game state.
- Every helper (`0x002C2B1C`, `0x00287B10`, `0x00295CBC`, `0x00287AB4`,
  `0x00299064`, `0x00287AFC`, `0x00287ADC`, `0x002990DC`, `0x0028F460`,
  `0x002E8558`, `0x002E876C`, `0x00287A68`) is stubbed; no real inventory
  lookup, UI reporting or pending-selection state is exercised.
- The original dereferences the `0x00287B10` result without a null check; a
  null row faults rather than taking a branch. The harness never feeds a null
  row to the early path.
- The semantic meaning of the reporter mode numbers and of the four counter
  fields is not established; they are treated as opaque control values.
- The candidate's frame layout and register allocation differ from the original
  (in particular the unrolled slot loops); only the documented ABI, call
  arguments, returned status and observable fixture memory are compared.
- No caller-composition, script-VM state-machine or whole-game runtime
  equivalence is claimed.
