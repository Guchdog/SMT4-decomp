# `0x0029F278` — stateful two-axis cursor updater

Status: readable production C++ with bounded direct, original-caller, and
accumulated-H2 overlay evidence. The ledger classification is `non_matching`.
Independent review also confirmed the statically recovered initialized H2
cursor setup and exercised its special query-ID path. The original span is
1536 bytes; the compiled C++ body is 1024 bytes followed by a four-byte local
mask table, so both fit inside the original function slot.

## Contract

Inputs are a valid cursor pointer in `r0` and a 32-bit sound-enable value in
`r1`. A nonzero byte at cursor `+0x62` returns zero immediately. Otherwise the
function initializes shared input globals, optionally updates each axis via
`0x001FF3C4`, reads a quotient/remainder pair from `0x002C615C`, adjusts axis
positions through `0x002892C0`, queries logical input, updates directional
bitsets and status bytes, stores the previous combined positions, and returns
one if either movement helper reported movement. It calls `0x002BC200(0x0100016C)`
only when movement occurred and `r1` was nonzero.

The typed divide API returns `u64`: quotient in `r0`, remainder in `r1` under
the ARM 32-bit ABI. The updater uses the quotient for first-axis clamping and
the remainder for second-axis adjustment and its boundary status case. The
first and second axis records start at cursor offsets `0` and `0x28`; their
fields and the ordered input-query/bitset behavior are detailed in the
[recovered contract](../agent-work/h2-0029f278-contract.md).

## In-place integration and evidence

The production definition is in `src/engine/leaf_batch46_b.cpp`. Its 15 ARM
call relocations target pinned original helper addresses. The sole local
`R_ARM_ABS32` at body offset `0x3FC` points to `.rodata.cst4`, the four-byte ID
mask table `08 04 01 02`; it is placed at `0x0029F678` immediately after the
1024-byte body. The body and table are written in place at the original even,
word-aligned entry `0x0029F278`. A word-aligned scan found no external ARM
`B`/`BL` or aligned absolute pointer into the original function interior. The
remaining 508 bytes of its original slot are preserved exactly, and the single
record IPS reapplies byte-for-byte.

Run002 passed 144 direct original-versus-patched cases, three compositions
through the original `TitleConfig_Calc` state-1 callback, and three more
compositions through the accumulated H2 image. The direct cases compare return,
fault/stop state, `r4-r11` and SP, full cursor bytes, input globals and counters,
helper call/argument order, and ordered non-stack writes. Caller cases run the
real updater and its direct binary helpers; the existing Calc harness models
unrelated outer service boundaries. A wrong-helper-target control was detected.

The supplemental H2 setup run005 passed 158 direct cases, all four original
`TitleConfig_Calc` compositions, all four accumulated-image compositions, and
the wrong-target control. Its fixture uses the recovered H2 axis-0 fields and
query IDs, reaches the `(6,15)` and `(5,14)` paths and nested calibration
queries, and skips initialized axis 1. The reviewer noted that the runner
observes nested helper calls but not the outer mode arguments; the mode
sequence remains supported by pinned static disassembly and corroborating
traces, rather than direct mode capture.

## Limits

Fixtures use synthetic aligned ordinary RAM and the pinned original helpers for
the standalone comparison. The accumulated comparison changes only this
function slot in the reviewed H2 image and keeps its outer Calc service
boundaries modeled. Physical input mapping/scheduling, object lifetime, runtime
sound delivery, malformed pointers, concurrent access, MMIO aliasing, discarded
read/fault order, and whole-game equivalence remain unproven. Runtime was not
run.
