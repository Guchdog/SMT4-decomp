## Behavior

node_index)` and converts each record's signed 16-bit elements 4/5 (byte
offsets `+0x8`/`+0xA`) to floats with `vcvt.f32.s32`:

1. Four icon points: node `i+0x59` -> `+0x328/+0x32C`, node `i+0x5D` ->
   `+0x330/+0x334` for `i = 0..3`.
2. Title point: node `0x61` -> `+0x300/+0x304`.
3. Three tab points: node `0x64-i` -> `+0x308+i*8` for `i = 0..2`.
4. Item positions: node `i+0x65` -> `+0x368+i*8` for `i = 0..3`.
5. Label Y values, element 5 only: node `0x6A` -> `+0x38C`, node `0x69` ->
   `+0x388`.
6. Tab end: copy the last tab Y to `+0x324` and extrapolate one spacing,
   `+0x320 = (tab2.x - tab1.x) + tab2.x`, evaluated as two VFP operations in
   that order.
7. `engine_func_002c4b30(panel, 0x2F4)` zero-fills bytes `0x000..0x2F3` after
   all geometry stores (the geometry lives at `>= 0x300` and survives).
8. Installs the idle state: `+0x2F4 = 0`, `+0x2F8 = +0x2FC = -1`,
   `+0x398/+0x39C/+0x3A0 = 0.0f`, `+0x394 = 4.0f`, `+0x390 = 4`; returns 4.

`0x59,0x5D,0x5A,0x5E,0x5B,0x5F,0x5C,0x60,0x61,0x64,0x63,0x62,0x65..0x68,0x6A,0x69`.

Related reader `ui_func_0033ceb8` (`0x0033CEB8`) consumes `+0x2F4/+0x2F8/+0x2FC`,
`+0x368`, `+0x388/+0x38C`, `+0x390/+0x394/+0x398/+0x39C/+0x3A0`, which fixes the
widths used here, but the meaning of individual layout nodes is not established.
