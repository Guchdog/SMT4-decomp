# Function Record: camp_func_001a7cac (0x001A7CAC)

## Summary
- **Address:** `0x001A7CAC`
- **Size:** 644 bytes (160 ARM instructions plus the literal word `0x00000604`
  at `0x001A7F2C`)
- **File:** `src/engine/leaf_batch45_a.cpp`
- **Role:** Initialises a 0x604-byte camp selection record. It clears the
  record, stores the 16-bit id and the slot argument, optionally claims the
  first free entry of the 24-slot camp list and sets the id's flag bits, copies
  either a table entry (modes 0/3) or a 0x34-byte detail record (mode 1) into
  the record, sets the entry's bit in the record bitmap, then tail-calls the
  selection updater.
- **Status:** Semantically equivalent C++ (`non_matching`). The compiled body
  is 1304 bytes versus the 644-byte original: the compiler unrolled the 24-slot
  scan, duplicated the entry lookup per control path, and split the mode-1
  byte copies. No byte-identity claim is made.

## Contract and Behavior

### Signature and ABI
```c
extern "C" u32 camp_func_001a7cac(void* record, u32 slot, u32 id, u32 mode);
```
- `record = r0`, `slot = r1`, `id = r2`, `mode = r3`.
- Return: the `u32` produced by `camp_func_0029c084(record)`, forwarded by the
  tail branch at `0x001A7F28`.
- Prologue `push {r4, r5, r6, r7, r8, sb, lr}` plus `sub sp, sp, #0x34`;
  epilogue `add sp, sp, #0x34`, `pop {r4, r5, r6, r7, r8, sb, lr}`, then
  `b 0x0029C084`. `r10`/`r11` are never touched.
- `id` is truncated with `uxth` before every use (stores, flag helpers, entry
  lookup), so the effective id is `(u16)id`.
- `slot` is stored as a byte (`strb`) and is written into the slot list as one
  byte; only its low 8 bits are observable.

### Control flow
1. `0x001A7CCC..0x001A7CD4`: after the zero-fill, store
   `record+0x46 = (u16)id` and `record+0x4A = (u8)slot`.
2. `0x001A7CD8`: if `mode == 3`, skip step 3.
3. `0x001A7CDC..0x001A7D20`: call `camp_func_002a8a08` with the zero-fill's
   return value (`record + 0x604`) still in `r0` (the callee ignores it); scan
   the 24 signed slot indices and replace the first negative one with
   `(u8)slot`; then `func_002032b8((u16)id, 1)` and
   `script_vm_func_001dd9f4((u16)id, 1)`.
4. `0x001A7D24..0x001A7D2C`: `entry = camp_func_002b9364((u16)id)` is called
   unconditionally, including the modes that do not copy it.
5. `0x001A7D2C..0x001A7D4C`: dispatch on `mode`:
   - `0` or `3` -> table-entry copy (step 6);
   - `1` -> detail-record copy (step 7);
   - any other value -> skip both copies (step 8).
6. `0x001A7D50..0x001A7E14`: copy the table entry fields listed above, force
   `+0x1C/+0x1E` to zero, then update the bitmap from `entry+0x38`.
7. `0x001A7E18..0x001A7EFC`: `camp_func_002883bc((u16)id, sp)` fills a
   0x34-byte stack record; copy the fields listed above, store the 32-bit word
   and the `+0x601` nibble, then update the bitmap from `entry+0x38`.
8. `0x001A7F04..0x001A7F28`: `script_vm_func_0029c950(record)`, copy
   `+0x2A = *(u16*)(record+0x0E)` and `+0x2C = *(u16*)(record+0x10)`, then
   tail-call `camp_func_0029c084(record)` and return its result.

Mode 3 therefore does not touch the camp list, but it still copies the table
entry and refreshes the record.

## Limits
- All eight helpers are stubbed. Their real bodies, the real camp list backing
  `0x002A8A08`, and the real table/detail records are not exercised.
- In modes 0/1/3 a null entry pointer from `0x002B9364` is outside the real
  caller's domain; the test maps address 0 with the same fixture so the
  synthetic null case remains comparable instead of faulting.
- Bit index `0xFFFF` makes the bitmap write land at `record+0x204B`, beyond the
  0x604-byte record but inside the test page; the original performs the same
  unbounded write. Real entries are expected to hold small indices.
- Caller composition (`0x0025630C`) is documented but not executed against a
  patched image, and no whole-game runtime equivalence is claimed.
