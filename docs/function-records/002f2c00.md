## What this span actually is

This row is **not a standalone function**. It is the second half of the
text-entry routine that begins at `ui_func_002f2a5c` (`0x002F2A5C`, ledger 420
bytes). Evidence:

- `0x002F2A5C` pushes `{r4, r5, r6, r7, r8, sb, sl, fp, lr}`, subtracts
  `0x14`, and the only epilogue in the whole span is at `0x002F2E18`
  (`add sp, sp, #0x14; pop {r4, r5, r6, r7, r8, sb, sl, fp, pc}`).
- The block at `0x002F2C00` reads `r4` (the object), `r6`/`r7` (its `x`/`y`
  words), `r8` (`object + 0x21`), `sb` (glyph table) and `sl` (`0x27`) without
  establishing any of them, and it pops registers it never pushed.
- A scan of every ARM `B`/`BL` in the pinned image finds only two callers of
  the span, both targeting `0x002F2A5C` (`0x00219C4C` and `0x002E6F5C`).
  Nothing calls `0x002F2C00` itself; it is reached by internal branches:
  - `0x002F2BC4` -> `0x002F2C00` (key-input entry)
  - `0x002F2B2C`, `0x002F2BFC` -> `0x002F2C94` (cursor-move entry)
  - `0x002F2C88` fall-through -> `0x002F2C94`
  - `0x002F2A7C` -> `0x002F2CF8` (redraw-only entry, `state == 1`)

Because the task scope owns only this half, the reconstruction exposes one
ordinary C++ function per real entry point and shares the redraw tail:

```c
extern "C" u32 ui_func_002f2c00(u8* object);  // 0x002F2C00 key input
extern "C" u32 ui_func_002f2c94(u8* object);  // 0x002F2C94 cursor move
extern "C" u32 ui_func_002f2cf8(u8* object);  // 0x002F2CF8 redraw only
```

## Contract, object layout and ABI

The first half establishes the entry state, so each entry function recovers it
from `object` and constants:

| Entry register | Value | Recovered as |
| --- | --- | --- |
| `r4` | object | the `object` argument |
| `r5` | `-1` on every entry | constant `-1` |
| `r6` | `*(s32*)(object + 0x00)` | `obj->x` |
| `r7` | `*(s32*)(object + 0x04)` | `obj->y` |
| `r8` | `object + 0x21` | `obj->name` address |
| `sb` | `0x004724F0` | glyph table base |
| `sl` | `0x27` | `kBackspace` |

Object layout (all words signed 32-bit; object created by `0x0025036C`):

```text
+0x00 s32 x                 text origin, also the returned base
+0x04 s32 y
+0x08 s32 state             0 = editing, 1 = confirmed, 2 = cancelled
+0x0C s32 cursor            0x00..0x25 grid glyph, 0x26 filler, 0x27 "BS", 0x28 "OK"
+0x10 s32 length            characters currently in name
+0x14 s32 capacity          maximum characters (9)
+0x18 s32 suppress_draw     non-zero skips the grid pass and is returned
+0x1C u8  extension[5]      fixed suffix copied by 0x0025036C (e.g. ".EP")
+0x21 u8  name[10]          capacity + terminating NUL
```

The pinned image's two callers pass `object` in `r0` and a string in `r1`; this
span never reads `r1`. The object is an effect-editor file-name field: the
callers build `"effect_editor/ep/"` + `".EP"` paths (`0x00219C24`). The first
half returns `void`; the value left in `r0` by this half is
`obj->x + 0x72` (or the raw `suppress_draw` word) and both callers ignore it.

## Behavior

### Key-input entry (`0x002F2C00`)

```text
if (key(0) == 0 && key(0x14) == 0) {          // short-circuit order preserved
    if (key(1) != 0 || key(0x16) != 0)        // key(0x16) only when key(1) == 0
        obj->state = 2;
    if (obj->cursor == 0x26) obj->cursor = 0x27;
    apply(-1);
} else {
    cursor = obj->cursor;                      // signed word
    if      (cursor == 0x28) { if (obj->length > 0) obj->state = 1; }
    else if (cursor == 0x27) apply(0x2A);      // delete
    else if (cursor == 0x26) { obj->cursor = 0x27; apply(-1); }
    else                     apply(cursor);
}
terminate + redraw
```

`0x002BFFBC` is the key predicate (`u32 key` -> "pressed" word); each call and
its order is observable.

### Cursor-move entry (`0x002F2C94`)

```text
if (obj->cursor == 0x26) obj->cursor = 0x27;
apply(-1);
terminate + redraw
```

### `apply(index)` (`0x002F2CA4..0x002F2CE8`)

```text
if (index > 0x29) {                 // signed compare -> delete/backspace
    if (obj->length > 0) {          // signed compare
        obj->length -= 1;
        return;                     // redraw follows
    }
}
if (index == -1) return;            // CMN r5, #1
if ((u32)index >= 0x26) return;     // unsigned compare
obj->name[obj->length] = glyph_table[index];
if (obj->length < obj->capacity) obj->length += 1;   // signed compare
```

The glyph store happens even when `length == capacity`, so `name[capacity]` is
temporarily overwritten and then re-terminated by the redraw.

### Redraw (`0x002F2CEC` / `0x002F2CF8`)

```text
if (terminate) obj->name[obj->length] = 0;          // 0x002F2CEC only
draw(obj->x, obj->y, 0x86, 0x14);                   // 0x002829F0
sprintf(text[0x14], "%s%s", obj->name, obj->extension);  // 0x002BE7FC (Thumb)
draw(obj->x, obj->y + 0x18, 0x86, 0x44);            // 0x002829F0
if (obj->suppress_draw != 0) return obj->suppress_draw;
for (cell = 0, row = 0; row < 3; ++row)
    for (column = 0; column < 13; ++column, ++cell)
        if ((u32)cell < 0x26)
            *(volatile u8*)0x004724C9 = glyph_table[cell];
return (u32)obj->x + 0x72;
```

The redraw-only entry skips the terminating store, so a caller that sets
`state = 1` first sees the name's pre-existing bytes up to the first NUL.

## Static data and helpers

- `0x004724F0`: `"ABCDEFGHIJKLMNOPQRSTUVWXYZ0123456789-_"` (38 glyphs, NUL
  terminated). Loaded on every entry; not modified.
- `0x004724C9`: a single `.data` byte that receives `glyph_table[cell]` once per
  drawn cell (38 stores). No other literal in the image holds this address.
  The store is kept `volatile` so all 38 writes remain observable; nothing in
  this span reads the byte back.
- `0x002BFFBC`: `u32 key` -> pressed word (reads a global key table).
- `0x002829F0`: UI-element/text constructor; called twice per redraw with
  `(x, y, 0x86, id)`. Its return value is unused here.
- `0x002BE7FC`: Thumb `sprintf(char* dst, const char* fmt, ...)`, reached with
  `blx` in the original. The destination is the `0x14`-byte stack local, whose
  content is not consumed by the span.

## NOP-patched call sites

Four instruction slots are `mov r0, r0` (`0xE1A00000`) with fully prepared
arguments around them. They execute as no-ops in the pinned image, so the
reconstruction omits them (documented, not reproduced):

| Site | Prepared arguments | Apparent intent |
| --- | --- | --- |
| `0x002F2D30` | `(x+4, y+4, 0, text)` | draw the formatted name |
| `0x002F2DA0` | `(x + 4 + 10*col, y + 0x18 + 12*row, cursor==cell ? 4 : 0, 0x004724C9)` with the cell glyph already stored | draw one grid glyph |
| `0x002F2DF4` | `(x+0x72, y+0x3C, cursor==0x27 ? 4 : 0, "BS")` | draw the backspace label |
| `0x002F2E14` | `(x+0x72, y+0x48, cursor==0x28 ? 4 : 0, "OK")` | draw the confirm label |

Because the calls are absent, the `cursor` comparisons that feed them have no
observable effect either. The literal pool still holds `"%s%s"`, `"BS"`,
`"OK"`, `0x004724C9` and `0x004724F0`; these bytes are part of the original
span but the C++ emits its own literals.

## Validation

`tools/test_leaf_002f2c00.py` compiles `src/engine/leaf_batch45_b.cpp`, resolves
the entry symbols, and runs each one against the pinned original started at the
same entry address with the first half's register/stack context. It compares:

- return `r0`, continuation PC (`0x90000000` trap) and final `r4-r11`
  (sentinel values on both sides);
- the original's stack-frame reclamation (`sp == frame + 0x24`) versus the
  candidate's balanced stack;
- the ordered call log: every key predicate (argument and short-circuit order),
  both draw calls with all four arguments, and the sprintf call with the format
  string and both `%s` arguments read as C strings;
- the bytes written into the sprintf destination;
- the complete `0x1000`-byte object page (every field, the extension, the name
  buffer and untouched sentinels) and the complete `0x1000`-byte `.data` page
  that holds the glyph table and the shared probe byte.

Coverage: both predicate short-circuit orders, keys `0`, `0x14`, `1`, `0x16`,
`state = 2`, "OK" with positive/zero/negative length, "BS" with 3/1/0/negative
length, the filler cursor `0x26`, every glyph index `0..0x25`, index boundaries
`0x29`, `0x2A`, `0x1000`, `0x7FFFFFFF`, `-1`, `-2`, `-0x1000`, `-0x80000000`,
lengths `0`, `8`, `9`, `10`, `-1`, zero/negative capacity, `suppress_draw`
`0`, `1`, `-1`, `0x7FFFFFFF`, `0x80000000`, and signed `x`/`y` wrap-around.

Negative controls mutate the grid bound, the "OK" cursor value and the returned
`x` offset; each mutant is detected.

## Limits

- The first half (`ui_func_002f2a5c`, 420 bytes) is still a raw block, so the
  whole-function caller composition and the runtime scenario are untested.
- The two callers are debug/development paths (`effect_editor/ep/`); their
  runtime reachability in the retail flow is unverified.
- The removed call targets are unknowable from the image. Their argument shapes
  and the `"BS"`/`"OK"` literals identify them as label draws, but no address or
  helper contract can be recovered.
- `0x002829F0` is modeled from its arguments and caller relationship; its
  internals and the consumer of `0x004724C9` are outside this span.
- No emulator run was performed; all evidence is offline Unicorn differential
  testing with deterministic helper stubs.
