# `0x002B88C4` — touch-region registration

## Reconstruction

`camp_func_002b88c4(group_id, node_id)` obtains `IfTouchWork*` from `0x0043DCB4`, resolves the node through `camp_func_002bf6d0`, and reads the signed region count at `work + 0x64A`. Counts at or above `0xC8` return `-1`. It then chooses one of two four-halfword record forms:

- With a non-null node pointer at `node + 0xC`, copy signed halfwords from `node + 8/+0xA` followed by the first two signed halfwords of the pointed rectangle.
- With a null pointer there, copy signed halfwords from `node + 8/+0xA`, then copy node halfwords `+4/+6` with bit 15 cleared.

The record is written at `work + count*8 + 0xA`; the global work pointer and signed count are reloaded before the second capacity check, then count is incremented at `+0x64A` and the old count is returned. The table stores 200 eight-byte records before the count field. The helper assumes a valid manager chain, node and optional rectangle pointer. It does not validate any of them.

The compiled C++ body for this function is 156 bytes with one `R_ARM_CALL` to `0x002BF6D0`, within its original 220-byte slot. `0x002BF6D0` itself remains the original 64-byte ARM body. Volatile accesses preserve the original work-pointer/count reloads and ascending halfword store order. The ordered write traces match. These accesses are not an atomic transaction or synchronization primitive. Ledger status for `0x002B88C4` is `non_matching`.

## Contract limits

The fixtures use nonnegative counts through the full-capacity boundary, group `0x1D`, node `0x572`, readable 32-bit pointers and a valid writable touch-work area. Other node groups, invalid pointer behavior, concurrent mutation, full input scheduling and runtime reachability are outside the tested domain. Volatile preserves the observed access order, but no lock, atomic transaction, or inter-thread synchronization is established.
