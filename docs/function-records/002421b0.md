# Function Record: ui_func_002421b0 (0x002421b0)

## Summary
- **Address:** `0x002421b0`
- **Size:** 436 bytes (103 ARM instructions through the unconditional `pop`,
  plus six literal words: `0x00600001`, `0x0044ea80`, the `"GENERAL %d"`
  string and `0x00400002`)
- **File:** `src/engine/leaf_batch41_c.cpp`
- **Role:** UI context poll / create step for the global UI context block at
  `0x0044EA80`. It either polls the active context object and dispatches on its
  state word, or clears the owner word, registers 22 generic entries and creates
  a fresh object.
- **Status:** Semantically equivalent C++ (`non_matching` in the ledger).
  Verified with a Unicorn ARM differential test across 45 cases and four
  negative controls.

## Contract and Behavior

### Signature and frame
```c
extern "C" u32 ui_func_002421b0(u32 flags);
```
- `r0` (`flags`): only bit 3 (`0x8`) is tested; it gates the generic-entry loop
  on the create path. `r1`..`r3` are never read.
- Prologue: `push {r4-r8,lr}`, `sub sp, #0x140`; epilogue `add sp, #0x140`,
  `mov r0, r6`, `pop {r4-r8,pc}`. The return word lives in `r6`.
- Local frame: `sp+0x004..sp+0x0CB` is the 0xC8-byte text buffer handed to
  `0x00323660`; `sp+0x0CC` holds its returned id; `sp+0x0D0` is the latched
  state (initialised to 0 at entry); `sp+0x0D4` holds the `0x00318DF8` value;
  `sp+0x0D8..sp+0x13F` is the 0x68-byte name buffer; `sp+0x000` is the outgoing
  stack word for `0x002DE2A4`.
- `r7` is loaded with the absolute address `0x0044EA80` from the literal pool,
  not with a pointer to the literal.

### Owner word set: `*(u32*)0x0044EABC != 0` (0x002421DC..0x00242218)
1. `0x002F8270(*(u32*)0x0044EAC0)` - poll the active object.
2. Re-read `+0x40` and latch `state = *(u32*)(object + 8)`.
3. Re-read `+0x40` and call `0x00323660(object, text)`; the return (`kind`) is
   stored at `sp+0x0CC`. The helper renders the object label into `text` and
   returns the id word at `[[object+0x30]]` (0 when `object+0x30` is null).
4. Re-read `+0x40` and call `0x00318DF8(object)`; the signed return is stored at
   `sp+0x0D4`.
5. When the latched state is 1: `0x002473AC(*(u32*)0x0044EAC0)`, clear `+0x40`,
   `0x0024736C(*(u32*)0x0044EABC)`, clear `+0x3C`. Both global words are
   re-read immediately before their call. The latched state still drives the
   dispatch below, so a destroyed object is dispatched with its last state.

### Owner word null (0x0024221C..0x00242298)
1. Store 0 to `+0x3C` (the value is already 0; see Limits).
2. When `(flags & 8) != 0`, run `i = 0..21` (`r5 = 0x16`, unsigned `bhi`
   termination). Each iteration formats `"GENERAL %d"` with `i` through
   `0x002BE7FC(name, "GENERAL %d", i)` and then calls
   `0x002DE2A4(*(u32*)0x0044EABC, name, 8, i, <stack f32 bit pattern 0>)`.
   `+0x3C` is re-read for every registration, so a helper that writes the word is
   observed by the following iteration. The fifth argument is a *stack* word:
   the callee loads it with `vldr s16,[sp,#0x28]` after its 0x28-byte frame, so
   the caller must not pass it in `s0`.
3. `new_obj = 0x0030ED58(*(u32*)0x0044EABC)`, publish it at `+0x40` and store
   `{0xBA, 0x1C}` at `new_obj+0` / `new_obj+4`.

### Dispatch on the latched state (0x002422B4..0x0024233C)
| state | result |
| --- | --- |
| 2 | `0x00400000` |
| 1 | `0x00400002` after the selection step |
| anything else (including the just-created object, whose state word is 0) | `0x00600001` |

State 1 with `kind == 8`:
```c
0x00242964(*(u32*)0x0044EA94, *(u32*)0x0044EAA4);   // release selected node
0x0025CC14(*(u32*)0x0044EA9C, &value, 4, 4);        // commit u32 with kind 4
```
State 1 with any other kind:
```c
container = *(u32*)0x0044EA94;
selected  = 0x00246A4C(container, 0u - value);      // unsigned -value
previous  = *(u32*)0x0044EAA4;                      // loaded after the lookup
if (previous != selected) {
    0x00242964(*(u32*)0x0044EA94, previous);        // +0x14 re-read
    0x0025C888(*(u32*)0x0044EA94, *(u32*)0x0044EAA4, selected); // both re-read
}
```
`0x00246A4C` walks the sibling chain at `container+0x8C` (`+0xAC` links) and
returns the node at the unsigned index, or 0 when the index runs past the end.
Because `value` is negated with `rsb r1,r0,#0`, a positive `value` becomes a
huge unsigned index (always 0) and a negative `value` becomes a small forward
index.

### Corroborating sibling
`0x00243234` (reconstructed separately, record
`docs/function-records/00243234.md`) is the same poll/create skeleton without the
inline dispatch, and its wrapper `0x00242364` dispatches with exactly the same
status words `0x00600001` / `0x00400000` / `0x00400002` (literals at
`0x00242460`). `0x002421b0` differs by inlining that skeleton, dropping the
`0x003243BC(object, out+0xC8)` call, and keeping only the `kind == 8` /
generic-kind forms of the selection step.

## Limits
- All twelve callees are stubbed by contract; their real bodies (allocation,
  text formatting, tree locking) are not exercised here. The return values they
  supply cover every branch, but the internal effects are not recovered.
- The create path passes the *already-cleared* owner word (`0`) to `0x002DE2A4`
  and `0x0030ED58`. The pinned bodies of those helpers dereference their first
  argument (`ldr r0,[r5,#8]`, `ldr ip,[r4]`), so this path would fault in the
  shipped code unless a caller initialises `+0x3C` beforehand. The behaviour is
  reproduced as-is; the test models the stubs returning normally.
- The redundant store of 0 to `+0x3C` at `0x0024222C` is elided by the compiler
  in the candidate because the branch predicate already proved the word zero
  and no call intervenes. Final memory is identical; only a concurrent writer to
  that global between the load and the store could observe the difference.
- The second core register of `0x0030ED58` is dead at entry; the original leaves
  a path-dependent leftover there (the loop's name-buffer pointer after a
  registration iteration, the call argument otherwise). It is not part of the
  contract and is not compared.
- No runtime (emulator) verification was performed for this batch; the evidence
  is offline differential emulation with stubbed callees.
