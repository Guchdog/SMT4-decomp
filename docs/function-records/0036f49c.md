# engine_func_0036f49c (0x0036F49C)

## Contract and ABI

```c
extern "C" u32 engine_func_0036f49c(void* object);
```

- `r0` (`object`, kept in `sb`) is the container. `r1..r3` are not read; there
  are no stack arguments. The prologue saves
  `{r4,r5,r6,r7,r8,sb,sl,fp,lr}` and the epilogue restores the same set, so
  `r4-r11` and `sp` survive.
- No direct caller exists in `extracted/exefs/code.bin` (no `bl`/`blx` reaches
  `0x0036F49C`), so the leftover `r0` is never consumed. The reconstruction
  returns that architected value only so the differential register comparison
  is exact; it is not a semantic result.
- There is no null guard. A null object, or an object whose first word does not
  carry the required tag bits, sets the container register to zero and the
  routine then reads and writes the "container" fields through low addresses
  `0x2C`, `0x30`, `0x38..0x50`, `0x18`, `0x1C`. That is reproduced literally.

## Behavior

```text
container = (object != 0 && (*(u32*)object & 0x20000009) == 0x20000009)
            ? object : 0;

if (*(u32*)(container + 0x2C) != 0) return;      // r0 untouched
*(u32*)(container + 0x2C) = object;              // original pointer, even when container == 0

format_word = *(u32*)(container + 0x30);         // cached once (r8)

for (u32 index = 0; index < 6; ++index) {
    slot    = container + 0x38 + (index & 0xFF) * 4;
    offset  = *(u32*)slot;
    entry   = offset != 0 ? slot + offset : 0;   // 32-bit wrapping

    if (*(u32*)(entry + 0x18) != 0) {            // already materialised
        *(u32*)(entry + 0x1C) = 0;
        continue;                                // r0 = format_word
    }

    format = format_word != 0 ? format_word : 0x02010000;
    format = (format >> 16) << 16;               // top 16 bits only

    size = *(u32*)(entry + 0x08);
    if (size == 0)
        size = (*(u32*)(entry + 0x00) * *(u32*)(entry + 0x04)
                * *(u32*)(entry + 0x14)) >> 3;   // 32-bit multiply, logical shift

    if (format == 0x02010000) {
        field  = entry + 0x0C;                   // pre-indexed writeback
        rel    = *(u32*)field;
        buffer = rel != 0 ? field + rel : 0;
        r0     = c25f0(buffer, size);            // return observed only here
    } else if ((s32)format < (s32)0x02010000) {
        difference = format - 0x01010000;
        if (difference != 0) { r0 = difference; continue; }
        buffer = callback(0x10000, 0x101, object, size);
        field  = entry + 0x0C;
        rel    = *(u32*)field;
        if (rel != 0) {
            source = rel + field;
            if (source != 0) {
                memcpy(buffer, source, size);    // 0x002ACD38
                c25f0(buffer, size);
            }
        }
        *(u32*)(entry + 0x18) = buffer;
        *(u32*)(entry + 0x1C) = 0x10000;
        r0 = 0x10000;
    } else {
        difference = format - 0x02010000;
        if (difference != 0x10000 && difference != 0x20000) {
            r0 = format;
            continue;
        }
        kind   = format & 0x30000;
        buffer = callback(kind, 0x101, object, size);
        field  = entry + 0x0C;
        rel    = *(u32*)field;
        if (rel != 0) {
            source = rel + field;
            if (source != 0) queue(source, buffer, size);  // 0x002A69B0
        }
        *(u32*)(entry + 0x18) = buffer;
        *(u32*)(entry + 0x1C) = kind;
        r0 = kind;
    }
}
```

Details preserved from the ARM:

- The tag test is `bics r1, r2, r1` with `r2 = 0x20000009`, i.e. all three bits
  must be set; extra bits are ignored. The tag word is read only when the
  object pointer is non-null (`cmp r0,#0` / `ldreq` + branch).
- The initialisation guard at `+0x2C` returns before writing anything. The
  store that follows writes the original `r0`, not the rewritten container.
- `+0x30` is read exactly once per call into `r8`; helpers that change it do not
  affect later iterations.
- The slot index is masked with `0xFF` before scaling, the loop bound is six,
  and the counter comparison is signed (`blt`). Slots may contain relative
  offsets that wrap below zero; the resolution is plain 32-bit addition.
- The entry pointer is not guarded: a zero slot resolves to address 0 and the
  `+0x18`/`+0x1C` accesses then use the low page, as on the original. Each
  field is re-read from memory every iteration, so the `+0x18` store of an
  earlier pass changes the behaviour of a later slot that aliases the entry.
- The format word is truncated with `lsr #16`/`lsl #16` after the zero default,
  and the dispatch uses signed `bge`. Only `0x02010000`, `0x01010000`,
  `0x02020000`, and `0x02030000` reach a helper; every other value falls
  through with `r0` equal to the subtraction result (lower half) or the
  truncated format (upper half).
- The `0x02010000` arm uses `ldr r0,[r5,#0xC]!`, so the resolved pointer is
  `field + rel` with `field = entry + 0x0C`. A zero `rel` passes address 0 to
  the helper.
- The `0x01010000` arm checks both `rel != 0` and `source != 0` (the second is
  the `adds`/`beq` zero test of `rel + field`) before copying and calling the
  veneer a second time.
- The `0x02020000`/`0x02030000` arm likewise skips the queue call when `rel` is
  zero or when `rel + field` wraps to zero. It stores the kind word
  (`format & 0x30000`) in `+0x1C`, not the full truncated format.
- The cached arm stores zero in `+0x1C` and does not consult the format word or
  the size fields.
- The allocator's return value is stored even when it is null; in that case the
  entry stays "not materialised" and a later alias of the same entry dispatches
  again.

## Static data and helpers

- `0x0044E330`: 32-bit function-pointer slot, also declared as
  `g_TextureAllocCallback` in `src/engine/block_133568.cpp` with the signature
  `void* (*)(u32 size, u32 align, u32 flags, u32 extra)`. This call site passes
  `(size_or_kind, 0x101, object, byte_size)`; that exact allocator contract is
  not recovered here, so the reconstruction treats the slot as an opaque
  four-argument function pointer.
- `0x002C25F0`: 4-byte veneer (`b 0x00147830`) reconstructed in
  `src/engine/leaf_batch36_c.cpp`. `0x00147830` reloads the word at
  `0x0040B5AC`, asks `0x002AD4F0` for the process/thread request base, and
  tail-branches to `0x00147C0C`, which stores the pair in the CP15 TLS block and
  issues `SVC 0x32`. The kernel service is not recovered; the call is therefore
  declared as `s32 (void* address, u32 size)` and its return is used only as the
  observed `r0` of the `0x02010000` arm.
- `0x002A69B0`: appends the three incoming words (`r0`, `r1`, `r2`) to a
  manager queue record (`*(0x004C6290)+0x9C`, index at `+0x20`, base at
  `+0x18`, stride 7 words after a leading byte). The reconstruction forwards
  `(resolved source, buffer, byte size)`.
- `0x002ACD38`: byte copy from `r1` to `r0` for `r2` bytes (small-size ladder
  plus a word loop). Return value is not observed at this call site.
- The only indirect calls are the `0x0044E330` allocator slot and the direct
  veneer. There are no vtable or computed code targets.

## Validation

`tools/test_leaf_0036f49c.py` compiles `src/engine/leaf_batch41_c.cpp`, extracts
the `engine_func_0036f49c` body (516 bytes including its literal pool), resolves
its four `R_ARM_CALL` relocations to stubs at the original target addresses, and
runs the pinned original against the candidate in identical Unicorn ARM
machines. It compares:

- return `r0`, continuation PC (`0x90000000` trap), final `sp`, and the `r4-r11`
  sentinels;
- the ordered call log with every register argument for `0x002C25F0`,
  `0x002A69B0`, `0x002ACD38` and the allocator (none takes a stack argument);
- the full `0x00000` low page, object page, source-data page, allocator output
  page and the `0x0044E330` slot page;
- every emulated write outside the private stack.

Coverage: the re-entrancy guard; null-object and every tag-bit combination
(each required bit missing, zeros, and extra bits); the low-page container path
with cached entries, default dispatch, and raster allocate/copy/publish;
zero and nonzero format words; format truncation (`0x0201ABCD`, `0x0101FFFF`,
`0x0202FFFF`); all six loop indices including six slots aliasing one entry and
one slot whose relative offset wraps across the 32-bit address space into the
low page; cached and fresh mixes; explicit sizes `0`, `1`, `0x80000000`,
`0xFFFFFFFF`; derived sizes with ordinary, overflowing and wrap-to-zero
products; every dispatch arm with absent, present, low-page and wrap-to-zero
relative sources; signed format boundaries `0x7FFF0000`, `0x80000000`,
`0xFF000000` and non-matching values around `0x02010000`; and a null allocator
result where a repeated entry dispatches twice.

Negative controls mutate the tag mask, the default format constant, the derived
size shift, the kind mask, the slot count, the relative-data offset, and the
resolved-source zero guard; each mutant is detected.

## Limits

- The four helpers are deterministic stubs; the `SVC 0x32` service behind
  `0x002C25F0`/`0x00147830` and the allocator behind `0x0044E330` are not
  recovered, and the queue consumer of `0x002A69B0` is outside this span.
- The low-page container path is exercised under a test mapping that makes
  address 0 readable and writable; on hardware those accesses are a latent
  fault, exactly as in the original.
- The `u32` return is the original's dead `r0`; no caller in `code.bin` reads
  it, so it is not a semantic return value.
- No emulator or whole-game run was performed; evidence is offline Unicorn
  differential testing with deterministic stubs.
