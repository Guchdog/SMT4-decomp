# Function Record: func_00159028 (0x00159028)

## Summary
- **Address:** `0x00159028`
- **Size:** 840 bytes (original span `[0x00159028, 0x00159370)`; the final 128
  bytes, `0x001592F0..0x0015936F`, are an embedded reciprocal lookup table)
- **File:** `src/engine/leaf_batch45_b.cpp`
- **Role:** Extended-precision mantissa division core. It consumes two 96-bit
  extended operands (a sign/exponent word plus a 64-bit explicit-integer-bit
  mantissa) and produces the quotient sign word, the 64-bit quotient mantissa,
  the biased exponent difference and a three-bit guard word. The pinned caller
  at `0x00155A08` invokes it, then immediately calls `engine_func_00159370`
  (`0x00159370`) with the results to round/renormalise them.
- **Status:** Semantically equivalent C++ (`non_matching`). The compiled body is
  1228 B versus 840 B: the translation keeps the register-accurate arithmetic
  (including all ARM carry dependencies) but the compiler chooses a different
  register allocation, keeps the lookup table in its own read-only section and
  emits 64-bit helper sequences for the carry emulation. The ledger row is
  classified `non_matching` with this record.

## Contract and Behavior

### Signature and ABI
The original is reached through a private register convention, not AAPCS:

```text
in:  r0 = dividend sign/exponent word   r1:r2 = dividend mantissa (hi:lo)
     r3 = divisor sign/exponent word    r4:r5 = divisor mantissa (hi:lo)
out: r0 = quotient sign (bit 31, other bits zero)
     r1:r2 = quotient mantissa (hi:lo)
     r3 = biased exponent difference (dividend exponent - divisor exponent
          + 0x3FFF, then -1 on the renormalising return)
     r6 = guard word (low bits folded below the 64-bit mantissa)
```

The reconstruction exposes the same values as a C++ parameter/return contract:

```c++
struct ExtendedDivideResult {
    u32 sign;         // r0
    u32 mantissa_hi;  // r1
    u32 mantissa_lo;  // r2
    u32 exponent;     // r3
    u32 guard;        // r6
};

extern "C" ExtendedDivideResult func_00159028(
    u32 a_exp, u32 a_hi, u32 a_lo, u32 b_exp, u32 b_hi, u32 b_lo);
```

- Word 0 / word 3 layout: sign in bit 31, a 24-bit exponent in bits 23..0.
  Bits 30..24 are ignored (`bic ip, r0, #0xff000000`).
- The mantissa words are 64-bit values with an explicit integer bit in bit 63.
  Normalised operands therefore have the divisor's top byte in `0x80..0xFF`.
- The original **does not preserve `r7`**: it preloads `r7 = divisor_exp &
  0xFFFFFF` *before* `push {r7, r8, fp, lr}`, so the epilogue's saved-r7 slot
  returns that value. `r7` is therefore a scratch/incidental output, not a
  callee-saved register. `r8`, `r11` (fp), `r9` and `r10` are preserved.
  `r4`, `r5`, `r6` and `r12` are scratch.
- The routine makes no calls (direct or indirect) and performs no stores other
  than its own push/pop frame.

### Control flow
1. **Exponent/sign word** (`0x00159028..0x00159048`):
   `sign = (a_exp ^ b_exp) & 0x80000000`;
   `exponent = (a_exp & 0xFFFFFF) - (b_exp & 0xFFFFFF) + 0x3FFF`.
   Both are saved on the stack (`push {r7, r8, fp, lr}` / `push {r0, r3}`).
2. **Reciprocal estimate** (`0x00159050..0x001590B4`): indexes the byte table by
   the divisor's most significant byte, fits a reciprocal with two Newton
   steps, splits `a_hi` right by one bit into `r2`'s top bit, and seeds the low
   accumulator `r0` with the bit shifted out of `a_lo`
   (`movhs r0,#0x80000000` / `movlo r0,#0` after `rrxs r2,r2`).
3. **Three multiply-subtract refinements** (`0x001590B8..0x0015923C`): each
   group removes `quotient_digit * divisor * 2^shift` from the running
   `r1:r2:r0` remainder and accumulates the quotient into `r4:r5`. The shifts
   are `19/13`, `3/29`, `19/13`, `3/29` and `16/16`. Each group ends with the
   original's `sublo`/`subshs` pair; only one of those conditional instructions
   executes and they differ in whether they update the flags, which the
   translation models explicitly.
4. **Three 96-bit compare/shift guard steps** (`0x00159250..0x001592B4`): the
   compare `(r1:r2) - divisor` contributes one guard bit to `lr` per step and
   conditionally keeps the subtraction; the remainder is then shifted left.
   The third step is not followed by a shift.
5. **Round and return** (`0x001592B8..0x001592EC`): set the sticky bit from the
   remaining remainder, add the guard word into the mantissa
   (`r6 += lr << 28`, `r2 = r5 + carry`, `r1 = r4 + carry`).
   - If the resulting `r1` has bit 31 set, return immediately with the saved
     exponent (no renormalisation), via `popmi {r0, r3, r7, r8}` /
     `popmi {fp, pc}` (`0x001592CC`).
   - Otherwise shift `r6:r2:r1` left by one and return with
     `exponent - 1` (`0x001592D4..0x001592EC`).

### Embedded reciprocal table
`add r6, pc, #0x220` (`0x00159048`) computes `0x00159048 + 8 + 0x220 =
0x00159270`; the indexed byte is `table[divisor_mantissa_hi >> 24]`.
- Indices `0x80..0xFF` address `0x001592F0..0x0015936F`, the genuine 128-byte
  reciprocal table (`~128 / (1 + i/128)`).
- Indices `0x00..0x7F` address `0x00159270..0x001592EF`, i.e. the instruction
  bytes immediately preceding that table. Only a non-normalised divisor can
  produce such an index.
The reconstruction embeds all 256 bytes verbatim in
`func_00159028_detail::kDivisorLut`, so normalised *and* non-normalised inputs
select exactly the same byte as the pinned original.

## Contract corrections found during implementation
- **`sublo`/`subshs` are not a flag-preserving pair.** `sublo` is a plain `SUB`
  (no S bit) while `subshs` is `SUBS` + HS. Exactly one executes, and the
  following `sbc` observes whichever carry state results. Modeling both as a
  flag-setting subtraction (or both as flag-preserving) changes quotients.
- **Most single-word borrow propagations have no S bit.** The five `sbc
  r1,r1,r7,...` instructions do not update the carry; only the `sbcs r2,...`
  instructions do. The C++ uses an `sbc_nf` helper that preserves the carry.
- **`adc lr,lr,lr` / `adc fp,fp,fp` do not set flags.** The subsequent `movhs`
  selects therefore use the carry from the preceding `sbcs`, which the
  translation captures explicitly before the add.
- **`r7` is not callee-saved.** See the ABI section: the original saves a
  precomputed exponent fragment in the r7 slot before the prologue push.
- **`ldr r7,[sp,#0xc]` at `0x00159130` is dead.** Its value is overwritten by
  `lsr r7,r1,#0xf` at `0x00159140`; the reconstruction omits it.
