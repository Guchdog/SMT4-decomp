# Function Record: func_0011c87c (0x0011C87C)

## Summary
- **Address:** `0x0011C87C`
- **Size:** 704 bytes (span `[0x0011C87C, 0x0011CB3C)`, including the eight
  literal-pool words at `0x0011CB1C..0x0011CB38`)
- **File:** `src/engine/leaf_batch34_c.cpp`
- **Role:** Reads the ARM11 shared-page `DATETIME_0` / `DATETIME_1` snapshot,
  combines its "milliseconds since 1900" value with the delta between the
  current `svcGetSystemTick` and the tick stored in the snapshot, and returns a
  signed 64-bit millisecond value aligned into the 2000..2100 window.  The only
  direct caller treats the result as a millisecond delta and adds it to the
  64-bit clock at `0x0044E630`.
- **Status:** Reconstructed as readable C++ and **semantically verified**
  against the pinned original.  The candidate body is 600 bytes (9 call
  relocations, no data relocations) and is not byte-identical, so the ledger
  row is `non_matching` and this record carries the semantic evidence.

## Contract and Behavior

### Signature and ABI
```c
extern "C" s64 func_0011c87c(void);
```
- No entry register is read; `r0`-`r3` are caller-clobbered scratch.  The
  returned 64-bit value is in `r0:r1`.
- Callee-saved `r4-r11` and `SP` are restored.  `r12` is neither saved nor
  preserved by the original, which matches AAPCS.
- Nine direct `BL` relocations, no indirect calls and no data relocations:
  `0x002B5B94` three times, `0x002B5F90` twice, `0x002B5B44` three times and
  one `svc #0x28` (`nn::os::GetSystemTick`).  The ABI of the three helpers is
  recovered below.
- A raw-word scan of the pinned `.text` finds exactly one branch reference to
  `0x0011C87C`: `BL 0x0011C87C` at `0x002C5878` inside `0x002C586C`
  (`engine_func_002c586c`).  There is no literal-pool function pointer.
  `0x002C586C` stores `now + func_0011c87c()` into its 16-byte output after
  scaling the returned value through `0x0011C184`.

### Control flow and arithmetic
```text
t2000  = make_time(2000,1,1,0,0,0,0)          // 0x002B5B94, result via r0
clock  = (u64)[0x0044E634] << 32 | (u32)[0x0044E630]
Qfirst = scale_1e6(t2000 - clock)             // 0x002B5F90
t2100  = make_time(2100,1,1,0,0,0,0)
t2000b = make_time(2000,1,1,0,0,0,0)          // third call, independent
Qspan  = scale_1e6(t2100 - t2000b)

tick     = GetSystemTick()                    // svc #0x28, once
selector = [0x1FF81000]
record   = 0x1FF81020 + (selector & 1) * 0x20
N, S, F, B = record fields above
delta = tick - S                              // wrapping u64
Q1    = signed_divmod(1000 << 32, (s64)F).quotient
H1    = middle64_signed(delta * Q1)           // ms since the record update
X     = 3600000 - H1                          // wrapping s64
frac  = (X > 0) ? (u32)X : 0
Q2    = signed_divmod((s64)frac << 32, 3600000).quotient
H2    = middle64_signed(B * Q2)
D     = H1 + H2 + N - Qfirst                  // wrapping u64
result = Qfirst + signed_divmod((s64)D, Qspan).remainder
```

- `scale_1e6(x)` is `0x002B5F90(&(x * 1000000), 0x431BDE82D7B634DB, 18)`:
  the high 64 bits of the signed product, arithmetic `>> 18`, plus one when the
  input is negative.  With that magic the stage is effectively a truncating
  division by 1,000,000, so the two results are the signed millisecond deltas.
  The `* 1000000` product is kept as a wrapping 64-bit multiply.
- The two hand-expanded multiply blocks at `0x0011C9EC` and `0x0011CAA4` keep
  bits 32..95 of the signed 128-bit product, i.e. the Q32.32 middle word, not
  the high 64 bits.  With random and boundary operands the rest of the original
  agrees with `(low64 >> 32) | (high64_signed << 32)`.
- The original adds the shared-page `N` to the first product and subtracts it
  again before the clamp (`H1 + N - N`); the candidate performs the same
  wrapping operations, so the two additions cancel exactly and only `H1` feeds
  the clamp.
- `0x002B5B44` is the signed 64-bit divmod: quotient in `r0:r1`, remainder in
  `r2:r3`.  The first two results are used only for their quotient (the
  remainders are ignored); the last call's quotient is ignored and its
  remainder is the result.  The candidate keeps each call as one `BL` with the
  register pairs bound in inline assembly, so the helper's actual remainder is
  consumed rather than recomputed in C++.
- When `X == 0` both the `> 0` clamp and a `>= 0` clamp select zero; that
  boundary is therefore not separable, and the candidate uses `> 0` as
  encoded by the original's `movlt`.
- `0x002B5B94` returns its destination pointer and the original reads each
  64-bit timestamp back through `r0`; the candidate does the same.  Its epoch
  is 2000-01-01 00:00:00.000, verified by running `0x002AD714` with the pinned
  code (2000-01-01 returns 0 and 2100-01-01 returns 3,155,760,000,000).

### Helper contracts
- `0x002B5B94` is a 56-byte wrapper over `0x002AD714(out, year, month, day,
  hour, minute, second, millisecond)`; the first four arguments travel in
  `r0-r3` and the last four on the stack.  It returns `out`.
- `0x002B5F90` is already reconstructed in `src/engine/leaf_batch31_c.cpp` as
  `s64 func_002b5f90(const s64* value, s64 mul, u32 shift)` under
  `pcs("aapcs")`: high 64 bits of the signed product, arithmetic shift, plus
  one for a negative input.
- `0x002B5B44` is the local `__aeabi_ldivmod` variant (it calls the unsigned
  divider `0x002AA504`), negating operands and results to obtain truncating
  signed division and a remainder with the dividend's sign.
- `nn::os::GetSystemTick()` is the revision's `svc #0x28` wrapper at
  `0x001240C0` (`nop; svc #0x28; bx lr`).

No field name beyond the ARM-visible role and the 3dbrew record layout is
claimed.

## Domain Limits
- All three direct-call helpers and `nn::os::GetSystemTick` are stubbed, so
  their internals are not exercised.  In particular, the zero-divisor and
  `INT64_MIN / -1` behaviour of `0x002B5B44` is whatever the stub returns (the
  runner models truncating division and returns `(0, 0)` for a zero divisor);
  the real helper's edge behaviour remains unverified.
- The shared page is filled by the test.  The real `DATETIME` records are
  written by PTM in device memory; the double-buffer selection and any torn
  read across an update are not modelled, because the original's `cmp r3, r3`
  self-comparison never retries.
- The units and meaning of `N`, `S`, `F` and `B` follow 3dbrew's "Configuration
  Memory" page, not a runtime capture.  The 1,900 epoch of `N` and the 2,000
  epoch of `0x002B5B94` are consistent with the observed arithmetic but were
  not checked against hardware.
- `0x0044E630` is only read in this unit; the writer that gives the game clock
  its runtime value was not located.  The test drives the clock directly.
- The candidate emits `nn::os::GetSystemTick()` as a call instead of an inline
  `svc`; the test supplies the revision's wrapper so both paths execute the
  same `svc #0x28` with the same values.  The extra call frame is not
  observable in the compared state.
- The original's stack frame layout is not reproduced (600 vs 704 bytes).  The
  test excludes the private stack and only compares the architectural state and
  observable memory.
- No runtime/emulator execution, staging or production promotion is claimed.
