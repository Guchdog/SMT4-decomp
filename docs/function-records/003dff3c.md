# Function Record: func_003dff3c (0x003dff3c)

## Summary
- **Address:** `0x003dff3c`
- **Size:** 400 bytes (original span `[0x003dff3c, 0x003e00cc)`): ARM code
  `0x003dff3c..0x003e00ab` plus an eight-word literal pool at
  `0x003e00ac..0x003e00cb`.
- **File:** `src/engine/leaf_batch41_c.cpp`
- **Role:** Emits a 10-word (or 14-word) rendering descriptor from a small
  source structure and, when `submit` is non-zero, forwards the descriptor to
  the shared continuation entry `0x0022673c`. The descriptor contains two
  opaque header words, an optional four-word extension, a 24-bit fixed-point
  value with a substituted low bit, two opaque trailer words and a packed pair
  of truncating binary16 values.
- **Status:** Semantically equivalent C++ (`non_matching`). The compiled body is
  584 B versus the 400 B original; Clang reorders the stores, rebuilds every
  unaligned field from byte loads, expands the float comparisons with integer
  predicates and combines the binary16 helper inline. The ledger row is
  classified `non_matching` with this semantic record.

## Contract and Behavior

### Signature and ABI
```c
extern "C" u32 func_003dff3c(const u8* object, u32* out, u32 submit, u32 extra);
```
- `object = r0` (copied to `r12`/`ip` and never modified), `out = r1`,
  `submit = r2`, `extra = r3`.
- Return value is `out` after the last store when `submit == 0`, otherwise the
  return value of the tail call to `0x0022673c`.
- Preserves `r4`; the candidate additionally uses `r5-r8` but restores them.
  Final `sp` equals the entry value (the original only does `push {r4,lr}` /
  `pop {r4,lr}` or `pop {r4,pc}`).
- All stores are 32-bit, in increasing address order, and use
  `str ... [r1], #4` post-increment; the output cursor is byte-addressable but
  always advanced by four.
- `0x0022673c` is a separate ARM entry point that the ledger folds into
  `func_00226690` (its `push {r4,r5,r6}` prologue at `0x22673c` and
  `bx lr` at `0x22679c` are distinct from `0x00226690`'s own epilogue at
  `0x226730`). It is declared as `func_0022673c` and stubbed in the harness.

### Control flow and calls
1. `0x003dff44`: `if (object[0] == 0) goto step 9`. No word is written, but
   the tail call still happens.
2. Store `0x00e40103` (literal `0x003e00ac`) and `0x00010100` (literal
   `0x003e00b0`).
3. If `extra != 0` (`cmp r3,#0` at `0x003dff58`, branch at `0x003dff68`) store
   `0`, `0x00200080` (literal `0x003e00b4`), `0`, `0`.
4. `v = *(f32*)(object + 0x04)`; store `(ToFixed24(v) & ~1) | low_bit`, where
   `low_bit = (object[1] == 0) ? 1 : 0`.
5. Store `0x000f008b` (literal `0x003e00c4`).
6. `a = *(f32*)(object + 0x0c)`, `b = *(f32*)(object + 0x10)`;
   store `ToHalf(a + b) | (ToHalf(-a) << 16)` (the `vadd.f32 s0, s1, s0` at
   `0x003dfff0` is `a + b`, and `vneg.f32 s0, s1` at `0x003e0034` is `-a`).
7. Store `0x000f0130` (literal `0x003e00c8`).
8. `0x003e0088`: if `submit == 0` return the cursor.
9. `0x003e0094`: `continuation = *(u32*)(object + 0x14) + 0x7c` and tail call
   `0x0022673c(continuation, cursor, 1)`.

`ToFixed24` (`0x003dff7c..0x003dffc0`):
```text
bits = bit_cast<u32>(v)
if (!(v > 0.0f))                 return 0      # VCMPE + BLS, also covers NaN
if (((bits << 1) >> 24) == 0xFF) return 0      # exponent all ones: inf/NaN
scaled = v * 16777216.0f                       # literal 0x003e00bc (2^24)
if (!(bit_cast<u32>(scaled) < 0x4b800000))     # literal 0x003e00c0
                                 return 0x00FFFFFF   # mvn r0,#0xff000000
return (u32)scaled                             # VCVT.U32.F32, toward zero
```
The `cmp r3,r0` at `0x003dffb4` is a signed compare of two non-negative bit
patterns, hence the unsigned `<` above; the exactly-2^24 case saturates.

`ToHalf` (`0x003dffdc..0x003e0030`, reused at `0x003e0034..0x003e0074`):
```text
bits = bit_cast<u32>(v)
if ((bits & 0x7fffffff) == 0)  return (bits >> 31) << 15
exponent = (bits << 1) >> 24
rebased  = exponent - 0x70
if (rebased < 0)               return (bits >> 31) << 15
return (u16)((rebased << 10) | ((bits >> 13) & 0x3ff) | ((bits >> 31) << 15))
```
This is truncating IEEE binary16 with a `0x70` exponent rebase. Because the
original ORs the unclamped `rebased << 10` and then applies `uxth`, exponent
values above `0x1f` wrap into the sign/upper bits exactly as the `u16` cast
does. `+0`, `-0`, denormals and every value below `2^-15` become signed zero;
`inf`/`NaN` are *not* special-cased and produce `0x3c00`/`0x3e00`-style
patterns from their mantissa bits.

## Contract corrections found during implementation
- The tail call is `0x0022673c`, not the ledger boundary `0x00226690`: the
  target is an interior entry with its own prologue and `bx lr`, reached by a
  tail `b` after `pop {r4,lr}`.
- The VFP literal addresses use the `Align(PC,4)` (`instruction + 8` here)
  base: `0x003dff80` loads `0.0f` from `0x003e00b8` and `0x003dffa8` loads
  `2^24` from `0x003e00bc`; the sign the other way would have produced the
  denormal words at `0x003e00b4` and `0.0f`. Confirmed by emulating the
  pinned image (a `0.5` input yields the fixed value `0x00800000`).
- The `bics`/`beq` zero test is redundant with the `rebased < 0` test for
  `+/-0`; both produce `sign << 15`.
- The `0x4b800000` literal appears twice: once as raw bits for the `cmp`
  (`0x003e00c0`) and once as the multiply constant (`0x003e00bc`).

## Limits
- Fixtures are synthetic; `object`, the pointer at `object+0x14` and the
  continuation stub are not captured game data.
- `0x0022673c` is stubbed (`bx lr` plus a deterministic word write and return);
  no real descriptor submission is exercised.
- The meaning of the opaque words (`0x00E40103`, `0x00010100`, `0x00200080`,
  `0x000F008B`, `0x000F0130`) is not established; they are treated as opaque
  32-bit payload words, not as floats or pointers.
- The 24-bit and binary16 conversions are recovered exactly, including their
  truncation and saturation quirks, but their source-domain meaning (colour,
  normalised coordinate, packed attribute) is not claimed.
- FPSCR is recorded but not compared. The original performs one VFP compare;
  Clang additionally lowers the integer zero test in the binary16 helper to
  `vcmp.f32` and speculates the out-of-range `vcvt` onto the saturating path.
  That changes FPSCR[31:28] and can set the sticky `IOC` bit even where the
  original skips the conversion. FPSCR is not consumed by this routine or its
  caller.
- No caller-composition, rendering, or whole-game runtime equivalence is
  claimed.
