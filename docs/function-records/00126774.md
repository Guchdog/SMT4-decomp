# Function Record: engine_func_00126774 (0x00126774)

## Summary
- **Address:** `0x00126774`
- **Size:** 428 bytes (101 ARM instructions through the unconditional
  `pop {r4-r8, sb, sl, pc}` at `0x00126904`, plus the six literal words at
  `0x00126908..0x0012691F`)
- **File:** `src/engine/leaf_batch41_c.cpp`
- **Role:** Claims the first free entry of the four-pointer voice table of the
  active stream slot, gates the request on the sound-system state, asks the
  manager virtual at `AsdSoundSystem + 0x184` to publish a voice into that slot,
  then seeds the voice envelope with `0.0f` and retargets it to
  `(target, level_scale)`. The result is the claimed slot index or `-1`.
- **Status:** Semantically equivalent C++ (`non_matching`). The compiled body is
  432 bytes versus the 428-byte original (different register allocation, a
  signed `(level - 64)` conversion instead of unsigned conversion plus
  subtraction, `vmul`+`vadd` instead of `vmla`, and literal-pool placement). No
  byte-identity claim is made.

## Contract and Behavior

### Signature and ABI
```c
extern "C" s32 engine_func_00126774(void* object, u32 level, u32 target);
```
- `object = r0` (saved in `r8`), `level = r1` (saved in `r5`),
  `target = r2` (saved in `sb`); no float arguments.
- Return: `s32` in `r0`.
- Prologue `push {r4, r5, r6, r7, r8, sb, sl, lr}` / `vpush {d8}` at
  `0x00126774..0x00126788`; every exit restores `d8` and all eight core
  registers (`0x00126900..0x0012690C`). The function clobbers only `r0-r3`,
  `ip`, `lr`, `s0-s3`, `s16` and the caller-saved `s0`; `s16`/`d8` is preserved
  for the caller.
- `level` is clamped with an **unsigned** compare (`cmp r5,#0x7F` /
  `movhi r5,#0x7F`); the caller supplies a byte in practice. `target` is
  forwarded verbatim as the second argument of `0x002BCD94`.

### Global and object layout (offsets only, as evidenced by the ARM)
- `0x004E1F68`: global `AsdSoundSystem` base. The single literal at
  `0x00126908` is loaded into **both** `r7` and `sl` (two identical pool
  references), so every `system` argument below is that address.
- `AsdSoundSystem + 0x1218` (`0x004E3180`): pointer to the active stream slot
  (`add r0,r7,#0x1000` / `ldr r0,[r0,#0x218]` at `0x0012678C..0x00126790`).
- Active stream slot: four `void*` voice pointers at `+0x20, +0x24, +0x28,
  +0x2C`; byte `+0x3B` gates the kind-3 lookup.
- `AsdSoundSystem + 0x184` (`0x004E20EC`): manager sub-object passed to
  `0x002BCDF8`.
- Voice object: only the pointer is handled here. `0x002BCD94` itself rewrites
  `+0xA0..+0xAC`; `0x002BCDF8` may call `0x0014BEF8`, which sets the enable
  byte at `+0x85`.
- Literal pool values: `0x004E1F68` (`0x00126908`), `0x00000000` (0.0f,
  `0x0012690C`), `0x42800000` (64.0f, `0x00126910`), `0x3C810204`
  (0x1.020408p-6, `0x00126914`), `0x3F800000` (1.0f, `0x00126918`),
  `0x40000000` (2.0f, `0x0012691C`).

### Control flow and calls
1. `0x00126794..0x0012679C`: `active_stream == NULL` returns `-1`
   (`mvneq r0,#0` then `pop` via `0x00126900`).
2. `0x001267A0..0x001267E0`: scan `+0x20, +0x24, +0x28, +0x2C` in order and
   keep the first null index in `r4` (`0..3`). `r4` starts as `mvn #0`; when all
   four are non-null the `bne` at `0x001267E0` returns `-1`.
3. `0x001267E4..0x001267F8`: `engine_func_002bf85c(system)`; on `0` return the
   claimed slot index (`r4`).
4. `0x001267FC..0x00126810`: `engine_func_00141940(system, object)`; on `0`
   return the claimed slot index.
5. `0x00126814..0x0012681C`: the **same** lookup is issued a second time (the
   pool value is live in both `sl` and `r7`); this second result is the kind.
6. `0x00126820..0x00126864`:
   ```text
   gate = stream->byte_3B;
   if (gate != 0) {
       if (kind == 3) {
           if (func_00138800(object) != 0) goto proceed; else return slot;
       }
       if (kind == 2) goto proceed;
       return slot;
   }
   if (kind == 3) return slot;
   if (kind == 2) goto proceed;
   return slot;
   ```
   So the request proceeds exactly when `kind == 2`, or when
   `kind == 3 && gate != 0 && func_00138800(object) != 0`. Every other kind
   (including `0`, `1`, `4`, `0x80000000`, `0xFFFFFFFF`) returns the slot index.
7. `0x00126868..0x0012687C`: `func_002bcdf8(AsdSoundSystem + 0x184,
   &voices[slot], object, 0)`. The slot address is `table + 0x20 + slot*4`
   (`add r6,r6,r4,lsl #2` then `add r1,r6,#0x20`).
8. `0x00126880..0x00126888`: `allocated = (result & 0xFF) == 0`
   (`tst r0,#0xFF` + `moveq/movne r7`).
9. `0x0012688C..0x001268CC`: level scale:
   ```text
   value = (level > 127u) ? 127u : level;      // `movhi` on unsigned compare
   value == 0          -> 0.0f                 // `vmoveq s16, s0` (s0 = 0.0f)
   otherwise           -> 1.0f + ((f32)value - 64.0f) * 0x1.020408p-6
   clamp               -> 2.0f when the raw word is signed-greater than
                          0x40000000 (`vmov r0,s16; cmp r0,#0x40000000;
                          vldrgt s16,[...2.0f]`)
   ```
   The clamp is a signed comparison of the float bit pattern, not a
   floating-point comparison.
10. `0x001268D0..0x001268E0`: re-read `voices[slot]`; when non-null call
    `func_002bcd94(voice, 0, s0)` where `s0` still holds the 0.0f loaded at
    `0x00126890` — the computed scale is **not** passed to this first call.
11. `0x001268E0..0x001268F0`: `vmov.f32 s0, s16` (the scale), re-read
    `voices[slot]`, and when non-null call
    `func_002bcd94(voice, target, scale)`.
12. `0x001268F4..0x00126904`: `return allocated ? slot : -1`
    (`cmp r7,#0` / `mvneq r4,#0` / `mov r0,r4`).

The slot pointer is re-read from memory before each `0x002BCD94` call, so a
helper that changes the slot is observed exactly like the original.

- `0x00141940` (40 B): `[system+4]` -> `[+0x3C]` -> `0x002A6D58`, then
  tail-branches to `0x002A6D28` when the chain exists. The kind values observed
  elsewhere are `1` (id range) and `3` (forward range); `0` means the chain is
  unavailable. `2` is accepted here as the direct-start form.
- `0x00138800` (120 B): reads `AsdSoundSystem + 0x1218` again and its `+0x3B`
  byte, then looks the object up in the `AsdSoundSystem + 0x250` list through
  `0x00132CC8`; returns `1` when found, otherwise the result of `0x002AF648`.
  Only its zero/non-zero value is consumed here.
- `0x002BCDF8` (64 B): reads the vtable at `[registry]` and calls
  `[[registry]+8](registry, slot, object, 0, arg3)`; when the virtual's low
  result byte is zero and the published slot is non-null it calls
  `0x0014BEF8(slot)`. Both of its own exits return `0`, so the "allocation
  failed" branch at `0x001268F4` is unreachable with the shipped helper; the

  stub return values.
- `0x002BCD94` (100 B): clamps `s0` against its minimum constant, rewrites

  which is why the original can reuse `s0` (0.0f, then the scale) across the

## Limits
- All five helpers are stubbed. The real bodies, the `AsdSoundSystem + 0x184`
  virtual table, the object list at `+0x250` and the voice internals beyond the
  listed offsets are not exercised.
- The indirect target read from `[[registry]+8]` is logged and varied in the
  fixture but not executed as ARM code; only its slot-publication contract is
  modelled.
- The 2.0f clamp at `0x001268CC` is unreachable for every accepted level: after
  the `0..127` clamp the largest scale is `1 + 63 * 0x1.020408p-6 = 1.9921`, so
  the signed bit-pattern test never fires. The clamp is preserved for fidelity
  but no test can distinguish a wrong threshold; it is documented rather than
  claimed as differentially covered.
- The allocation-failure return at `0x001268F4` is unreachable with the shipped
  `0x002BCDF8` (both exits return `0`); it is verified only through the stub
  status values.
- The candidate uses `vcvt.f32.s32` of `(level - 64)` instead of the original's
  `vcvt.f32.u32` followed by a 64.0f subtraction. Both are exact over the
  accepted `0..127` domain, confirmed by the exhaustive byte sweep. `vmul` +
  `vadd` matches the original's `vmla` because VFPv2 `VMLA`/`VMLS` round the
  product before the add (fused `VFMA` only exists from VFPv4).
- Caller composition (`0x00105FA8`, `0x001241A8`) is documented but not
  executed against a patched image.
- No whole-game runtime equivalence is claimed.
