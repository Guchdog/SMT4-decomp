## Contract and Behavior

- `layout = r0`, `type_slot = r1`. The record pointer is `*type_slot`; the

- Returns the final `layout->max_alignment` in `r0` (the original leaves the

4. `0x00148ffc..0x00149070`: resolve sub = self-relative field at `+0x0C`.

## Limits
- The only direct callee, `0x002C3290` (`engine_func_002c3290`), is modelled by
  a deterministic `strlen` stub; its body is not reconstructed here. No indirect
  calls, imports or globals are involved.
- The original calls `strlen` with a null pointer when a `0x04000000` record has
  a zero name field. The stub returns 0 for null, which matches the arm's
  `strlen(NULL)` behavior only as far as this test models it; a real runtime
  would fault. Caller data in the pinned build is expected to set the field.
- Byte identity is not claimed (724 vs 1208 bytes). The difference is compiler
  code generation: `.rodata` switch tables and strength-reduced reservation
  arithmetic.
- Fixtures are synthetic. No real type table, caller, allocator or engine
  context is exercised, and no emulator, caller-composition or whole-game
  equivalence is claimed.
