# `0x002BF41C` — task-registration lookup

## Reconstruction

`battle_func_002bf41c` in [`leaf_batch32_c.cpp`](../../src/engine/leaf_batch32_c.cpp) takes a task handle in `r0` and returns a boolean-like word. It reads the bucket-table pointer from `0x004E3CF4`, selects bucket `handle >> 20` from a 4,096-entry table with 8-byte entries, then follows the linked list. Each node stores its task handle at `+0x28` and next-node pointer at `+0x4C`. A matching handle returns `1`; an empty bucket or exhausted list returns `0`. A null handle uses bucket zero and can match a node whose stored handle is zero.

The helper performs reads only, preserves `r4-r11` and SP, and uses no floating-point registers. It assumes the registry pointer and traversed nodes are readable; it has no cycle, null-registry, or pointer validation. The C++ definition and direct callers now use the typed `u32(void*)` ABI.

The compiled body occupies 68 bytes with no relocations. It differs from the original bytes, so the ledger is `non_matching`.

## Contract limits

The test lists are well-formed, acyclic and sentinel-terminated by null next pointers. Cycles, unreadable pointers, registry teardown races, concurrent mutation, malformed task nodes, and system scheduling are outside the tested domain. The readiness caller check uses its original body and controlled memory fixtures, not an emulator session.
