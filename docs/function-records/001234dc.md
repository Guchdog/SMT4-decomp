# Function Record: func_001234dc (0x001234dc)

## Summary
- **Address:** `0x001234dc`
- **Size:** 408 bytes (original span `[0x001234dc, 0x00123674)`)
- **File:** `src/engine/leaf_batch28_a.cpp`
- **Role:** Emit the renderer parameters for one or both of two views of the
  global render state at `0x004C6290`. The mode argument selects the views,
  the view's scene-node type selects class/scale values, node and state fields
  are folded into three 32-bit parameters, and the view's boolean is inverted
  after the renderer call.
- **Status:** Semantically equivalent C++ (`non_matching`). The compiled body
  is 648 bytes versus the 408-byte original (the compiler duplicates the
  renderer call for the view-0/view-1 paths and uses a different frame layout);
  the ledger row is classified `non_matching` with this semantic record.

## Contract and Behavior

### Signature and ABI
```c
extern "C" void func_001234dc(u32 mode);
```
- `mode = r0`; no other register input is read.
- Return: none (`void`). The original restores `sp`, `r4-r11` (`r4, r5, r6,
  r7, r8, sb, sl, fp`) and returns with `pop {r4, r5, r6, r7, r8, sb, sl, fp,
  pc}` from a 12-byte frame.
- Sole direct caller: `0x0010ED48` inside `ui_func_0010ec6c` (0x0010ec6c),
  which passes `0x402`. No literal word or function-pointer reference to
  `0x001234dc` exists elsewhere in `code.bin`.

### Mode selection
The loop runs `i = 0, 1`. For each iteration it accepts:
- `mode == i + 0x400`, or
- `mode == 0x402` (the shared "both views" value).

Therefore `0x400` -> view 0 only, `0x401` -> view 1 only, `0x402` -> both,
and any other value -> no work. The comparison is unsigned equality against
`mode - 0x400 - 2 == 0` for the shared case.

### State layout (fixed global `0x004C6290`)
Offsets are used as raw evidence; no higher-level type is claimed:
- `+0x008/+0x00C`: view-0/view-1 source coordinate (`+i*4`).
- `+0x128/+0x12C`: view-0/view-1 scene-node pointer (`+i*4`).
- `+0x130`: extra scene-node pointer read only by the `0x702` path.
- `+0x134/+0x138`: view scale/bias slots used by the extent term (`+i*4`).
- `+0x140/+0x144`: view limit slots subtracted from the node extent (`+i*4`).
- `+0x148`, `+0x13C`: extra-node extent and bias used by the `0x702` path.
- `+0x14C/+0x150`: view boolean (`+i*4`); passed to the renderer twice
  (register and stack copy) and then replaced by its logical inverse.
- `+0x164`: renderer state, compared as `0x700`, `0x701`, `0x702`.

### Scene-node layout
- `+0x004`: base value added at the end of the first parameter.
- `+0x008`: signed type id, classified below.
- `+0x00C`: multiplier used for both the extent fold and the third parameter.
- `+0x010`: extent term.
- `+0x014`: mode; exactly `0x10000` contributes `0x100` to the flags,
  otherwise `0x300`.

### Type classification
The original compares the type with `0x8057` using a signed `bgt`:

| type | class bits | scale multiplier |
| --- | --- | --- |
| `0x8051` | 1 | 3 |
| `0x8056` | 4 | 2 |
| `0x8057` | 3 | 2 |
| `0x8058` | 0 | 4 |
| `0x8D62` | 2 | 2 |
| other | 0 | 0 |

The equality tests are exact 32-bit comparisons after subtraction. The signed
direction is not observable in this table: every negative type falls into the
low branch and then fails both equality tests, exactly like an unsigned value
below `0x8000`; both produce class 0 / scale 0.

### Arithmetic and branch structure
For the selected view `i`:
```text
extent  = node[0x10] - state[0x008+i*4] - state[0x140+i*4]
scaled  = node[0x0C] * extent + state[0x134+i*4]
paramC  = node[0x0C] * typeScale
paramA  = typeScale * scaled + node[0x004]
flags   = classBits | (node[0x014] == 0x10000 ? 0x100 : 0x300)
```
All operations are 32-bit wrapping add/subtract/multiply.

For `i == 0` only, depending on `state[0x164]`:
- `0x700`: `flags |= 0x40`.
- `0x701`: flags keep only the class/mode bits (no `0x40`/`0x20`).
- `0x702`: `flags |= 0x20` and:
  ```text
  extraExtent = extra[0x10] - state[0x008] - state[0x148]
  paramB      = typeScale * (extra[0x0C] * extraExtent + state[0x13C])
                + extra[0x004]
  ```
  where `extra = *(u8**)(0x004C6290 + 0x130)` (`state+0x130`).
- any other value: `flags |= 0x40`.

`paramB` is zero otherwise, including every `i == 1` call.

### Direct call
One call per selected view to `func_001376a4` (0x001376A4), a 7-argument
wrapper that forwards to `0x0013AAF0`:
```c
func_001376a4(i, flag, paramA, paramB, paramC, flags, flag);
```
Register arguments `r0..r3 = (i, flag, paramA, paramB)`; stack arguments
`[sp] = paramC`, `[sp+4] = flags`, `[sp+8] = flag`. `0x001376A4` copies the
three incoming words to its own outgoing frame and tail-calls `0x0013AAF0`,
which writes a record into the two-slot table selected by its first argument.

After the call the original re-reads `state[0x14C+i*4]` (so a callee-side write
is observed) and stores `1` when it was zero, otherwise `0`.
