# Function Record: func_0015b1a4 (0x0015b1a4)

## Summary
- **Address:** `0x0015b1a4`
- **Size:** 408 bytes (original span `[0x0015b1a4, 0x0015b33c)`, including the
  two bounded literal-pool words at `0x0015b334`/`0x0015b338`)
- **File:** `src/engine/leaf_batch28_a.cpp`
- **Role:** Appends three records (tags `0x80000016`, `0x80000017`,
  `0x80000018`) to the GPU command stream rooted at
  `g_GpuCommandCursor` (`0x004652a0`) for one draw entry. The third record
  carries the transformed entry scale.
- **Status:** Semantically equivalent C++ (`non_matching`). The compiled body is
  452 bytes and is not byte-identical; the ledger row is `non_matching` and
  this record carries the semantic evidence.

## Contract and Behavior

- **Signature:** `extern "C" void func_0015b1a4(void* object)`
- **Return value:** none. On the full path the original incidentally leaves the
  advanced cursor in R0; on the gate-failure path it leaves the `bics` result
  (`4`); with a null node it leaves `object`. These scratch values are not part
  of the ABI contract.
- **Callers:** none found as a direct `BL`/`BLX` in `code.bin`; the routine is
  only reachable indirectly.

### Object layout read by the original
| Expression | Meaning |
| --- | --- |
| `[object+0x08]` | state pointer; `[state+0x08]` is a pointer to a `u32` |
| `[object+0x44]` | node pointer |
| `[object+0xA4]` | matrix-set pointer; the 3x4 matrix starts at `+0x148` |
| `[node+0x00]` | vtable pointer |
| `[node+0x08]` | entry pointer |
| `[node+0x0C]` | non-zero enables the vtable transform |
| `[entry+0x18]` | entry flags; bit 1 enables the vtable transform |
| `[entry+0xB8]` | 16-byte block copied by the first record |
| `[entry+0xC8]` | 16-byte block copied by the second record |
| `[entry+0xD8..0xE0]` | three `f32` scale values |
| `[entry+0xE4]` | raw 32-bit word copied verbatim into the third record |

### Early exits
1. `node == 0` → return without emitting anything.
2. `(*(u32*)(*(u8**)(*(u8**)(object+0x08)+0x08)) & 4) == 0` → return.
   The original loads the full 32-bit word and tests bit 2 with `bics`; the
   candidate compiler narrows this load to a byte because only bit 2 is used
   (same address, same bit on little-endian).

### Command emission
The original obtains the cursor, then for each record:

1. writes the 8-byte header `{tag, 0x804f02c0}` at the cursor,
2. calls `func_002a1a08(cursor+8, source)`, which stores the four source words
   in reverse order (`dst[0]=src[3]`, `dst[1]=src[2]`, `dst[2]=src[1]`,
   `dst[3]=src[0]`),
3. reloads `g_GpuCommandCursor` after the call and advances it by `0x18`
   (`0x18 / 4` words).

The first two records copy `entry+0xB8` and `entry+0xC8`. The cursor is advanced
after the first record only *after* the helper returns, so a helper observing the
global sees the old cursor.

### Third-record transform
- Initial vector `(s0,s2,s1) = (entry+0xD8, entry+0xDC, entry+0xE0)`.
- If `(entry+0x18 & 2) != 0` and `node+0x0C != 0`, the routine calls the node's
  vtable slot at `+0x14` with the node as the only argument. The returned
  matrix is read as three rows at `+0x00`, `+0x10`, `+0x20` with columns at
  `+0`, `+4`, `+8`:
  `x = m[0x00]*a + m[0x04]*b + m[0x08]*c`, `y = m[0x10]*a + m[0x14]*b +
  m[0x18]*c`, `z = m[0x20]*a + m[0x24]*b + m[0x28]*c`.
  The scale triple is **reloaded after the vtable call**; a callee that rewrites
  `entry+0xD8..0xE0` is observed.
- The same row transform is then applied with the matrix at
  `[object+0xA4]+0x148`, producing the first three payload words.
- The fourth payload word is the raw word at `entry+0xE4` (re-read after the
  vtable call), not a converted float.

### Observed call order
`func_002a1a08` three times; between the second and third copy, one indirect
`[node vtable +0x14]` call when both transform conditions hold. The helper and
the vtable target are the only calls.

### VFP and rounding
The original uses `vmul.f32` followed by `vmla.f32` chains. Unicorn (and the
VFPv2 architectural model) treats `VMLA` as an unfused multiply-accumulate, so
the candidate's `vmul`/`vadd` sequence produces the same single-precision
results; the differential test compares the emitted payload words bit for bit.
Signed-zero, denormal, infinity and NaN inputs are exercised; NaN payload bits
are implementation-defined and are not independently modelled.

## Domain Limits
- The vtable slot `+0x14` target is unresolved; the test substitutes a
  deterministic matrix provider. A null return is not guarded by the original
  and would fault in both the original and the reconstruction.
- The exact identity and ownership of `g_GpuCommandCursor` beyond the observed
  `u32*` cursor semantics are not recovered; the function does not consume the
  records it writes.
- The render-gate word and entry-flag word are loaded as bytes by the compiled
  candidate (the original loads full words); only bits 2 and 1 respectively are
  observed at the same addresses.
- The original's scratch R0 differs on the gate-failure path (`4` versus the
  candidate's loaded flag byte) because the routine returns `void`.
- Runtime consumption of the command stream and in-game behaviour were not
  exercised; this record covers offline differential equivalence only.
