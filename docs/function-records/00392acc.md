# Function Record: engine_func_00392acc (0x00392ACC)

## Summary
- **Address:** `0x00392ACC`
- **Size:** 632 bytes (`[0x00392ACC, 0x00392D44)`)
- **File:** `src/engine/leaf_batch45_a.cpp`
- **Classification:** `non_matching` with semantic evidence (compiled body is
  584 bytes; register allocation, frame size and switch layout differ)
- **Domain:** Engine message/state machine
- **Role:** Advances a message-source state machine owned by a caller context.
  States 0/2 create a polymorphic source through `0x00234160`; states 1/3
  query the source's 20-byte message and dispatch on its first byte; state 4
  runs a signed three-tick countdown; state `0x270F` signals `0x00234004`.
  Every owned source is released through vtable slot `+0x04` (deleting
  destructor) before `+0x208` is cleared.

The body is 154 ARM words (`0x00392ACC..0x00392D30`, ending with the epilogue
at `0x00392D2C..0x00392D30`). The final 16 bytes, `0x00392D34..0x00392D40`,
are the literal pool: `0x0000270F`, `0x00432FC8`, `0x00000139` and `0x000009AA`.
The only reference to the entry point in the pinned image is the handler-table
word at `0x003FF0A4` (an array of pointer/zero pairs starting at `0x003FF084`);
no `bl`/literal caller exists.

- `r1`-`r3` are never read.
- No defined return value. `r0` on exit is an incidental residue of the last

## Behavior

1. `0x00234278(sp)` constructs the local 20-byte message object.
2. `root = *(u32*)0x00432FC8` is sampled after that call, before the state
   dispatch.
3. `switch (*(u32*)(context + 0x08))`:
   - **0**: `created = 0x00234160(context+0x20C, 0)`; `state = 1`;
     `source = created`; return. No existing source is released.
   - **1**: `message = source->vtable[3]()`; copy the 20 bytes onto the local
     message. If `0x0027EC84(&message) != 0`, set `state = 2` and return. If
     `0x002A17C0(&message) == 0`, return. Otherwise dispatch the opcode.
   - **2**: if `source != nullptr`, call `source->vtable[1](source)` (deleting
     destructor). `created = 0x00234160(context+0x20C, 4)`;
     `source = created`. `index = 0x002337A0(context+0x240)`;
     `table = *(u32*)(root + 0x678)`;
     `offset = 0x9AA + ((index * 0x139) << 3)` (32-bit wrap);
     `*(u32*)(created + 0x14) = *(u16*)(table + offset)` (zero-extended);
     `state = 3`; return.
   - **3**: `message = source->vtable[3]()`. If `0x0027EC84(&message) != 0`,
     re-read `source` from `+0x208`, store `result = 10`, `state = 0`, then
     release and clear the source if it is non-null; return. If
     `0x002A17C0(&message) == 0`, return. Otherwise dispatch the opcode.
   - **4**: `counter = counter - 1` (wrapping 32-bit subtraction, signed `> 0`
     test). If still positive, return. Otherwise, re-read the source, store
     `result = 6`, `state = 0`, then release and clear the source if non-null.
   - **`0x270F`**: `0x00234004(context, 5, 3)`; return.
   - **anything else**: return.
4. Opcode tail (shared by states 1 and 3, only reached when the first message
   byte is `>= 0x64`):
   - `0x66` (`'f'`): copy the 20 bytes to a private stack slot and call
     `0x002342B8(context, &copy)`. That helper stages the message fields into
     `+0x224/+0x234`, sets `result = 0x13`, `state = 0`, and releases/clears
     the owned source.
   - `0x67` (`'g'`): `state = 4`, `counter = 3`; return.
   - any other `>= 0x64` byte: `state = 0x270F`; copy the 20 bytes to
     `context + 0x210`; return.
   - bytes `1..0x63` never reach the tail: `0x002A17C0` returns zero and the
     routine returns without changing the context.

The destructor path always performs the same sequence: optional
`source->vtable[1](source)` then `*(u32*)(context+0x208) = 0`.

## Contract corrections found during implementation

- **`0x002342B8` takes a pointer to a 20-byte copy, not a register-split
  value.** The original copies the message to `sp+0x28` and passes its address
  in `r1` (the recovered invisible-reference convention for a by-value
  aggregate). Clang's ARM lowering splits a by-value 20-byte parameter across
  `r1-r3` and the stack, which would be ABI-incompatible with the pinned
  helper. The candidate declares `func_002342b8(void*, const Message*)` and
  performs the explicit copy, exactly reproducing the original stack slot.
- **The state-4 countdown must wrap in 32 bits.** A signed
  `s32 remaining = counter - 1` is undefined for `counter == 0x80000000` and
  clang folded the comparison to `counter > 1`, taking the expiry path. The
  candidate subtracts as `u32` and compares `(s32)result > 0`, matching
  `SUBS`/`BGT` including the `0x80000000 -> 0x7FFFFFFF` boundary.
- **The global root is sampled after `0x00234278` and before any state work.**
  Two tests (constructor mutating the slot, factory mutating the slot) prove
  the sample order: state 2 uses the value captured before the factory call.
- **`0x00234004` takes `(context, 5, 3)`.** Only the visible argument values
  are reproduced; the callee is stubbed.
- **`0x002342B8` performs its own indirect delete.** In the `'f'` tail the
  original does not reload the source; `0x002342B8` releases `+0x208` itself.

## Limits
- All seven direct callees and both vtable slots are stubbed. The real factory
  constructors, list-index composition, message helpers and state-step helper
  are not executed, so their internal side effects are not exercised.
- Fixtures are synthetic; no captured game context or message data was used.
- The 20-byte message is opaque beyond its first byte. The literal `0x66`/`0x67`
  comparisons are ASCII `'f'`/`'g'`, but the opcode vocabulary is not
  established. Field names `field_04`..`field_10` are placeholders.
- The handler table at `0x003FF084` and its consumer are unresolved; only the
  entry word at `0x003FF0A4` is known.
- The countdown's gameplay meaning and the roles of result codes 6, 10 and
  `0x13` are descriptive only.
- No emulator run and no canonical full build were performed; all memory is
  synthetic RAM mapped for the two Unicorn machines.
