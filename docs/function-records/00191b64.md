### Control flow and calls
The body is straight-line with no branches. It performs exactly ten
`BL 0x002B66EC` calls in this order, once for each halfword field:

1. **Call** (read pass). Load the table halfword with `LDRSH`
   (`s16`) at `table + 0x12 + 2*i`; load the selected index with `LDR`;
   load the entry halfword with `LDRSH` at `entry + 0x6A + 2*i`; add
   `(s32)table - (s32)entry` to the signed sum.
2. **Call** (copy pass). Re-read the index, re-compute the entry pointer,
   load the entry halfword with `LDRH` (`u16`) and store it with `STRH` to
   `table + 0x12 + 2*i`.

The index is re-read after *every* call because both the getter and the entry
array are writable globals; merging or caching the calls changes behavior
when the getter updates the index or the entry fields. The accumulator is
read and written with `LDR`/`STR` and the signed sum is added with normal
32-bit wrap-around.
