# Function Record: engine_func_002a37dc (0x002a37dc)

## Summary

- **Size:** 448 bytes (original span `[0x002a37dc, 0x002a399c)`; the last
  sixteen bytes at `0x002a398c..0x002a399b` are the literal pool:
  `0x3b808081` (1.0f/255.0f), `0x004ea81c` (render state),
  `0x437f0000` (255.0f), `0x00464110` (type table)).
- **File:** `src/engine/leaf_batch41_c.cpp`
- **Role:** `AsdPart_SetColor(part, color)`. Publishes the packed
  `0xAARRGGBB` color on the part, stages its normalized channels in the shared
  `0x004EA81C` render block, then walks the child list at `+0x8c`. Every child

  and handed to the per-instance type hook at `0x00464110` entry `+0x30`.
- **Status:** Semantically equivalent C++ (`non_matching`). The compiled body

  `non_matching` with this record.

## Contract and Behavior

### Signature and ABI
```c
extern "C" void engine_func_002a37dc(void* part, u32 color);
```
- `part = r0`, `color = r1` (packed 32-bit, no signed interpretation). `r2`/`r3`
  are scratch at entry.
- Returns nothing. `r0` on exit is residual: `part` on the empty-list path, the
  instance pointer or the last hook return otherwise. All callers ignore it.
- The original saves `r4-r8`, `lr` and `d8-d10` (`s16-s21`); `s16-s19` hold the
  parent tint, `s20 = 1/255` and `s21 = 255.0f`. The C++ does not need those
  exact registers and the compiler's frame differs.

### Control flow (original PCs)
1. `0x2a37e0..0x2a37fc`: extract the four bytes, store `color` at `part+0x64`.
2. `0x2a3804..0x2a383c`: zero-extend each byte, `vcvt.f32.u32`, multiply by
   `1/255` and store `{lane0,lane1,lane2,lane3}` at `0x004EA81C+0x100`, where
   lane0 is bits 31..24 and lane3 is bits 7..0.
3. `0x2a3840`: `node = *(part+0x8c)`. If null, return at `0x2a3984`.
4. `0x2a3854..0x2a38c4`: per node, normalize `node+0x64` the same way into
   `+0x100`, then re-store the unchanged parent tint at `+0x110`.
5. `0x2a38c8..0x2a3904`: `+0x100[i] *= +0x110[i]` for all four lanes.
6. `0x2a3908..0x2a3954`: multiply each lane by `255.0f`, convert with
   `vcvt.u32.f32` (round toward zero), mask each byte and rebuild
   `(lane0<<24)|(lane1<<16)|(lane2<<8)|lane3`. A white parent round-trips the
   original word (verified: `0x01020304` in, `0x01020304` out).
7. `0x2a3958..0x2a3974`: `instance = *(node+0x90)`, `type = *(u16*)(instance+4)`,
   `entry = 0x00464110 + type*0x44`, `hook = *(entry+0x30)`. If `hook != 0`,
   call `hook(*(void**)(instance+8), packed)`.
8. `0x2a3978..0x2a3980`: `node = *(node+0xac)` and repeat while non-null;
   otherwise `vpop {d8-d10}` / `pop {r4-r8,pc}`.

The `node+0xac` link is reloaded after the hook, so a hook that rewrites it
changes the traversal (covered by two test cases). A child's own `+0x8c` list is
never read.

### Layout facts recovered from the ARM
- `part+0x64` is the packed color, written once at entry and read per child.
- `part+0x8c` is the child-list head; `child+0x90` is its instance;
  `child+0xac` is the next link.
- `instance+0x04` is a `u16` type index; `instance+0x08` is the hook context.
- The `0x004EA81C` block uses `+0x100` for the normalized color and `+0x110`
  for the staged parent tint; `+0x120` and beyond are untouched.
- Lane order is byte 0 (bits 31..24) first. `{A,R,G,B}` naming follows
  `UiPart`'s `UnpackColor`/`PackColor` in `src/ui/ui_runtime.cpp`, which use the
  same lane convention for the same scratch block.

## Limits
- Fixtures are synthetic: part/node/instance pages, the type table, the hook
  targets and all register inputs are scripted. No real effect-part graph,
  scene, render device or allocator is exercised.
- The `+0x30` hook bodies were not reconstructed; the test stubs model only the
  observed `(r0, r1)` argument reads and the ignored return value.
- The type table is runtime-populated absolute data. Type indices that would
  address outside the mapped table page (e.g. `0xFFFF`) fault in both
  implementations and are intentionally not exercised; only zero slots inside
  the page are used to prove no call happens.
- The compiler hoists the `instance`/`type`/`+0x30` loads above some of the
  `+0x100` product stores. That is unobservable for a non-aliasing instance
  pointer; an instance overlapping the render block would fault/observe
  differently and is not modelled.
- The C++ does not reproduce the original's exact frame, register allocation or
  VFP scratch usage.
- No emulator, caller-composition, scene-runtime or whole-game equivalence is
  claimed.
