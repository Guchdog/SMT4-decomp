# 0x002AF854 — H2 indexed field selector

Status: production C++ with focused direct and caller-composition evidence; ledger `non_matching`.

The function reads the list pointer from `object+0x58`. A null pointer returns the original object pointer in `r0` without writes. For a non-null list, it writes the low halfword of `index` to `object+0x5C`, clears the halfword at `+0x5E`, clears bytes `+0x87` and `+0x8A`, writes the low byte of `mode` to `+0x60`, then selects a word from `list + index*12` (offset 4 when mode is nonzero, otherwise offset 0) and writes it to `object+0x20`. It returns the original object pointer.

The supported domain is valid readable/writable ordinary RAM, aligned word and halfword fields, a non-overflowing index with its selected list word mapped, and list storage disjoint from the written object fields. Fault equivalence and aliasing/concurrent-observer/MMIO behavior are not claimed. Other callers should pass the observed three AAPCS words; one source caller has a `void` declaration and raw ARM call, while `src/camp/unite_extras.cpp` declares the first three arguments and ignores the return.

Offline evidence covers 371 direct cases across null/non-null lists, indices 0, 1, 2, 7, 19 and 127, four mode patterns, and seeded values; it compares `r0`, SP, `r4-r11`, object/list memory and write effects. Four negative controls cover the null path, selection offset, index stride and return pointer. A 32-seed original `0x002B8D24` composition selects table index 2, asserts exactly two calls to `0x002AF854`, and runs the original `0x001384F0` byte-store tail; candidate and production effects match. Candidate and production bodies are 64 bytes and identical; production differs from original bytes. No cumulative H2 runtime result is claimed.
