## Recovered contract and behavior

- The registered callback ignores input `r0` and resolves `g_TitleConfigWork` through `0x0044E2D0`. Workspace size is `0x158`; config is addressed at `0x0044E0F8`.
- Dispatch is an unsigned state check: `0..4` use the original paths; `>=5` returns zero. State 4 returns `-1`; other common paths return zero.
- State 0 gates on resource/sprite/script readiness, registers the three `0x2F:{0x1F,0x20,0x21}` touch regions, displays a row, calls script processing, and stores its returned script value at workspace `+0x154` (the final original store uses post-indexed base `work+8`, then offset `+0x14C`). This output slot differs from the initializer's table pointers at `+0x14C/+0x150`.
- State 1 uses selected row plus scroll offset to select the option word at `work + 0x28 + 4*selection`; captures that word's entry value; handles raw touch result branches and logical query IDs/modes; clamps the observed decrement/increment paths to `0..10`; maps row defaults; writes config bytes `+0..+3`; and takes a change-effects path only when the selected work value differs from its entry snapshot.
- The candidate preserves TBB row byte arithmetic `0x16 + selection*0x96` for the display callback path. The harness/unit check covers offsets `0x16`, `0xAC`, and `0x142` for indices 0, 1, and 2. These are tested initialized indices, not a proven full or malformed cursor domain.
- State 1's logical queries remain IDs/modes (`(9,1)`, `(4,0)`, `(3,0)`, `(0,1)`, `(1,1)`). No physical controller-button names are inferred.
- The special `+0x22` path now computes `script_value - current` modulo `2^32`, then multiplies by 5 and 2 modulo `2^32` using `u32`. This preserves ARM argument bit patterns for all `s32` helper return patterns without invoking signed-overflow undefined behavior. The helper's semantic/range contract remains unresolved; differential fixtures include `INT32_MIN`/`INT32_MAX` combinations and safe mapped return values `0`, `3`, `7`, and `10`.
- State 2 waits for script runner result 2, then handles poll result 1 by returning to state 1, result 0 by setting state 3 and config byte `+4` to one, and other values by leaving state unchanged. These values are not labeled cancel/confirm. State 3 advances to state 4 when sprite readiness is true.
- The touch getter `0x0029D8FC` has a typed production-source implementation and bounded direct differential (see [its function record](0x0029d8fc.md)); its raw state producer and event meaning remain original dependencies. The state-2 script dispatcher `0x0019DFBC` also has typed production C++ with synthetic-handler differential evidence (see [its function record](0x0019dfbc.md)); real script handlers and their return semantics remain original. The Calc differential still intercepts touch, logical-input, cursor, task/script, UI/render, sound/audio, animation, and state-decision services with shared controls on both sides. The H2 IPS image still uses the original touch getter and script dispatcher because each C++ body exceeds its original span. Three config mappers and four byte encoders execute the pinned original ARM inside the callback harness.

## Limits and unresolved evidence

- All compiler and ARM differential results here use the same mocked service boundaries on both sides. They support the callback's branch/memory behavior only under those declared service outcomes. They do not validate actual touch/key producers, renderer/task/script/audio helper internals, or deterministic guest input.
- The input seam research identifies an unresolved mismatch: initializer fills `work+0x1C/+0x20` with `-1`, while Calc polls those four halfwords; the observed region-registration returns are stored at `+0x14/+0x16/+0x18`. Do not mutate guessed event handles.
- The pinned-image audit inspected 83 direct `BL` references to `UiTouch_RegisterRegion` across 18 functions. The three TitleConfig registration returns go to `+0x14/+0x16/+0x18`; Calc's four polled arguments at `+0x1C..+0x22` remain initialized to `-1`. `IfTouch_Init` sets `IfTouchWork+0x64E` to `-1` and registers internal entry `0x00107CCC` as the `TOUCH CALC` callback; hit-test paths in that callback write an index to `+0x64E` and set/clear the raw byte at `+0x08`. The callback's state meaning, runtime ordering, and relation between its index and the three H2 registration indices remain unresolved. Registration records use `IfTouchWork+8*index+{0xA,0xC,0xE,0x10}`, not a `+0x600` record base. See [the direct handle audit](../agent-work/h2-input-handle-producer-audit.md) and [the reviewed manager-state producer audit](../agent-work/h2-input-manager-touch-state-producer-audit.md).
- The special `+0x22` path uses mocked `script_value`/`script_index` returns, including the signed 32-bit extremes; its helper meaning/range remains unknown. The safe bounded-helper results protect the initialized option slot but do not establish real helper behavior. Cursor out-of-range/malformed indices and arbitrary work layouts are outside the exercised initialized domain.
- State 1-to-State 2/3, state-2 polling/decision branches, and State-3 readiness now have persistent callback-sequence evidence under the declared service controls; there is still no sequential real title-caller test, changed-option cancellation/confirmation comparison, re-entry, file persistence, or clean restart. No emulator, RSP, or OS input was used.
- The production source integration is independently reviewed and classified `non_matching`; this does not close H2. Persistence and semantic labels for state-2 results remain unresolved, and no whole-title or runtime equivalence is claimed.
