## Limits
- Fixtures are synthetic: the part/node/instance pages, the type table, the
  hook targets and all register inputs are scripted. No real effect-part graph,
  scene, render device or allocator is exercised.
- The per-type hook bodies were inspected only for the registers they consume
  to recover the argument contract. Their full semantics, the layouts of the
  structures they store into, and any global effects are not reconstructed
  here; the test stubs model only the observed argument reads.
- The type table is runtime-populated absolute data. The test installs its own
  35-entry table and stub targets, so real table contents and hook lifetimes
  are not validated.
- The C++ does not reproduce the original's dead `s0`/`s1` arithmetic leftovers
  at the `+0x2C`/`+0x20` calls, nor its exact byte encoding, register
  allocation, `ldrb`-lane flag tests or the absolute-address staging stores.
- Floating-point fixtures avoid custom NaN payloads: the candidate may
  reassociate a commutative `vadd`/`vmul` operand order across a compiler
  boundary, which can change NaN payload propagation while leaving ordinary
  finite, infinite and signed-zero results identical.
- `src/engine/leaf_batch30_c.cpp` declares the call target as `func_002a399c`,
  while this TU exports the ledger symbol `engine_func_002a399c`; cross-TU
  linking of that call site was not exercised.
- No emulator, caller-composition, scene-runtime or whole-game equivalence is
  claimed.
