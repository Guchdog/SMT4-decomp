# Function Record: engine_func_00339b18 (0x00339B18)

## Summary
- **Address:** `0x00339B18`
- **Size:** 640 bytes (original span `[0x00339B18, 0x00339D98)`; instructions end
  at `0x00339D80`, followed by the 24-byte literal pool `0x000044A8`,
  `0x00000225`, `0x000001E1`, `0x000043AC`, `0x000043B0`, `0x000043B4`).
- **File:** `src/engine/leaf_batch45_a.cpp`
- **Role:** Battle-main unit-slot setup. Resets 42 unit-slot pairs, clears the
  id scratch and a 3600-byte block, selects up to four source ids (four fixed
  presets, a party-count prefix of those presets, or a scan of the twelve party
  slots), resolves each id to an s16 value, then registers the distinct values
  in the 42-entry unit-record table and appends them to the slot id list.
- **Status:** Semantically equivalent C++ (`non_matching`). The compiled body
  is 536 bytes versus the 640-byte original. Clang uses an inline switch table
  for the four preset stores and merges the auto-scan/collected-count tails,
  while the original keeps a linear compare chain and a separate store site.
  The observed ABI, call order, argument values, stores, loop bounds, signed
  comparisons and return value are identical. The ledger row is classified
  `non_matching` with this record.

## Contract and Behavior

### Signature and ABI
```c
extern "C" u32 engine_func_00339b18(BtlUnitSetupWork* work); // r0
```
- `work = r0` points at the 0x4A58-byte battle main work object used by the
  adjacent `0x00339D98` state machine.
- The original saves `r4-r8` plus `lr` and allocates a 0xA8-byte stack scratch
  area. The C++ compiler preserves the same callee-saved set; the entry `sp`
  is restored on every return.
- The return value is the collected-id count, i.e. the word at
  `work+0x4390`. The original loads that word into `r0` at `0x339CC0` and
  reloads it at `0x339D54` on every final-pass iteration; the last load
  survives to the `pop {r4-r8,pc}`.
- The routine is synchronous and terminates for every input; both internal
  loops are bounded by 42 and 12.

### Control flow (original PCs)
1. `0x339B18..0x339B58`: for 42 iterations write 0 to
   `work+0x1FE4+i*8` and -1 to `work+0x1FE8+i*8`.
2. `0x339B5C..0x339B8C`: call `0x002C4450(sp, 0xA8, -1)`,
   `0x002C4450(work+0x43A8, 0xA8, -1)` and `0x002C4B30(work+0x357C, 0xE10)`
   in that order.
3. `0x339B90..0x339BC4`: read `work+0x44A8`. If bit `0x40` is clear, read
   `work+0x2F34`, compute `party_count - 1` and compare unsigned with 3. Values
   1..4 continue at `0x339BC8`; 0 and values >= 5 branch to the auto scan at
   `0x339C78`.
4. `0x339BC8..0x339BE8`: if the flag bit is set, force `count = 4` and enter
   the dispatch body at `0x339BEC`. Otherwise use `count = party_count`; the
   original's `count > 0` test at `0x339BDC` is unreachable because the
   unsigned test above already routes 0 to the auto scan.
5. `0x339BEC..0x339C6C`: dispatch on the loop index `r4 = 0..count-1`:
   - index 0 stores `0x225` at `work+0x43A8`;
   - index 1 stores `0x1E1` at `work+0x43AC`;
   - index 2 stores `0x218` at `work+0x43B0`;
   - index 3 stores `0x83` at `work+0x43B4`.
   The stored word is then reloaded, truncated with `uxth`, resolved through
   `0x002B087C`, and the s16 at record `+0x88` is stored at `sp + index*4`.
6. `0x339C70`: store `count` at `work+0x4390` and go to the final pass.
7. `0x339C78..0x339CBC` (auto scan): for `index = 0..11` while fewer than four
   ids have been collected, call `0x0026F25C(index)` and read its u16 at
   `+0x48`. A non-zero id is stored at `work+0x43A8+collected*4`, resolved
   through `0x002B087C`, and its s16 `+0x88` value is stored at
   `sp+collected*4`. The loop exits after index 11 or when four ids have been
   collected; `collected` is stored at `work+0x4390`.
8. `0x339CC0..0x339D60` (final pass): `n = work+0x4390`; if `n <= 0` skip to
   the count store. For each collected value `v`:
   - scan `work+0x2134[0..41]`; a non-null record whose `+4` word equals `v`
     ends the search and the value is skipped;
   - otherwise call `0x00294334(v, 1)`, scan again for the first null registry
     slot and store the returned record there if a free slot exists;
   - append `v` to `work+0x1FE8 + added*8` and increment `added`.
9. `0x339D64`: store `added` at `work+0x438C`, restore the stack and return
   with `r0 = n`.

### Unresolved or unchecked behavior
- `0x002B087C` and `0x0026F25C` are dereferenced without null checks. The
  original faults if either returns null; the test stubs always return valid
  records.
- A full registry (`0x2134` has no null slot) does not receive the newly
  created record, but the value is still appended to `+0x1FE8` and counted in
  `+0x438C`. This is reproduced and covered by the test.
- Duplicate collected values match the record inserted by the first occurrence
  (its `+4` word is the value), so only one record is created and appended.
- The internals of the five helpers are not reconstructed here; the test
  replaces each with a deterministic stub at its original address.
- The original reloads `work+0x2F34` before testing the flag bit; the load has
  no observable effect and is omitted from the C++.

## Differential Verification
`python tools/test_leaf_00339b18.py` compiles
`src/engine/leaf_batch45_a.cpp`, relocates the candidate's five direct calls
and inline switch table, and runs the pinned 640-byte original against the
candidate in separate Unicorn ARM machines with identical fixtures.

Compared: return `r0`, continuation PC, final SP, callee-saved `r4-r11`, the
ordered call log with every register argument, the full 0x10000-byte work page,
the twelve party-slot pages, the `0x2B087C` record pages, the `0x294334`
creation pages, the registry records, the rodata page, and every emulated write
outside the fixture pages.

Coverage (36 cases):
- flag bit `0x40` with flag values `0x40`, `0xFFFFFFFF` and otherwise irrelevant
  party counts, plus flag values `0x00`, `0x01`, `0x80` and `0xBF`;
- party counts 1, 2, 3 and 4 (preset prefixes);
- auto scan for party counts 0, 5, 6 and `0xFFFFFFFF`; all twelve slots
  non-zero, only slot 11 non-zero, slots 8..11 non-zero, first non-zero at
  slot 3, all zero, and id `0xFFFF`;
- signed s16 values `-0x8000`, `0x7FFF`, `-1` and `0`;
- registry hits, misses, partial tables, a full table with and without a
  matching value, the first free slot at 2 and at 41;
- duplicate positive and negative collected values, and a case where
  `collected != appended` so the return value is distinguished from
  `work+0x438C`.

Negative controls mutate the first preset id, the slot count, the flag bit, the
scan bound, the party-id offset, the record-value offset, the clear size, the id
scratch size and the return value; each mutant is detected by at least one
case.

Limits: this is an isolated function-level differential test. It does not prove
whole-game runtime equivalence, the helper bodies, or the behavior of a null
`0x002B087C` / `0x0026F25C` result. No emulator run was performed.
