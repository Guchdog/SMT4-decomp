# Function Record: engine_func_0023adc4 (0x0023adc4)

## Summary
- **Address:** `0x0023adc4`
- **Size:** 456 bytes (original span `[0x0023ADC4, 0x0023AF8C)`; the last 20
  bytes are the literal pool `0.5f, 2.0f, 0x003FF7C4, 0.0f, 0x00433D98`)
- **File:** `src/engine/leaf_batch41_c.cpp`
- **Role:** Computes one scaled screen position (x, y, z = 0) for a layout
  source, adding the `143.0f` vertical bias and the runtime float at the head of
  the enemy-draw global `0x00433D98`. It is a leaf helper called by
  `0x0023C670` (camp/UI frame code), `0x0034CA2C` and `0x003DB258`; all three
  pass a source object in `r0`, a three-float scratch vector in `r1` and a scale
  in `s0`, then add the result to a position they already hold. No caller reads
  `r0` or `s0` afterwards.
- **Status:** semantically equivalent C++ (`non_matching`). The compiled body is
  468 B versus the 456 B original: 444 B of text versus 436 B, a 24 B literal
  pool (the two saturation bounds are also materialised as literals) versus the
  20 B original pool, and different register allocation. The ledger row carries
  this semantic record.

## Contract and Behavior

### Signature and ABI
```c
extern "C" void engine_func_0023adc4(func_23adc4::Source* source,
                                     func_23adc4::Position* out, f32 scale);
```
- `source = r0`, `out = r1`, `scale = s0`. Only `r4`/`r5` are saved; `SP` is
  untouched and `r4-r11`/`d8-d15` are preserved.
- `void` result. On the `flag1c == 0` tail the original leaves the source
  pointer in `r0`; on the other tail `ldrsh r0, [r0, #0x18]` overwrites it with
  the sign-extended halfword. Neither value is a return value, and every caller
  overwrites `r0`. The final `vmul s0, s2, s0` leaves `x * scale` in `s0`, again
  unread by the callers. The reconstruction is therefore `void`; `r0`/`s0`
  residue is deliberately not reproduced.
- All `add`/`sub` arithmetic that the original performs on 32-bit integers is
  done through `u32` in C++ so wrap-around is not undefined behavior.

### Computation (ARM addresses)
1. `0x0023ADC8..0x0023AE0C`: `span = (f32)Rect+0x14 + 143.0f - (f32)Rect+0x16`.
   `143.0f` is the read-only word at `0x003FF7C4`; the two `Rect` halfwords are
   sign-extended.
2. `0x0023AE10`: `flag1c != 0` selects the frame-record path, otherwise the
   abs-offset path.
3. Frame path `0x0023AE14..0x0023AE60`:
   - comparison pair: `(f32)Frame+0x14` and `(f32)Frame+0x18`;
   - extent: `0.5f * (s32)((u32)Rect+0x26 - (u32)Frame+0x18)`, then
     `+ (f32)Source+0x1A`, `+ (f32)Rect+0x22`, `+ (f32)Frame+0x18` in that
     order. The subtraction wraps; the result is re-interpreted as signed.
4. Abs-offset path `0x0023AE64..0x0023AE98`:
   - comparison pair: `(f32)(u32)Rect+0x24 + 2.0f * |Source+0x10|` and
     `(f32)(u32)Rect+0x26 + 2.0f * |Source+0x14|` (`vcvt.f32.u32`, `vabs.f32`);
   - extent: `(f32)(s32)((u32)Rect+0x22 + (u32)Rect+0x26)`.
5. `0x0023AE9C..0x0023AEB8`: `ratio = 0`; when `first > second`,
   `ratio = (s32)((first - second) * 0.5f)` via the round-toward-zero
   `vcvt.s32.f32` (saturating, NaN -> 0). Unordered comparisons (NaN) do not
   take the branch.
6. `0x0023AEBC..0x0023AEF4`: `y = 0.0f + ((span - extent) - (f32)ratio)`. The
   `+ 0.0f` is an actual `vadd.f32` and is kept because it turns a `-0.0`
   intermediate into `+0.0`. When `flag1c == 0 && flag1d == 0`,
   `y += Source+0x14 * 2.0f`.
7. `0x0023AEF8..0x0023AF08`: `out->y = y * scale + *(f32*)0x00433D98`; the same
   `vstmia` stores `+0.0f` into `out->x`.
8. `0x0023AF0C..0x0023AF60`:
   `horizontal = (s32)Rect+0x12 - (s32)((s32)Rect+0x20 + ((u32)Rect+0x24 >> 1))`
   (wrapping), `x = 0.0f - (f32)horizontal`; `flag1c != 0` adds
   `(f32)Source+0x18`, otherwise `Source+0x10`.
9. `0x0023AF64..0x0023AF74`: `out->z = +0.0f`, `out->x = x * scale` (the last
   multiply targets `s0`).

### Calls
None. `0x0023ADC4` is a true leaf: no `bl`/`blx`, no indirect call, no stack
arguments. The only external inputs are the read-only word at `0x003FF7C4`
(`143.0f`) and the writable float at `0x00433D98`.

### Memory effects
- Writes exactly `out->y` (`+0x04`), `out->x` (`+0x00`) and `out->z` (`+0x08`).
  The original additionally restages `out->y` and `out->x` before the final
  values; only the final contents are contractual, and the reconstruction does
  not reproduce the transient duplicates.
- Reads the two record holders, the rect/frame records, `0x00433D98` and
  read-only data. No other memory is touched.
- Input and output are assumed not to alias; an aliasing caller would expose the
  original's intermediate store order.

## Limits
- Fixtures are synthetic: the source, record holders, rect and frame records are
  not captured game data.
- The writable global `0x00433D98` is modeled as one standalone float word; its
  surrounding `g_EnemyDrawGlobal` fields and their producers are out of scope.
- The three direct callers are not exercised; only the leaf contract above is
  tested. No runtime, caller-composition or whole-game equivalence is claimed.
- The reconstruction assumes the input and the output vector do not overlap.
- Only the final contents of `out` are contractual; the transient duplicate
  stores of the original are intentionally not reproduced.
