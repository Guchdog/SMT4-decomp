# Function Record: camp_func_003abd08 (0x003abd08)

## Summary
- **Address:** `0x003abd08`
- **Size:** 668 bytes (original span `[0x003abd08, 0x003abfa4)`, including the
  literal pool at `0x3abf7c..0x3abfa0`)
- **File:** `src/engine/leaf_batch45_a.cpp`
- **Role:** Camp party-row draw. Resolves the plain/selected layout anchor,
  optionally notifies `0x22D994`, queries the row id, draws a rect-relative
  text line with the translucent scale derived from `arg5`, then draws the
  demon-bar row and one `"%8d"` value label. `flag` selects the layout key,
  the label ids, the forwarded colours and the `0x231D60` notification.
- **Status:** Semantically equivalent C++ (`non_matching`). The compiled body is
  652 B versus the 668 B original. The compiler keeps the `"%8d"` string in
  `.rodata.str1.1` (the original stores it in the function's literal pool at
  `0x3abf9c`), factors the constants differently and allocates a slightly
  different frame. The ledger row is classified `non_matching` with this
  semantic record.

## Contract corrections found during implementation
- **`0x231D60` stack words are not VFP arguments.** The original stores
  `arg5` and `1` with `str`/`str` and the callee reads them via
  `vldmia [sp,#0x38]`. Declaring them as `f32` in the candidate moves them to
  `s0/s1` and drops the stack words. The candidate declares `u32 a_bits,
  u32 b_bits`.
- **The slot id is read twice at the same address.** The early copy
  (`0x3ABD3C`, stored at `[sp,#8]`) feeds `0x2890D0`; the copy after
  `0x22D994` (`0x3ABDE4`) feeds `0x262EDC`. Both reads must stay at their
  original program points.
- **`0x2BF6C8` ignores its key for the returned base.** The 8-byte symbol is
  `ldr r0,[r0,#0x10]` and then falls through into `0x2BF6D0`, which uses the
  key for the actual lookup. The candidate preserves the `(table, key)` pair.
- **`0x2BE744` is a rect-relative text wrapper.** It loads four floats from
  `r0`, adds `rect[0]+rect[2]` to `s0` and `rect[1]+rect[3]` to `s1`, converts
  to int and back to float, shuffles `r1/r2/r3` into `r0/r1/r2`, and falls
  through into the Thumb-less ARM body at `0x2BE77C` (`UiFont_DrawText`).
  Its declared contract above is therefore the wrapper's, not the inner
  function's.
- **`0x2B6F74` receives both trailing words as zero**, not as the `3`/`7`
  draw-mode pair used by `0x230C80`.
- **`0x230C80` receives `0xFFFFFFFF`, not `0`**, as its third stack word
  (`mvn r0,#0` at `0x3ABF30`).
- **`0x2BE7FC` interworking.** It is Thumb; the harness converts the
  candidate's `R_ARM_CALL` into `BLX` for that symbol.

## Limits
- Fixtures are synthetic: `ctx`, `work`, the layout anchor records, the slot
  fields, the text page and the scripted format output are not captured game
  data.
- Every helper (`0x2BF6C8`, `0x22D994`, `0x262EDC`, `0x2BE744`, `0x231D60`,
  `0x231D4C`, `0x2890D0`, `0x2B6F74`, `0x2BE7FC`, `0x230C80`) is stubbed; no
  real layout lookup, record resolution, text formatting, GPU submission or
  camp UI state is exercised. `0x2BF6C8`'s indirect fall-through into
  `0x2BF6D0` and `0x2BE744`'s into `0x2BE77C` are documented from static
  disassembly but not executed.
- The semantic meaning of `arg5` is not established: it is forwarded to
  `0x22D994`, `0x231D60`, `0x2B6F74` and `0x230C80` as a raw 32-bit word and
  also converted as a signed integer for the text scale. Its callers pass
  `0x1F` (plain) and `0x20` (selected), but no runtime role is proven.
- The colours `0xFF`, `0xFFFFFFFF`, `0x5A5A5AFF` and the draw constant
  `0xFFFFFFFF` are treated as opaque raw words, not validated pixel formats.
- The `0x20`-byte text buffer size is inferred from the original's frame
  (`sp+0x20..sp+0x40`); `0x2BE7FC`'s real width/overflow contract is not
  modelled and the harness writes only a short deterministic payload.
- The candidate's internal frame layout and register allocation differ from
  the original; only the documented ABI inputs, call arguments, saved
  registers, format output and returned state are compared.
- No rendering, text-layout, camp-state, caller-composition or whole-game
  runtime equivalence is claimed.
