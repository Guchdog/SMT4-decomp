# Function record: interior callback `0x0015555C`

## Identity and entry boundary

The pinned ARM image is `extracted/exefs/code.bin`, SHA-256
`1f98884fe997af22e032a14c51a46c872b05b0e079a0f29e307b0e059cfaa558`.
The ledger partitions the preceding bytes as `func_00155540` (68 bytes), but

## Contract

Static control/data flow and the synthetic caller trace support the ARM
hard-float signature `float callback(float lower, float upper, float value)`:
`lower` arrives in `s0`, `upper` in `s1`, and `value` in `s2`; the returned
clamp value is in `s0`. The callback has no memory writes. It does not alter
`r4-r11`, `sp`, or `d8-d15`; caller-saved state and APSR condition codes are
not promised. VFP comparisons update FPSCR condition flags and `VCMPE` sets
invalid-operation status for quiet NaN operands.

The original instruction sequence is:

| PC | Instruction | Effect |
|---|---|---|
| `0x0015555C` | `vmov.f32 s3, s0` | Save lower bound. |
| `0x00155560` | `vmov.f32 s0, s2` | Move candidate value into result register. |
| `0x00155564` | `vcmpe.f32 s0, s1` | Signaling compare of candidate with upper bound. |
| `0x00155568` | `vmrs APSR_nzcv, FPSCR` | Transfer compare flags for the branch. |
| `0x0015556C` | `vmovgt.f32 s0, s1` | For GT, move the upper bound into the result. |
| `0x00155570` | `bgt 0x00155580` | Return immediately after the upper clamp; this skips the lower compare. |
| `0x00155574` | `vcmpe.f32 s0, s3` | Compare current result with saved lower bound. |
| `0x00155578` | `vmrs APSR_nzcv, FPSCR` | Transfer lower comparison flags. |
| `0x0015557C` | `vmovlo.f32 s0, s3` | For LO, replace a below-lower value with lower. |
| `0x00155580` | `bx lr` | Return. |

Consequently, upper clamp is tested first and returns immediately on the GT
path. For reversed bounds, a value above the upper bound returns the upper
bound even when it is below the lower bound. An unordered VCMPE sets
`NZCV=0011`: ARM GT is false and LO is false. Thus a NaN input value passes
both conditional moves unchanged and is returned as NaN. When a bound is NaN,
the unordered comparison likewise does not select that bound. The signaling
compare still sets FPSCR invalid-operation status. The C++ candidate uses
narrowly scoped inline VFP compare/flag primitives to preserve these FPSCR
effects and expresses the branches/assignments as readable C++.

## Caller and selection evidence

The static title callback map identifies `0x002872E4` as the first positive
H1 transition's indirect `BLX` through an object callback slot; its callback
argument is loaded from object `+0x50`. A separate indexed-track body calls
its selected record callback at `0x00210010`. Existing synthetic original-ARM
experiments have executed `0x0015555C` from a deliberately populated object or
track record. They demonstrate executable reachability and the register
contract for those constructed paths, not live asset selection.

The setup trace establishes a default callback pointer of `0x0015555C` and a
type-byte-1 override to `0x00151404`. The runtime source object's `+0x10` type
byte and live title callback slot have not been captured. A serialized CANM
category is not sufficient evidence that the live title uses this function.

## Differential evidence

`tools/h1_type0_callback_experiment.py` compiles the readable candidate for
ARMv6K hard-float and executes original and candidate entries in separate
Unicorn machines, comparing returned `s0`, FPSCR, callee-saved integer/VFP
registers, SP, and observable data/stack writes. All 17 targeted cases pass:
interior and exact boundaries, above/below clamp, reversed/equal bounds,
quiet NaNs in each operand position, infinities, and signed zero. The
deliberately wrong ordered-comparison implementation returns the same `s0`
bits, including NaN payloads, but is rejected on all four unordered cases
because its quiet comparison fails to set the `VCMPE` invalid-status bit in
FPSCR. Focused unittest coverage is in
`tests/test_h1_type0_callback_experiment.py`.
