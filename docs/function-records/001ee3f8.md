# Function Record: camp_func_001ee3f8 (0x001EE3F8)

## Summary

- **Address:** `0x001EE3F8`
- **Ledger span:** 428 bytes, `[0x001EE3F8, 0x001EE5A4)`
- **File:** `src/engine/leaf_batch34_c.cpp`
- **Role:** Camp/battle row message dispatch. A lookup gate plus the signed id
  decide whether two record lookups run, whether the row value comes from the
  battle record's signed `+0x88` word or the camp node's `u16` at `+0x90`, and
  which of three message helpers finally runs.
- **Status:** Reconstructed as readable C++ and semantically verified against the
  pinned original with a differential Unicorn harness. The candidate body is
  464 bytes and is not byte-identical, so the ledger row is `non_matching` and
  this record carries the semantic evidence.
- The 428-byte span contains 420 bytes of code and two literal-pool words:
  `0x001EE59C = 0x00000266` (the fallback bound) and
  `0x001EE5A0 = 0x00433158` (the address of the bundle-pointer slot). No other
  entry point exists inside the span.

- `r1` = `arg1`, `r2` = `arg2`, `r3` = `arg3`; all three are forwarded to the

- `[sp]` on entry (the fifth argument, read as `[sp+0x48]` after the original's

- **Return:** `r0` is not used by the only recovered caller (`0x001A3744` calls

- Callee-saved `r4-r11` are preserved; final `SP` equals entry `SP`.
- No indirect calls. Nine direct `R_ARM_CALL` relocations: `0x002B9364` twice,

## Differences from the original

- Candidate size is 464 bytes versus 428. The compiler folds the fallback test
  `u16 + 1 >= 0x266` into `u16 > 0x264` (unsigned) and the selected test
  `>= 0x81` into `> 0x80` (signed); both are equivalent because the operands are
  bounded.
- The original keeps the row value in `r4` and the subindex in `r1`; the
  candidate spills the row value and the short count to its own frame. The
  call-visible argument values, call order and stack arguments are identical.
- The original's literal pool is gone; the candidate materialises `0x266` as a
  comparison immediate and `0x00433158` through its own `.text` literal.
- The original has no null test for the battle record after a non-null camp
  node; a null battle record with a live camp node therefore faults in both
  bodies. The test covers the reachable null cases only.
