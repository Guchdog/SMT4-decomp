`+0x4CB` to 1, and returns 1. The real pinned copy dependency is invoked.

## Frozen H1 title-table rows

The later asset-validation run used the 880-byte ignored
`build/semantic-equivalence/real-assets/romfs/title/TitleTable.tbb`, SHA-256
`edd6bc1de5388e5689f797861ae6947c7c339f9b6bdb63d6c35951d72020fa41`. Its
TBCR header has size `0x20` and two tables. Table 0 is TBL1 at file offset
`0x20`, with 344 payload bytes beginning at `0x30`. The H1 callback's pinned
row formula uses the payload pointer plus `0x56 * selection + 0x16`; the four
string starts in the file are therefore `0x46`, `0x9C`, `0xF2`, and `0x148`.

| Selection | Payload-relative string offset | File offset | NUL-terminated text | Byte length |
| ---: | ---: | ---: | --- | ---: |
| 0 | `0x16` | `0x46` | `Start a new game from the beginning.` | 36 |
| 1 | `0x6C` | `0x9C` | `Load a saved game and continue playing.` | 39 |
| 2 | `0xC2` | `0xF2` | `Configure audio settings.` | 25 |
| 3 | `0x118` | `0x148` | `Download additional content.` | 28 |

All four NULs occur within their `0x56`-byte rows and each line is shorter
than the candidate's 64-byte safe-slot limit. The offline experiment maps the
entire frozen asset and passes pointers at those row-derived offsets to both
the pinned helper and candidate. All four asset cases pass their complete
defined workspace projection. It does not execute the title callback's TBB
lookup or establish localized data beyond this one frozen asset.
