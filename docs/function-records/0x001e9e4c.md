# Caller-window record — `0x001E9E4C` H1 title touch scan

## Identity and boundary

- Original: inline window in the title callback, from `0x001E9E4C` through the
  branch at `0x001E9EB4`; continuation is `0x001E9EB8`.
- Candidate: `h1_touch_caller_candidate` in
  `experiments/semantic_equivalence/h1_touch_caller_candidate.cpp`.
- Pinned original `code.bin` SHA-256:
  `1f98884fe997af22e032a14c51a46c872b05b0e079a0f29e307b0e059cfaa558`.

## Recovered behavior

- The caller loads the work pointer through global slot `0x0044E300`. It reads
  four signed halfword handles at work `+0x74`, `+0x76`, `+0x78`, and `+0x7A`.
- First scan: handles are visited in index order 0 through 3. The caller invokes
  `UiTouch_GetRegionTouchState(s16)` at `0x0029D8FC`. A response of 1 selects
  that index immediately. Every other first response causes a second helper
  call for the same handle; only this second response is compared with 2. A
  response of 2 selects that index and stops this scan. No selection leaves the
  prior cursor at work `+8` untouched.
- Second scan always visits all four handles once. Each response of 6 writes
  that index to work `+8` and writes byte 1 to work `+0x63`; later matches
  replace earlier cursor values. Other states do not clear either field.
- The candidate models the helper with the explicit pinned ARM ABI type
  `s32 (*)(s16)` and calls the function pointer at `0x0029D8FC`. Its harness
  intercepts only that helper entry and supplies per-call results; it does not
  synthesize a `touch_state[]` candidate argument.

## Evidence and limits

The focused experiment is recorded in
`build/agent-work/H1-semantic/h1-touch-caller-candidate/sleep-20261025-touch-candidate/checks/final/report.json`.
Compiled candidate and original caller window matched seven directed cases,
including state changes between repeated calls/passes, handle sign boundaries,
sticky confirmation/no-match behavior, and two detected wrong-behavior controls
(reversed first-selection order and ignored state 1). The comparison includes
work bytes, helper order/arguments/responses, continuation PC, candidate return
value, SP/VFP preservation, and candidate callee-saved integer registers.

Caller evidence remains partial: the original is inline in a larger callback,
whereas the candidate is an AAPCS function. Caller-saved and inline scratch
registers are not required to match. Helper implementation, physical touch
coordinates and hitboxes, surrounding callback effects, installed runtime, and
whole-game behavior were not exercised. No runtime equivalence is claimed.
