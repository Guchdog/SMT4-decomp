# Function Record: shop_func_003a8b14 (0x003A8B14)

## Summary
- **Address:** `0x003A8B14`
- **Size:** 428 bytes (original span `[0x003A8B14, 0x003A8CC0)`; 100 ARM
  instructions through the `pop` at `0x003A8CA0` followed by 28 literal bytes)
- **File:** `src/engine/leaf_batch41_c.cpp`
- **Role:** Camp/shop "counter list" screen update callback. It advances the
  cursor sprite, writes its screen coordinates, selects one of two
  mode-dependent panel updates, raises the sub-object refresh flag, and rebuilds
  the result-row list through a tail call.
- **Status:** Semantically equivalent C++ (`non_matching`). The compiled body is
  408 B versus 428 B; the compiler uses `r8` for the `0xA5B2` displacement,
  shares the two `0x00233804` call sites, and emits the same access widths,
  ordered call sequence, signed clamp, and tail return. The ledger row is
  `non_matching` with this semantic record.

## Contract and Behavior

### Signature and ABI
```c

```
- `work = r0`; `r1`-`r3` are ignored.
- The original pushes `r4-r7,lr`, reserves `0x44` stack bytes, and restores the
  frame on every path. `r8-r11` are not touched.
- The routine has no explicit return value. Its two exits are:
  - the early `pop {r4,r5,r6,r7,pc}` at `0x003A8C9C`, which leaves `r0` as the
    `0x002313D4` result (the destination pointer `work+0xC8` in the real
    helper);

  The differential test compares `r0` anyway and the candidate reproduces both.
- The only reference to the entry in the pinned image is the callback pointer
  at `0x004022A4` (the table around `0x00402284`); no `BL`/`B` targets it.

## Implementation notes and contract corrections
- **The mode byte is re-read after each helper.** The original reads it at
  `0x003A8B74` (sound request), `0x003A8B8C` (panel branch) and `0x003A8C4C`
  (row selector). The candidate reads `work[0x5A4]` at the same sites; a test
  case lets `0x002B8B78` flip it to prove there is no cached value.
- **The cursor is re-read after `0x002334D8`.** `record` uses the second
  signed `+0xA5B2` load, not the argument passed to the sprite helper.
- **The sub-object pointer is reloaded after the virtual call.**
  `0x003A8C3C` executes `ldr r0,[r6]` again before the halfword flag update;
  the candidate reloads from `work+0x590`. The test swaps the pointer inside
  the virtual stub to make the reload observable.
- **The first `0x0022CC38` argument is dead** but still the original stack
  scratch (`sp+0x40`). The candidate passes `text+0x40`; the callee's body and
  the differential comparison ignore it except for stack normalization.
- **`0x002BE7FC` is Thumb code.** The original uses `BLX`; the candidate's
  `R_ARM_CALL` is converted to a `BLX` immediate by the differential harness
  (and would be by a real linker).
- **The fallback and label are pinned strings.** `0x004022BC` is
  `81 9B` repeated three times; the static `0x0043D998` word points at
  `0x00423251` ("カウンターリスト"). The candidate keeps the fallback bytes and
  reads the label pointer from the original absolute table address.
- **`0x00233804` is a void helper and is tail-called.** The candidate keeps its
  original declaration and relies on the compiler's tail-call/return sequence;
  both implementations leave the helper's `r0` visible at the callback exit.
- **The `0x1C/0x1030` and `0x1D/0x040E` pairs match the sibling Bible/camp
  initialization at `0x003A9200`**, where the same mode split is used for the
  result-row list.

## Limits
- Fixtures are synthetic. The work page, cursor records, list entries, sub-object
  vtables and resource strings are not captured game data.
- Every helper is stubbed. `0x002334D8` is modelled as a gate plus optional
  cursor mutation; `0x0022CC38` returns a fixture string or null;
  `0x002313D4` performs the real two-`f32` store; `0x002BEF70`/`0x002BEF7C`
  read the modelled record; `0x002A0F68` only logs its byte; `0x00233804` and
  the sound request only log and return fixture values.
- Cursor values whose 140-byte stride wraps outside the mapped fixtures
  (`0x7FFF`, `-0x8000`) are passed to safe stubs that return a deterministic
  value derived from the record address. The original's out-of-map record
  reads are therefore not executed byte-for-byte; the record-address arithmetic
  itself is compared in the call log.
- The real `0x002334D8` jump-table behaviour, `0x0022CC38` resource tables,
  `0x002B8B78` profile transition, `0x002A0F68` manager side effect, rendering of
  the formatted help text, and the virtual refresh implementation are not
  exercised.
- No rendering, menu-state, caller-composition, emulator, or whole-game runtime
  equivalence is claimed.
