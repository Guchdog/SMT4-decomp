# `ui_func_002a8a8c` — decrement the shared signed status counter

## Recovered behavior

The helper has no meaningful input argument. It loads the pointer at `0x0043DCB4`, forms the raw return address `P + 0x600`, then reads a signed halfword at `P + 0x64C`. Only a value greater than zero is decremented and stored back as a halfword. Zero and negative values are left unchanged. On every non-faulting path, `r0` returns `P + 0x600`; the function does not return the counter or a success flag. The incoming `r0` is ignored.

There are no pointer guards. A null pointer value `P=0` still forms `0x600` and faults while reading `0x64C` if that address is unmapped. An invalid counter read faults before any write. A positive value with a read-only counter location faults on the conditional halfword store. The candidate preserves the raw pointer and these observed fault boundaries.

## Implementation and evidence

The typed implementation is in [`leaf_batch23_b.cpp`](../../src/engine/leaf_batch23_b.cpp). Its ARMv6K body is 36 bytes, exactly the original slot size, with no relocations. It differs from original bytes and must be tracked as a non-matching reconstruction. A zero-instruction compiler constraint keeps the returned `P+0x600` base distinct from the `+0x4C` counter access so the body fits the slot; no raw instruction replacement is used.

The focused runner is [`h2_status_service_experiment.py`](../../tools/h2_status_service_experiment.py). Its final differential passed the signed halfword cases `-32768`, `-1`, `0`, `1`, `2`, and `32767`, plus incoming-r0, byte-neighbor, null-pointer, unmapped-counter, and read-only-store cases. It compares the raw return, signed scratch result, preserved registers/SP, complete mapped data/global state, ordered writes, and fault address. Four controls detected an incorrect zero threshold, unsigned comparison, byte-width store, and global-pointer offset.

The composition runner compiles the typed `0x002B85BC` selector and rebases its ARM calls, then executes that body with the status helper installed at its final VMA. Six statuses `[0,1,7,8,9,2]` exercise nine status-helper calls per selector run. The separate global counter starts at 3 or 1; it reaches zero after respectively three or one stores while all six selector status bytes remain unchanged. This explicitly separates the service's global counter from the selector's status-byte rereads. Profile lookup and `0x002BF030` are deterministic hooks in the composition; the evidence is a bounded selector fixture, not live H2 runtime behavior.

The selector TU declaration has been aligned to the `u32` return type. The
independently reviewed production ledger classifies the changed body as
`non_matching`; aggregate byte coverage is reconciled in `README.md`.

No full build or emulator run was performed. The global pointer chain, counter location and selector profiles are controlled fixtures. Natural profile population, counter lifecycle, broader callers, concurrency, and runtime audio behavior remain unverified.
