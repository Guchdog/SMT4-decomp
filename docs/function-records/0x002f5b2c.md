# 0x002F5B2C — indexed H2 configuration byte getter

Status: production typed C++; ledger `non_matching`. Original span: 44 bytes; compiled ARMv6K body: 44 bytes with no relocations.

## Contract

The function reads the manager pointer from `0x0043DA2C`, which is the word at offset `+4` from the literal-pool base `0x0043DA28`. It returns zero if the pointer is null or unsigned `r0` is at least 6. Otherwise it zero-extends the byte at `manager + index*4 + 0x494` into raw `r0`. It makes no memory writes and has no callees. A nonzero invalid manager pointer can still fault; only valid mapped ordinary memory is covered.

The original `0x00286928` helper calls this getter for indices 0 through 5 in its six-entry loop. The field meaning and the higher-level effect of the returned byte remain unknown. See the [H2 helper contract](../agent-work/h2-final-helper-conversion-contract.md).

## Evidence

`tools/h2_indexed_config_getters_experiment.py` compares the production body with the pinned original at its final VMA. Across null/non-null managers and indices `0..7`, `0x7FFFFFFF`, `0x80000000`, and `0xFFFFFFFF`, all cases matched registers relevant to the ABI, return value, full manager/global bytes, write trace, SP, and faults. Two caller compositions execute the original `0x00286928` and observe six calls at indices 0 through 5; only its guard and main service callees are stubbed. The offset and upper-bound mutation controls were detected. The body fits its 44-byte slot; an IPS replay changes only the declared slots. Independent review: [review report](../agent-work/h2-indexed-config-getters-independent-review.md).

This proves the isolated getter contract over the tested mapped-memory domain. It does not validate the full `0x00286928` caller path, manager lifecycle, sound-setting meaning, or runtime behavior.
