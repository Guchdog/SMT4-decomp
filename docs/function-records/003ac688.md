## Limits

- The harness fixtures are synthetic. The real UI object contents, manager
  object, vtable and helper side effects are not captured game data.
- Every direct helper (`0x2A63F8`, `0x2941B4`, `0x2BF9F0`, `0x2AF854`,
  `0x294568`, `0x295B9C`) is stubbed; no real record lookup, animation update,
  list selection, or script/UI state machine is exercised.
- The virtual target at `vtable[3]` is unresolved. The harness supplies a
  distinct stub per vtable slot solely to observe which slot is called.
- `0x003AC6A0` and `0x003AC908` are in-span entry points, not ledger rows. Their
  callers in the shipped game are not identified; the differential harness calls
  them directly.
- The global words at `0x0043D9E4` and `0x0043D990` are treated as opaque
  pointers. Their owning classes, lifetimes, and the meaning of the UI state
  values (0..6) are not established.
- The candidate's internal register allocation and code layout differ from the
  original; only the documented ABI inputs, call arguments, saved registers,
  memory effects and returned state are compared.
- No emulator run, whole-game scenario, or caller-composition test was
  performed for this record.
