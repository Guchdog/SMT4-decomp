## Contract recovered from the body and caller

- ABI: `r0` points to the child/model object; the binary32 alpha argument arrives
  in VFP `s0` under the configured ARM hard-float ABI. The helper has no
  meaningful return value. Its caller at `0x001EA070` supplies the child and
  live `s16` alpha; the sibling call path supplies live `s17`.
- Object fields: signed 32-bit gate at `+0x34`; 32-bit target pointer at `+0x4C`;
  binary32 component scale at `+0x74`; binary32 child alpha at `+0x78`. When the
  gate is positive and the pointer is nonnull, the destination binary32 is at
  `target+0x40`.
- Effects and order: always store `s0` to child `+0x78`. For signed gate `>0`,
  load `+0x74`, load `+0x4C`, perform `component_scale * s0` in VFP, then store
  the product to `target+0x40` if the target is nonnull. The multiply occurs
  even when the target is null and can update FPSCR. The helper does not write
  globals or stack in the original. It changes caller-saved VFP/GP state; the
  caller must not treat the helper as returning the original child pointer.
- Domain exercised: valid aligned child storage and ordinary RAM; target may be
  null, external, or alias the child so its `+0x40` store overlaps child `+0x78`
  or the pointer field at `+0x4C`. Invalid pointers, MMIO, concurrent observers,
  timing and hardware-specific traps are outside the validated domain.

## Candidate detail

The candidate uses explicit offset-checked C++ structures and keeps the normal
control flow readable. A constrained `vmul.f32` is used for the product because
Clang reports that `STDC FENV_ACCESS` is unsupported on this ARMv6K target and
otherwise removes the multiply on the null-target path. A volatile read retains
the original `+0x74` load on that path. This is a compiler/target-specific detail
needed to preserve the observed VFP status effect; it is not a byte-matching
claim.
