# Function Record: engine_func_0038b75c (0x0038B75C)

## Summary
- **Address:** `0x0038B75C`
- **Size:** 404 bytes (original span `[0x0038B75C, 0x0038B8F0)`)
- **File:** `src/engine/leaf_batch44_b.cpp`
- **Role:** Builds a large local engine object (a named text/resource handle),
  copies a UTF-16 name into it, initialises the subsystem, asks
  `0x00361888` to register/serialize the object, then converts a selector-table
  string twice into a caller buffer. Returns `0` when the initialisation or
  status gate fails, `1` on the success path.
- **Status:** Semantically equivalent C++ (`non_matching`). The compiled body is
  364 B versus the 404 B original; the compiler uses a different register
  allocation/frame size and folds three adjacent byte stores into one halfword
  store, but the observed ABI, call order, memory effects and return values are
  identical. The ledger row is classified `non_matching` with this record.

## Contract and Behavior

### Signature and ABI

```c
    void*  unused_context,   // r0, not read

```
- Base AAPCS (`pcs("aapcs")`): the first four arguments are in `r0-r3`; the
  remaining three occupy the caller's stack words at `[sp]`, `[sp+4]`,
  `[sp+8]`. The original loads `flag_a`/`flag_b` with `ldm` from
  `sp+0x448`/`sp+0x44C` and the seventh word with `vldr s16,[sp+0x450]`
  (the prologue consumes `0x448` bytes). `value` is copied through the
  callee-saved VFP register `s16`/`d8` and passed on as the fifth argument of
  `0x00361888`.
- `unused_context` (`r0`) is overwritten by the constructor call and never
  read.
- The function returns `0` or `1` in `r0`. It preserves `r4-r11` and `d8`.
  Final `sp` equals the entry value.
- The lone caller (`0x0038F2B4`, inside `engine_func_0038f1d0`) passes a
  pointer bit pattern (`ctx + 0x6D4`) in the `value` slot. The callee only
  moves those bits through VFP and forwards them, so `value` is treated as an
  opaque 32-bit payload (declared `f32` to reproduce the `vldr`/`vstr` path).

## Limits
- Fixtures are synthetic: the object, output buffer, UTF-16 names and BSS
  selector table are not captured game data.
- Every helper (`0x00361710`, `0x00100C74`, `0x003617EC`, `0x001472A8`,
  `0x003619CC`, `0x003619FC`, `0x00361888`, `0x0035A614`, `0x002BCE48`,
  `0x002C3B48`) is stubbed; no real object construction, text conversion,
  subsystem registration or error reporting is exercised.
- The exact callee that writes `object+0x138`/`+0x144` was not resolved. The
  `0x00361888` body calls `0x002C0F28`, which performs an indirect
  `blx ip` at `0x002C1004`; that runtime callback is the likely writer. The
  differential test therefore applies the documented postcondition (`status`,
  `index`, out byte and return value) in the `0x00361888` stub.
- The semantic meaning of the BSS `u16` table selected by `object+0x144` is
  not established; it is treated as an addressable table of 16-bit entries.
- The `0x0035A614` conversion contract (UTF-16/encoding, destination size,
  in/out word meanings) is only partially recovered. The function's use of the
  return sign and its re-use of the two in/out locals are preserved and
  tested, but the helper's internal text conversion is not modelled.
- The seventh argument is an opaque 32-bit payload in practice (the lone
  caller supplies a pointer value); it is declared `f32` only to reproduce the
  original's VFP move path. No floating-point arithmetic is performed.
- The candidate's internal frame layout and register allocation differ from
  the original; only the documented ABI inputs, call arguments, object fields,
  copied text, memory effects and return values are compared.
- No caller composition, whole-game runtime, or real resource/text subsystem
  equivalence is claimed.
