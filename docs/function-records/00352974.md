The function resolves a UI icon resource from a 64-bit key pair. The zero key
selects a fixed default value. Any other key formats an icon name, widens it to
UTF-16, asks the resource table for a holder, and then selects one of three
result decodings based on the lookup status. The 64-bit result is written
through the caller's output pointer.

## Control flow

1. **Zero key.** If `key[0] | key[1] == 0`, call `0x2BAD80(out, 0xE0A13882)` and
   return. No other helper runs.
2. **Icon name.** `0x23A2EC(utf8, 0x30, "/icons/%u.icn", a3)` formats ASCII into
   `sp+0x78`. `0x2ACB3C(text, utf8, 0x30)` widens up to 48 code units into
   `sp+8` and returns the produced unit count. `0x2B5C2C(text)` returns the
   number of nonzero UTF-16 units before the terminator; the descriptor byte
   length is `(units + 1) * 2`, including the terminator.
3. **Lookup.** `0x355F78(&holder, key[0], key[1], descriptor, 1)` writes a holder
   word and returns a signed status. The holder defaults to zero and stays zero
   when the lookup fails.
4. **Status decode.**
   - Special icon: `((status & 0x3FC00) >> 10) == 0x11` **and**
     `(status & 0x3FF) >= 100` **and** `(status & 0x3FF) <= 179`.
     `0x2BAD80(&value, 0xD881388C)`.
   - Negative: `status < 0` (bit 31). `0x2BAD80(&value, status)`.
   - Otherwise: `0x2A4DF0(second_dst, holder, 0, 0, a2, 0x1200)`. A negative
     result decodes that value through `0x2BAD80(&value, result)`; a
     non-negative result decodes `0` into `sp+0xA8`.
   The special-icon test precedes the sign test, so a negative status whose tag
   and index match still takes the special-icon path.
5. **Release and store.** If `holder != 0`, call `0x2B93F0(holder)` (virtual
   release through `vtable[0x2C]`). Then copy the selected 8 bytes to `out` and
   return.

The low 10 bits are compared with signed `blt`/`bgt` after a zero-extending
`lsl #22` / `lsr #22`; because the value is 0..1023 the signed and unsigned
comparisons agree. The candidate keeps the unsigned form.
