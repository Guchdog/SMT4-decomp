# Function Record: camp_func_001f4e2c (0x001F4E2C)

## Summary
- **Address:** `0x001F4E2C`
- **Size:** 408 bytes (span `[0x001F4E2C, 0x001F4FC4)`, including the six
  literal-pool words at `0x001F4FAC..0x001F4FC0`)
- **File:** `src/engine/leaf_batch34_c.cpp`
- **Role:** Camp-work gate and flag-mask builder. The signed phase word at
  `object+0x3064` decides between an early abort, a completed-phase flag
  accumulation, a single-bit mask and an empty mask. After the phase handling it
  asks `0x0028CDE4` for a signed 16-bit result and publishes that result in the
  second 64-bit output.
- **Status:** Reconstructed as readable C++ and **semantically verified**
  against the pinned original. The candidate body is 460 bytes and is not
  byte-identical, so the ledger row is `non_matching` and this record carries the
  semantic evidence.

`work` is the pointer returned by `0x002A8A08`. Other reconstructed camp
functions treat `+0x9107` as a per-slot signed-byte row and `+0x9108..+0x910A`
as three fixed entries; this body only observes the raw bytes, so no stronger
field name is claimed.

The four gates are `ldrb` loads followed by a `!= 0` test: any non-zero byte,
including `0x80` and `0xFF`, enables the contribution.

### Shift and sign-extension semantics
Each contribution is computed as the ARM sequence
`add byte,#1; lsl 1, count; asr sign,#31`:
- `lsl` by a register uses the low byte of the count and produces zero for
  counts of 32 or more. The reconstructed `ShiftedFlagValue` therefore uses
  `(byte + 1) & 0xFF` and returns `0` for counts `>= 32`. In particular byte
  `0xFF` wraps to a count of `0` and contributes `1`, and byte `31` (count 32)
  contributes `0`.
- `asr #31` sign-extends the 32-bit shifted value to 64 bits, so the addend is
  `(s64)(s32)(1u << ((byte + 1) & 0xFF))`. `0x80000000` therefore subtracts
  `2^31` and borrows across the 64-bit high word.

### Control flow
```text
entry_phase = *(s32*)(object + 0x3064);
if (entry_phase < 0) return 0;          // outputs untouched

*flag_mask = 0;                          // 64-bit store
*(u32*)result = 0;                       // two 32-bit stores
*(u32*)(result + 4) = 0;

work = 0x002A8A08(entry_phase, flag_mask, 0);
phase = *(s32*)(object + 0x3064);        // reload after the fetch

if (phase == 0x270F) {
    if (*(u8*)(object + 0x345C)) *flag_mask += 1;
    if (*(u8*)(object + 0x345D)) *flag_mask += Shifted(work[0x9108]);
    if (*(u8*)(object + 0x345E)) *flag_mask += Shifted(work[0x9109]);
    if (*(u8*)(object + 0x345F)) *flag_mask += Shifted(work[0x910A]);
} else if (phase == 0) {
    *flag_mask = 1;
} else if (phase > 0) {
    *flag_mask = Shifted(work[0x9107 + (u32)phase]);
}
// phase < 0 leaves the zeroed mask in place.

s16 aux = 0;                             // original sp+4
s16 value = 0;                           // original sp+0
0x0028CDE4(object, &aux, &value);
*result = (s64)value;
return 1;
```

Each completed-phase gate re-loads `*flag_mask` and stores the sum, matching
the original's `ldrd`/`add`/`strd` sequence rather than accumulating in a local.
The two stack slots are both pre-zeroed because `0x0028CDE4` has paths that
return without writing the second slot; the caller reads the `sp+0` slot with
`ldrsh` and sign-extends it.

### Calls
- `0x002A8A08` — camp work getter. Its five-instruction body is
  `return *(u32*)(*(u32*)0x0043E2A8 + 4) + 0x8C;`; it reads no argument
  register. The original nevertheless leaves `r0 = entry_phase`,
  `r1 = flag_mask` and `r2 = 0` at the call. The C++ declaration carries those
  values, and the differential test compares `r0-r2`. `r3` is dead scratch
  (`0` in the original) and is not part of the declared contract.
- `0x0028CDE4` — direct camp helper (684 bytes). It takes the object in `r0`
  and two `s16*` output pointers in `r1`/`r2`, and writes only 16-bit values
  through them (verified across all of its switch cases). The call here passes
  `r1 = &aux` and `r2 = &value`; only `value` is read back. Its return value is
  ignored by the original and by the reconstruction.

Both callees are outside this translation unit and are unresolved at the
reconstruction level; the test replaces them with deterministic stubs at their
pinned addresses.

### Differences from the original
- Candidate size is 460 bytes versus 408. GCC uses a different frame layout and
  register allocation, materialises the `0x270F` comparison and the shift guard
  differently, and does not reuse the original literal pool.
- The original's `result` clear is two 32-bit stores; the C++ uses two `u32`
  stores as well, while `flag_mask` is cleared with a 64-bit store.
- The two output pointers are assumed not to alias the object or the camp work
  base. The original's intermediate stores would be observable only under such
  aliasing, which no recovered caller uses.
- Access order of the completed-phase stores is preserved (load/add/store per
  gate), so a caller that aliases `flag_mask` with a later-read gate byte would
  still see the same value.
