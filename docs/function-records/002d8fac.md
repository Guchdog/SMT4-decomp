# Function Record: ui_func_002d8fac (0x002D8FAC)

## Summary
- **Address:** `0x002D8FAC`
- **Size:** 420 bytes (original span `[0x002D8FAC, 0x002D9150)`; the last four
  bytes are the literal `0x0044DE28`)
- **File:** `src/engine/leaf_batch41_c.cpp`
- **Role:** Applies the save/load UI manager's selected slot page to the current
  profile object and status pipeline. It is called from the `saveLoadUI` calc
  task (`func_001c8d28`) at `0x001C9744` and `0x001C983C`.

  824 bytes versus the 420-byte original. The original uses word/halfword
  accesses for packed fields; Clang lowers the packed reconstruction to
  byte-wise accesses on this target. No byte-identity claim is made.

## Contract and Behavior

### Signature and ABI
```c

```
- The routine takes no arguments. The original prologue is
  `push {r4, r5, r6, r7, r8, lr}` and every exit restores the entry SP. `r8` is
  saved but not otherwise used.
- The return value is not consumed by either caller. The original leaves the

### Control flow
1. Load `selected = manager->selected`.
2. Return `selected` when `work->applied_selection_18 == selected`, then when
   `work->busy_28 != 0`, then when `work->transition_355 != 0`.
3. Store `work->applied_selection_18 = selected`.
4. Read `work[selected + 0x34C]`. Zero takes the deactivate path:
   `0x0029E260(0)`, `0x0029EB14(1)`, then tail branch `0x00299974(0)`.
5. Otherwise set `work->transition_355 = 1`, call `0x0029E260(1)`,
   `0x0029EB14(1)`, `0x00299974(0)`, and then re-read `manager->selected` to
   address the slot page for the copy block.
6. Copy the page into `work->profile_350` in the original order (word,
   halfword and byte fields, including the unaligned page word at `+0x3E` and
   profile word at `+0x0E`), then `0x002BCF58(profile + 0x1C, page + 0x30, 14)`
   and `0x002BF86C(profile + 0x4C, page)`.
7. `0x002BF86C(0x002C0B94() + 0x54, page)`. `0x002C0B94` returns
   `[0x0043E2A8] + 4 + 0x88`.
8. `0x0029A384(work->profile_350)`. The profile pointer and `manager->selected`
   are re-read here; a helper may have changed either.
9. Re-address the page from `manager->selected`. When the resulting pointer is
   null, skip `0x0026B810`; otherwise call `0x0026B810(page + 0x64 != 0 ? 1 : 0)`.
10. `0x0029C768(0)`.
11. `p = 0x002B66EC()` (`[0x0043E2A8] + 4 + 0x90`), then
    `0x002BCF58(p, work->profile_350, 14)`.
12. Dispatch the current profile's halfwords:
    `0x002998D8(1, profile + 8)`, `0x002998D8(2, profile + 0xA)`, then tail
    branch `0x002998D8(0, profile + 6)`.

All `work->profile_350` uses after the copy block re-load the pointer. The two
manager re-reads are observable: the differential suite covers helpers that
change `manager->selected` before the copy block and after `0x0029A384`, as well
as helpers that change `work->profile_350`.

### Unresolved targets and domain limits
- The helper bodies are stubbed in the differential suite. Their real internal
  behavior (task scheduling, status copies, text rendering) is not executed
  here; only the caller-visible arguments, order, return registers and memory
  effects are validated.
- The original's packed word/halfword accesses are expressed as `u32`/`u16`/`u8`
  fields. Clang emits byte-wise accesses for the packed views; the resulting
  values and final memory are identical for normal RAM. Device memory with
  access-size-sensitive semantics is outside the verified domain.
- The profile object has no known total size. The reconstruction writes only the
  bytes the ARM writes and uses a `0x77`-byte view; the original's unbounded
  `strcpy` into `profile + 0x4C` and `page` text are preserved.
- No emulator/runtime whole-game test was run for this leaf. The evidence is the
  offline Unicorn differential suite.
