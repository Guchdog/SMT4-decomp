# `0x00289640` — H2 callback state-word getter

Status: typed production C++; ledger `non_matching` because the compiler folds
the literal global address. The original span and compiled body are both 20
bytes. Original code loads literal `0x0044DE98`, reads the pointer at
`0x0044DEB8`, then returns the full word at `state+0xD0`. C++ addresses
`0x0044DEB8` directly, performs the same two memory reads in order, ignores its
input word, performs no writes and returns the raw `u32` value in `r0`.

The global pointer slot and pointed-to word must be valid, aligned normal RAM.
There is no null check. Invalid pointers, MMIO, concurrent mutation and runtime
ownership/lifetime are outside the supported domain. The callback at
`0x00221168` invokes the helper twice; a caller composition retained that ARM
callback and the original `0x0028DF3C`, while controlling its other helper
returns. Each composition reached the actual getter twice and preserved the
six final-helper arguments and callback return.

Evidence: 40 direct cases (eight explicit raw-word boundaries and 32 seeded
values), five original-callback compositions, zero differential failures, and
a detected `+0xD4` wrong-offset mutant. The reports compare the raw result,
ordered reads, all writes, callback-visible registers/SP, call trace and
relevant memory. See the [conversion report](../agent-work/h2-00289640-conversion.md).
