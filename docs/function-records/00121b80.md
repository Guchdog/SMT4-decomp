# Function Record: ui_func_00121b80 (0x00121B80)

## Summary
- **Address:** `0x00121B80`
- **Size:** 472 bytes (span `[0x00121B80, 0x00121D38)`). The last eight words are
  the literal pool `[0x00121D38, 0x00121D58)`; the last instruction is the
  failure-path `pop` at `0x00121D34`.
- **File:** `src/engine/leaf_batch34_c.cpp`
- **Role:** First-pass parser for a chunked font resource (the `0x002C4710`
  font-entry loader calls it after `AsdMem_Alloc`-ing the 0x18-byte info object
  from `0x00121D58`). It validates a `'CFNT'` container, rebases the resource
  offsets that the later glyph pass dereferences, rewrites the container magic
  to `'CFNU'`, and records the resource plus its `'FINF'` chunk in the info
  object. A `'CFNU'` container is only searched for its `'FINF'` chunk.
- **Status:** Reconstructed as readable C++ and **differentially verified**
  against the pinned original. The candidate body is 456 bytes and is not
  byte-identical, so the ledger row is `non_matching` and this record carries
  the semantic evidence.

## Contract and Behavior

### Signature and ABI
```c

```
- `r0 = info`: the 0x18-byte object created by `0x00121D58`. Only `+0x04` is
  read (`0x00121B8C`); `+0x04` and `+0x08` are written by `0x00131414` on
  success. `+0x00` and `+0x0C..+0x17` are untouched.
- `r1 = resource`: the loaded container image. Both entry paths read it and the
  `'CFNT'` path rewrites its first word.
- `r2`, `r3`: not read (the differential test seeds them with sentinels).
- **Return value:** `1` from the single `mov r0,#1` at `0x00121D20`, `0` from
  the failure `mov r0,#0` at `0x00121D30`, and `0` from the helper-rejected path
  (`0x00121C0C beq 0x00121D24` keeps the helper's `0` in `r0`).
- Callee-saved registers are preserved: the body pushes
  `{r0,r1,r4,r5,r6,r7,r8,sb,sl,fp,ip,lr}` (48 bytes), discards only the two
  spilled argument words (`add sp,sp,#8`) and pops
  `{r4,r5,r6,r7,r8,sb,sl,fp,ip,pc}`. Final SP equals entry SP.

Details pinned by the ARM encoding:
- The `'CFNT'` path is taken for **every** magic other than `'CFNU'`; the header
  check then rejects anything whose magic is not `'CFNT'`, so the effective
  domain is `'CFNT'` or `'CFNU'`.
- The `'FINF'` literal is loaded conditionally (`ldrgt r3,[pc,#0x178]` at
  `0x00121BBC`), i.e. only after the count was accepted; that is unobservable in
  the result but matches the original instruction order.
- Both loops advance the cursor before testing the index, so a zero size word
  reprocesses the same chunk once per index step; the differential test pins the
  doubled/tripled rebasing stores this produces.
- The `'CFNU'` search loads the count once, while the `'CFNT'` rebasing loop
  reloads it from `[resource+0x10]` every iteration (`0x00121CF0`); the
  reconstruction keeps that reload behind a compiler memory barrier.
- A `'FINF'` chunk does not stop the `'CFNT'` loop; only the index bound, an
  unknown tag, or the end of the table does. `found` therefore ends up pointing
  after the **last** `'FINF'` chunk.
- The magic word is rewritten on every normal loop exit, including a zero count,
  but not when the header check fails and not when an unknown tag aborts the
  loop. Rebasing stores already performed on earlier chunks are kept on abort.
- The tag split uses a **signed** `bge` against `'CMAP'` (`0x00121C54`), so tags
  `>= 0x80000000` fall into the `'FINF'`/`'CWDH'` group. Both groups reject every
  non-enumerated tag through `0x00121D2C`, so the sign choice has no observable
  alternative; the reconstruction keeps it for fidelity.
- `info+0x04` is the only early-out condition and is tested before the magic is
  read, so an already-parsed info object leaves even an unparsed container
  untouched.

## Domain Limits
- Both helpers are stubbed by address. The `0x0012AA74` model is transcribed
  from its disassembly and the differential test exercises its accept/reject
  branches, but its own machine code is not executed, and the real
  `0x00131414` object code is replaced by an equivalent Python store.
- The `'CFNU'` search path's chunk walk is only exercised over fixtures whose
  size words stay inside the resource page; a production resource with a
  corrupt size word would walk into whatever follows the allocation, exactly as
  the original does. No fault-injection case is claimed.
- The `'CFNT'` loop's per-iteration count reload can only observe a changed count
  if a chunk payload overlaps `resource+0x10`, which requires `chunk_offset == 0`
  and is therefore unreachable (the tag at `resource+0` would be the magic and
  the loop aborts as an unknown tag). The reload is reproduced for fidelity but
  no fixture can distinguish it.
- The signed tag split is documented above as unobservable: every tag that is
  not one of the five accepted names leaves through the same failure exit.
- No runtime, staging or production promotion is claimed.
