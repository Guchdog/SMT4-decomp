# Function Record: script_vm_func_00256078 (0x00256078)

## Summary
- **Address:** `0x00256078` (original span `[0x00256078, 0x002562E4)`, 620
  bytes, including the two marker literals `0x00000481`/`0x00000881` at
  `0x002562DC`/`0x002562E0`)
- **File:** `src/engine/leaf_batch45_a.cpp`
- **Role:** Commits a script/command request into a freshly claimed unit slot.
  The request's 15-word transfer tail is cleared in place, a unit slot is
  claimed according to `mode`, the 0x18C-byte request is copied to
  `slot+0xCC`, a per-mode payload handle is resolved, and a common join clears
  the actor scratch area, mirrors the request id and index into the owner's
  per-index actor table, and tail-calls `0x00255318` with the slot summary.
- **Status:** Semantically equivalent C++ (`non_matching`). The compiled body is
  604 bytes versus the 620-byte original. Clang folds the two literal-pool
  markers into immediates, reorders the mode dispatch (`2, 1, 0`), groups the
  15-word tail clear, and reorders a few provably disjoint loads/stores. The
  tail call still compiles to `b` (`R_ARM_JUMP24`) and every callee-saved
  register is restored before it. The ledger row is classified `non_matching`
  with this semantic record.

## Contract and Behavior

### Signature and ABI
```c
extern "C" u32 script_vm_func_00256078(void* owner, u8* request, u32 mode,
                                       s32 index, u32 flag);
```
- `r0 = owner` work area, `r1 = request` (0x18C-byte record), `r2 = mode`,
  `r3 = index`, `[sp] = flag` (the original reads it as `ldr r9, [sp, #0x20]`
  after the 0x20-byte `push {r4-r10, lr}`).
- The original saves `r4-r8, r9 (sb), r10 (sl), lr`, never touches `r11`, uses
  no VFP, and restores every saved register before the tail branch.
- Return value: every path ends in the tail branch to `0x00255318`, so `r0` is
  whatever that helper returns. The C++ returns that value; all recovered
  callers ignore it.
- No indirect calls, no stack arguments beyond the incoming `flag`.

### Mode dispatch (ARM evidence only)
The dispatch is three equality tests; any other 32-bit value falls through to
the join with the slot pointer still zero.

| `1` | `0x0033A7D4(owner)` (first free unit, index 4..0x35) | kind `0x11`, handle `0x002B087C((u16)request[+2])`, kind bit `0x100` when `request[+0xD4] == 1` |

### Sequence (exact order)
1. Clear the request's transfer tail: fifteen `u32` stores at
   `request+0x14C .. request+0x184` (range `[0x14C, 0x188)`).
2. Claim the slot and copy: `0x002BCF58(slot+0xCC, request, 0x18C)`. The copy
   is executed after the mode-specific claim in every mode and before every
   mode-specific field store.
3. Per-mode kind/handle stores, then the mode counter:
   - mode 0: `u16 owner+0x1FC4 += 1` (wraps modulo 2^16),
   - mode 1: `u16 owner+0x1FC6 += 1` (wraps modulo 2^16),
   - mode 2: no counter.
4. Common join:
   - `u16 slot+8 = (u16)index`;
   - `0x002C3B48(slot+0x72, 0x3C)` zero-fills `slot+0x72..slot+0xAD`;
   - zero `u32` at `slot+0xAE, +0xB2, +0xB6, +0xBA`, `u16` at `slot+0xBE`,
     and `u32` at `slot+0x258 .. slot+0x274` (eight words);
   - when `flag != 0`, set bit 29 (`0x20000000`) in the kind word at `slot+0`;
   - `entry = *(u32*)(owner+0x1E98) + (u32)index * 0x114`;
   - `u32 entry+0x50 = index < 4 ? 0x281 : index < 0x36 ? 0x481 : 0x881`
     (the original's unconditional `0x81` store is always overwritten);
   - `u16 entry+0x60 = u16 slot+0x6E` — this field lies **before** the copied
     region, so it is the slot's pre-existing value, not request data;
   - `u16 entry+0x62 = (u16)index`.
5. Tail branch: `0x00255318(index, 0xC, 0x003BE980(slot), 0)`.

### Field widths and signedness
- `index` is used as a full 32-bit value for the unit-array arithmetic in
  `0x00256418`/`0x0033A7D4` and for the actor-table offset
  `(u32)index * 0x114` (modular); it is truncated to `u16` only for the two
  index echoes.
- The two marker comparisons are signed (`cmp`/`blt`, `cmp`/`ldrlt`/`ldrge`),
  so negative indices take the `< 4` branch and store `0x281`.
- Mode 0 reads the payload index with `ldrsh` (`s16 request[+8]`); mode 1
  reads the id with `ldrh` (`u16 request[+2]`, zero-extended into `r0`); the
  mode 1 flag byte and the mode 0 selector are `ldrb`.
- Counters are read and written with `ldrh`/`strh`.

## Domain Limits
- All ten direct callees are stubbed. Their real bodies (unit-array scans,
  global-pointer dereference, the 0x604-stride record arithmetic, the memcpy
  and zero-fill loops, the id lookup and the 0x00255318 tail body) are not
  executed; only the arguments and return values observed here are modeled.
  The contracts above come from disassembling the pinned helpers.
- Null slot results are exercised with address 0 mapped as a zero page. The
  original then performs its low-address stores/reads (`0x8`, `0x72`, `0xCC`,
  `0x27C`, ...) exactly as the candidate does; with address 0 unmapped both
  would take a data abort, but fault timing and the abort type are not
  modeled. The same applies to modes outside `{0, 1, 2}`, which the original
  also runs with a zero slot pointer. No such mode was observed at a recovered
  call site (six pass constants 0/1/2; `0x003C14DC` forwards its own argument,
  which its caller compares against 0 and 1), so the null-slot join is
  reproduced but not exercised by a known caller.
- The C++ assumes the unit array (`owner+0x1FC0`) and the actor table
  (`owner+0x1E98`) are distinct allocations. Clang moves the `slot+0x6E`
  load before the `entry+0x50` store; that is only observable if the two
  tables overlapped, which the recovered callers never arrange.
- The mode 1 selection is delegated to `0x0033A7D4`; the test stub reproduces
  the recovered scan (`4 .. 0x35`, word 0 bit 0 clear), but the real helper's
  full body is not executed.
- The test covers the function in isolation. No emulator run, staged image,
  caller composition, production integration or whole-game equivalence is
  claimed.
