## Limits
- Fixtures are synthetic: the status work area, the panels, the sub-id exclusion
  lists, the demon-info record, and the manager use deterministic byte patterns,
  not captured game data.
- All helpers are stubbed; only the effects this function observes are modelled
  (the sub-id buffer write, the `Status_UpdateAffinityTable` flag set, and the
  demon `+0x4B` byte). No real status-down UI, list population, sound, rendering,
  or script-VM state is exercised.
- The panel at `+0x18B0` is not present in the current `StatusWork` layout
  (it lies inside `unk_1300`), so the `+0x18B0`/`+0x18F8` relationship is taken
  from the instructions only.
- Offset names beyond the two menu-id bytes are descriptive labels taken from
  the call contracts; they are not field declarations.
- No runtime or whole-game equivalence is claimed. Integrated status-screen
  behavior still requires runtime validation.
