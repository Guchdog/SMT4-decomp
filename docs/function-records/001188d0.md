# Function Record: ui_func_001188d0 (0x001188d0)

## Summary
- **Address:** `0x001188d0`
- **Size:** 660 bytes (original span `[0x001188d0, 0x00118b64)`: 159 ARM
  instructions through the conditional epilogue at `0x00118a50`, the two
  list/grid bodies, and the six literal words at `0x00118b4c..0x00118b63`)
- **File:** `src/engine/leaf_batch45_a.cpp`
- **Role:** Refresh one UI list/grid panel. When the panel status byte is 1 or
  5 the function pushes the `0xF10` viewport command onto the layer-3 render
  command stack, draws every row of the panel's current kind (`0x0B` list or
  `0x13` grid) from the camp node table, resets the render colour, and pops the
  viewport command. Unhandled kinds only push and pop the command.
- **Status:** Semantically equivalent C++ (`non_matching`). The compiled body
  is 572 bytes versus the 660-byte original. The candidate keeps `d9` live as
  well (saving both `d8` and `d9`) and uses a different register allocation,
  a `0xF10`-style mask test (`and #0xFB; cmp #1`) instead of the two
  comparisons, duplicated post-loop reset code instead of one shared block, and
  a `.rodata` copy of the node-id table instead of a stack copy. No
  byte-identity claim is made.

## Contract and Behavior

### Signature and ABI
```c
extern "C" void ui_func_001188d0(u8* panel);
```
- `panel = r0`, saved in `r4`; no other arguments are read.
- No computed return value. Every exit restores `r4-r8, sb, sl, fp` and `d8`
  (the candidate also restores `d9`) and returns to the caller's `lr`; final
  `sp` equals the entry value. `r0` after the body is whatever the final
  `0x2BEF88` pop returns (the popped entry value). On the rejected status path
  the original leaves the loaded status byte in `r0`; that value is not part of
  the `void` contract.
- The four callees reached through a real `bl` (`0x2C5F7C`, `0x2BEFDC`,
  `0x2BDA00`, `0x2BEF88`) are ordinary AAPCS functions. The candidate performs
  the final `0x2BEF88` call as a tail call after restoring its frame; the callee
  returns through `pop {..., pc}`, so the observable continuation is identical.

### Panel and global layout (offsets only, as evidenced by the ARM)
- `panel + 0x04`: `u8*` render object. Reloaded from `[r4,#4]` at every use
  site (store at `+0xB0`, `0x2BDA00`, `0x2B792C`, `0x126754`, tail reset).
- `panel + 0x08`: `u8` status. The body runs only for `1` or `5`.
- `panel + 0x09`: `u8` kind. `0x0B` = list path, `0x13` = grid path, anything
  else skips both bodies (but still pushes/pops the command).
- `panel + 0x18`: `s32` selected row, compared for equality with the row index.
- `panel + 0x20`: `s32` row count; signed `> 0` gates each loop and is re-read
  after every row.
- Render object: word `+0xB0` receives the row colour/format selector, and
  `0x2BDA00` writes `[+0x9C] = arg1`, `[+0xA0] = arg2`, `[+0xA4] = arg3`,
  `f32 [+0xA8] = value`.
- `0x0044EA00`: global `u8*` render base. Read before the push and again before
  the pop; the intervening callees could in principle replace it.
- `0x0040417C + 0x34` (`0x004041B0`): nine authentic signed node ids
  `{0xA8, 0xA9, 0x9C, 0x9D, 0x9E, 0xB0, 0xB1, 0xB2, 0xB3}`. The original copies
  them to `sp+8..sp+0x28`; the candidate embeds the same nine words in
  `.rodata` (verified byte-identical against the pinned table).
- Node record (from `0x2BF6D0`): `s16 +0x08` x, `s16 +0x0A` y, `u32 +0x0C`
  anchor pointer; the grid path reads `s16 [anchor]`.
- Literal pool values: `0x0044EA00`, `0.0f`, `1.0f`, `0x0040417C`,
  `0x5A5A5AFF` (inactive row colour), `0x646464FF` (post-list reset colour).

### Control flow and calls
1. `status = panel[8]`; if `status != 1 && status != 5`, return immediately
   (`0x1188e0..0x1188ec`). No command is pushed or popped.
2. `func_002befdc(*[0x0044EA00], 3, ui_func_002c5f7c(1, 0))`. The real
   `0x2C5F7C` returns `0xF10`; `0x2BEFDC` pushes it into the layer-3 command
   stack at `base + 3*0x20 + 0x11EC`, and calls `[stack+0x1C]` when the stack
   callback flag is non-zero or the previous entry differs.
3. Kind dispatch:
   - `0x0B` (list):
     `window = count == 3 ? 2 : count == 4 ? 5 : 0`.
     If `count > 0`, for `index = 0 .. count-1` (count re-read each round):
     `node = camp_func_002bf6d0(0x0E, table[window + index])`;
     read `render = panel[4]`;
     if `panel[0x18] == index`, `[render+0xB0] = 0x0A` and
     `ui_func_002bda00(render, 0, 0xFFFFFFFF, 0.0f)`, else
     `[render+0xB0] = 0x0B` and
     `ui_func_002bda00(render, 0, 0x5A5A5AFF, 0.0f)`;
     then `func_002b792c(panel[4], (s16)node[8], (s16)node[0xA] - 4, 0x33,
     1.0f, 6, index)`.
     After the loop (also when `count <= 0`): `[panel[4]+0xB0] = 0` and
     `ui_func_002bda00(panel[4], 0, 0x646464FF, 0.0f)`.
   - `0x13` (grid):
     `origin = camp_func_002bf6d0(0x3A, 0x97)` **before** the count test.
     If `count > 0`, for `index = 0 .. count-1` (count re-read each round):
     `node = camp_func_002bf6d0(0x3A, index + 0x98)`;
     if `panel[0x18] == index`,
     `func_002bf558(2, 0x3A, 0x12, (s16)node[8], (s16)node[0xA], 0x0B)` and
     `[panel[4]+0xB0] = 0x0F`, else the same call with `0x11` and
     `[panel[4]+0xB0] = 0x0E`;
     `scale = (s32)func_00126754(panel[4], index)`;
     `x = (s16)origin[8] + (s16)node[8] + ((s16)[origin[0xC]] >> 1) -
     (scale >> 1)`;
     `y = (s16)origin[0xA] + (s16)node[0xA]`;
     `func_002b792c(panel[4], x, y, 0x33, 1.0f, 6, index)`.
     After the loop (also when `count <= 0`): the same
     `[+0xB0] = 0` / `0x646464FF` reset as the list path.
   - Any other kind jumps directly to step 4, skipping the reset.
4. `func_002bef88(*[0x0044EA00], 3)` — pop from the layer-3 command stack with
   the same callback condition.

### Architected stack arguments
```text
0x2BF558 (grid rows):  r0 = 2  r1 = 0x3A  r2 = 0x12/0x11  r3 = (s16)node[8]
                       [sp + 0x0] = (s16)node[0xA]   (sign-extended)
                       [sp + 0x4] = 0x0B
0x2B792C (both paths): r0 = render  r1 = x  r2 = y  r3 = 0x33  s0 = 1.0f
                       [sp + 0x0] = 6
                       [sp + 0x4] = row index
```
Both words are read by the callees (`0x2BF558` reads them before its own frame
is built; `0x2B792C` reads them at `[sp,#8]` / `[sp,#0xC]` after
`push {r4,r5}`), so the test compares them. The grid path's temporary
`stm sp, {node_y, 0x0B}` at `0x118a9c` is exactly the argument pair consumed by
`0x2BF558`; it is overwritten by `6`/`index` before `0x2B792C`.

### Signedness and arithmetic details
- `panel[0x20]` (count) and `panel[0x18]` (selected) are signed 32-bit values;
  every bound check is a signed `bgt`/`ble`.
- Node and anchor coordinates are signed halfword loads (`ldrsh`).
- `x`/`y` sums are 32-bit wrapping adds (the candidate performs them in `u32`
  to keep the same low 32 bits).
- Both half-extents use an **arithmetic** right shift (`asr #1`, rounding
  toward negative infinity), not a division. The float-to-int step is
  `vcvt.s32.f32` (round toward zero); the candidate expresses it as
  `static_cast<s32>(f32)`.

## Frame and unresolved limits
- The original copies the nine node ids from `0x004041B0` into its own frame.
  For a list count above the selected window it reads past that copy into
  caller stack memory (`window = 2` allows at most 7 rows; `window = 5` at most
  4). Such calls are not semantically defined by the original and are excluded
  from the differential cases; the candidate instead reads the same table from
  `.rodata`, so out-of-range list counts would read different adjacent data.
- `0x2BF6D0`, `0x2B792C`, `0x2BF558` and `0x126754` are stubbed; their real
  behaviour is out of scope. `0x2BF6D0` is never observed returning null, nor
  are the anchor pointers; the original dereferences them unconditionally, so a
  null result would fault in both bodies.
- `0x126754` values outside the `s32` range of `vcvt.s32.f32` are not
  exercised.
- No emulator or whole-game runtime scenario was run; this record covers the
  offline differential contract only.
