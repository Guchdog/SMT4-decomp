# Function Record: ui_func_00108300 (0x00108300)

## Summary
- **Address:** `0x00108300`
- **Size:** 496 bytes (`[0x00108300, 0x001084F0)`; the last word at
  `0x001084EC` is this function's literal-pool entry `0x0044EA00`)
- **File:** `src/engine/leaf_batch34_c.cpp`
- **Role:** `"HDRCL"` frame-capture callback. It resolves the packed widget
  handle to the FrameTex scene, trims the capture-texture chain after a
  completed capture, publishes the trim helper's byte result and the completion
  flags, and always returns 0.
- **Status:** Semantically equivalent C++ (`non_matching`). The compiled body is
  412 B versus 496 B: the candidate uses only `r4-r6` (plus `lr`) instead of
  `r4-r8, sb, sl`, folds the count decrement into
  `count - (mode == 0 && count > 1)` and merges independent scene loads. The
  ledger row is classified `non_matching` with this record.

## Contract and Behavior

### Signature and ABI
```c
extern "C" u32 ui_func_00108300(u32 handle);
```
- `handle = r0`, forwarded unchanged to `0x002C0AC8`.
- The callback is registered as the calculation callback of the `"HDRCL"`
  task (`AsdUi_Create("HDRCL", 0x6A, 0, 0, 0x00108300, 0x00107890, scene)`,
  `0x00104494..0x001044A8`). The callback parameter is therefore whatever the
  task layer passes in `r0`; `0x002C0AC8` interprets it as a packed lookup
  handle (`index = handle >> 20`, `key = handle & 0xFFFFF`).
- Returns `0` on every path.
- The original saves `r4-r8, sb, sl, lr` and restores all of them; final `sp`
  equals the entry value.
- No indirect calls and no stack arguments.

## Compiler transformations that preserve observable behavior
- The initial `scene->+0xE95 = 0` and the `+0xE8C` load are independent
  addresses, so the candidate emits the load first. Both orders end with the
  same memory and the same return, including the null-lookup case with the low
  page mapped.
- The success stores `+0xE95 = 1` / `+0xE96 = 0` are emitted in the opposite
  order. They target distinct bytes and produce the same final memory.
- `count -= 1` with a `max(..., 1)` clamp is emitted as
  `count - ((u32)CaptureMode(0) == 0 && count > 1)`, which is equivalent because
  `count > 1` makes `count - 1 >= 1`.
- Independent source-pointer and source-field loads are merged where the
  original reloads them; helpers cannot observe the difference unless the scene
  and a texture object overlap in memory (they are separate allocations in the
  pinned game; the tests use distinct pages).

## Limits
- All five callees are stubbed; no real widget lookup, GPU pass, texture trim,
  layout-mode query or texture blit is exercised. Their internal contracts are
  inferred only from their register use at this call site.
- Helper side effects are synthetic. The stubs deliberately mutate scene and
  texture memory to prove reload behaviour, but the real helpers may write other
  fields.
- The packed handle encoding, `+0xE8C/+0xE8D/+0xFD8/+0xFE0` meanings and the
  capture-texture chain semantics are not established beyond their role here.
- The test maps the low page so the null-lookup path is observable; on a real
  unmapped page the original faults at the `+0xE95` store while the candidate
  faults at the preceding `+0xE8C` load (compiler reordering), which is not
  modelled.
- No caller-composition, emulator-run or whole-game runtime equivalence is
  claimed.
