# Function Record: func_001c0610 (0x001c0610)

## Summary
- **Address:** `0x001c0610`
- **Size:** 476 bytes (original span `[0x001c0610, 0x001c07ec)`). The body ends
  with the `pop {r4, r5, r6, pc}` at `0x001c07d8`; the four words
  `0x001c07dc..0x001c07eb` are the literal pool (`0x004e0e88`, `0x004e1e88`,
  `0x004e1ed4`, `0x004e1f14`). `0x001c07ec` starts the next function.
- **File:** `src/engine/leaf_batch34_c.cpp`
- **Role:** Submits up to 16 caller-supplied words to the subsystem object at
  `0x004e0e90` through `0x0035efbc`, then latches the non-zero words of the
  produced 16-word buffer into a global result table and returns the result
  table address.
- **Status:** Reconstructed as readable C++ and **differentially verified**
  against the pinned original (56 cases + 8 negative controls). The candidate
  body is 604 bytes and is not byte-identical (the compiler zeroes the word
  buffer through `__aeabi_memclr8`, unrolls the copy loop and merges the final
  status OR), so the ledger row is `non_matching` and this record carries the
  semantic evidence.
- **Class:** non-leaf on the semantic ledger (`unknown` category retained).

## Contract and Behavior

### Signature and ABI
```c
extern "C" u32 func_001c0610(u32* values, s32 count);
```
- `values = r0`: pointer to a caller-owned word array; only `values[i]` for
  `i < min(count, 16)` is read, as 32-bit words.
- `count = r1`: signed request. Interpreted with **signed** comparisons at
  `0x001c0644` (`cmp r1,#0x10` / `bgt`) and `0x001c0658` (`rsbs` / `beq`).
- **Return value:** `0` on all three exit paths, `0x004e1f14` on success.
  The in-image caller dereferences the result (`0x00397f48` loads
  `[result]`), so the success value is the result-table address.
- `r2`, `r3`, `r12` are never read. The prologue pushes `{r4, r5, r6, lr}`;
  `r4-r6` are restored, `r8-r11` are never touched, `r12` is caller-saved.
- The frame is 0x48 bytes: `[sp+0x00]` is the single stack argument of the
  helper, `[sp+0x08..0x44]` is the 16-word buffer handed to the helper.
  `[sp+0x04]` is never written (argument padding).
- One direct ARM `bl` (`0x001c0750` -> `0x0035efbc`); no indirect call.

### Caller evidence
- The only `bl` to this address in `code.bin` is `0x00220ef4`, inside
  `0x00220eb4`. It copies a text buffer (`0x002bf86c`), converts it with
  `0x002acac4([sp+0x104], sp, 0x100)`, then calls
  `0x001c0610(sp+0x104, original r2)` and returns the result unchanged.
  `0x00397f30` is its only caller and passes `r2 = 1`, so that caller reads
  only `values[0]`.
- No word in the image equals `0x001c0610` (no function-pointer table entry).
- The base address literal `0x004e0e88` is also loaded by `0x00103b54` inside
  the subsystem initializer `0x00103aa0`. That initializer sets up the object
  at `+0x08` through `0x0010fc44` / `0x0010fca0` and then sets **bit 0** of
  `[0x004e0e88]` (`0x00103b0c`/`0x00103b10`); this is the gate tested at
  `0x001c0624`.

### Object layout
Control block at `0x004e0e88` (only the words this routine touches are named):
```text
+0x0000  u32  state     bit 0 = subsystem initialized
+0x0004  u32  status    sticky status bits, OR-accumulated
+0x0008  ...            object forwarded to 0x0035efbc
```
Scratch block at `0x004e1e88` (= control + 0x1000; literal `0x001c07e0`):
```text
+0x048  u32    source            caller word pointer
+0x04c  u32[16] input            clamped copy of the caller words
+0x08c  u32[16] result           zeroed, then non-zero buffer words
+0x0cc  u32    requested         request before clamping
+0x0d0  u32    capacity          constant 16
+0x0d4  u32    word_d4           cleared
+0x0d8  u32    word_d8           cleared
```
`input` spans `0x4c..0x8b` and `result` starts immediately at `0x8c`; the
`static_assert`s in the source pin both literals to their struct offsets.

### Control flow
1. `0x001c0624`: `([0x004e0e88] & 1) == 0` returns 0 without any other access.
2. `0x001c0628..0x001c0648`: store `values` at `+0x48`, clear `+0xd4` and
   `+0xd8`, then store the raw request at `+0xcc` and `0x10` at `+0xd0`
   (a single `stm`), *before* the clamp decision.
3. `0x001c0644..0x001c065c`: signed clamp.
   - `count > 0x10` -> limit `= 0x10`;
   - else limit `= count`, and `count == 0` returns 0 here (no buffer or result
     zeroing yet).
4. `0x001c0664..0x001c06e4`: zero the 16-word stack buffer and the 16-word
   global result table (two separate inline store runs in the original).
5. `0x001c06e8..0x001c0738`: copy `limit` words into `+0x4c`.
   - `limit > 0`: `index = limit & 1`; when odd, `input[0] = values[0]`
     (the *original* `r0`, read with a word load at `0x001c06f8`).
   - copied in pairs while `index < limit`: `input[index] = source[index]`,
     `input[index + 1] = source[index + 1]`, with `source` reloaded from
     `+0x48` between the two stores.
   - a non-positive limit skips the loop (`index` is set to 0 and
     `0 <= limit` is false).
6. `0x001c073c..0x001c075c`:
   `0x0035efbc(0x004e0e90, buffer, 1, 0x004e1ed4, limit)` with `limit` in the
   stack argument slot. `ands r0,r0,#0x80000000` + `bpl`: bit 31 set is a
   failure.
7. Failure (`0x001c0760..0x001c0774`): status `|= 0x00040000`, return 0.
8. Success (`0x001c0784..0x001c07c0`): only while `limit > 0`, for
   `slot = 0..limit-1`, a non-zero `buffer[slot]` latches status
   `|= 0x00020000` and stores the word at `+0x8c + 4*slot`; zero words are
   skipped. Then status `|= 0x00010000` and return `0x004e1f14`.
9. Every exit restores `sp` by `0x48` and returns through
   `pop {r4, r5, r6, pc}`.

The zero/non-zero test at `0x001c0798` is `cmp r1,#0` on a full word, so a
value with only bit 31 set is treated as **non-zero**.

## Contract corrections found during implementation
- **The request fields are written before the clamp test.** The `stm` at
  `0x001c0648` stores the raw `r1` and `0x10` before the `bgt`/`rsbs` pair, so
  both `+0xcc` and `+0xd0` change even when the function returns 0 for a zero
  request. The C++ keeps that order.
- **The limit is signed.** `count > 0x10` and `count == 0` use signed
  `bgt`/`beq` after `rsbs`. Negative requests survive the clamp unchanged and
  are then passed to the helper as a huge unsigned count. A later
  `cmp r4,#0` / `ble` guards both loops with a signed test.
- **`values[0]` on the odd path is read through the original `r0`**, while the
  pair loop reloads the pointer from `+0x48`. Both resolve to the same address
  because `+0x48` was just written with `r0`.
- **The non-zero test is a full-word compare**, not a byte or sign test; bit 31
  alone makes a word "non-zero".
- **The result table zeroing precedes the copy.** If `values` aliases
  `0x004e1f14`, the copy therefore reads zeros, not the caller's previous
  values (covered by a test case).

## Limits
- `0x0035efbc` was not reconstructed here. It is stubbed from the observed
  register contract (object, output buffer, mode, input table, stack count) and
  the observed sign-bit result. Its internals (`0x003e1050` validation,
  `0x0035f71c`, `0x0035f1b0`, `0x002bb8e4`, `0x002bce48`, `0x002b93f0`) and any
  side effects on the object at `0x004e0e90` are outside this routine.
- The candidate zeroes its stack buffer with an `__aeabi_memclr8` call emitted
  by Clang; the test links a zero-fill implementation at a private address and
  excludes it from the compared call log. The original inlines the 16 stores.
  The final buffer contents are identical.
- The candidate's gate test is compiled as a byte load of `[0x004e0e88]`
  (Clang narrowed the `& 1`), while the original loads the full word. The
  observable bit-0 result is identical and the read has no side effect; no
  volatile was added.
- The candidate keeps the source pointer in a register across one copied pair
  instead of reloading `+0x48` between the two stores. This differs only if the
  input table aliases the stored pointer slot, which cannot happen (the slot is
  at `+0x48`, the table starts at `+0x4c`).
- No emulator/runtime scenario was run: the evidence is offline Unicorn ARM
  execution of the pinned bytes versus the compiled candidate with identical
  fixtures. The caller context (`0x00220eb4`/`0x00397f30`) is static reading,
  not a runtime capture.
