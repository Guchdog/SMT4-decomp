# Function Record: ui_func_002fe358 (0x002fe358)

## Summary
- **Address:** `0x002fe358`
- **Size:** 680 bytes (`[0x002fe358, 0x002fe600)`), including the five-word
  literal pool at `0x002FE5EC..0x002FE5FC`
- **File:** `src/engine/leaf_batch45_a.cpp`
- **Role:** Builds or copies the caller's 0x20-byte UI record array for a
  descriptor. The descriptor type byte selects between generating records
  through `ui_func_002fe600` and copying a pre-baked record block that
  `ui_func_002e2750` post-processes. A time-like value assembled from four
  signed descriptor bytes chooses the descriptor variant / block offset.
- **Status:** Semantically equivalent C++ (`non_matching`). The compiled body is
  608 bytes versus 680: Clang turns the type-0 forward call into a tail call,
  folds the two constant-time comparisons, and allocates registers differently.
  Branch structure, helper arguments, call order, written bytes and return
  values were validated differentially.

                                const u8* descriptor,
                                const ui_fe600::CatalogSlot* catalog,

- `r0 = out` (0x20-byte record array), `r1 = capacity` (signed record limit),
  `r2 = descriptor`, `r3 = catalog` (0x48-byte slots), first stack word

  copied `count` for type 1), or 0 for any other type.
- Prologue: `push {r4-r8,sb,sl,fp,lr}`, `vpush {d8}`, `sub sp,#0xFC`. Every exit
  restores them; the final SP equals the entry SP.
- Sole caller: `0x00334498` in the frame starting at `0x00334458`:
  `out = work + 0x3F4`, `capacity = 50`, `descriptor = *(u32*)(work + 0x1E88)`,
  `catalog = work + 0x1074`, `catalog_count = *(u32*)(arg + 8)`. The caller

## Control Flow

1. **Prologue** (`0x2FE358..0x2FE3C0`): save registers, derive `time`, read the
   type byte.
2. **Dispatch** (`0x2FE3B8..0x2FE3D0`): type 0 → `0x2FE43C`, type 1 →
   `0x2FE3D4`, anything else → return 0.
3. **Type 0**:
   - `time >= 1300` (`0x2FE440`): `0x002FE600(out, capacity, sub, catalog,
     catalog_count)` and return its result.
   - `time < 1300` (`0x2FE46C`): default four header words, call `0x002C5F58`,
     copy the header words and groups from the sub-block, store the six floats,
     then call `0x002FE600` with the stack source and return its result.
4. **Type 1** (`0x2FE3D4..0x2FE5E8`):
   - choose `mode`/`base`, compute `count`, cap it, and call
     `0x002BCF58(out, sub + base, count * 0x20)`.
   - If `time == 1200`, store `0.0f` at `+0x14` of each copied record.
   - Fill `capacity - count` remaining records with
     `{key = 0xFFFFFFFF, u16@+4 = 0, byte@+6 = 0xFF}`.
   - For each copied record, linearly search `catalog_count` slots of stride
     0x48 for `*(s32*)(catalog + j*0x48 + 4) == record->key`; on the first
     match store `(u8)j` at record `+0x06` and stop.
   - Call `0x002E2750(out, count, mode, catalog)` and return `count`.

argument, so this is a dead store retained only by the original frame.

## Limits
- `0x002BCF58`, `0x002C5F58`, `0x002FE600` and `0x002E2750` are deterministic
  stubs. The real initialiser at `0x00333FEC`, the catalog tables, the
  `0x002FE600` generator and the `0x002E2750` post-pass are not executed.
- Fixtures are synthetic. The catalog, descriptor and output pages are mapped
  separately; aliasing between them is not tested.
- Negative `capacity` or a `count` that stays negative after capping can make
  the original copy a very large wrapped size. Those states are outside the
  supported test domain; positive and zero capacities are covered.
- The descriptor is dereferenced without a null check by both versions; a null
  descriptor is not a supported input.
- The `+0x24` word of the stack source is copied but not read by the current
  `0x002FE600`; it is preserved because the original writes it.
- No caller composition, game data capture, emulator run or whole-game runtime
  equivalence is claimed. The integrated caller at `0x00334498` is documented
  but not executed against a patched image.
