## Interface

`extern "C" void camp_func_0033504c(void)` — standard AAPCS. No register or
stack argument is read, and the routine returns nothing: the original never
sets `r0` for the caller, which keeps whatever the last helper left there, so
`r0` is not part of the contract. `r4`-`r11` are preserved; the prologue pushes
`r4-r11` and `lr`, reserves `0x4c` bytes of stack, and the tail restores both.

`r7` is the ascending key loop counter (`1..0x8C`); `sb` holds the recovered
literal `0x001455DC`; `sl` is `1`, the bit mask base; `fp` is cleared but unused.

## Behavior

For each key `1..0x8C` (inclusive; the compare is unsigned `< 0x8D`):

1. Read the game-work bit area once in the prologue:
   `flag_bits = engine_func_0023f554()` (`0x0023F554` returns
   `[0x0043E2A8]+4 + 0x981E`). The saved value is reused for the final bit
   stores, even though the bit-test loop calls the getter again.
2. Search TBB global slot `0x0B` for the key:
   - `table = Tbb_GetGlobalSubTable(0x0B, 0)` (`0x002C0EC4`); null skips the key.
   - `payload = Tbb_GetPayloadData(table)` (`0x002C0E9C`);
     `rows = Tbb_GetRowCount(table)` (`0x002C0E4C`).
   - The key is a 0x40-byte scratch record whose only initialized field is the
     `u16` at `+0x20`, written immediately before each search. The search is
     `script_vm_func_002b48dc(key, payload, rows, 0x40, comparator)`
     (`0x002B48DC`, Thumb), a binary search returning the element whose
     comparator result is zero or null.
   - The comparator is the interior block `0x001455DC`:
     `return *(u16*)(a + 0x20) - *(u16*)(b + 0x20)`, i.e. the key is matched
     against the record's `u16 +0x20`.
   - A null element, or a non-zero `u16` at element `+0x26`, skips the key.
3. Repeat the same lookup (same key, same slot, same comparator). A null table
   or a null element skips the key.
4. `state = script_vm_func_002b66ec()` (`0x002B66EC` returns
   `[0x0043E2A8]+4 + 0x90`). Compare `record[0x2B]` (u8) with `state[0x76]`
   (u8) unsigned: `> ` skips the key, `<=` (including equality) continues.
5. Flag gate over the three `u16` ids at `record +0x2C, +0x2E, +0x30`:
   a zero id is not probed (no call); a non-zero id calls
   `script_vm_func_002c0ba8(id)` (`0x002C0BA8`, event-flag test) and a zero
   result aborts the key. All three positions are always visited, so a failure
   on the third id still costs three calls.
6. Bit gate over the three `u16` indices at `record +0x32, +0x34, +0x36`: a
   zero index is not tested; otherwise `engine_func_0023f554()` is called again
   and the key continues only when
   `bits[index >> 3] & (1 << (index & 7))` is non-zero.
7. A third lookup is performed exactly like steps 2-3; its result is discarded.
   When its table is null the search is skipped (the two paths converge).
8. `script_vm_func_00295f90()` (`0x00295F90`, reads one work word at
   `[0x0043E2A8]+4 + 0x9870`) is called and its result is discarded.
9. Set the key bit in the prologue snapshot:
   `byte = flag_bits + (key >> 3)`, `byte[0] |= 1 << (key & 7)` and
   `byte[0x12] |= 1 << (key & 7)`. The original's sign-corrected split
   (`asr r1, r7, #31; add r2, r7, r1, lsr #29; asr r1, r2, #3; ...`) reduces
   to `>> 3` / `& 7` for the non-negative key.

Keys `0` and `0x8D` are never processed.

## Verification

- `python tools/test_leaf_0033504c.py`: 12/12 differential cases and 5/5
  negative controls pass.
  - The real pinned `0x002B48DC` (Thumb) and `0x001455DC` comparator are
    executed from `extracted/exefs/code.bin`, so the 5th stack argument and the
    0x40 stride genuinely drive a binary search over a sorted 140-record table.
    The other seven callees are deterministic stubs at their original
    addresses.
  - Compares continuation PC, final SP, callee-saved `r4`-`r11`, the ordered
    call log (table/payload/rows per lookup, flag ids and results, both getters,
    the discarded work read), the full 0x10000-byte bit page, the 0x1000-byte
    state page and the 0x4000-byte record page.
  - Cases cover every key `1..0x8C` (keys `0`/`0x8D` must stay clear), table
    null on each of the three searches, a zero-row search on each of the three,
    `+0x26` filter zero/non-zero, the `+0x2B`/`state[0x76]` unsigned boundary
    (less, equal, greater, `0xFF` vs `0x20`), all three flag positions (zero
    skipped, true, false on second and third), all three bit positions (zero
    skipped, set/clear, byte `0x00`, `0x20` and `0x2F`), and a combined branch
    mix.
  - Negative controls patch the pinned original: loop bound `0x8D -> 0x8B`,
    filter compare against 1, `BHI -> BGE` on the `+0x2B` test, the clear-bit
    abort replaced by a NOP, and the flag-result compare against 1; each change
    must be detected.
- `python -m py_compile tools/test_leaf_0033504c.py` passes.

## Limits

- The seven stubbed callees are replaced by deterministic seams. Their real
  table walk, game-work layout and event-flag storage are not exercised here;
  the test covers the arguments and return values this function observes.
- The TBB slot `0x0B` payload is a synthetic sorted record table; the real
  record field meanings beyond the offsets above are not established.
- `r0` at return is not compared because the original does not define it.
- No caller-composition, runtime or whole-game equivalence is claimed. The
  compiled candidate exceeds the 480-byte original slot (540 B), so placement
  would need a span/slot decision; byte identity is not claimed.
