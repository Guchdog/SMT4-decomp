# Function Record: battle_func_002bc3c8 (0x002bc3c8)

## Summary
- **Address:** `0x002bc3c8`
- **Size:** 424 bytes (original span `[0x002bc3c8, 0x002bc570)`; 98 ARM
  instructions through the unconditionally executed `pop` at `0x002bc54c`,
  followed by 32 bytes of literal data at `0x002bc550`)
- **File:** `src/engine/leaf_batch41_c.cpp`
- **Role:** Closes the current GPU command-buffer segment of the active render
  node and appends one 28-byte replay entry describing it. The entry is handed
  to the node's optional pending-entry writer, committed, and, when this node is
  the active one, the pending list may be flushed. All work is performed while
  holding the engine lock at `0x004E6C5C`.
- **Status:** Semantically equivalent C++ (`non_matching`). The compiled body is
  412 B versus the 424 B original; the ledger row is now classified
  `non_matching` with this record. Differences are register allocation,
  branch layout, and the fact that the candidate reaches the two lock thunks
  with `bl`/`b` from a common return path instead of one tail branch.

### Control flow
1. `node = *(RenderNode**)(0x004C6290 + 0x9C)` (no null check).
2. `offset = g_GpuCommandCursor - node->buffer_04` (32-bit subtraction) and
   `node->cursor_0C = offset`.
3. If `node->committed_14 == offset`, return immediately (the cursor store
   above is still performed).
4. Segment rounding:
   - `offset & 8 != 0` (`tst r2,#8`): `node->cursor_0C = offset + 0x18` and the
     marker record is **not** emitted.
   - `offset & 8 == 0`: `node->cursor_0C = offset + 0x20`; when
     `entry_time_cursor < g_GpuCommandEnd` append the 8-byte record
     `{0x00000000, 0x0008025E}` and advance `g_GpuCommandCursor` by 8.
5. Append, each only while `g_GpuCommandCursor < g_GpuCommandEnd` (unsigned
   `bhs`), with both globals reloaded for every record:
   - `{0x00000001, 0x000F0111}`
   - `{0x00000001, 0x000F0110}`
   - `{0x12345678, 0x000F0010}`
6. `entry = node->entries_18 + node->count_20 * 28` (32-bit wrapping
   multiplication), then fill the four fields listed above. `entry->flags_0C`
   is written as `(old & ~2)` and bit 0 set only when `node->enabled_3D != 0`.
7. If `node->writer_34 != 0`, call `0x002AA8B0(node, entry)`. The flags word is
   read **after** this call, so a writer that ORs bit 2 into it is observed.
8. Reload `node->cursor_0C`, store it to `node->committed_14`, acquire the
   `0x004E6C5C` lock (`0x0013AF78`), then reload `node->count_20`, increment it
   and store.
9. Flush gate:
   - `*(0x004C6290+0xA0) != node` -> no flush;
   - equal and `+0x12 == 0` -> no flush;
   - equal, `+0x12 != 0`, `+0x11 != 0` -> no flush;
   - equal, `+0x12 != 0`, `+0x11 == 0` -> store `+0x11 = 1` and call
     `0x002BA5F8`.
10. Release the `0x004E6C5C` lock (`0x0013AF88`) as a tail branch.

The rounded segment length is consistent with the buffer state: when every
record fits, `node->cursor_0C` equals the new `g_GpuCommandCursor` minus
`node->buffer_04` (0x20 bytes when the marker was emitted, 0x18 otherwise).

## Unresolved / domain limits
- **`0x002AA8B0` is not reconstructed here.** Disassembly shows it reads
  `node+0x34` (writer object), `entry+4`/`entry+8`, calls `0x0014782C`, ORs bit
  2 into `entry+0x0C`, rewrites `entry+8` from `node+0x30`, and clears
  `node+0x30`/`node+0x34`. The differential runner stubs it deterministically
  (including those observable writes); the real writer's `0x0014782C`
  behavior remains outside this record.
- **`0x002BA5F8` flush semantics are not reconstructed.** It is a 612-byte
  routine that walks entries from the same node (`+0x18`, `+0x20`, `+0x24`,
  `+0x28`), dispatches on entry byte 0 through a jump table (`0..5`), calls
  `0x0014297C`, and sets `state+0x18`. Only its call site and post-call `r0`
  are modelled.
- **Lock helpers** `0x002C3AA8` (acquire) / `0x002C3A24` (release) operate on
  the literal object `0x004E6C5C`; they save/replace a thread id and refcount.
  They are modelled as no-argument side-effect-free stubs in the differential
  test.
- **Node/replay semantics** (what consumes the 28-byte entries, and why the
  segment is padded with the `0x0008025E` marker when `offset & 8 == 0`) are
  inferred from the offsets and command words, not from a recovered structure
  definition. Field names are descriptive only.
- **No runtime whole-game comparison** was performed; the only evidence is the
  offline differential runner below. The command-buffer/entry fixtures use
  synthetic sentinels, not captured game data.
- `r0` on the early-return path is dead and intentionally not compared: the
  original leaves `0x004652A0` there, which no caller can rely on. The runner
  asserts the original value and documents the exemption.
