# Function Record: camp_func_0033138c (0x0033138c)

## Summary
- **Address:** `0x0033138c`
- **Size:** 836 bytes (original span `[0x0033138c, 0x003316d0)`, 208 ARM
  instructions plus the 16-byte literal pool at `0x003316c0`: `0x0043da90`,
  `0x0000056d`, `0x0100016d`, `0x323232ff`)
- **File:** `src/engine/leaf_batch45_b.cpp`
- **Role:** One step of the camp identifier-page state machine. Reads the shared
  camp workspace from `*(u8**)0x0043DA90`, selects the page for command
  `0xB`/`0xC`/`0xD`, and drives the workspace u32 state word at `work+0x1C`
  through its publish / poll / commit / reset transitions. Command `0xB`
  additionally commits the identifier-list entry under the page cursor.
- **Status:** Semantically equivalent C++ (`non_matching`). The compiled body is
  772 bytes versus 836 bytes; the compiler reorders the command dispatch,
  merges the four `0x002BC200` tail sequences into one shared block, and uses a
  different frame/register allocation. The ledger row is classified
  `non_matching` with this semantic record.

## Contract and Behavior

### Signature and ABI

- Static callers are `0x0032DB30` (`mov r0,#0xB; b 0x0032DBF0`),

## Contract corrections and notes
- **`0x002994B4` is not called with the command.** The poll-return branch loads
  `work+0x98` as an `s8` and passes it as `r0`, with the `0x0029EBA8` result in
  `r1` (`0x00331474..0x00331488`). `0x00299B9C` then receives the leftover
  `r0` from `0x002994B4`, not `command`.
- **`0x002BC200` determines the return value.** The last action of the reset,
  identifier and menu paths is that call; its `r0` becomes this routine's
  result. The file-scope declaration of `0x002BC200` is `void`, so the
  reconstruction uses an aliased prototype
  (`camp_func_002bc200_result(...) __asm__("camp_func_002bc200")`) to keep the
  register visible without changing the shared declaration.
- **`out_flag` sign extension is preserved but not distinguishable.** The s8
  is sign-extended with `ldrsb` and OR-ed into the gate result; only the
  zero/non-zero result is tested, so sign and zero extension behave identically
  for every byte value. The C++ still performs the sign extension.
- **Table index is 32-bit wrapping.** `0x0033154c..0x00331550` adds the two
  cursor results and shifts left by one with 32-bit wrap before the table base
  `0x1400 + 0x7C` is added.
- **The literal at `0x003316cc` is data.** `0x323232ff` is the colour argument
  to `0x0029F10C`, not an instruction.
