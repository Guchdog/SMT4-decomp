## Behavior

1. `index = *(u32*)(manager + 0xE10)`; `row = manager + index * 0x38`
   (32-bit multiply).
2. `row[0x0E] = value`.
3. `owner = *owner_slot`; read `heading = row[0x28]`; `owner[0xE3C] = 1`.
4. Publish the initial pair into `0x0049F91C`:
   - origin = `(row[0x1C], row[0x20] + 100.0f, row[0x24])`;
   - `rad = heading * 0x3C8EFA35`;
   - target = `(row[0x1C] + sin(rad) * 400.0f, row[0x20] + 100.0f,`
     `row[0x24] + cos(rad) * 400.0f)`.
   The X/Y/Z stores happen in that order; the target Y store happens between
   the sin and cos calls, and X/Z are re-read from the row after each call.
5. If `*(u32*)(row + 0x38) == 0`, return. Otherwise build `origin`/`target`
   copies from the published state.
6. `hit = 0x00266E88(&target, &origin, sp+0x20)`; if `hit == -1`, return.
7. `best_distance = 0x00287D54(origin, target)`.
8. `camera_eye = *(Vec3*)(*(u8**)0x004474F4 + 0x4C)`;
   `camera_angle = 0x00287E4C(row_position, camera_eye)`;
   `delta = 0x00287D74(heading, camera_angle)`;
   `step = delta < 0.0f ? -90.0f : +90.0f` (equality and NaN take `+90`).
9. Four samples, offsets `0, step, 2*step, 3*step`:
   - `snapped = 0x00282588(row[0x28] + offset)`;
   - `rad = snapped * 0x3C8EFA35`;
   - rewrite target X with `row[0x1C] + sin(rad) * 400.0f` and target Z with
     `row[0x24] + cos(rad) * 400.0f` (target Y is not rewritten and is copied
     from the published state);
   - `hit = 0x00266E88(&target, &origin, sp+0x20)`; if `hit == -1`, store
     `snapped` into `row[0x28]` and return, leaving the rejected target
     published;
   - `d = 0x00287D54(origin, target)`; if `d < best_distance`, set
     `best_heading = snapped` and call `0x00287D54(origin, target)` a second
     time to obtain the new threshold (the original really makes both calls).
10. After the loop, republish the winning target from
    `rad = best_heading * 0x3C8EFA35`, with Y = `row[0x20] + 100.0f`.
    `best_heading` starts at the unsnapped row heading and only changes on a
    strict distance improvement.
