# `0x002668DC` — per-frame LMAP actor refresh

## Contract

The pinned US ARM image `code.bin` (SHA-256
`1f98884fe997af22e032a14c51a46c872b05b0e079a0f29e307b0e059cfaa558`) contains
the 892-byte ledger span `0x002668DC..0x00266C57`. The executable body ends at
`0x00266BF4`; the bounded literal pool `0x00266BF8..0x00266C54` holds the call
targets, the layout-table pointers, the float constants and one absolute
address (`0x00476630`). The routine is `extern "C" void` and has no return
contract: the only value left in `r0` is the loop bound, and the three pinned
callers `0x001D4510`, `0x001D7BA0` and `0x001D8434` overwrite `r0`
immediately.

The host is the global pointer slot `0x00447060` (`LmapMainWork*`, see
`include/engine/map_runtime.h`). If the slot is null the routine returns without
touching anything.

1. **0x002668F8..0x00266914.** Call `0x003170B8(*(u32*)(host+0xA98), 0x2A)` and
   publish the returned object at `host+0xA9C`; then clear `host+0xA94` and
   `host+0xA98`. The host slot is re-read at `0x0026691C` (the listing's `r6`).
2. **0x00266918..0x00266990.** If `*(u32*)0x0049F91C == 101`, read
   `state = *(u32*)0x0049F920`. For `state` in `1..9`, call
   `0x00328440(0x00447088 + (state - 1) * 0x50)` and skip step 3. Outcomes
   outside `1..9` and every other mode fall through to step 3.
3. **0x00266994..0x002669F4.** Let `list = *(host+0xA9C)` with layout
   `{ void** items; s32 count; }`. While `index < count` (signed, the count is
   re-read after every iteration): call `0x0020FE3C(list, index)`; re-read the
   host slot and, if non-null, set byte `host[index*0x88 + 0xB30]` to `1` only
   when it is already `0`; call `0x00265DA4(index, 1)`.
4. **0x002669F8..0x00266BEC.** If `*(host+0xA9C)`'s count is `<= 0`, return.
   Otherwise, per `index`:
   * if `(*(u32*)0x00476630 & 1) == 0` and `0x002C00D4((u32*)0x00476630)`
     returns non-zero, write the 3x3 identity matrix to `0x004EFD48` (the
     Thumb helper is a single-threaded test-and-set, so only the first caller
     reaches the store);
   * call `0x002863F4(frame_scratch, 0x004EFD48)` (nine floats);
   * `scale = (*(u32*)0x0049F920 == 99) ? 3775.0f : 3575.0f`;
   * `item = items[index]`, `sub = *(u8**)(item + 8)`, relative link
     `link = *(u32*)(sub + 0xC)`, `digits = (u8*)(sub + 0xC) + link` when
     `link != 0` (the listing leaves `0` for a zero link and then reads address
     `5`);
   * `x = row[0] + vmla(1787.5f, (f32)(s8(digits[5]) - 0x31), 3575.0f)`,
     `z = row[2] + vmla(1787.5f, (f32)(((s8)digits[7] - 0x30) * 10 +
     (s8)digits[8] - 0x31), 3575.0f)`,
     with `row = rows + ((*(s32*)(host+0x40) - 100) * 3)`;
   * write the record `host + 0xAAC + index*0x88`: `+0 x`, `+4 10.0f`, `+8 z`,
     `+0xC..+0x2C` the nine scratch floats, `+0x30/+0x34/+0x38` the scale.
5. Restore `r4..r11`, `d8..d12` and return.

The four-entry row table (re-initialized every iteration in the listing) is
`{0,0,0}`, `{-24560,0,-16730}`, `{-16200,0,-15480}`, `{-12160,0,-14000}`.
`0x0049F920` is a single shared word: the title sub-state selector and the
`99` placement-scale comparison read the same location.

## Caller evidence

The pinned callers listed above are reached from `lmapMain` (`0x001D2B14`). Each
calls this routine and then immediately reloads `r7` from its own context, so
the return register is dead. The helper set is fixed: `0x003170B8` (object
constructor/libc list build), `0x00328440` (title layout expansion, the only
call reachable on the title screen), `0x0020FE3C` and `0x00265DA4` (per-entry
list enable), `0x002863F4` (24-byte nine-float block copy), and the Thumb
`0x002C00D4` test-and-set. `0x00476630` is the one-time initializer flag for
`0x004EFD48`; the same pattern appears in `0x0010B578` and `0x003661C0`.

## Reconstruction / evidence

Readable C++ is in `src/engine/leaf_batch45_b.cpp` and compiles with the project
ARMv6K clang pipeline (`-O2`, `-std=c++20`, hard VFP). Clang does not contract
`1787.5f + digit * 3575.0f` to `VMLA.F32`, so the single-rounding step is kept
in the local `placement_term` inline-asm helper to preserve the original VFP
result bits.

Differential test: `python tools/test_leaf_002668dc.py` (Unicorn ARM, 58 cases
plus four compiled negative controls). It compares PC, SP, `r4..r11`,
`d8..d15`, the ordered call log with arguments, the non-stack write set, and the
full global (0x00400000 page), LMAP work and actor-list fixture pages. Result:
58/58 cases pass, all four mutants
(`title_mode`, `layout_stride`, `scale_63`, `guard_mask`) are detected. The
compiled replacement is 792 bytes versus the original 892, so the ledger
classification is `non_matching`; no byte-identity or whole-game equivalence is
claimed.

## Limits

The helpers are deterministic stubs at their original addresses, so the test
establishes the caller contract against those stubs, not the helper bodies.
`(host+0xA9C)` must be non-null (the listing dereferences it unconditionally).
A zero relative link word and `(*(s32*)(host+0x40))` outside `100..103` read
invalid/uninitialized stack in the original and are not exercised. Only the
single-threaded behavior of `0x002C00D4` is modelled; no atomicity, interrupt,
invalid-pointer, unaligned-access, runtime-boot or concurrency guarantee is
established.
