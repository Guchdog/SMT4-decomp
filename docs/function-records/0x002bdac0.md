# Function record: `0x002BDAC0` row-driven animation state initializer

## Identity and ABI

Pinned `extracted/exefs/code.bin` SHA-256:
`1f98884fe997af22e032a14c51a46c872b05b0e079a0f29e307b0e059cfaa558`.
The 108-byte function extent is `[0x002BDAC0, 0x002BDB2C)` and its body
SHA-256 is `e9c60d31db041884aa6fe44db47bcabc849bf08464d1465a68cad24c4b1f152a`.
It has two `bx lr` returns at `0x002BDB0C` and `0x002BDB28`, no prologue,
stack arguments, or stack accesses. It uses caller-saved `r1-r3` and `ip`;
`r4-r11`/SP are untouched. `r0` remains the input object pointer; there is no
documented value return.

The conservative prototype for the recovered call boundary is
`void setter(void* object, int32_t row_index, int32_t mode_or_selector)`.
This avoids asserting a source-level object type. In the H1 preview helper,
calls at `0x002BFB48` and `0x002BFB78` pass the object in `r0`, an
sign-extended 16-bit animation word in `r1`, and a sign-extended byte in `r2`.

## Pinned behavior

At entry, the function loads the table pointer from object `+0x4C`. If it is
zero, it returns immediately with no object writes. A null object is not
checked; the first load faults for an unmapped null pointer and is outside the
valid object contract.

For a non-null table, the function performs these stores and reads:

1. Store the low 16 bits of `r1` to object `+0x50`.
2. Clear halfword `+0x52`.
3. Compute the row address from the full `r1` register using 32-bit ARM
   arithmetic: `table + 12 * r1` modulo `2^32`. This is not an index sign
   extension from the just-stored `+0x50` halfword.
4. Clear byte `+0x86` and byte `+0x8A`.
5. Compare the full `r2` with zero; store its low byte at `+0x54`.
6. For `r2 == 0`, load signed halfwords from row offsets 0 and 2; otherwise
   load signed halfwords from offsets 4 and 6.
7. Sign-extend each coordinate, shift it left by 12 with 32-bit wrap, and store
   the resulting words at object `+0x0C` and `+0x10`.

The table stride is 12 bytes. The table pointer and computed row are not
bounds-checked. The target C++ candidate uses unsigned multiplication/addition
and unsigned-before-shift coordinate conversion to avoid signed-overflow UB
while preserving ARM modulo-`2^32` behavior.

## Differential evidence and limits

The isolated runner compares pinned original ARM against the compiled
ARMv6K hard-float candidate. Passing valid-pointer fixtures cover a null table,
both mode branches, nonzero full mode with zero low byte, row stride 12,
row-index `-1` pointing back from one-past table storage, and signed coordinate
extremes. A null-object fixture records that both Unicorn executions fault at
their first load; this is not claimed as defined C++ behavior. Comparison
covers `r0`, callee-saved registers, SP, caller-owned stack, and the full
synthetic data mapping. The target negative control omitting the `+0x86` clear
is detected by the memory comparison.

H1 caller evidence remains static: the two animation-helper call sites in
`0x002BF9F0` pass the object and sequence-derived selector values described
above. No runtime scene object or concrete initializer binding was observed.
Rows use valid independent storage; overlapping table/object memory, invalid
table/row pointers, arbitrary index domains, and runtime aliasing are not
validated. The function ledger remains `matching`; this experiment does not
change it or integrate this C++ candidate.
