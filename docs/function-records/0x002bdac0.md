# `0x002BDAC0` — configure a table-selected position

## Recovered behavior

The helper accepts an object pointer, a full-width table index and a full-width selector. It reads the table pointer at `object + 0x4C`; a null pointer returns the original object pointer without any writes or table reads. With a table, it writes the low 16 bits of the index at `+0x50`, clears `+0x52`, `+0x86` and `+0x8A`, stores the selector's low byte at `+0x54`, and selects an entry at `table + index * 12`. The full 32-bit selector chooses signed halfwords at offsets `0/2` when zero and `4/6` otherwise. Each sign-extended halfword is scaled by 4096 modulo 2^32 and written to `+0x0C` then `+0x10`. It returns the original pointer in `r0`. There is no table bounds check; observed indices are not proof of an array length.

The accesses are expressed as volatile where the source ordering matters, because the table can alias the object and earlier stores can affect later table reads. Signed values are converted to unsigned before shifting, preserving ARM wraparound without signed-shift undefined behavior.

## Callers

`TitleConfig_Calc` calls this helper in its state-1 path at `0x001EAF38` and state-2 path at `0x001EAFD4`, both with `(work + 0x5C, 1, 0)`. `titleConfig_func_002F4CA0` calls it during initialization with index and selector zero. The initializer stores a pointer sourced from `work + 0x3C` into the subobject, but the resource table's valid length and lifetime are not established. The image also contains other direct callers outside H2; see the contract scan at [h2-002bdac0-contract.md](../agent-work/h2-002bdac0-contract.md).

## C++ reconstruction and evidence

`camp_func_002bdac0` is implemented in [leaf_batch13_c.cpp](../../src/engine/leaf_batch13_c.cpp), with matching typed declarations at C++ and assembly call sites. The compiled ARM body is 80 bytes in the original 108-byte slot, has no relocations, and differs from the original. The ledger classification is therefore `non_matching`.

`tools/h2_002bdac0_experiment.py` compares the pinned original against temporary, final-VMA and cumulative staged images. The differential covers 72 direct cases, three null-table cases, and an aliasing case that checks the original interleaved access order. It includes mode stride, full-width and truncated indices, selector `0x100`, signed halfword boundaries, and three compiled negative controls (wrong stride, byte-only selector check and wrong second field). Both actual `TitleConfig_Calc` setup/call/return slices (`0x001EAF2C–0x001EAF3C` and `0x001EAFC8–0x001EAFD8`) match between original and staged image. The IPS changes 77 bytes, stays within this 108-byte slot, and round-trips.

Staged code SHA-256: `3afbd263381b66d18f8ac680529fb27e4291899b70cb74401c8b812552df8774`. IPS SHA-256: `af194f9646402bd6dd7e421d1fe3478e7ad50f4c3dabcbcba7db4eb5d0c2b3ec`. The independent review accepted the bounded candidate, and the full ARMv6K build passed 204/204 translation units. Runtime was not run.

## Limits

Evidence is offline Unicorn execution over controlled, readable and aligned fixtures. The table length, malformed pointers, unaligned access behavior, concurrency and natural game scheduling are unverified. The caller slices begin at the real argument-setup instructions; they do not establish the entire H2 state transition or a full menu cycle.
