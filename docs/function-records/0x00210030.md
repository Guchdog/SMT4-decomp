# `0x00210030` — title fade front gate

Status: partial reconstruction; front-gate differential `probada_arm`. The
positive fade bodies and the true title caller scenario remain original-code
dependencies. Do not promote this record as a complete replacement.

## Contract recovered from the pinned image

The entry is ARM state, 68 bytes, at `0x00210030` in the pinned US
`code.bin` (SHA-256
`1f98884fe997af22e032a14c51a46c872b05b0e079a0f29e307b0e059cfaa558`). The
function receives its object pointer in `r0` and its fade value in VFP `s0`.
It saves `r4`, `lr`, and `d8`, copies the input float from `s0` to `s16`, loads
the child pointer from object `+8` at `0x00210040` and calls `0x002872A4`,
restores the original float to `s0`, reloads object `+8` at `0x0021004C` and
calls `0x0020FFA0`, then reloads object `+8` again at `0x00210054` and restores
the original float to `s0` at `0x00210058` before testing signed
`child->word[0x68/4]`. A value `<= 0` returns with that child pointer still in
`r0`; a positive value falls through to the adjacent body at `0x00210074` and
returns whatever `r0` that body leaves. The final `s0` restore applies to both
the early-return and positive-continuation paths.

Both first callees are 12-byte signed-zero gates, not boolean-return helpers:

- `0x002872A4` reads signed `child+0x34`; `<= 0` returns to this function,
  while `> 0` falls through into `0x002872B0`.
- `0x0020FFA0` reads signed `child+0x58`; `<= 0` returns, while `> 0` falls
  through into `0x0020FFAC`.
- The first positive body can dispatch through a callback pointer in the
  object graph and writes fade state. The second body reads a separate object
  graph, selects a table slot, and can also dispatch indirectly. The final
  positive gate falls through into `0x00210074`, another body with an indirect
  callback path.

Thus the full reached-callee set depends on input state. The experiment
exercised direct calls to both gate entries, the first positive body with one
explicit callback, the second positive body through its initial zero-field
return, and the final positive continuation through its initial zero-field
return. Deeper table/callback paths of the latter two bodies remain unresolved.

The entry has no documented C++ return contract. Its machine-visible `r0` is
the latest child pointer on the early-return path and is determined by the
positive continuation otherwise. `r0` is caller-saved and direct caller scans
did not establish that it is consumed. The isolated candidate exposes `r0` as
`u32` only so its machine result can be compared; integration still requires
the caller contract. The original preserves
`r4-r11`, `SP`, and `d8-d15`; only `r4` and `d8` are explicitly saved in this
entry, while any further preservation is supplied by the called bodies/ABI.

Static H1 caller audit identifies this helper in transition code around
`0x001E9F4C..0x001E9FD0` and `0x001EA01C..0x001EA128`. No caller-window or
runtime-normal object test was run for this candidate.

## Candidate and differential evidence

Readable front-gate C++ is in
[`h1_title_fade_candidate.cpp`](../../experiments/semantic_equivalence/h1_title_fade_candidate.cpp).
It models the three separate `object+8` loads, hard-float argument forwarding,
the signed final gate, and the final positive fallthrough. It intentionally
dispatches to the pinned original bodies at `0x002872A4`, `0x0020FFA0`, and
`0x00210074`; this is an isolated partial candidate, not a full replacement.
It uses a constrained ARM `vmov.f32 s0, <fade>` after the third pointer reload
and before reading the final gate, matching the original's
`0x00210054..0x0021005C` order.

The focused repair experiment compiled an ARMv6K object with no relocations and
compared original and candidate execution in Unicorn for 15 directed cases:
signed low/negative/zero/positive gate values, a first-positive callback,
second-positive early body return, and final positive fallthrough. It checked
completion, memory, callback count, `r0`, `r4-r11`, SP, `d8-d15`, call arguments,
and path reachability. The comparator checks returned `s0` as well as returned
`r0`. Two additional external-entry seam cases clobber `s0` to `0x41200000` at
`0x0020FFA0`; one takes the final-gate early return and one continues positively
through `0x00210074`'s first zero guard. Both original and candidate restore and
return with input bits `0x3F400000`. An adversarial case mutates parent `+8` at
the first external callback seam and again at entry to the second helper; it confirms
that the second helper receives the new child and the final continuation
receives the third child. The comparator checks ordered helper/body/callback
events, callback `s0/s2`, return `r0`, memory, callback count, `r4-r11`, `SP`,
and `d8-d15`. A
deliberately wrong final boundary (`< 0` rather than `<= 0`) was detected at
the zero case: the wrong version reached `0x00210074`, while the original
returned. The counted callback was an explicit synthetic `bx lr` fixture, not
an observed runtime binding.

The `s0` repair report is
[`report.json`](../../build/agent-work/H1-semantic/h1-title-fade-s0-repair/sleep-20261025-fade-s0/checks/differential/report.json).
Focused unittest: `python -m unittest tests.test_h1_title_fade_experiment -v`
passed. No caller integration, emulator run, whole-H1 scenario, or full
positive object graph was tested. Source SHA-256 is
`e5c05eecd57c7b965ae4f2406d4770b32eb68d50a69c643eaa315104eaf717d6`, object
SHA-256 is `258db8e94623f5c41e68704836ddf9901da626ac43ac6150011b0d8b6b2df01a`,
and differential report SHA-256 is
`3cc1ab7ae04b182fa972dc505ab26eb4c4bb53562914a9995dae471050a4fdd8`.

## Limits and next action

The object structures and boundary values are synthetic. The positive second
gate table/callback path, final positive continuation's deeper body, caller
consumption of `r0`/`s0`, and callback target selected by the game remain
unresolved. The added second-helper-entry `s0` clobber seam verifies restoration
before early return and continuation, but does not exercise the deeper positive
body of `0x0020FFA0`. Assign the positive body paths and caller contract their
own bounded work or keep them as original dependencies. Do not promote this
partial candidate into production until the actual caller contract and required
positive paths are covered.
