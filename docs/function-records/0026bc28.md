# Function Record: camp_func_0026bc28 (0x0026BC28)

## Summary
- **Address:** `0x0026BC28`
- **Size:** 688 bytes (original span `[0x0026BC28, 0x0026BED8)`; 171 ARM
  instructions through the tail branch at `0x0026BE94`, plus the `0x0043DCF0`
  literal at `0x0026BED4`)
- **File:** `src/engine/leaf_batch45_a.cpp`
- **Role:** Camp status-panel rebuild. It counts the 24 live-slot entries whose
  signed byte is non-negative, publishes a `1`/`2` layout mode from the byte at
  `+0x910B`, copies the slot list into a dword array at `+0x738` (stride 8),
  refreshes the camp row helper, then configures four widget slots
  (`0x940`/`0xA08` and `0x9A4`/`0xA6C`) and applies each slot's saved layout
  values.
- **Status:** Semantically equivalent C++ (`non_matching`). The compiled body is
  668 B versus 688 B; the compiler keeps the 26 getter calls, rolls both
  24-iteration loops, preserves the signed/unsigned comparisons and the ordered
  helper calls, and reproduces every observable register and memory effect in
  the differential runner. The ledger row is `non_matching` with this semantic
  record.

### Implementation notes and contract corrections
- **The getter call count is observable.** The original calls `0x002A8A08`
  once per count-loop iteration (24) plus once for the mode byte and once for
  the copy base, for 26 total. The candidate keeps the call inside the loop.
- **The getter and row helper ignore their argument.** The original forwards
  incidental `r0` values (the first count iteration passes `0`, later ones pass
  the previous loop value, and `0x0026BED8` receives `base+0x9108` remaining in
  `r0`). Both callees overwrite `r0` before use, so the candidate passes `0` (or
  whatever the compiler leaves) and the test logs only the call order.
- **The mode byte is re-read between layout calls.** The second `< 0x0C`
  call, both `>= 0x0C` second calls, and both second-group calls reload
  `base[0x910B]` after the previous `0x0029FAE8` returns. The candidate performs
  the same volatile-visible reads; the test's stub mutates the byte from inside
  `0x0029FAE8` to prove it.
- **The mode compare is unsigned.** `cmp r0,#0xC` followed by `movhi`/`bhs`
  treats the byte as unsigned; only `ldrsb`/`blt` in the count loop is signed.
- **A tail result is returned.** `r0` on exit is `0x0029EDFC`'s return value for
  the `0xA6C` slot; the candidate returns it directly.

## Limits
- Fixtures are synthetic: the state, base and manager pages are generated, and
  the `0x0043DCF0` pointer is redirected to a private manager page.
- Every helper is stubbed. The real `0x002A8A08` global getter, `0x0026BED8`
  row refresh, `0x0029EBA8`/`0x0029F248` guarded field getters, and the four
  `0x0029FAE8`/`0x0029EB58`/`0x0029EDFC` widget-update bodies are not
  exercised. The stubs only model their arguments and return values.
- The original passes differing leftover `r0` values to `0x002A8A08` and
  `0x0026BED8`; both callees overwrite `r0` before use, so the test does not
  compare those ignored arguments.
- No caller composition, render/menu state, emulator, or whole-game runtime
  equivalence is claimed.
