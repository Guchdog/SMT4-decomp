# Function Record: shop_func_003a3e98 (0x003A3E98)

## Summary
- **Address:** `0x003A3E98`
- **Size:** 684 bytes (original span `[0x003A3E98, 0x003A4144)`; 170 ARM
  instructions through the `pop` at `0x003A40EC` followed by two literal words)
- **File:** `src/engine/leaf_batch45_a.cpp`
- **Role:** Shop menu idle/opening update callback. It steps the opened script,
  refreshes the live item list, decides whether the pending-change flag or a
  selection input ends the pass, cycles the selection through a pinned
  two-column table, and advances the next sub-screen state on confirm.
- **Status:** Semantically equivalent C++ (`non_matching`). The compiled body is
  560 B versus 684 B; the compiler shares identical branch tails, keeps the
  signed comparisons and the ordered helper calls, and reproduces every
  observable register/memory effect in the differential runner. The ledger row
  is `non_matching` with this semantic record.

## Contract and Behavior

### Signature and ABI
```c

```
- `work = r0`; `r1`-`r3` are ignored.
- The original pushes `r4-r7,r8,lr` (24 bytes) and has no local stack. Every
  exit restores the frame; `r9-r11` are never touched.
- The routine is a callback: the pinned image stores its address in the table
  slot at `0x004075E0` (neighbouring slots are `0x003A3CB8`, `0x003A4144`,
  `0x003A4C7C`, ...); no `BL`/`B` targets it.
- The source declares a `u32` result because the original leaves an observable
  `r0` on every exit even though the callback's caller ignores it. The
  differential test compares those values:
  - state other than 0/1: the state word itself;
  - state 1, script result not 2: the signed script result;
  - state 1, success: `1` (the helper stores its argument but does not clobber
    `r0`);
  - pending-change tail: `0x0022E7DC`'s result;
  - selection cycle tail: `0x0022FC8C`'s result;
  - "second check" zero: `0`;
  - second-screen tail: `0x0022FBC0`'s result;
  - confirm path: the final sign-extended `s16` row counter (the last

## Implementation notes and contract corrections
- **State-1 success resets before the message.** The `strd` pair writes
  `+0x04 = 3` and `+0x08 = 0` before `0x0029F10C`, so a re-entrant callback
  would already see the reset state.
- **The equip gate bypasses the changed check.** `0x003A3FAC` is a signed
  `ble` to the selection block, not to the changed check; the candidate keeps
  the short-circuit as `list == 8 && ... && equip_count <= 1`.
- **The row loop re-reads the bound.** The count is loaded before the loop and
  reloaded after every `0x002B9008`; the candidate uses the helper call as the
  loop body with the load in the condition. The differential runner mutates
  the counter from the stub to prove the re-read.
- **`0x0022FC8C` is a thunk.** Its body loads `0x000100016F` and branches to
  the sound/id lookup at `0x002B91C4`; it ignores all incoming registers. The
  candidate therefore declares it with no parameters and only compares its
  result.
- **The selection table is read from its pinned absolute address.** Integral
  arithmetic on the `0x0044E020` constant reproduces the original's 32-bit
  stride wrap; no local table is materialised.
- **`changed` is `s32` and the count comparison is signed.** `cmp r0,#0; ble`
  and `cmp r0,r4; bgt` are signed in both the count gate and the row loop.

## Limits
- Fixtures are synthetic. The work page, list records, item tables, selection
  table page and script context are not captured game data.
- Every helper is stubbed. `0x0019DFBC` only returns its modelled script state;
  `0x0022FD54` returns the modelled changed flag; `0x002337A0` returns the
  modelled accessor index; the touch probes return the modelled state; the
  confirm path helpers only log their arguments. The real script VM, list
  refresh, equip lookup, touch-region state, menu transition and sound/id
  lookup are not exercised.
- The real `0x002972E8`, `0x00230F84`, `0x002339E8` and `0x002339AC` global-side
  stores are not modelled; only their arguments and return registers are.
- Selection-table indices beyond the mapped `0x0044E000` page are not
  exercised; the two wrapping cases stay inside the page. The original would
  fault for an unmapped table address just as the candidate does.
- No rendering, menu-state, caller-composition, emulator, or whole-game runtime
  equivalence is claimed.
