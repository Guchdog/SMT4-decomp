# camp_func_001d1728 (`0x001d1728`)

- **File**: `src/engine/leaf_batch34_c.cpp`
- **Address / Size**: `0x001d1728`, `868` bytes (compiled C++ candidate: `1132` bytes)
- **Classification**: `non_matching` (semantically equivalent C++)
- **Callers**: two direct `bl` sites in the pinned image target this entry
  point, both in the party-member selection flow:
  - `0x001c5ab4` (inside `0x001c5a60`-family selection update), reached when the
    selection counter at `+0xB3C` reaches 2;
  - `0x001c61ec` (second selection slot path), same guard.

  No literal-pool word or data-table entry in `.text` encodes `0x001d1728`. No
  runtime caller scenario was executed.

## Contract

- Signature: `extern "C" u32 camp_func_001d1728(void)`. The incoming `r0-r3` are
  never read; the function returns `0` on its two early exits and `1` after the
  unite list is finalised.
- Manager: `u8* manager = *(u8**)0x0043DCF0` (the camp state pointer used by the
  surrounding camp code).
- Manager fields used:
  - `+0xB34`, `+0xB38` — `u32[2]`; only the low halfword of each is consumed
    (`uxth`) as the selected save-record id. `+0xB3C` (fill counter) is written
    by the callers and not read here.
  - `+0xB48` — 64-bit unite descriptor. `0x002626F0` rewrites it from the two
    records; the result fields are:
    - bits `0..14` primary save-record id,
    - bits `15..29` secondary save-record id,
    - bits `30..31` descriptor kind bits (not consumed here),
    - bits `34..48` unite id (written to `word1` bits `2..16`).
  - `+0xB50` — unite result record (`0x0029DF14` seeds it, `0x0029C7C8`
    combines into it, `0x0029C950` finalises it).
  - `+0xB84` — the result record's own unit-id list (`+0xB50 + 0x34`), `u16[8]`.
  - `+0x115C` — pointer to the fusion workspace; read fresh before each of the
    three workspace calls.
- Save-record layout (halfwords only): `+0x46` `u16 id`, `+0x34..+0x42` eight
  `u16` unit ids.

## Behaviour

1. Read the manager; call `0x002A8A08()` and discard its result.
2. For `i = 0,1`: resolve `records[i] = 0x002B0824(uxth(*(u32*)(manager + 0xB34 + 4*i)))`.
   The `uxth` truncation is significant when the upper halfword is non-zero.
3. If either record is null, return `0` (the second lookup is still performed;
   the original short-circuits the null test, not the calls).
4. Clear `*(u32*)(workspace + 0x178)` via `0x00269E28`; if `0x002626F0` rejects
   the pair, return `0`.
5. Read the descriptor as a 64-bit value; the unite id is
   `(descriptor >> 34) & 0x7FFF`. Seed the result record at `+0xB50`, then
   combine both records into it with mode `0`.
6. Read descriptor word 0 again. Find the record with id `word0 & 0x7FFF`
   (primary) and then the record with id `(word0 >> 15) & 0x7FFF` (secondary).
   The finder reproduces the listing exactly: count first, then per probe a base
   call, a signed index byte, `0x002A89E4`, a `u16` id compare at `+0x46`, and a
   count re-read after each mismatch (`count > index`); on a miss it returns
   null, which is still dereferenced (the original reads the low vector page).
7. Append the non-zero halfwords at `+0x34..+0x42` of each found record to a
   16-entry stack array (8 per record, ascending, zeros skipped, so 8..16
   entries).
8. `Unite_Init(array, count, nullptr, nullptr)`.
9. `count = 0x0029CB94()` (signed, `<= 0` disables insertion). For each of the
   **first eight** collected ids only: skip zero ids, skip ids already present
   in the first `count` slots (via `0x0029D080`), otherwise store the id in the
   first empty slot; no store when all `count` slots are occupied.
10. Finalise the result record with `0x0029C950` and return `1`.

## ABI / code generation

- The original pushes `{r4, r5, r6, r7, r8, sb, lr}` and restores them, so the
  only callee-saved registers it observes are `r4-r9`; `r10`/`r11` are never
  touched. The C++ candidate is a normal AAPCS function and preserves all of
  `r4-r11`; the differential test compares `r4-r11` for both.
- The 16-entry unit array and the 5th (`stack`) argument of `0x0029C7C8` are the
  only stack slots; their addresses are private and are normalised out of the
  call log.
- One deliberate register barrier (`CampPlatformPointer`) prevents the optimizer
  from treating the miss path (`record == nullptr`, then reads at `+0x34`) as
  undefined and deleting the `count > index` loop bound. It is a no-op on the
  emitted value and exists only to model the platform's readable low page.

## Limits

- Byte identity is not preserved (`non_matching`).
- All twelve helpers are stubbed deterministically, so their internal behaviour
  (unite validation, descriptor packing, result seeding/combination, list
  finalisation) is not verified here; the differential covers this function's
  use of their documented contracts only. `0x0029B3CC` is itself
  `non_matching` (`Unite_Init` in `src/camp/unite.cpp`).
- The miss path's low-page reads use a deterministic fixture pattern; the real
  vector-page contents and the exact contents of the save-entry index table are
  not modelled.
- `slot_count > 8` is outside the helper's documented domain and was not run
  (the original would walk past the `u16[8]` list); `slot_count <= 8` is
  covered, including the negative case.
- No emulator or whole-game runtime scenario was executed; caller behaviour is
  inferred from the two `bl` sites only.
