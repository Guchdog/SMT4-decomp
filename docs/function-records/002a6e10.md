### Algorithm
With `n = day_count - 60` (the 60 days before March in the leap year 2000):
1. `era = floor(n / 146097)`; `doe = n - 146097 * era`, so `doe` is in
   `[0, 146097]`.
2. `century = doe / 36524` (0..3); `doe -= 36524 * century`.
3. `quad = doe / 1461` (0..24); `doe -= 1461 * quad`.
4. `year_in_quad = doe / 365` (0..4); `day_of_year = doe - 365 * year_in_quad`.
5. `month_index = (5 * day_of_year + 2) / 153` (0 = March .. 11 = February).
6. `day = day_of_year - (153 * month_index + 2) / 5 + 1`.
7. `year = 2000 + 400 * era + 100 * century + 4 * quad + year_in_quad`.
8. If `year_in_quad == 4` (always the leap day `February 29`), the original
   forces `month = 2`, `day = 29` and leaves `year` unchanged: it writes
   `0x0B`, subtracts 9 later, writes `0x1D`, and its `ip -= 1` / `ip += 1`
   pair cancels. The normal month path would instead report `March 1` of the
   following year.
9. Otherwise, `month_index <= 9` yields `month = month_index + 3` with the year
   unchanged; `month_index >= 10` yields `month = month_index - 9` and
   `year += 1`.

The second half of the original comparison (`century == 4`) is retained for
fidelity but is unreachable: `doe < 146097` bounds the century quotient to 3.

signed value, and preloading the high word with the multiplicand makes the

multiplier. The reconstruction writes the equivalent signed integer divisions;
Clang selects its own `smmul`/`smmla` sequences, which produce the same
quotients.

is reproduced explicitly. Year results reach about 5,881,610 for the wrapped
extremes, so no year-stage overflow occurs.
