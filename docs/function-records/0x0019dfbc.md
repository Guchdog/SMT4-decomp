# Function record — script-step dispatcher (`0x0019DFBC`)

## Identity and status

- Pinned original: 120-byte ARM function in the US v0.1.0 image, SHA-256
  `1f98884fe997af22e032a14c51a46c872b05b0e079a0f29e307b0e059cfaa558`.
- Production source is a typed C++ function in `src/engine/leaf_batch29_a.cpp`,
  declared as `s32 script_vm_func_0019dfbc(void* work)`. Six assembly-caller
  translation units now use the same declaration.
- The extracted production body is 128 bytes and relocation-free. The original
  ledger span remains 120 bytes, so the exact-byte classification is
  `non_matching`. The helper is not installed in the H2 IPS image.

## Recovered contract

For a valid work record and handler ID, the function reads a 32-bit script
instruction index from `work+0x18`, a method-table pointer from `work+0xBC`,
then a halfword handler ID at `method_table + 4*instruction`. It looks up a
callback pointer in the handler table at `0x0044DED0 + 4*handler_id` and calls
that callback with the same `work` pointer.

The callback result controls the dispatcher:

- `0`: clear `work+0xD0`, return `2`.
- `2`: increment the 32-bit counters at `work+0xCC` and `work+0xD0`, return `1`.
- `1`: clear `work+0xD0`, then dispatch again. The callback is responsible for
  advancing or otherwise changing script state.
- Any other result: dispatch again without this function changing those
  counters. The callback may still update the work record.

The function preserves `r4-r6` and stack balance. H2's `TitleConfig_Calc`
passes the script state pointer from `work+0x154` during state 2 and proceeds
only when this dispatcher returns `2`. The task runner establishes the poll
contract; it does not identify the script callback's meaning or label the
result as cancel, confirm, save, or commit.

## Evidence limits

Handler pointers and callbacks are synthetic controls. The experiment does not
exercise the game's actual script table, opcode contents, callback side effects,
valid work-object extent, runtime task scheduling, H2 edit/exit labels, save
behavior, persistence, or Azahar execution. Out-of-range handler IDs and invalid
pointers remain outside the contract. The C++ body exceeds the original span;
no patch-image/cave integration was performed.
