### Primary pass

1. `slot_a = *(u16*)a`, `slot_b = *(u16*)b`.
2. `id_a = *(u32*)(work + slot_a*8 + 0x1390) & 0x7FFF`,
   `id_b` likewise.
3. `node_a = camp_func_002b9364(id_a)`, `node_b = camp_func_002b9364(id_b)`.
4. `diff = camp_func_00288380(*(u16*)(node_a)) - camp_func_00288380(*(u16*)(node_b))`;
   return if non-zero.
5. Repeat both `camp_func_002b9364` lookups (the original does not cache the
   pointers across the first comparison).
6. `diff = node_a[2] - node_b[2]`; return if non-zero.
7. `diff = node_b[3] - node_a[3]`; return if non-zero.
8. `diff = *(u16*)(node_a) - *(u16*)(node_b)`; return if non-zero.

### Fallback pass

9. Re-read `slot_a`/`slot_b` from `a`/`b`.
10. Re-load both slot words from the **cached** work pointer.
11. `id_a = (word_a >> 15) & 0x7FFF`, `id_b` likewise.
12. Repeat the same two-lookup/rank/byte2/byte3/word0 comparison sequence.
13. Return the final word0 difference (which is `0` when all fields match).

## Unresolved and limits

- `camp_func_002b9364`, `camp_func_00288380` and `engine_func_002aa7f4` are
  external dependencies. Their internals were not reconstructed here; the test
  stubs them deterministically and logs their raw arguments. The real helpers'
  tables and record layout beyond the fields listed above are outside this row.
- The reconstruction does not prove whole-game equivalence, natural caller
  reachability, scheduler behavior or runtime parity. No emulator launch was
  performed.
- A null record pointer returned by `camp_func_002b9364` is invalid input: the
  original dereferences it unconditionally. Both sides fault; the test compares
  the call-log prefix and the fact of the fault, not the faulting PC.
- The two tail comparators are separate function-pointer targets whose bytes
  happen to live inside this ledger span. The C++ definitions preserve their
  symbols and behavior, but the ledger tooling still reports the single
  428-byte `camp_func_001e1440` row.
- Compiled sizes are `camp_func_001e1440` 364 bytes (the original body plus
  pool word is 376), `camp_func_001e15bc` 16 bytes, and
  `camp_func_001e15cc` 24 bytes. The row is therefore `non_matching`; this is a
  size/allocation difference, not a known semantic gap.
