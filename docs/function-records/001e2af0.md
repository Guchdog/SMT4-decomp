# Function Record: script_vm_func_001e2af0 (0x001E2AF0)

## Summary

- **Address:** `0x001E2AF0`
- **Ledger span:** 420 bytes, `[0x001E2AF0, 0x001E2C94)` (392 code bytes plus
  the seven literal words at `0x001E2C78..0x001E2C90`).
- **File:** `src/engine/leaf_batch41_c.cpp`
- **Role:** Advances and emits one entry of a nine-entry advice/hint sequence.
  The selected entry is a `u32` message id plus inline Shift-JIS text; the
  routine fills three words of a pending script command array and queues one
  message record through `0x002BFDFC`, then stores the next sequence index in
  the engine context.
- **Status:** Reconstructed as readable C++ and semantically verified against
  the pinned original with a differential Unicorn harness. The ledger row is
  `non_matching`: the compiled candidate happens to occupy the same 420 bytes
  (404 code bytes plus a 16-byte literal pool) but 101 of its 105 words differ
  from the pinned encoding, so the row keeps the non-matching classification
  and this record carries the semantic evidence.

## Contract and ABI

```c
extern "C" u32 script_vm_func_001e2af0(void);
```

- No arguments are read. `r0..r3` and `s0..s15` are dead on entry; both callers
  (`0x001FAB64` and `0x002FBB20`) invoke it with `bl` and ignore `r0`.
- **Return:** the original leaves a defined value in `r0` on every path (see
  below). The C++ returns that value so register-level differential tests are
  exact even though the game ignores it.
- Callee-saved `r4-r8` are pushed; `r9-r11` and the VFP callee-saved registers
  are untouched. Epilogue `pop {r4, r5, r6, r7, r8, pc}`; final `SP` equals
  entry `SP`. No stack arguments, no indirect calls, no loops.

`0x00447AB0` holds nine 0x60-byte entries: a `u32` message id followed by 0x5C

bounds-checked, so the reconstruction indexes the flat `index*0x60` address just
like the ARM code.

## Caller context

Both call sites (`0x001FAB64`, `0x002FBB20`) share the same shape: a counter at
`context + 0xD94` is incremented and, when it exceeds `0x384`, this routine is
called and the cooldown `context + 0xD98` is set to `0xE10` while the counter is
reset. The routine is therefore a periodic advice emitter, not a per-frame call.

## Verification

Tool: `tools/test_leaf_001e2af0.py`

Command:

```text
python tools/test_leaf_001e2af0.py
```

Result: **74/74 differential cases pass**, plus **5/5 negative controls** are
detected. The test compiles `src/engine/leaf_batch41_c.cpp` with the pinned
ARMv6K flags (candidate: 420 bytes = 404 code + 16-byte literal pool), extracts
`script_vm_func_001e2af0`, patches its call relocations
to deterministic stubs at the original addresses and its `R_ARM_ABS32` switch
table to absolute addresses, and runs the pinned original
(`extracted/exefs/code.bin`) and the candidate in separate Unicorn machines
with identical fixtures (the whole 5 MiB image is mapped, so the absolute
globals and the advice table are read from real addresses).

Compared state:

- return `r0`, continuation `PC`, final `SP`, callee-saved `r4-r11` and VFP
  `s16-s31`;
- the ordered call log with every register argument, including the four integer
  and two float arguments of `0x002BFDFC` (no helper takes a stack argument);
- the 64 KiB engine-context page (only `+0xD5B` may change), the pending command
  page (words 2..4 must keep their sentinel) and the full image, which must stay
  byte-identical;
- every emulated write must land in the private stack window, the context page
  or the command page.

The two profile-byte accessors are additionally verified against their pinned
16-byte bodies (byte loads at `0x004C5634 + 0x1E4/0x1E5`) before they are
stubbed.

Coverage includes: each suppression gate in isolation and in combination
(including gate ordering), event-flag 0 and 1, every state 0..9 plus `0x7F`
and the negative `0x80`/`0xFF` indices (out-of-range table reads), the
populated-count boundary 0/1/23/24 and a signed-negative count, the exact
1800/3600/7200 s boundaries and their neighbours inside each of states 5, 6 and
7 (including `elapsed = -1` and `0x7FFFFFFF`), the full fallthrough chain, the
signed half-value comparison at equality, +/-1, zero, and the `s16`
minimum/maximum values, and distinct forwarded profile/coefficient bytes.

Negative controls mutate `kCommandKind` (2 -> 3), `kSaveGateWindow`
(0x708 -> 0x709), `kAdviceEntryCount` (9 -> 8), the half-value comparison
(`>=` -> `>`) and `kAdviceFlagsOr` (4 -> 5); each mutant is caught.

## Unresolved and limits

- The ten direct-call dependencies are not reconstructed here. The test stubs
  them deterministically and logs their raw arguments; their real internals
  (`0x002BFF9C/0x002BFFAC` are verified byte loads) are outside this row.
- `func_0025c1dc` is the already-documented elapsed-seconds helper at
  `0x0025C1DC` (`docs/function-records/0025c1dc.md`); its value domain and the
  save-timestamp global are not re-derived here.
- The meaning of the two signed 16-bit record fields read by
  `0x0033426C`/`0x0028D5B4` is not proven. The first is compared as a half of
  the second, which is consistent with a current/maximum pair such as HP, but
  the record was not traced to its producer.
- The nine text entries are identified by their image data and decoded
  Shift-JIS; the surrounding UI that consumes command kind 2 and the
  `0x002BFDFC` message queue is not reconstructed.
- No emulator launch was performed; the evidence is offline differential
  emulation only. This does not prove whole-game equivalence, natural caller
  reachability or scheduler parity.
