# Function Record: func_0036ff14 (0x0036ff14)

## Summary
- **Address:** `0x0036ff14`
- **Size:** 432 bytes (107 ARM instructions through the unconditional `pop`,
  plus the 4-byte literal at `0x003700C0`)
- **File:** `src/engine/leaf_batch41_c.cpp`
- **Role:** Lazy name resolver and blob builder for one entry container.  It
  walks the container's relative slot array, resolves every entry whose `+0x08`
  word is still the `-1` sentinel against a table selected by the container's
  `+0x84` offset, and finally sizes, allocates and serializes that table record
  when the container has no cached blob.
- **Status:** Semantically equivalent C++ (`non_matching`).  The compiled body
  is 472 B versus the 432 B original; the extra bytes are the different frame,
  register allocation and constant materialisation.  The ledger row is
  classified `non_matching` with this semantic record.

## Contract and Behavior

### Signature and ABI
```c
extern "C" s32 func_0036ff14(u8** self_slot, void* allocator);
```
- `self_slot = r0`: address of a word holding the entry-container pointer.
  The container is re-read from that word at each documented program point;
  the caller (`func_0036f674`, `bl` at `0x0036F8FC`) passes the address of a
  stack slot that holds one entry.
- `allocator = r1`: allocator-interface object (a word at `+0x00` is its
  vtable).  When `r1 == 0`, the original loads the fallback pointer from the
  pc-relative literal `0x00471C40`; the surrounding loader at
  `0x0036F6C8..0x0036F6D4` uses the same global, and stores it at `+0x44`.
- `r2`, `r3` are not read.
- Return `r0` is a state word: `0`, or `0x10` when at least one entry failed
  both lookups.
- The body preserves `r4-r11` and restores `sp`; it uses no VFP and makes no
  stack argument except the fifth argument of `0x003E2E40`.

### Control flow
1. **0x0036FF38..0x0036FF48:** `count = *(s32*)(container+0x14)`.  Only
   `count > 0` enters the loop (`movgt`/`ble`); negative counts skip it.
2. **0x0036FF4C..0x0036FF6C:** for `index = 0..count-1`, resolve the slot array
   and then the entry.  The slot is `(array_offset ? container+0x18+offset : 0)
   + index*4`; the entry is `(entry_offset ? slot+entry_offset : 0)`.
3. **0x0036FF70..0x0036FF78:** an entry whose `+0x08` is not exactly
   `0xFFFFFFFF` (`cmn r0,#1`) is skipped.
4. **0x0036FF7C..0x0036FFB0:** primary lookup.  `name = name_offset ?
   entry+name_offset : 0`; `table = *(u32*)((table_offset ?
   container+0x84+offset : 0) + 0x40)`; index = `container+0x0C`.  Calls
   `0x003E2594(out=sp, table, index, name)` and reloads the word at `sp`.
5. **0x0036FFB4..0x00370018:** when that word is `>= 0` (`strbge`/`bge`), it
   stores byte `0` at entry+5 and the word at entry+8, then continues.  On a
   negative result it repeats the lookup with `container+0x10`.
6. **retry result:** `>= 0` stores byte `1` at entry+5 and the word at entry+8;
   `< 0` stores `0xFFFFFFFF` at entry+8 and ORs `0x10` into the return state.
7. **0x00370028..0x00370038:** after the loop, a non-zero `container+0x7C`
   returns the state word immediately.
8. **0x0037003C..0x003700B4:** otherwise resolve the table block from
   `container+0x84`, read `table = block+0x40`, and read both indices from a
   fresh container load.  `size = 0x003E2EEC(table, index_a, index_b)`;
   `buffer = allocator->vtable[2](allocator, size, 4)` (indirect `blx`);
   `used = 0x003E2E40(table, index_a, index_b, buffer, size)` with `size` as
   the architected fifth argument.  Then store `buffer` at `container+0x7C`
   and `used` at `container+0x80`, and return the state word.

### Helper contracts
- **`0x003E2594`** (`engine_func_003e2594`, 244 B): resolves a name against
  `*(u32*)(table + 4*index + 8)`.  It walks the record's `+0x34` entries, each
  eight bytes wide from `record + *(record+0x30)`, compares the name against
  the offset string at `record + *(record+0x38)`, maps the matched `u16` code
  into the ranges `>=0x88` (failure), `0x78..0x87`, `0x70..0x77`, `0x10..0x6F`
  and `<0x10`, and writes `{s32 value, u8 kind}` at `out+0` / `out+4` (failure
  writes `-1` and kind 0).  It returns its `out` pointer in `r0`; the caller
  only reads the memory.  The candidate passes the same `(out, table, index,
  name)` and ignores the return exactly like the original.
- **`0x003E2EEC`** (`func_003e2eec`, 248 B): computes a record byte size from
  the table's `+0x1C` entry count and the value of each entry's first `u16`
  (0/1/2 add 8/16/0x18 bytes), plus a fixed 0x78/0x98 header depending on the
  signedness of the second index.
- **`0x003E2E40`** (`func_003e2e40`, 172 B): builds/copies the record into the
  destination and returns `end - start` (the used byte count).

The three helpers are declared with explicit argument order above the
candidate; the allocator method is called indirectly through the vtable word at

## Limits
- All three helpers and the allocator vtable method are stubbed.  The real
  table lookup, record sizing, serialization, allocation and any heap side
  effects are not exercised; the fixture table pointer and record contents are
  synthetic.
- Field names are deliberately not invented.  `+0x0C`, `+0x10`, `+0x14`,
  `+0x18`, `+0x7C`, `+0x80` and `+0x84` are known only by offset and width; the
  semantic role of the primary/retry index pair (for example two locales or two
  table versions) is not established.
- The `0x003E2594` kind byte written at `out+4` is loaded by the helper but the
  caller never reads it; only the value word is consumed.
- If a slot stores the offset 0, both bodies first read the sentinel word at
  absolute address 8.  That page is unmapped on the target, so the divergence
  that follows (the original reads the name offset from absolute address 0
  while the optimized candidate may use the slot address) is unreachable
  without a mapped zero page.  The harness maps it to exercise the reachable
  skip path only.
- Caller composition (`func_0036f674`) is read statically but not executed; no
  emulator or whole-game runtime equivalence is claimed.  The container's
  origin and the lifetime of the cached blob are not recovered.
