# `0x002C17D4` — logical input bit query

## Recovered behavior

The function accepts a full unsigned query ID. IDs `31` and above return `0` without reading query data. For IDs `0..30`, it reads a two-word row from `0x004099C0 + 8*id`. A nonzero first word is a gate that returns `0` immediately. If the gate is zero, the second word is a mask; the function reads the mode word at `0x004650A8`, selects the fixed state word at `0x004E3C48` when bit 0 is set or `0x004E3C28` when clear, and returns `1` if that state intersects the mask, otherwise `0`.

The pinned table has 31 rows. IDs 0–15 have zero gates and masks `1,2,8,0x10,0x20,0x40,0x80,0x100,0x200,0x400,0x800,0x1000,0x10000000,0x20000000,0x40000000,0x80000000`. IDs 16–30 have gate `1`, so they return zero in the pinned initial table. The table can still be modified by runtime code; this initial content does not prove it stays constant.

The query makes no writes and has no helper calls. The original reads a word at the mode address; Clang narrows the C++ read to one byte because only bit 0 affects the result. The mode resides at an aligned ordinary RAM global in the exercised profile. The report keeps the read address/order and records the width difference; it makes no MMIO or partial-page equivalence claim. Physical control labels are not established.

## Offline evidence

`tools/h2_2c17d4_experiment.py` passes 134 direct comparisons over all pinned IDs `0..30`, out-of-range/high-bit IDs, both mode choices with higher bits set, differing selected-state words, zero/nonzero gates, zero/no/one/multiple-bit masks and explicit gate/mask controls. It compares return, ordered target read addresses, absence of writes, `r4-r11`, SP and LR. Four mutation controls were detected: an off-by-one ID bound, four-byte row stride, wrong mode bit, and inverted gate.

The mode-2 caller composition executes the pinned original `0x002C1830` wrapper with only this 92-byte slot replaced. Seventeen cases cover primary hits, secondary `id+9` hits, no hits, primary short-circuit when both bits are present for IDs `3..6`, plus ID `31`. It checks helper IDs/order, return, slot/global reads and original-versus-staged results. The four `0x0029F278` call PCs and `0x20` skip are documented from pinned instructions; the full cursor updater is not executed by this harness.

Candidate and production bodies are 92/92 bytes with no relocations; the body uses `BX LR`. Both original wrapper calls at `0x002C18F0` and `0x002C19B0` target the even ARM entry `0x002C17D4`. The one-slot IPS roundtrip passed and changed only bytes inside the 92-byte span (80 bytes differ). The ledger is `non_matching`. Focused build passed for `leaf_batch32_c.cpp`, the full ARMv6K build passed 204/204 units at `build/h2-2c17d4-full`, and independent review recommends bounded integration. Runtime was not run.

## Limits

The synthetic table/state fixtures and dispatcher mode-2 composition establish the helper's bounded query behavior, not physical input, scheduler cadence, or natural H2 runtime delivery. Prior reports disagree on the producer refresh stride for `0x004E3C28`; this function itself reads one of two fixed addresses, independent of ID. Concurrent global changes, runtime table mutation, malformed mappings, and the four full `0x0029F278` paths remain outside the tested domain.
