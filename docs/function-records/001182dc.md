# Function Record: engine_func_001182dc (0x001182DC)

## Summary
- **Address:** `0x001182DC`
- **Size:** 428 bytes (span `[0x001182DC, 0x00118488)`). The last instruction is
  the epilogue `add sp,#0xC; pop {r4, r5, r6, r7, r8, sb, sl, fp, pc}` at
  `0x0011846C`; the trailing 20 bytes `[0x00118474, 0x00118488)` are the literal
  pool (`0x00464AF0`, `0x004DAD80`, `0x00464BB4`, `0x00003FFF`, `0x0044EA00`).
- **File:** `src/engine/leaf_batch41_c.cpp`
- **Role:** Release/teardown pass for the **second** (index 1) engine render slot
  of the process-wide AsdModel manager. It registers the slot with the shared
  engine sync helper, detaches the slot token from the registry pointer vector
  and releases the slot's work/view objects. `0x00117504` and `0x00118848` are
  the index-0 variants of the same family and use the `+0` table entries.
- **Status:** Reconstructed as readable C++ and **differentially verified**
  against the pinned original (68 cases + 6 negative controls). The candidate
  body is 376 bytes and is not byte-identical, so the ledger row is
  `non_matching` and this record carries the semantic evidence.

## Contract and Behavior

### Signature and ABI
```c
extern "C" u32 engine_func_001182dc(void);
```
- **Arguments:** none. `r0..r3` and `s0..s15` are not read; the differential
  test seeds `r0..r3` with sentinels.
- **Return value:** `0` on every executed path **except** the
  `count <= 0 && (*(u32*)0x00464AF0+0x88 & 1) == 0` exit, which returns the
  whole tested activity word. `tst`/`beq` leaves that word in `r0`
  (`0x0011830C..0x00118314`), so e.g. `0x00000002` or `0xFFFFFFFE` is returned
  verbatim. The normal exit reloads `r0 = 0` at `0x00118464`.
- Callee-saved `r4-r8, sb (r9), sl (r10), fp (r11)` are preserved by the
  `push {r4, r5, r6, r7, r8, sb, sl, fp, lr}` / `pop {..., pc}` pair; final SP
  equals entry SP.

### Stack layout
`sub sp, sp, #0xC` at `0x001182E0`. Only two words are used:
- `[sp+0x0]`: the token word passed by address to `0x002B780C`
  (`mov r3, sp` / `str r0, [sp]` at `0x00118364..0x00118368`).
- `[sp+0x4]`: `*(u32*)(view + 4)`, captured at `0x00118328` **before** the first
  helper runs and reloaded at `0x00118434` for the `0x002B77B8` call.
- `[sp+0x8]` is never touched (padding for the outgoing alignment).

4. `if (slot1.registered_04 != 0 && slot1.inited_05 == 0)` (`0x0011833C..0x00118358`):
   - `token = T[1]; registry = R[1];`
   - linear scan of `[registry->begin_18, registry->end_1c)` for the first

   `0x002C028C(R[1], T[1]);` then `0x002ABDB0(A[1], R[1]);`

9. `0x002C3C18(*(u32*)0x0044EA00);` (`0x00118458..0x00118460`).

The `script_vm_func_002b780c` helper is libc++-style `remove`: it forward-copies
every element of `[first, last)` that differs from `*value` into `result` and
returns the final destination. Combined with the pre-scan, the net effect is
"erase every element equal to the token", and the caller only clears
`token+0x0C` when the end pointer actually moved.

## Verification
`python tools/test_leaf_001182dc.py` compiles `src/engine/leaf_batch41_c.cpp`,
extracts the `engine_func_001182dc` body, relocates its nine `R_ARM_CALL` sites
to deterministic stubs placed at the pinned targets, and runs the original bytes
against the candidate in separate Unicorn ARM machines with identical fixtures.

Compared outputs: return `r0`, continuation PC, final SP, `r4-r11`; the ordered
call log with each helper's architected register arguments (and, for
`0x002B780C`, the dereferenced value word, because its fourth argument is a stack
pointer and the two builds use different stack slots); the ordered list of every
guest write outside the private stack; and the manager page, frame-sync page,
GPU pointer page, object heap (view/work/registry/token objects, registry vector
elements) and the stub journal page.

68 differential cases cover: master enable `0`/`2`/`0xFF`; signed counts
`> 0`, `0`, `-1`, `INT_MAX`, `INT_MIN` crossed with the activity bit; activity
words `0x0`, `0x1`, `0x2`, `0x100`, `0xFFFFFFFE`, `0xFFFFFFFF` (the early exit
must return the whole word); the registered/inited matrix including `2` and
`0xFF`; slot flag `+0x14` `0`/`1`/`2`/`0xFF`; ten registry-vector shapes
(empty, no match, single token, first/middle/last match, all equal, interleaved
duplicates, alias that is not the token, four pads) crossed with full /
not-registered / already-initialised slot state; null view payload; null GPU
state pointer; manager value `0`/`INT_MAX`/`INT_MIN`/`0xFFFFFFFF`; and an
already-zero release word. Six negative controls (frame-sync slot index, table
slot index, activity bit mask, `0x00132240` selector, token clear offset, signed
count bound) are each detected.

**Result:** `All 68/68 differential cases PASSED.`

## Unresolved / domain limits
- The eight direct callees are modelled only by their observable register
  contract and the effects this routine depends on: `0x001324E8` stores its value
  word into `payload->dispatch[index]`; `0x002B780C` performs the forward
  compacting copy and returns the new end; the rest are side-effect-free for this
  caller. Their internal behaviour (vtable dispatches, command dumps, GPU state
  flushing) is out of scope.
- `0x002ABDB0` and `0x00132240` perform indirect calls internally
  (`[registry]`+0x10); those targets are not resolved here and their effects on
  the slot objects are not reproduced by the stubs. A real helper that rewrites
  `0x00464B7C..0x00464BB8` between the calls is covered (every table entry is
  re-read at each use site), but a real helper that rewrites the frame-sync
  bytes or the manager word is only covered for the re-read points this routine
  actually has.
- All four slot pointers are dereferenced without null checks. The test keeps
  every slot-0 and slot-1 object valid, so a null-entry fault is documented
  rather than exercised; the harness treats a fault at the same PC as an equal
  outcome.
- The semantic role of `manager+0x18`, `manager+0x2C`, `manager+0x88` and of the
  frame-sync count is not proven beyond the access pattern and the sibling
  routines; the reconstruction names them by offset with the evidence above.
- No emulator or runtime session was run; equivalence is offline differential
  evidence only.
