# Function Record: engine_func_0015d944 (0x0015d944)

## Summary
- **Address:** `0x0015d944`
- **Size:** 408 bytes (original span `[0x0015d944, 0x0015dacc)` plus an
  unused literal pool at `0x0015dacc`; the last executed instruction is the
  `pop` at `0x0015dac8`)
- **File:** `src/engine/leaf_batch44_b.cpp`
- **Role:** Initialises a one- or two-slot engine object set and fills it with
  entries created through `0x002BD48C`. The requested count is clamped to
  `[1, 2]`, the id is unsigned-saturated to 15 bits, and each slot is created
  with one of two factory callbacks. A pre-existing object with the same id
  makes creation retry the same slot; otherwise a null creation marks the set
  failed and releases every entry created so far. The success path finishes by
  initialising a flag/float block and returns 1.
- **Status:** Semantically equivalent C++ (`non_matching`). The compiled body is
  368 B versus the 408 B original; clang emits the id saturation as a single
  `usat` instruction, combines several adjacent byte/halfword stores, and uses
  a shorter register/allocation layout. The ledger row is classified
  `non_matching` with this semantic record.

## Contract and Behavior

### Signature and ABI
```c
extern "C" u32 engine_func_0015d944(void* self, s32 requested_count,
                                    s32 raw_id, u32 arg_0c,
                                    u32 stack_float_bits);
```
- `self = r0` (object at offset 0 of the caller block), `requested_count = r1`,
  `raw_id = r2`, `arg_0c = r3`.
- `stack_float_bits` is the **first incoming stack word** (`[sp]` on entry):
  the original does `vldr s16, [sp, #0x30]` after pushing 40 bytes of
  callee-saved registers and `d8` (8 bytes). It only copies the 32-bit pattern
  to `self+0x10`; the value is never interpreted here. Soft-float callers pass
  the fifth argument on the stack, so the reconstruction takes the bits as a
  `u32` parameter, which hard-float AAPCS also places in that same stack slot.
- Return: `1` on success, `0` on every failure path.
- The original preserves `r4-r8, sb, sl, fp, ip` and `d8`; final `sp`
  equals the entry value. The reconstructed body preserves the same
  callee-saved set (`r4-r11`); it does not need `d8`.

### Count clamp
```c
if (requested_count > 2)      count = 2;
else if (requested_count < 1) count = 1;
else                          count = requested_count;
```
The comparisons are signed (`bgt`/`blt`), so negative values and `INT_MIN`
select 1 and any value greater than 2 selects 2. `count` is therefore always
1 or 2.

### Id saturation
The original executes `usat r11, #15, r2`:
- `raw_id < 0` -> `0`
- `raw_id > 0x7FFF` -> `0x7FFF`
- otherwise `(u32)raw_id`

`0x002BD48C` forwards the id to the manager at `0x004E8568`, which itself
rejects ids `>= 0x8000`; with the saturation that early-out is unreachable.

### Control flow and calls
1. `self+0x1A = 1`, `self+0x08 = 0`, `self+0x1B = 0`.
2. `count == 1` (single-slot path):
   `entry = 0x002BD48C(id, 0x0015E458, self)`.
   - null -> return `0` immediately (no cleanup, no tail initialisation);
   - non-null -> `self[0x00] = entry`, `self+0x08 = 1`, go to the success tail.
3. `count == 2` (multi-slot path), `index = 0` while `index < count`:
   `entry = 0x002BD48C(id, 0x0015E4A8, self)`.
   - non-null -> store at `self + index*4`;
   - null -> `manager = 0x002BB270()`, then
     `0x0015E590(manager, id)`; a non-zero result retries the **same** slot
     without advancing `index`; a zero result sets `self+0x1B = 1` and stores
     the null entry;
   - `self+0x08 += 1` (reloaded/stored), then `++index`.
4. After the loop, if `self+0x1B != 0` (`ldrb`, signed `count` loop):
   for `slot = 0; slot < self+0x08; ++slot`, reload `entry = self[slot]` and
   call `0x002BD620(entry)` only for non-null entries, then return `0`.
   `self+0x08` is reloaded after every destroy call in the original.
5. Success tail (stores in original order):
   `+0x1A = 0`, `+0x20` halfword `= 0`, `+0x17 = 0`, `+0x18 = 0`,
   `+0x16 = 0`, `+0x1C = 0`, `+0x24 = 1.0f`, `+0x38 = 1.0f`, `+0x22 = 0`,
   `+0x3C = 0.0f`, `+0x30 = 0.0f`, `+0x34 = 0.0f`, `+0x44 = 1.0f`,
   `+0x0C = arg_0c`, `+0x10 = stack_float_bits`, `+0x48 = 0.0f`,
   `+0x4C = 0.0f`, `+0x28 = 1.0f`, `+0x2C = 0`, `+0x2D = 0`, `+0x14 = 1`;

   `+0x15` is not touched by this function (the single-slot factory callback

### Helper `non_matching` calls (direct)
- `0x002BD48C(id, factory, owner)` – thin wrapper around
  `0x00155D60(0x004E8568, id, factory, owner)`. The factory callback is
  invoked inside the manager, not by this function.
- `0x002BB270()` – returns the global manager pointer used by the retry check.
- `0x0015E590(manager, id)` – returns non-zero when an object with `id` already
  exists (the retry condition).
- `0x002BD620(entry)` – wrapper around `0x00155EF4(0x004E8568, entry)`; releases
  one entry.

## Unresolved / limits
- The real manager (`0x004E8568`), `0x00155D60`, factory callbacks
  (`0x0015E458`, `0x0015E4A8`), `0x0015E590` and `0x00155EF4` were stubbed, not
  executed. The differential test therefore validates this function's
  contract, argument flow, control flow and memory effects, not the manager's
  internal object layout or allocation behavior.
- Retry behavior is only tested with bounded stub responses; an unlimited
  non-zero "already exists" response would spin forever in both bodies.
- `unknown_15`/`unknown_19` and the space at `+0x40` are untouched padding
  observed from the instruction stream; their semantic meaning is unknown.
