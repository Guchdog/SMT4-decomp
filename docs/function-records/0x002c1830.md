# `0x002C1830` — logical input query dispatcher

## Recovered behavior

`camp_func_002c1830(u32 id, u32 mode)` compares both full 32-bit words. Modes 0, 1 and 2 call the corresponding logical query helper at `0x002B902C`, `0x002BFFBC` and `0x002C17D4`. Any nonzero primary result is returned unchanged. For IDs 3 through 6, a zero primary result triggers a second call with ID `id + 9`; its nonzero word is also returned unchanged. After zero results, the dispatcher returns the mapped fallback code for IDs 0, 1 and 7 through 10 by tail-calling a mode-specific routine. IDs without a fallback return zero. Any mode outside 0..2 returns zero without calling a helper.

The fallback map is ID 0→1, 1→2, 7→6, 8→5, 9→3, 10→4. IDs 3..6 have secondary IDs 12..15 and no fallback. Other IDs have no fallback. Wrapper-owned effects are limited to the saved register area on the stack; helpers and fallbacks retain their original side effects. The three helper call relocations are `R_ARM_CALL`; the candidate also has three secondary-path ARM calls. All six target even ARM addresses. Mode-specific fallback targets are the pinned ARM addresses `0x00125C10`, `0x00124FA8` and `0x00124F0C`.

## H2 caller context

The original `TitleConfig_Calc` state-1 path reaches six PCs: `0x001EAABC` (ID 9, mode 1), `0x001EABDC` (4,0), `0x001EAC20` (3,0), `0x001EAC50` (4 or 3, mode 0), `0x001EAE64` (0,1) and `0x001EAF14` (1,1). These calls couple the dispatch to option selection, decrement/increment and confirmation/cancel branches. The 43 scripted caller scenarios reach all five unique ID/mode pairs and exercise both alternatives at the shared `0x001EAC50` site. They seed logical query counters directly; no physical input or natural scheduling is implied.

## C++ reconstruction and evidence

`camp_func_002c1830` is readable C++ in [leaf_batch40_a.cpp](../../src/engine/leaf_batch40_a.cpp). The two C++ declarations and the `0x002C17D4` helper prototype now preserve the word arguments and return bits. The body is 264 bytes in the original 504-byte span and has six direct ARM call relocations. Its bytes differ from the original, so the row is correctly classified `non_matching`.

`tools/h2_2c1830_experiment.py` compares original, temporary, final-VMA and cumulative staged wrapper execution with deterministic hooks at the three query helpers and three fallbacks. It passes 114 direct cases over modes 0..2, IDs 0..12 and high-bit IDs, including raw high-bit returns, short-circuiting, secondary-query order and fallback propagation. Three compiled negative controls detect a wrong secondary ID, fallback mapping and nonzero-return polarity.

The caller composition compares the pinned original image against that image with only the dispatcher replacement across 43 scenarios. It runs with original query helpers and with the previously validated typed mode-0/mode-1 candidates. All caller returns, work/config state, traces and ABI checks match. Static call-site hooks and LR-derived wrapper-entry traces cover all six PCs and seven call combinations, including both alternatives at `0x001EAC50`. The slot-only IPS changes 410 bytes, round-trips, and produces staged image SHA-256 `65d8014821287f2a66a417459dcc105e34c7c6c4af351e7d577051d28616f6ef`; IPS SHA-256 `ee3e9bf5c9561849a63551ea427cd1816d7eacc546e96eb9a155c6414a16c994`. The full ARMv6K build passed 204/204 translation units, and independent review accepted this bounded evidence in [run006](../agent-work/h2-002c1830-independent-review-run006.md). Runtime was not run.

## Limits

Direct helper/fallback calls use deterministic hooks, so these direct cases prove wrapper mapping and raw return flow, not helper behavior. Caller scenarios use controlled logical counter seeds and other pre-existing HLEs; they do not prove physical input, event timing, scheduler lifecycle or a complete natural titleConfig cycle. Invalid runtime global state and fallback side effects beyond the caller cases remain outside this evidence.
