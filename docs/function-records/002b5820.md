# Function Record: engine_func_002b5820 (0x002B5820)

## Summary
- **Address:** `0x002B5820`
- **Size:** 484 bytes (`[0x002B5820, 0x002B5A04)`: 116 ARM instructions through
  the unconditional `pop {r4, r5, r6, r7, r8, sb, sl, fp, pc}` at `0x002B59EC`,
  plus the five literal-pool words at `0x002B59F0..0x002B5A03`)
- **File:** `src/engine/leaf_batch41_c.cpp`
- **Role:** Bounded retry loop around the six-argument `svc #0x32` request at
  `0x00148210`, serialised by the engine object lock. It reads the engine
  object word through `0x002BB440`, submits `(context, arg0, flags, buffer,
  size, extra)`, and on the single retriable status `0xC8A0CC02` sleeps 10 ms
  and polls again until one of the two 64-bit marker words or the signed
  elapsed-nanosecond budget says to stop.
- **Status:** Reconstructed as readable C++ and **semantically verified**
  against the pinned original. The candidate body is 484 bytes but is not
  byte-identical (the prologue saves a different register set), so the ledger
  row moves from `matching` to `non_matching` and this record carries the
  semantic evidence.

## Contract and Behavior

### Signature and ABI
```c
extern "C" u32 engine_func_002b5820(u32 arg0,   // r0
                                    u32 flags,  // r1
                                    u32 buffer, // r2
                                    u32 size,   // r3
                                    u32 extra,  // [sp+0x00]
                                    u64 timeout_ns); // [sp+0x08], 8-byte aligned
```
- Four register arguments plus `extra` at `[sp+0x00]` and the 64-bit timeout at
  `[sp+0x08]`; `[sp+0x04]` is the alignment pad between them and the original
  never reads it.
- **Return value:** `r0` only. The result of `0x00148210` is returned unchanged:
  non-negative statuses immediately, other negative statuses immediately, and
  `0xC8A0CC02` once its retry budget is exhausted.
- The original pushes 13 registers (`r0-r3`, `r4-r8`, `sb`, `sl`, `fp`, `lr`)
  and then `sub sp, sp, #0x1C`, which is how it reaches the stack arguments;
  the epilogue is `add sp, sp, #0x2C` plus a 9-register pop, so the four saved
  argument words are discarded. Callee-saved `r4-r11` and the entry SP are
  restored. `r12` is caller-clobbered scratch.
- 8 call relocations resolve to 7 distinct direct calls; `0x002BB648` (the
  unlock) is called from two sites (the success path and the failure path).
  No indirect calls.

### Control flow
```text
if (timeout_ns == *(u64*)0x0044E378 || timeout_ns == *(u64*)0x0044E370)
    baseline = 0;
else
    baseline = GetSystemTick();              // svc #0x28, once, before the loop

followup_latch = (flags >> 16) & 1;          // `and` + `lsr` into sl

for (;;) {
    length = size;                           // re-loaded from r8
    if (size > 0x1000) 0x002BCE48();         // notification, r0 dead
    data = buffer;
    if (data == 0 || length == 0) { data = 0; length = 0; }

    0x002BB6B8();                            // lock
    context = 0x002BB440();                  // [0x0044E394]
    result  = 0x00148210(context, arg0, flags, data, length, extra);
    if (result >= 0 && followup_latch) 0x00147FE0(0);
    0x002BB648();                            // unlock, both arms

    if (result >= 0) return result;
    if (result != 0xC8A0CC02) return result;

    if (timeout_ns == *(u64*)0x0044E378) return result;
    if (timeout_ns != LoadPair(0x0044E370)) {
        elapsed_ns = TickToNanoseconds(GetSystemTick() - baseline);
        if ((s64)timeout_ns < (s64)elapsed_ns) return result;
    }
    0x002BB490(10000000, 0);                 // 10 * 1,000,000 ns, then poll again
}
```

Notes on the exact shape:
- The entry marker checks use one 64-bit load each and short-circuit in the
  order `0x0044E378`, then `0x0044E370`; the retry path re-reads `0x0044E378`
  as one `ldrd` and `0x0044E370` as two 32-bit loads, so both are re-sampled
  after every request.
- The tick baseline is stored in the frame at `[sp+0x10]`; a marker equality at
  entry leaves it zero, so the first retry compares against an absolute tick.
- The `size > 0x1000` notification is re-run on **every** iteration because the
  loop branches back to `0x002B5890`, above the guard. `0x002BCE48` ignores
  `r0`: in the original that register holds `flags & 0x10000` on the first pass
  and the previous callee's leftover value (e.g. the sleep request's
  `10,000,000`) on later passes, and the callee overwrites it with `0` before
  tail-calling `0x002AD8A8`. The candidate therefore calls it without an
  argument, and the differential runner does not compare that dead register.
- The `buffer == 0 || length == 0` test is `cmp`/`cmpne` plus two conditional
  moves; both operands collapse to zero together and the request still runs.
- The bit-16 latch is computed once, before the loop, from the original `r1`.
- The result is re-stored to the frame every iteration and the epilogue returns
  that slot (`ldr r0, [sp]`), which is the same value the sign/retry tests used.

### Elapsed-time reduction (`0x002B5940..0x002B59B4`)
One `svc #0x28` (`GetSystemTick`, 64-bit in `r0:r1`), a wrapping 64-bit
subtraction of the baseline, then bits 32..95 of the signed 64x34 product with
`0x3BAD34AEE = 3*2^32 + 0xBAD34AEE` (268,111,856 Hz ticks -> nanoseconds), the
same reduction documented for `0x0011B6A8` and `0x0013B508`. The final test is
a signed 64-bit compare (`subs`/`sbcs` + `blt`) of the timeout against the
reduced elapsed value. ARMv6K has no 128-bit integer type, so the candidate
rebuilds the 128-bit product from the same 32-bit partial products
(`MultiplyHighUnsigned` / `MultiplyHighSigned`); the observed instruction
sequence was checked bit-exactly against that formula over 2,000 random 64-bit
deltas before being adopted.
- The retry sleep is `10 * 0x000F4240 = 10,000,000` ns, passed as the 64-bit
  `(lo, hi) = (10000000, 0)` pair that `0x002BB490` consumes.

## Domain Limits
- Every direct call is stubbed, so the real lock, the `svc #0x32` request and
  the follow-up step are driven deterministically by the fixtures. In
  particular the effect of `0x00148210` on the kernel/TLS descriptor, the
  meaning of its first (context) argument and the service behind `svc #0x32`
  are observed but not proven.
- The two marker words are equality-only sentinels. Their producer, their
  relationship to `0xC8A0CC02`, and their time unit are unresolved.
- The argument at `[sp+0x04]` is never read by the original; it is represented
  as alignment padding, and the runner fills it with a sentinel to confirm it
  is not observed.
- `r0` on entry to `0x002BCE48` is a dead caller-saved leftover in the
  original and is therefore not part of the reconstructed contract; the
  runner deliberately does not compare it.
- Tick values come from the test. The 268,111,856 Hz relation is inherited from
  the shared `0x3BAD34AEE` reduction documented for `0x0011B6A8`.
- No runtime/emulator execution, staging or production promotion is claimed.
