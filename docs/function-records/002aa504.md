### Semantics
For `divisor != 0` the function returns
`q = numerator / divisor`, `r = numerator % divisor` using unsigned 64-bit
arithmetic. For `divisor == 0` it calls `0x001524E8` with `r0 = r1 = 0` and
returns `q = 0`, `r = numerator`.

The C++ uses one restoring shift/subtract loop: compute the bit widths of the
operands (native `clz`), left-align the divisor with the numerator, then walk
the alignment down one bit at a time, subtracting whenever the partial
remainder permits and setting the matching quotient bit. `divisor << shift`
never exceeds `numerator`, so it always fits in 64 bits. This replaces the
original's four exponent-range specialisations with one loop that produces the
same quotient and remainder for every input pair.

## Limits
- The `0x001524E8` helper is stubbed by its pinned no-op body. Its real
  divide-by-zero policy (it sits beside other tiny runtime entries in the same
  36-byte ledger row) is not exercised beyond the `mov r0, r0; bx lr` entry the
  original actually calls.
- The hook receives residual `r2/r3` equal to the numerator in the original but
  `0` in the C++ (the C-level declaration has two arguments). The pinned callee
  ignores `r2/r3`, so this is unobservable; the test therefore compares `r0/r1`
  and documents the residual difference.
- The C++ is a different algorithm and register allocation; it does not
  reproduce the original reciprocal table, instruction scheduling, frame size or
  condition-flag trail. No byte identity is claimed.
- No emulator, caller-composition, or whole-game runtime equivalence is claimed.
