# Function Record: engine_func_0034fc14 (0x0034fc14)

## Summary
- **Address:** `0x0034fc14`
- **Size:** 400 bytes (original span `[0x0034fc14, 0x0034fda4)`)
- **File:** `src/engine/leaf_batch44_b.cpp`
- **Role:** Wait/counter stage of the action-step object that also drives
  `camp_func_00351040` (`0x00351040`) and `0x00351134`.  It inspects the
  animation subobject at `object+0x158`, only services step states 3 and 6,
  moves them to state 2 under the object lock, busy-waits until the step state
  becomes 1, 7 or 8, and then advances the two per-slot frame counters through
  the virtual tables of the per-index objects at `object+0x2EC`.
- **Status:** Semantically equivalent C++ (`non_matching`).  The compiled body is
  480 bytes versus 400 original bytes because the compiler unrolled the
  two-iteration slot loop and materialised the state mask; the ledger row is
  classified `non_matching` and this record carries the semantic evidence.

### Step-state machine

   (`0x0023a774`, 16 B) returns `[p+0x58] - [p+0x5C]` as a signed difference.

     stores `obj->state_0c = 7` **before** the next call.
   - `camp_func_00351040(obj)` is always called on this path.
3. `state != 3 && state != 6` returns `0` without touching anything else.  This
   also covers the state-7 abort written in step 2.
4. The original then re-loads the state and branches on `state == 1`; state 1
   cannot reach this point (step 3 filtered it), so that branch is dead.  It is
   kept in the C++ with a comment because the transition block matches the
   sibling step functions.
5. Otherwise:
   - `state == 6` first calls `nn_sdk_func_002c4244(&obj->sync_state_20)`.
   - `engine_func_002c3aa8(obj)` (recursive lock), `obj->state_0c = 2`,
     `engine_func_002c3a24(obj)` (unlock).  The store is inside the lock; the
     test stubs read the state at both calls so the order is observable.

## Domain Limits
- Every direct callee is stubbed; the real bodies of `0x0023A690` (including its
  internal wait/retry loop), `0x00351040`, `0x002C4244`, `0x002C3AA8`,
  `0x002C3A24` and `0x002BB490` are not executed.  `0x002C615C` is modelled as
  `__aeabi_idivmod` (quotient/remainder), with quotient `0xFFFFFFFF` and the
  numerator as remainder for a zero divisor; a zero granularity is multiplied
  back to zero by both the original and the candidate, so that edge case is not
  observable here.
- The wait loop only terminates when the sleeping task changes `+0x0C`.  The
  test drives that through the `AsdThread_Sleep` stub; the real scheduler
  interleaving is not reproduced.
- The compiled candidate is 480 bytes versus 400 original bytes (loop unrolling,
  state-mask materialisation, out-parameter slot at `sp+4`); byte identity is not
  claimed and the ledger row says `non_matching`.
- The `adds`/`beq` test of the computed entry address is reproduced as a 32-bit
  integer test.  It can only fire for a synthetic object whose address wraps
  through `0x30C` plus `index*40`, which cannot be built with a usable object in
  the 32-bit address space, so it is not exercised differentially; the resulting
  granularity-0 behaviour is exercised by `index >= limit`.
- The state-1 branch after the state filter is unreachable (states 3 and 6 are
  the only survivors) and is therefore never taken; it is retained for
  structural fidelity and covered only by inspection.
- Field meanings beyond the ARM offsets are not proven: `state_0c`,
  `sync_state_20`, `entry_limit_2e8`, `slot_object_2ec`, `slot_entry_30c`,
  `slot_index_46c` and `slot_counter_47c` are named after the observed roles.
  `mode_08` is named after the two-frame granularity it selects.
- No runtime, caller-composition or whole-game equivalence is claimed.  The
