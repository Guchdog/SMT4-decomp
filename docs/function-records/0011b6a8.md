# Function Record: engine_func_0011b6a8 (0x0011B6A8)

## Summary
- **Address:** `0x0011B6A8`
- **Size:** 400 bytes (span `[0x0011B6A8, 0x0011B838)`, including the four
  literal-pool words at `0x0011B828..0x0011B834`)
- **File:** `src/engine/leaf_batch34_c.cpp`
- **Role:** State-wait loop plus elapsed-time accounting for the engine task
  context at `0x004C3B20`. In state 6 it takes the object lock, publishes state
  5, releases the nnSdk lock, polls the state word until it becomes 3 (finish),
  7 or 1 (abort), sleeping 500,000 ns between polls. On the finish path it
  reduces the current system tick, subtracts the 64-bit baseline captured by
  `0x0011B5E8`, and adds the wrapping delta to the two 64-bit counters at
  `object+0x138` and `object+0x140`.
- **Status:** Reconstructed as readable C++ and **semantically verified**
  against the pinned original. The candidate body is 388 bytes and is not
  byte-identical, so the ledger row is `non_matching` and this record carries
  the semantic evidence.

### Control flow
```text
if ([object+0x0C] != 6) return 0;
0x002C3AA8(object);                 // enter the object lock
[object+0x0C] = 5;
0x002C3A24(object);                 // leave the object lock
0x002C4244(object + 0x20);          // release the nnSdk lock

for (;;) {
    if ([object+0x0C] == 3) break;         // reload #1
    state = [object+0x0C];                 // reload #2
    if (state == 7 || state == 1) return 0;
    0x002BB490(500000);                    // 500,000 ns, r1 = 0
}

now      = TicksToMicroseconds(GetSystemTick());
elapsed  = now - (u64)[object+0x150];
counterA = counterA + elapsed;             // 64-bit wrap
counterB = counterB + elapsed;             // 64-bit wrap
return 1;
```

The original reloads `[object+0x0C]` once for the `== 3` test and again for
the `7` / `1` tests on every iteration; the C++ keeps both loads. The sleep
call always forwards `r0 = 0x0007A120` (500,000) and `r1 = 0`. Original store
order on the finish path is `[0x144]` first, then `[0x138]`, `[0x13C]`,
`[0x140]`; the intermediate accesses are independent, so only the final words
are observable.

### Two-stage fixed-point reduction (`0x0011B71C..0x0011B7E4`)
The body contains one `svc #0x28` (nn::os::GetSystemTick, 64-bit result in
`r0:r1`) followed by two hand-expanded 128-bit multiplies. Pool literals:
`0x0007A120`, `0xBAD34AEE`, `0xE353F7CF`, `0x20C49BA5`.

1. **Tick → nanoseconds.** Bits 32..95 of the signed product
   `(s64)tick * 0x3BAD34AEE` (the `mov r3,#3` supplies the `3 << 32` term, so
   the multiplier is `0x3BAD34AEE = 3*2^32 + 0xBAD34AEE`). For 268,111,856
   ticks this yields 999,999,999.
2. **Nanoseconds → microseconds.** Bits 64..127 of the signed product
   `(s64)nanoseconds * 0x20C49BA5E353F7CF`, then an arithmetic `>> 7` plus the
   original's sign-bit adjustment (`lsr r6,r1,#31` → `adds/adc`), i.e.
   truncation toward zero of the magic division by 1000.

The 400-byte ARM body implements the 128-bit products with `umull` / `umlal` /
`mla` and the signed correction terms (`asr r6,r1,#31`, `mla r2,r6,r2,r8`,
`adc r2,ip,r5,asr #31`). ARMv6K has no `__int128`, so the candidate recovers
the same products from the identical 32-bit partial products
(`MultiplyHighUnsigned` / `MultiplyHighSigned`) and keeps the wrap-around
behaviour of both stages for every 64-bit input, including negative ticks and
the exact-multiple corner case the `+1` sign adjustment has.

## Domain Limits
- The four direct-call targets and `nn::os::GetSystemTick` are stubbed, so
  their internals are not exercised. In particular the sleep helper's effect on
  the state word is performed by the test stub (simulating the other thread the
  loop waits for) and the real thread interaction is unresolved.
- The wait loop's termination depends on called/external code writing
  `[object+0x0C]` to 3, 7 or 1; the test drives that deterministically. The
  double reload of `[object+0x0C]` within one iteration cannot be separated by
  a stub call, so its data-race behaviour is not differentially observable, but
  the candidate keeps both loads.
- `[object+0x150]` is proven to be the pair the sibling row `0x0011B5E8`
  stores; the helper `0x002B5F90` that produces that pair is not decoded, so
  the time unit of the baseline/counters is inferred from the reduction pattern
  only.
- The candidate emits the `nn::os::GetSystemTick` import as a call instead of
  an inline `svc`; the test supplies the revision's wrapper so both paths
  execute `svc #0x28` with the same values. The extra call frame is not
  observable in the compared state.
- `r12` is saved/restored by the original but is caller-clobbered in the
  candidate (AAPCS-legal); the differential test therefore compares only
  `r4-r11`.
- No runtime/emulator execution, staging or production promotion is claimed.
