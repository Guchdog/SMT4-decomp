# 0x00286928 — H2 titleConfig state dispatcher

## Production status and contract

`engine_func_00286928` is a typed C++ reconstruction in `src/engine/leaf_batch45_a.cpp`. Its raw ABI is six 32-bit words: `r0`–`r3`, followed by two words on the stack. Arg6 remains an opaque 32-bit value; no floating-point meaning is inferred. The implementation reproduces selector-specific pointer/mode/prewrite behavior and both incoming-`r2` state-machine families. The compiled C++ body is 812 bytes in the original 820-byte slot; two ARM NOPs fill the tail. Since the bytes differ from the original, `config/functions.csv` classifies it as `non_matching`.

The implementation retains 17 original ARM callees through 22 direct `R_ARM_CALL` references. These include the callback reset/write helpers, global-state queries, `0x002B8D24`, the title-config service updater, and the loop/index helpers. The complete branch and memory contract, including five corrections found during differential work, is recorded in [the exhaustive contract](../agent-work/h2-86928-exhaustive-contract.md). Independent static verification is in [the post-differential review](../agent-work/h2-86928-post-diff-review.md).

## Build and offline evidence

`tools/h2_86928_experiment.py` compiled an 812-byte candidate and passed 296 direct original-versus-candidate cases, four compositions through the original pinned callback `0x00221168`, and six mutation controls. The callback runs with synthetic returns from its three upstream getters. Every direct helper dependency is intercepted by deterministic stubs; `0x002B8D24` does not execute its body in this suite. The evidence therefore covers the dispatcher under the declared fixtures, not original dependency behavior for every branch. The differential and bounded domains are described in [the implementation report](../agent-work/h2-86928-implementation.md).

The production TU compiled to the same 812 function bytes and the same 22 named relocations as the standalone candidate. `tools/h2_86928_staged_image_patch.py` resolved all 22 calls to even, in-range ARM targets from the function ledger, placed two ARM NOPs in the slot tail, and verified IPS round-trip plus no changes outside this slot. ## Runtime and limits

The dedicated autonomous loopback Azahar run `build/h2-86928-integration/runtime-probe-002/autonomous-gdb-verification.json` used the cumulative H2 image (image SHA-256 `1616aa24873a72beafdc9ae12cf688f9d7575b11a3f9b3f366c77fddd1f4e703`, IPS SHA-256 `cc63c2fe655bdc38c3c017531cc429de6eb9c9a287f6f9c5ad31126a8e5a2252`). A software breakpoint at the even ARM entry captured 129 original and 129 patched calls to `0x00286928`; all six entry ABI words and raw `r0` returns matched. The paired scripted scenario also matched 19/19 checkpoints and 51 scripted actions. The report SHA-256 is `7ea75a944d1f72c62ae76bbdc3f86c2d4c2a5d1f5fe0ded85b6c02110b3d3c76`.

The cumulative manifest records source-identity caveats for its prior H2 base. The runtime claim is tied to these exact recorded image and IPS bytes, not a fresh source rebuild.

This is a bounded paired scenario, not full H2 acceptance: readiness and same-session re-entry did not complete, and physical input mapping and scheduling are unproven. The driver uses a one-frame logical query stub for deterministic scripted conditions. The offline fixtures still use fixed getter/callee results and do not establish fault parity for invalid pointers, arbitrary aliasing with MMIO, concurrent mutation, every caller argument domain, or the continuation of handler `0x001A07CC` above callback `0x00221168`. The runtime hit/argument/return capture does not prove all callees or whole-game equivalence; H2 remains open.
