# `0x00120AC8` -- AsdSound engine initialisation (`AsdSound_InitEngine`)

## Recovered behavior

The function is the one-shot setup routine reached from
`AsdSoundSystem_func_0010d40c` as `AsdSound_InitEngine(&config, engine_buf,
engine_size)`. It takes the configuration block in `r0` and the work-buffer
base in `r1`; the `r2` size word is never read by this body. The function is
`void`; `r0` on the normal path happens to hold the last `field_1c` byte load
(the early-return path leaves the config pointer there), so `r0` is not a
contract output.

Control flow:

1. If the byte at `0x0044E909` is non-zero, return immediately. No other loads,
   stores or calls happen on this path.
2. Call `0x00130FF8` with the fixed object address `0x004EA168`.
3. If `0x0044E90A` is zero, bind two regions with `0x00130D18`:
   * `0x002BB218()` at `buffer`, byte size `config->field_0c`;
   * `0x002BB1BC()` at `buffer + field_0c`, byte size `config->field_18`;
   * advance the cursor by `field_0c + field_18` and set `0x0044E90A = 1`.
4. If `config->field_1c` is non-zero, record the first window at the current
   cursor, advance by `config->field_08`, and, only when `config->field_04 == 1`
   and `config->field_1e != 0`, record a second window and advance again by
   `field_08`. Both window words and the cursor are zero/default otherwise.
5. Call `0x00130E10(0x002BD630())`, publish the current cursor as the window
   base, advance by `config->field_14`, then call
   `0x001441DC(0x002BB360())`, and store `{window_base, field_14}` at
   `0x0044E910` / `0x0044E914`.
6. Build two strided regions from the word at `0x0044E90C` (reloaded after each
   getter call):
   * `0x001311A0` returns `0x60 * count`; the first result advances the cursor,
     the second is passed with the unadvanced cursor to `0x00131128`;
   * `0x00130FE8` returns `0x144 * (count + 1)`; the first result advances the
     cursor, the second is passed with the advanced text base to `0x00130FA8`.
7. Clear the fixed table with `0x001311AC`, then call
   `0x00130438(0x001303BC(), config->field_10, &window_at_0x0044E910)`.
8. If `config->field_1c` is still non-zero, call `0x00130E6C` with
   `r0 = 0x002BD630()`, `r1 = first window`, `r2 = field_08`,
   `r3 = field_00`, and stack words
   `second window, field_08, field_00, field_04, sext8(field_1d)`.
9. If `field_1d != 0` and signed `field_20 > 0`, call
   `0x00130E18(0x002BD630(), cursor, field_20)`.
10. Store `field_1c` at `0x0044E908` and 1 at `0x0044E909`.

There are no loops, no indirect calls and no indirect branches. All 28 `bl`
sites target 19 distinct direct helpers; every call is reproduced in source
order with the same register and stack arguments.

## Memory and ABI facts

* `0x0044E908` is a five-byte state block: `+0` last `field_1c`, `+1` one-shot
  gate, `+2` first-pass binding flag, `+4` entry count.
* `0x0044E910` is a two-word window `{base, size}` passed to `0x00130438`.
* `0x004EA168` is the fixed object passed to `0x00130FF8`.
* The work-buffer cursor is pure 32-bit addition and wraps; the function never
  dereferences it itself.
* `field_1d` is read as an unsigned byte for the final gate but sign-extended
  with `ldrsb` into the fifth `0x00130E6C` stack word.
* `field_20` is compared as a signed 32-bit value (`ble` after `cmpne #0`).

## Offline evidence

`python tools/test_leaf_00120ac8.py` compiles `src/engine/leaf_batch34_c.cpp`,
relocates the 0x00120AC8 body (468 bytes, 28 `R_ARM_CALL` relocations) over the
pinned image address, and runs the original and candidate in separate Unicorn
ARM machines with deterministic stubs at every original call target.

The comparison checks the continuation PC (trap address), final SP, callee-saved
`r4-r11`, the ordered call log (all register arguments, the five `0x00130E6C`
stack words, the window pair read by `0x00130438`, the window bytes snapshotted
at the getter, `0x00130E10` and `0x001441DC` boundaries, and the sizes returned
by `0x001311A0`/`0x00130FE8`), the set of non-code/non-stack write addresses, and
the final bytes of the globals, config, buffer, helper-object and scratch
regions. The stack body itself is excluded because frame layout is a compiler
choice; helper-visible stack arguments are still compared.

Results: all 21 direct cases pass. They cover the one-shot gate (0 and 0xFF),
the first-pass flag, `field_1c` zero/non-zero, all `field_04`/`field_1e`
combinations, `field_1d` zero/0x80/0xFF (sign extension), signed `field_20`
values `0`, `1`, `INT32_MAX`, `INT32_MIN`, `-1`, null and non-null getter
returns, null and wrapping buffer bases, zero/large entry counts, and helper
getters that mutate the entry count and `field_1c` so every reload is observed.
Four source mutants (outer window gate, second region size field, final gate
inversion, binding gate inversion) are each detected.

Ledger classification is `non_matching`: the candidate body is 468 bytes versus
528 code bytes in the original, with 412 differing bytes in the common prefix.
The 540-byte ledger size includes the original's three literal-pool words.

## Limits

Helper bodies are modeled, not reconstructed here: the buffer getters, the
region initialisers, the renderer getter/draw pair and the final draw calls are
deterministic stubs that record their ABI arguments and apply representative
side effects. The game-level meaning of the opaque helper objects and of the
`0x004EA168` initialisation object is inferred from the sound-engine caller, not
proved. No emulator/runtime scenario, concurrent modification of the config
block, real heap placement or whole-game integration was tested. There are no
unresolved indirect-call targets in this function.
