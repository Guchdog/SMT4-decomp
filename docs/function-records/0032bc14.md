# Function Record: engine_func_0032bc14 (0x0032BC14)

## Summary
- **Address:** `0x0032BC14`
- **Size:** 404 bytes (span `[0x0032BC14, 0x0032BDA8)`, including the 12-byte
  literal pool at `0x0032BD9C..0x0032BDA4`)
- **File:** `src/engine/leaf_batch41_c.cpp`
- **Role:** Engine wait/step loop over the two global engine objects at
  `0x004C3AF8` and `0x004C3B20`. Each iteration probes the context object,
  compares the 64-bit time returned by `0x00351208` against the 64-bit baseline
  stored at `0x0044D020+0x08` and against six times that baseline, runs the
  matching transition helpers, latches the byte at `0x0044D020`, sleeps through
  `0x00351698`, and repeats until the overdue flag, the latched status flag, or
  context state 1 / 7 ends the loop.
- **Status:** Reconstructed as readable C++ and **semantically verified**
  against the pinned original. The candidate body is 352 bytes and is not
  byte-identical, so the ledger row is `non_matching` and this record carries
  the semantic evidence.

## Contract and Behavior

### Signature and ABI
```c

```
- `r0` is caller-supplied and **never read**. The original overwrites it with
  the literal `0x004C3AF8` before the first call (`0x0032BC24`).
- **Return value:** `1` only when the `r5` flag is set (the overdue branch of
  the six-times-baseline check); otherwise `0x00350530(0x004C3B20)` is called
  and `0` is returned. `r4` alone forces the `0x00350530` call but never returns
  `1`.
- `r4` means "the byte at `0x0044D020` was nonzero in some iteration"; `r5`
  means "the six-times-baseline comparison took its signed-less-than path with
  a non-negative time high word". Both flags persist across loop iterations
  (`0x0032BC18..0x0032BC1C` initialise them once, the loop-back target
  `0x0032BC24` skips the initialisation).
- Entry `push {r4, r5, r6, r7, r8, sb, sl, lr}`; exit
  `pop {r4, r5, r6, r7, r8, sb, sl, pc}`. `r4-r11` are preserved, there are no
  stack arguments and no indirect calls.
- The only direct caller found by a raw-word scan of the pinned `.text` is
  `0x001DD5A8` (`bl 0x0032BC14`). It passes `r0 = [r4+0x10] + 1` (a per-frame
  counter the callee ignores) and branches on the returned word.

### Exact comparison semantics
- First comparison (`0x0032BC80..0x0032BC90`): `subs`/`sbcs` followed by `blt`.
  ARM `blt` is `N != V`, i.e. the signed 64-bit comparison
  `(s64)now < (s64)baseline`. The C++ keeps that signed comparison.
- Second comparison (`0x0032BCCC..0x0032BCE0`): `umull r8, sb, r2, r7` with
  `r7 = 6`, then `mla r3, r3, r7, sb` and `mla r2, r2, ip, r3` (`ip = 0`)
  reproduce `baseline * 6` modulo 2^64; `subs`/`sbcs`/`blt` is again the
  signed 64-bit comparison.
- **The inner test is on `r1`, not on the difference.** `sbcs r0, r1, r2`
  writes the high difference word to `r0`, so `r1` still holds the high word
  of the value returned by `0x00351208`. `cmp r1, #0; blt` therefore means
  "the returned 64-bit value has bit 63 set", not "the difference is negative".
  The C++ tests `(s32)(u32)(now >> 32) >= 0` and is deliberately not folded into
  the signed comparison.
- Consequence: when `now < scaled` and `now` is negative, the overdue helpers
  are skipped even though the loop body took the `blt` arm. A case with
  `baseline = 1` and `now = 0x8000000000000000` exercises that asymmetry.

## Domain Limits
- All 18 direct callees are stubbed, so their internals are not exercised. In
  particular the real `0x0011B6A8` wait loop and the real `0x00351698` sleep are
  not executed; the test drives the state/status changes the loop depends on.
- The loop's real termination depends on other threads writing
  `[0x004C3B20+0x0C]` (state 1 or 7) or the byte at `0x0044D020`. The double
  iteration structure is reproduced, but the data-race timing is not observable.
- `0x00351698` ignores its caller argument and sleeps 500,000 ns before

- The candidate is 352 bytes and not byte-identical; no exact-match claim is
