# Caller-window record — `0x001E9D48` navigation reducer

## Identity and boundary

- Original: interior ARM caller window in `ui_func_001e989c`, not a standalone
  function. The measured state-5 window starts at `0x001E9D08` and stops at
  `0x001E9DE0`; the stop is immediately before the original blend clamp.
- Candidate: `h1_navigation_caller_candidate` in
  `experiments/semantic_equivalence/h1_navigation_caller_candidate.cpp`.
- This is a compiled caller-window proposal, not a replacement of the callback
  or a raw-PC patch. The candidate returns a status at a harness sentinel;
  original execution reaches either `0x001EA62C` (readiness failure) or
  `0x001E9DE0` (both gates passed).
- Pinned `code.bin` SHA-256:
  `1f98884fe997af22e032a14c51a46c872b05b0e079a0f29e307b0e059cfaa558`.

## Recovered caller contract

- `Script_IsReadyToAdvance` at `0x00289924` has no formal arguments and returns
  its predicate in `r0`. It runs first; false skips preview, input, singleton
  lookup and timer/cursor writes.
- `Camp_IsPreviewReady` at `0x0025A2BC` has no formal arguments and returns in
  `r0`. It runs only after the script gate passes; false skips input and the
  work update.
- After both gates pass, the caller loads `g_TitleMainWork` from the global
  pointer slot `0x0044E300`, then increments the binary32 timer at work `+0x64`
  by `1.0`.
- `UiInput_Trigger` at `0x002B902C` accepts one `u32` logical ID in `r0` and
  returns an integer predicate in `r0`. The call sequence is `5`, then `0xE`
  only if 5 is false; then `6`, then `0xF` only if 6 is false. The previous
  pair decrements the cursor at work `+8`; the next pair then increments it.
  Both directions can run in one update.
- The word arithmetic at `0x001E9DAC..0x001E9DC0` implements signed remainder
  by four, including the negative remainder result (`-1` maps to `3`), rather
  than unsigned `cursor & 3`. For valid cursor indices 0..3 this wraps 0↔3.
  The caller does not provide a general clamp for arbitrary corrupt values.
- The normalized cursor is stored at work `+8`. It is compared with cached
  cursor `+0xC`. If changed, `UiEvent_Request` at `0x002B91C4` is called with
  exactly one formal `u32` argument in `r0`, event `0x0100016C`; no stack
  arguments are used. The event call occurs before writing the new cache value
  to `+0xC`. No event is requested when the final cursor equals the cache.
- The event helper's internal queue/global effects are not included in this
  caller-window experiment. `r1-r3` are recorded diagnostically at the hook but
  are not formal event arguments.

## Candidate and evidence

The candidate uses explicit fixed-address function-pointer types for the two
readiness helpers, trigger query and event request. It does not accept synthetic
gate, trigger or event arguments. The harness hooks only those four external
helper entry PCs; it executes the candidate's own ordering, branches, arithmetic,
memory stores and helper calls.

The focused report is
`build/agent-work/H1-semantic/h1-menu-nav-candidate/sleep-20261025-nav-candidate/checks/final-candidate-run/report.json`.
It records the pinned image hash, compiler object/source hashes, per-call helper
entry observations, per-case arguments/events/final work bytes and register
differences. The run covers:

- script-not-ready (preview skipped), preview-not-ready (input skipped), and
  both-ready paths;
- ten directed alias/priority/wrap/net-zero/cache/event cases;
- all 256 combinations of cursor 0..3, cached cursor 0..3 and four logical
  trigger response bits;
- a negative raw signed `% 4` control at provisional `-1`, which returns
  `0xFFFFFFFF` rather than the original normalization result `3`;
- complete `0xA0` work-block comparison, with only bytes at `+8..+0xF` and
  `+0x64..+0x67` permitted to change, plus stack pointer/FPSCR and callee-saved
  integer/VFP observations.

The behavioral comparison passed for the recorded input domain. Full raw state
does **not** match at the continuation: original `r8` is `0x0044E300`, while the
standalone candidate preserves incoming `r8` (`0x88888888` in the test seed);
original `d8` changes from `0x1122334400000008` to `0x3F80000000000008` because
the inline sequence loads `1.0` into `s17` (the upper half of `d8`). The
candidate follows AAPCS and preserves `d8`. `r4` is work in both runs because
the seeded caller value is the work pointer. Thus this compiled function is not
drop-in substitutable at the original interior PC without a caller-context
adapter that accounts for `r8` and `s17` liveness. The report classifies ARM
differential and caller evidence as `partial`, not full-state equivalence.

## Limits and next step

No physical keyboard/gamepad binding, held-input policy, actual event-queue
effect, touch path, help-text/render behavior, fade/dispatch path, emulator
scenario or whole-game behavior is established. The next step is independent
review of the candidate and a caller-context integration proposal that resolves
the live `r8`/`s17` continuation contract before promotion.
