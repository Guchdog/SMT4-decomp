# Function Record: engine_func_001325d8 (0x001325d8)

## Summary
- **Address:** `0x001325d8`
- **Size:** 600 bytes (original span `[0x001325d8, 0x00132830)`; the body ends
  with the tail branch at `0x00132810`, the following seven words are the
  function's literal pool)
- **File:** `src/engine/leaf_batch45_a.cpp`
- **Role:** Engine frame/render synchronisation. Runs a one-time registration
  sequence for the two global render registries, calls the engine readiness
  probe, optionally dumps the words between the command cursor snapshot and its
  post-call value as `"0x%08x,"` (four entries per row), then releases the
  per-frame render state.
- **Status:** Semantically equivalent C++ (`non_matching`). The compiled body is
  576 B versus the 600 B original; the compiler keeps the guard block, registry
  slots and handles in `r9`/`r10`, folds the row reset into a conditional
  subtract, and places the `"0x%08x,"` literal in `.rodata.str1.1` instead of
  the original literal pool. The ledger row is classified `non_matching` with
  this semantic record.

## Contract and Behavior

### Signature and ABI
```c
extern "C" void engine_func_001325d8(void* obj, u32 state, u32 reserved,
                                     u32 dump_commands);
```
- `obj = r0`, `state = r1`, `reserved = r2`, `dump_commands = r3`.
- `reserved` (r2) is saved by the prologue but never read; it exists only
  because the two live arguments are `r1` and `r3`.
- `state` is forwarded verbatim to both `0x2ABBB8` calls.
- `dump_commands` is compared against zero (`ldr r0,[sp,#0x118]` reads the
  saved `r3`); every non-zero bit pattern takes the dump path.
- No computed return value: the epilogue reloads the render handle into `r0`
  and tail-branches to `0x2ABB50` (`b #0x2abb50`), so the observed `r0` is the
  value left by that helper.
- The original preserves `r4-r8, sb, sl, fp` (plus `r0-r3` temporarily);
  final `sp` equals the entry value and `sp+0x140` is the first incoming stack
  word (there are none).

### One-time registration sequence (guard `[0x4DAD85] == 0`, `[0x4DAD84] != 0`)
1. `0x2ABE74(*(0x464B84) + 0x10, *(0x464B8C))`.
2. Reload `A = *(0x464B84)` and `C = *(0x464B7C)`;
   `0x2ABDF4(*(u32*)(C+8), *(u32*)(C+4))`.
3. Indirect call through `*(u32*)A` (the vtable) slot `+0x10`:
   `callback(A, *(u32*)(C+8))` with `r0 = A`, `r1 = *(u32*)(C+8)`.
4. `0x2ABDE8(*(u32*)(C+8))`.
5. `0x2C50D0(*(u32*)(0x4DAD88))`.
6. `0x2ABC9C(sp+8, *(u32*)(P+0xC), *(u32*)(P+0x10), context, *(u32*)(obj+0x18))`
   (fifth argument on the stack at `[sp]`).
7. `0x2C52F0(*(u32*)(0x4DAD88), 0)`.
8. `0x2C028C(*(u32*)(0x464B84), *(u32*)(0x464B8C))`.
9. `0x2ABE74(*(0x464B84) + 0x10, *(0x464B94))`.
10. Reload `A` and `C` again and repeat steps 2-4 with the *new* pointers.
11. `*(u8*)(0x4DAD85) = 1`.

Every registry pointer is re-read from its slot after the preceding call; the
stubs in the differential harness mutate the slots to prove that the candidate
reproduces the reloads.

### Readiness probe and dump
`0x1384F8()` returns `(g[1] != 0 && g[2] != 0)` for the process-state object at
`0x00464AF0`; when it returns 0, `0x2ABB68(*(u32*)(0x4DAD90))` is called.

When `dump_commands != 0`:
1. `cursor = *(u32*)(0x4652A0)` (snapshot *before* the construction call).
2. `0x2ABC9C(sp+8, range[0], range[1], context, extra)`.
3. If `cursor != 0`, re-read `end = *(u32*)(0x4652A0)`; otherwise `end` stays 0
   and the slot is not read again.
4. Loop `while (cursor < end)` over 4-byte words:
   `written = 0x13C030(scratch + column, 0x100 - column, 0xFF - column,
   "0x%08x,", *(u32*)cursor)`; `row += 1`; `column += written`;
   when `row == 4` both `column` and `row` are reset to 0; `cursor += 4`.
   The `column` accumulator is a 32-bit wrap-around add and can therefore move
   the `0x100 - column` / `0xFF - column` bounds past zero.
Otherwise (`dump_commands == 0`) a single `0x2ABC9C` construction call is made
from the `0x132790` block and the cursor is not read at all.

2. If `[0x4DAD84] != 0 && [0x4DAD85] != 0`:

## Contract corrections found during implementation
- **`r2` is not an argument of record.** The prologue saves `r0-r3`, but only
  the saved `r1` (`[sp,#0x110]`) and saved `r3` (`[sp,#0x118]`) are ever read
  back; `r2` is dead.
- **The dump range is a cursor delta, not a begin/end global pair.** Both the
  start (`0x132708`) and the end (`0x13272C`) of the dumped range are read from
  the *same* word `0x004652A0`, separated by the `0x2ABC9C` call. The loop
  therefore only runs when that call advanced the cursor; `0x004652A4`
  (`g_GpuCommandEnd`) is not referenced.
- **`0x2ABB50` is not a ledger function.** The tail branch targets an interior
  entry point inside `0x002ABAB0`'s address range (after that function's
  literal pool). It is declared explicitly as `void func_002abb50(void*)`.
- **Four `0x2ABC9C` arguments are read through `ldrd`.** `[obj+0x14]` and
  `[obj+0x18]` are re-read at every construction site; the fifth argument is
  the only stack word used by the function.
- **The `"0x%08x,"` string address is a literal-pool word, not a code
  address.** `ldr r3,[pc,#0xD0]` at `0x132754` loads `0x00410348`, whose bytes
  are `30 78 25 30 38 78 2C 00` (`"0x%08x,"`). The candidate uses a real
  `.rodata.str1.1` literal and the harness relocates the reference.
- **The row reset discards the accumulated column.** `moveq r4,#0` executes
  *after* `add r4,r4,r0`, so the fourth entry is formatted at the accumulated
  offset and the fifth entry starts at offset 0 again.

## Limits
- Fixtures are synthetic: the guard block, registry objects/vtables, object and
  range record, receiver objects, command buffer and cursor are not captured
  game data.
- Every helper (`0x2ABE74`, `0x2ABDF4`, `0x2ABDE8`, `0x2C50D0`, `0x2ABC9C`,
  `0x2C52F0`, `0x2C028C`, `0x1384F8`, `0x2ABB68`, `0x13C030`, `0x138BB8`,
  `0x2ABBB8`, `0x2C5094`, `0x2B77B8`, `0x2ABB50`) is stubbed; no real
  allocator, registry, formatting, GPU or render work is exercised.
- The virtual call target is resolved through the fixture vtable; the real
  slot-`0x10` implementation behind `0x464B84`'s object is not identified.
  Its only observed contract is `(void* self, u32 value)`.
- The semantic meaning of the registry tokens (`0x464B8C`, `0x464B94`) and of
  the `0x2ABC9C` range/context/extra words is not established; they are
  forwarded unchanged. `0x2ABC9C` itself is 276 B of still-raw code
  (`leaf_batch40_a.cpp`) and its return value is discarded by this function.
- The dump loop's cursor advance is driven by the stub: the real `0x2ABC9C` may
  or may not move `0x4652A0`, and no captured trace establishes it. The loop
  bounds (1..8 words) are therefore a documented synthetic fixture.
- `0x13C030`'s real formatting/overflow contract is not modelled; the stub
  writes a bounded deterministic payload and returns the case-selected length.
- No VFP state is involved. The candidate's internal frame layout and register
  allocation differ from the original; only the documented ABI inputs, call
  arguments, accumulated memory effects and returned registers are compared.
- No rendering, engine-state, caller-composition or whole-game runtime
  equivalence is claimed.
