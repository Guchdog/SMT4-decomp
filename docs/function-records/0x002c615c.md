# `0x002C615C` — signed integer division helper

Status: experimental C++ reconstruction; not integrated. The pinned 556-byte
ARM body begins at `0x002C615C`, returns through `BX LR` at `0x002C6384`, and
ends at `0x002C6388` (exclusive). The full body hash for the pinned image is
`3d7cdf38585407be142951c950b3c44d2ba4d5d860470166cc4d5e4b3a2705b9`.

The sign-bit path at `0x002C629C` divides operand magnitudes and applies the
quotient sign. For nonnegative inputs, this is ordinary unsigned division.
The result words are quotient in `r0` and signed remainder in `r1`; the
remainder follows the dividend sign. `r4-r11` and `sp` are preserved. The
helper uses `r2`, `r3`, and `ip` as scratch and changes condition flags.
Callers inspected here consume `r0`; `r1` is caller-saved in the observed
callers, though the pinned body computes the remainder there.

For a zero divisor, the pinned code reaches `0x002C6378`, calls
`0x0014E604`, which branches to `0x001524EC` (`BX LR`), then returns with
`r0=0` and `r1` equal to the original numerator bits. Its push/pop leaves
temporary words in the restored stack area. The candidate models the result
words, not that incidental stack residue.

The H1 interpolation caller at `0x002BF9F0` supplies a signed coordinate delta
shifted left by 12 and an unsigned 16-bit row duration. It calls this helper at
`0x002BFBA4`, `0x002BFBC8`, `0x002BFBEC`, and `0x002BFC10`. Signed 16-bit
coordinate differences lie in `[-65535,65535]`; multiplying by 4096 fits
signed 32-bit. The intended interpolation domain has positive duration
`[1,65535]`. The candidate's quotient-only C entry is
`candidate_002c615c`; its `candidate_002c615c_divmod` entry exposes the two
result words using the ARM 32-bit `uint64_t` return convention.

Source aliases in `src/camp/unite_extras.cpp` and
`src/script/script_vm_extras.cpp` call the function unsigned. That shorthand
does not describe its sign-bit behavior in general. See
[`h1-interpolation-divide-candidate.md`](../agent-work/h1-interpolation-divide-candidate.md)
and the private differential report under `build/agent-work/H1-semantic/`.
The differential is finite and isolated; it is not caller-level or runtime
evidence, and stack scratch bytes are not treated as caller-visible state.
