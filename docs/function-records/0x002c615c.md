# `0x002C615C` — signed integer division helper

Status: readable production C++ with bounded final-address evidence on a
standalone original-image patch. The ledger is `non_matching`. The pinned
556-byte ARM body begins at `0x002C615C`, returns through `BX LR` at
`0x002C6384`, and ends at `0x002C6388` (exclusive). The full body hash for the pinned image is
`3d7cdf38585407be142951c950b3c44d2ba4d5d860470166cc4d5e4b3a2705b9`.

The sign-bit path at `0x002C629C` divides operand magnitudes and applies the
quotient sign. For nonnegative inputs, this is ordinary unsigned division.
The result words are quotient in `r0` and signed remainder in `r1`; the
remainder follows the dividend sign. `r4-r11` and `sp` are preserved. The
helper uses `r2`, `r3`, and `ip` as scratch and changes condition flags.
Callers inspected here consume `r0`; `r1` is caller-saved in the observed
callers, though the pinned body computes the remainder there.

The production API is `extern "C" u64 ui_func_002c615c(u32 numerator,
u32 denominator)`. Under the 32-bit ARM ABI, its low word is the quotient in
`r0` and its high word is the remainder in `r1`. C++ callers that use only the
quotient take the low word explicitly.

For a zero divisor, the pinned code reaches `0x002C6378`, calls
`0x0014E604`, which branches to `0x001524EC` (`BX LR`), then returns with
`r0=0` and `r1` equal to the original numerator bits. Its push/pop leaves
temporary words in the restored stack area. The candidate models the result
words, not that incidental stack residue.

The H1 interpolation caller at `0x002BF9F0` supplies a signed coordinate delta
shifted left by 12 and an unsigned 16-bit row duration. It calls this helper at
`0x002BFBA4`, `0x002BFBC8`, `0x002BFBEC`, and `0x002BFC10`. Signed 16-bit
coordinate differences lie in `[-65535,65535]`; multiplying by 4096 fits
signed 32-bit. The intended interpolation domain has positive duration
`[1,65535]`. The candidate's quotient-only C entry is
`candidate_002c615c`; its `candidate_002c615c_divmod` entry exposes the two
result words using the ARM 32-bit `uint64_t` return convention.

Source aliases in `src/camp/unite_extras.cpp` and
`src/script/script_vm_extras.cpp` call the function unsigned. That shorthand
does not describe its sign-bit behavior in general. See
[`h1-interpolation-divide-candidate.md`](../agent-work/h1-interpolation-divide-candidate.md)
and the private differential report under `build/agent-work/H1-semantic/`.
The differential is finite; stack scratch bytes are not treated as caller-visible state.

## Production conversion and bounded integration

The production definition in `src/engine/leaf_batch32_c.cpp` is readable C++.
Its compiled body is 164 bytes with no relocations. The standalone patch places
that body at `0x003FE624` and redirects only the original entry with an
unconditional ARM `B`; the original 556-byte body suffix remains intact because
six direct branches from `0x002C6C10` enter labels inside it:
`0x002C6190`, `0x002C61B8`, `0x002C61E8`, `0x002C621C`, `0x002C6240`, and
`0x002C6264`. The patch changes a 4-byte entry and the 164-byte cave body,
round-trips through IPS, and detects a wrong-target control.

The production-source body passes 368 direct original-versus-patched cases,
including nine zero-divisor returns, and two full compositions through the
pinned original preview helper `0x002BF9F0`. Each caller case takes two real
divide calls with positive duration and leaves all other callees original. The
standalone image SHA-256 is
`5d5fc7af6a39eda53418f41add058059d940cad30450870d2685572ccbc6f221`. The
accumulated five-callback H2 image allocates the same shared cave, so this
replacement is not claimed as part of that image. The H2 caller
`0x0029F278` was not executed. Runtime, scene/object lifecycle, non-H1 caller
domains, invalid pointers, concurrent access, MMIO, and whole-game behavior
remain unproven. See [the production integration report](../agent-work/h2-2c615c-production-integration.md)
and its independent review.
