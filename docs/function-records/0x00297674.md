# `0x00297674` — raw global state word getter

## Recovered behavior

The function performs two dependent 32-bit reads and returns the second word unchanged:

1. Read the pointer stored at `0x0043E190`.
2. Read and return the word at that pointer plus `0x1C`.

It takes no arguments and does not check for null, normalize the value, write memory, or adjust the stack. The field's owner, lifetime, and higher-level meaning remain unknown. Invalid or null pointers fault in the tested ARM fixture, matching the pinned original.

`TitleConfig_Calc` reaches this getter from state 2 at caller PC `0x001EAFAC` only when original helper `0x0019DFBC(work+0x154)` returns exactly `2`. Getter value `0` calls original `0x002BDAC0(work+0x5C,1,0)`, writes config byte `+4 = 1`, and stores state `3`; value `1` stores state `1`; all other 32-bit values make none of those state/config changes. The caller fixture uses a modeled return for `0x0019DFBC`; the original `0x002BDAC0` body executes on the zero path, while its nested service boundaries remain modeled.

## Offline evidence

`tools/h2_297674_experiment.py` compares pinned original ARM and compiled candidate/production bodies. Seven direct words (`0`, `1`, `2`, `0xFF`, `0x100`, `0x80000000`, `0xFFFFFFFF`) passed with the expected full-width return, identical two-read address/order traces, no writes, preserved `r1-r12`, callee-saved registers, SP/LR and CPSR flags. The null-pointer fault presence also matched. Three mutation controls were detected: wrong pointer slot, wrong field offset, and byte-width return.

The caller runner tested 28 state-2 cases: four prior-helper returns (`0`, `1`, `2`, `0xFFFFFFFF`) crossed with the seven getter values. The 7 gated cases reached the getter; the other 21 skipped it. Original `TitleConfig_Calc` versus the same pinned image with only this 20-byte slot replaced matched in return, ABI, full work/config bytes, service trace, getter reads, and original `0x002BDAC0` path. Static interworking confirms the original ARM `BL` at `0x001EAFAC` targets the even ARM entry `0x00297674`; the reconstructed body has no calls and returns with `BX LR`.

The replacement occupies the full 20-byte slot and differs in two bytes from the original. Its one-slot IPS roundtrip passed. The ledger is therefore `non_matching`. Focused checks passed for `leaf_batch21_b.cpp` and `leaf_batch22_c.cpp`; the full ARMv6K build passed 204/204 units at `build/h2-297674-full`. Independent review recommends bounded semantic integration and found no counterexample. Runtime was not run.

Evidence: [contract and caller census](../agent-work/h2-00297674-contract.md); [offline report](../../build/agent-work/H2-semantic/h2-titleconfig-00297674-convert/run001/report.json); [independent review](../agent-work/h2-00297674-independent-review-run001.md).

## Limits

The getter was tested with synthetic aligned pointers and selected word values. Concurrent writes, real object lifetime/ownership, natural runtime value reachability, and Azahar behavior are unverified. The `0x0019DFBC` return is a scenario input, not an executed helper; nested calls made by original `0x002BDAC0` follow the existing Calc harness service boundaries.
