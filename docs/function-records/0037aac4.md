# Function Record: ui_func_0037aac4 (0x0037aac4)

## Summary
- **Address:** `0x0037aac4`
- **Size:** 596 bytes (original span `[0x0037aac4, 0x0037ad18)`)
- **File:** `src/engine/leaf_batch45_a.cpp`
- **Role:** UI resource pass for a virtual UI object. Resolves the primary
  resource id (`key`) once, then walks four pending `{id, handle}` records:
  unresolved records are requested from the owning manager and resolved, every
  live record is bound into a local four-element result array, and a binding
  result of `-1`/`2` is committed and retried. A data-driven callback reports a
  failure command (`0`) or, on completion, a success command (`1`) with the
  key, the object's raw record array, the bound array and the per-entry flags.
- **Status:** Semantically equivalent C++ (`non_matching`). The compiled body
  is 580 B versus the 596 B original. The compiler reorders independent loads,
  carries the pending handle in `r2` across the request/resolve calls, folds the
  bind-result test into `cmp #2` / `cmn #-1`, and shares the epilogue; the
  original's literal pool held the initialiser address, the candidate keeps it
  as an `R_ARM_ABS32` literal to the same ROM routine. The ledger row is
  classified `non_matching` with this semantic record.

## Limits
- Fixtures are synthetic: the object, owner/extra pages, entry ids/handles and
  all stub return values are not captured game data.
- The four resource helpers are stubbed; only their call contracts are checked.
  The memory writing done by the `0x37C034` stub (`{handle, 0xB0B0000n}` and one
  flag byte per entry) is a deterministic stand-in for the real binding logic.
- The `0x2AF648`/`0x235E08`/`0x37C034`/`0x37B82C` contracts are inferred from
  their use here and a partial disassembly; their full semantics are not
  reconstructed.
- The callback target, its real argument interpretation (the `&entries[0]`
  array uses stride 8) and the `flags`/`bound` lifetime are not established.
- The candidate's internal frame layout and register allocation differ from the
  original (`bound` at `sp+0xC` vs `sp+8`); only the documented ABI inputs,
  call arguments, callback snapshots, saved registers and final object state are
  compared.
- No caller-composition, emulator or whole-game runtime equivalence is claimed.
