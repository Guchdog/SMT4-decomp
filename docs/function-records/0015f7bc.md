# Function Record: func_0015f7bc (0x0015f7bc)

## Summary
- **Address:** `0x0015f7bc`
- **Size:** 1000 bytes (238 ARM instructions plus an 8-byte literal pool)
- **File:** `src/engine/leaf_batch34_c.cpp`
- **Role:** Packed-byte edge filter over four strided 32-bit lanes.  For every
  lane it compares the words two rows up, one row up, the centre and one row
  down, then writes back only the two centre words.
- **Status:** Semantically equivalent C++ (`non_matching`). Verified with a
  Unicorn ARM differential test across 57 cases plus five negative controls.

## Contract and Behavior

### Signature and ABI
- **Signature:** `extern "C" void* func_0015f7bc(void* config)`
- `r0` points at a six-word config object; `r1`-`r3` are not read.
- **Return:** the config pointer itself. The original saves `r0` with
  `push {r0, lr}` and restores it with `pop {r0, pc}`, so the caller's `r0` is
  returned unchanged.
- **Stack/return:** `SP` is restored to its entry value (the original reserves
  20 bytes: the saved `r0`/`lr` pair, the two counters and the inner counter).
- **Callee-saved registers:** the original saves only `r0`/`lr` and therefore
  clobbers `r4`-`r11` (`r4`-`r7`, `r8`, `sb`/`r9`, `sl`/`r10`, `fp`/`r11`).
  This is an ABI violation in the pinned image. The C++ reconstruction is a
  normal AAPCS function and preserves `r4`-`r11`; the differential test checks
  that property and documents the original's divergence (the clobbered values
  are internal state, not a caller-visible contract).

### Config object (all reads are 32-bit `ldr`)
| Offset | Meaning |
|--------|---------|
| `+0x00` | never read |
| `+0x04` | absolute base address of the filtered buffer |
| `+0x08` | horizontal byte counter, consumed as `horizontal - 8` |
| `+0x0C` | vertical byte counter, consumed as `vertical - 8` |
| `+0x10` | threshold word A, prefix-OR expanded, compared against `|lower - upper|` (register `r8`) |
| `+0x14` | threshold word B, prefix-OR expanded, compared against `|above - lower|` and `|upper - below|` (register `sb`) |

The threshold expansion reproduces the two instructions
`orr rX, rX, rX, lsl #8` / `orr rX, rX, rX, lsl #16`. Because the second `orr`
uses the already-updated register, the expansion is a prefix OR per byte
(`b0`, `b0|b1`, `b0|b1|b2`, `b0|b1|b2|b3`), not a plain byte replication. This
only equals replication when the upper bytes are zero.

### Memory layout
The routine starts at `base + 0x2000`. At each 16-byte chunk, the four word
lanes at offsets `0, 4, 8, 0xC` read:

| Source | Address |
|--------|---------|
| `above` | `centre - 0x800 + lane` |
| `below` | `centre + 0x400 + lane` |
| `lower` | `centre - 0x400 + lane` |
| `upper` | `centre + lane` |

The loads occur in exactly that order (the original loads `above`, then
`below`, then `lower`, then `upper`), and only `lower` (written to
`centre - 0x400 + lane`) and `upper` (written to `centre + lane`) are stored
back. All accesses are aligned 32-bit words.

### Packed-byte arithmetic (per byte)
- `uhadd8(a,b) = (a + b) >> 1`
- `uqsub8(a,b) = max(a - b, 0)`
- `uqadd8(a,b) = min(a + b, 255)`
- `uadd8(a,b)  = (a + b) & 0xFF`
- `ssub8` stores `(a - b) & 0xFF` and sets `GE = signed(a_byte) >= signed(b_byte)`
- `sel Rd, Rn, Rm = GE ? Rn : Rm`
- Literal constants: `0x01010101` (two `uhadd8` rounding steps) and
  `0x20202020` (the `0x20` pivot).

Per lane (`above`=a, `lower`=b, `upper`=c, `below`=d):

```
mixed  = uhadd8(uhadd8(uhadd8(~d, a), 0x01010101), 0x01010101)
avg    = uhadd8(b, c)
raise  = uqsub8(mixed, 0x20202020)
drop   = uqsub8(0x20202020, mixed)
lower' = uqsub8(uqadd8(avg, raise), drop)
upper' = uqadd8(uqsub8(avg, raise), drop)
```

Three selection masks are computed with `ssub8` and consumed by `sel`:

1. `|a - b|` versus threshold B (`+0x14`),
2. `|c - d|` versus threshold B (`+0x14`),
3. `|b - c|` versus threshold A (`+0x10`).

`sel` keeps `lower`/`upper` whenever the corresponding `GE` is set. Since every
stage selects the current value when its `GE` is clear, the candidate
`lower'`/`upper'` survives only when **all three** signed comparisons are
strictly below their thresholds; otherwise the original words are left in
place. Note the comparisons are signed (`ssub8` `GE`), so differences and
threshold bytes above `0x7F` behave as negative signed bytes.

### Control flow
- **Inner loop (`0x0015F800..0x0015FA54`):** process one 16-byte chunk, then
  `inner -= 16`; continue while the signed result is `> 0`; on `< 0` leave the
  inner loop; on exactly `0` process the trailing 8 bytes (`0x0015FA58..
  0x0015FB70`), advance `8`, and leave the inner loop.
- **Outer loop (`0x0015FB74..0x0015FB90`):** `next = vertical_counter - 8`;
  `address += 0x2000 - 8`; if `next != 0`, restore the inner counter
  (`horizontal - 8`), subtract that counter from the address
  (`address -= horizontal - 8`) and repeat; otherwise return.
- The initial counter can be zero or negative; the original still executes one
  16-byte chunk before testing, which the C++ `do`-style loop reproduces.
- No direct or indirect calls and no relocations. The only literal-pool words
  are the two constants listed above.

## Unresolved Limits
- There are no helper or indirect calls, so nothing is stubbed.
- The original clobbers `r4`-`r11`; the candidate preserves them. The test
  therefore validates the candidate's AAPCS preservation rather than comparing
  two undefined post-call register values.
- The fixture layout is synthetic (deterministically generated buffer plus a
  hand-built config), not captured game memory. Field meaning beyond the
  offsets and widths above is not claimed.
- The C++ models the packed operations byte by byte rather than emitting the
  ARM SIMD instructions, so byte identity is not expected.
- No emulator or whole-game runtime session was run; equivalence is offline
  differential evidence only.
