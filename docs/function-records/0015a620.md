# Function Record: func_0015a620 (0x0015a620)

## Summary
- **Address:** `0x0015a620`
- **Size:** 416 bytes (original span `[0x0015a620, 0x0015a7c0)`): 97 ARM
  instructions `0x0015a620..0x0015a7a3` plus the seven-word literal pool at
  `0x0015a7a4..0x0015a7bf`.
- **File:** `src/engine/leaf_batch41_c.cpp`
- **Role:** Emits one 16-byte GPU command record carrying the clamped RGB bytes
  of the color quadruple at `entry+0xB4` and a flag-derived lead word, advances
  `g_GpuCommandCursor` (`0x004652a0`) by 0x10, then tail-branches to
  `ui_func_002a20a8(list, 0x17)` with the self-relative command list at
  `entry+0xC4`.
- **Classification:** `non_matching` with semantic evidence. The compiled body
  is 316 bytes versus the 416-byte original: four float literals and the cursor
  address are pooled, the `vcmp` clamp register dance and the `r2` scratch
  composition differ, but the record words, cursor update and tail branch are
  the same.

## Contract and Behavior

### Signature and ABI
```c
void func_0015a620(void* self);   // extern "C"
```
- `r0 = self` is the only live incoming register. The original reads
  `[self+0xA0]` into `r0`, overwrites `r1` with the entry pointer, and uses `r2`
  as an uninitialised scratch register (`bic r2, r2, #0xff` / `orr r2, r2, r3`).
  All four bytes of that temporary are subsequently replaced by the channel
  composition, so no bit of incoming `r2` reaches memory. Incoming `r3` is
  overwritten at `0x0015a63c`. This is a one-argument routine; the differential
  runner feeds `r1`/`r2`/`r3` junk values to confirm they are ignored.
- Result is `void`, but the tail branch leaves the helper's `r0` in the return
  register. The reconstruction performs the same tail call, so its `r0` is the
  helper's result as well.
- Prologue `push {r4,r5,r6,lr}` at `0x0015a620`; the null-state exit is
  `pop {r4,r5,r6,pc}` at `0x0015a7a0`, the other exit is
  `pop {r4,r5,r6,lr}` + `b 0x002a20a8` at `0x0015a798`/`0x0015a79c`.
  `r6` is saved but never used.

### Callers
- One direct reference: the unconditional tail branch at `0x00156700`, at the
  end of `func_00156594` (`0x00156594`, 396 B, same source file). It reaches
  this routine with `r0 = r5` (`mov r0, r5` at `0x001566f8` after
  `pop {r4,r5,r6,r7,r8,sb,sl,lr}`), i.e. `self` is that routine's `r5`. There
  are no `BL`/`BLX` call sites and no other branch targets.
- In that caller, `[r5+0xA0]` is the "current state" pointer: it is loaded as
  `r1` and compared against the table word `[[r5+0xC0] + [r7+0x29C]]`, and the
  table word is stored back with `strne`. `[r5+0xEC]` is the dirty byte that
  gates the tail branch. The reconstruction does not depend on those caller
  fields.

data effect.

### Channel conversion
For each channel `x`:
1. `0x0015a64c`-style clamp to `[0.0f, 1.0f]` (NaN passes through).
2. `s5 = 0.5f; vmla.f32 s5, x, 255.0f` — i.e. the single-rounding result of
   `0.5 + 255*x`. The pool words are `0x3F000000` (0.5f) and `0x437F0000`
   (255.0f).
3. `vcvt.u32.f32` (round toward zero) and `and #0xff`.

The fourth channel goes through the identical sequence at `0x0015a738`/
`0x0015a760`, is shifted into bits 24..31 by `orr ip, r3, r2, lsl #24`, and is
then cleared by `bic lr, ip, #0xff000000`, so the record always carries
`0x00BBGGRR`. The conversion is dead apart from VFP status flags.

### Tail call
`ui_func_002a20a8(list, 0x17)`:
- `list = [entry+0xC4] ? (u8*)&entry->rel_c4 + [entry+0xC4] : 0` — the field
  holds a self-relative pointer measured from its own address; a zero offset
  means null. `r0` is left at 0 by `mov r0, #0` at `0x0015a638` when the offset
  is zero.
- `r1 = 0x17` (`mov r1, #0x17` at `0x0015a790`).
- The original restores `r4/r5/r6/lr` before the branch, so the callee runs with
  the caller's stack pointer and return address.

`0x002A20A8` compares the pointer with `table[0x17]` (`table = 0x004E9DC8`),
stores it when different, appends the 8-byte command `{0, 0x000F00E6}` for slot
0x17 (`stmeq r6, {r3, ip}` with `ip = 0x000F01C5 - 0xDF`), advances
`g_GpuCommandCursor` by 8, and then appends the list body using the
self-relative field at `[list+0x10]` and the size at `[list+0xC]`. The
differential runner stubs this routine (see Domain Limits) and checks the
pointer and slot exactly.

## Domain Limits
- The `0x002A20A8` helper is stubbed deterministically (`bx lr` plus a return
  value derived from its arguments); its own command-stream writes and the
  `0x004E9DC8` slot table are not exercised by this test. The reconstruction
  passes exactly the pointer and slot the original passes.
- `g_GpuCommandCursor` is observed as a `u32*` bump cursor shared with
  `func_0015b1a4` (`0x0015B1A4`) and `0x002A20A8`. Its ownership, allocation
  bounds and the consumer of the records are not recovered here; neither the
  original nor the candidate guards against a null or exhausted cursor.
- The fourth channel's conversion is dead in the original (masked away). The
  compiled candidate still evaluates the same expression, but the optimiser
  drops the unused conversion, so any FPSCR exception-flag side effect of that
  single `vcvt.u32.f32` is not reproduced. No architectural register or memory
  difference was observed.
- The original converts with a fused `vmla.f32`; Clang expands the plain
  `0.5f + clamped * 255.0f` into `vmul` + `vadd`. The intermediate value
  differs in its low bit for some inputs, but an offline enumeration of every
  float in the reachable `[0, 1]` clamp domain found no difference in the
  truncated byte, and the boundary-sweep cases confirm it bit for bit against
  the original in Unicorn. NaN and infinity inputs are handled by the clamp and
  produce the same byte in both bodies.
- The exact type and ownership of the `self`, state and entry objects are not
  recovered; only the byte offsets listed above are evidence-backed. Field
  names describe roles, not original identifiers.
- The compiled candidate uses an extra `push {r4, lr}` to hold the
  `g_GpuCommandCursor` address, builds the two command headers with `mov`/`orr`
  instead of loading them, and stores `+0x0C`, `+0x04`, the cursor global,
  `+0x00`, `+0x08` in that order (the original stores `+0x0C` first and then
  `+0x00/+0x04/+0x08` before the cursor global). Final memory, registers and
  call order are identical; only a cursor that aliased the cursor global itself
  could observe the store order, which the fixtures do not exercise.
- Runtime integration (in-game rendering and command-stream consumption) was
  not exercised; this record covers offline differential equivalence only.
