# Function Record: ui_func_0025f538 (0x0025f538)

## Summary
- **Address:** `0x0025f538`
- **Size:** 436 bytes (107 ARM instructions through the unconditional `pop`,
  plus two literal words at `0x0025f6e4`: `0x0044ea00` and `0x3f800000`)
- **File:** `src/engine/leaf_batch41_c.cpp`
- **Role:** Minimap HUD overlay updater. It gates on the context object's
  visibility byte and signed state word, samples the panel's 20.12 fixed-point
  screen origin, applies the overlay scale, resolves one sprite node, draws four
  sprite overlays (`0x4B`, `0x4A`, `0x4C`, `0x4D`) offset by that node, and
  publishes two constant render layer descriptors on the overlay render stack.
- **Status:** Semantically equivalent C++ (`non_matching` in the ledger).
  Verified with a Unicorn ARM differential test across 67 cases and 15 negative
  controls.

## Contract and Behavior

### Signature and frame
```c
extern "C" u32 ui_func_0025f538(void* context);
```
- `r0` is the UI context object. The three pinned callers (`0x001e07b4`,
  `0x001e08a4`, `0x001e0be0` inside `0x001e0618`) pass the same object they hand
  to `Ui_MiniMapRender` (`0x0025f8f0`) and `0x0025f6ec`. `r1`..`r3` are dead.
- Prologue: `push {r4,r5,r6,r7,r8,sb,lr}` then `sub sp,#0xc`. Early exits:
  `add sp,#0xc; pop {r4,r5,r6,r7,r8,sb,pc}`. The main exit restores the frame,
  loads `s0 = 1.0f`, then branches to `0x002bf710` (a tail call that restores
  the overlay scale).
- Callers ignore `r0`, but the original leaves defined values there: the gate
  byte or raw gate word on the two early exits, and the return of the tail-called
  `0x002bf710` (`0x004d4680`, its float-block base) on the main path. The
  reconstruction returns them so register-level differential tests are exact.

### Gates (0x0025f548..0x0025f55c)
1. `ldrb r0,[ctx+0x3084]`; `cmp r0,#0`; `bne` to the early exit. The returned
   word is the zero-extended gate byte.
2. `ldr r0,[ctx+0x305C]`; `cmp r0,#3`; `bgt` (signed) to the early exit. Values
   `4..0x7fffffff` return with the raw word in `r0`; `0..3` and every negative
   word continue (so `0x80000000` and `0xffffffff` continue).

### Main path (0x0025f560..0x0025f6c8)
1. `record = ctx + 0x12B8`.
   `origin_x = 0x002bef7c(record)` reads `s32` at `record+0x0C` and shifts it
   arithmetically right by 12. Then `origin_y = 0x002bef70(record)` does the same
   for `record+0x10`. The order is X then Y.
2. `0x002bf710(*(f32*)(ctx+0x0CC))` in `s0` installs the scale. The original
   also leaves `ctx+0xAC` in `r0`, but that helper replaces `r0` from `s0`
   before reusing it, so it is not part of the contract.
3. The state word is **re-read** from `ctx+0x305C` after the scale helper.
   `node = 0x002bf6d0(0x15, state + 0x52)`; the bias is a raw 32-bit add. The
   helper resolves a signed index (signed divide by 1000, stride 20) and its
   result is dereferenced unconditionally.
4. The render-register base is read from `*0x0044EA00` **before** the first
   `0x002c5fa4(6, 1, 0)` command call (returns `0x16160000`). The overlay stack
   node is `base + 0x12AC`; the descriptor is stored as described below.
5. Four draws, in the order `0x4B`, `0x4A`, `0x4C`, `0x4D`:
   ```c
   0x002bf460(2, 0x15, sprite_id,
              (u32)origin_x + (s16)node[8],
              (u32)origin_y + (s16)node[0x0A],
              0x29);
   ```
   `node[8]` / `node[0x0A]` are re-read before every draw (the original is
   unrolled), so a helper that rewrites the node record is observed.
6. `*0x0044EA00` is re-read after the draws, then
   `0x002c5fa4(6, 7, 0)` (returns `0x76760000`) is stored into
   `new_base + 0x12AC`. A helper that rewrites `0x0044EA00` is therefore seen by
   the second store, while the first store keeps the base captured for it.
7. Tail: `s0 = 1.0f`; branch to `0x002bf710`.

### Overlay render-stack node (`*0x0044EA00 + 0x12AC`)
| Offset | Width | Meaning |
| --- | --- | --- |
| `+0x00` | u32 | slot index (no bounds check) |
| `+0x04` | u32 | unobserved |
| `+0x08 + index*4` | u32 | slot value |
| `+0x18` | u8 | dirty flag |
| `+0x1C` | u32 | flush callback (`blx`) |

Store rule (used for both descriptors):
```c
previous = slot[index];
slot[index] = value;
if (dirty != 0 || previous != value) {
    result = callback(value);   // r0 = value; no null check
    dirty = 0;                  // cleared after the callback
}
```
With no callback, `r0` keeps `value`; after a callback it keeps the callback's
return. This node layout matches the reconstructed siblings at `0x002f4804` and
`0x002e03ec` (which use `+0x124C`); `+0x12AC` is a separate overlay stack.

## Limits
- All six callees are stubbed by contract. Their real bodies (node-table walk,
  descriptor dispatch, render-state writes) are not exercised; only the
  arguments, call order, stack arguments, indirect targets and memory effects
  produced by the stubs are compared.
- A null `0x002bf6d0` result is not a supported input: the original loads
  `ldrsh [node,#8]` unconditionally, so both implementations fault. The same
  applies to a null flush callback (`blx` without a null test).
- The field semantics of the `+0x12B8` record, the `+0x305C` state and the
  `+0x3084` byte are unknown beyond the observed widths and comparisons.
- The candidate's bytes differ (452 vs 436) because the compiler additionally
  saves `sl`/`fp`, recomputes the `+0x12AC`/`+0x12B4` offsets and emits a
  PC-relative literal; the ledger classification is `non_matching`.
- No emulator/runtime verification was performed for this batch; the evidence is
  offline differential emulation with stubbed callees.
