# Function Record: script_vm_func_00275ca0 (0x00275ca0)

## Summary
- **Address:** `0x00275ca0`
- **Size:** 408 bytes (original span `[0x00275ca0, 0x00275e38)`; 99 ARM
  instructions plus the 12-byte literal pool at `0x00275e2c`: `0x004474d8`,
  `1.0f`, `0.0f`)
- **File:** `src/engine/leaf_batch41_c.cpp`
- **Classification:** `non_matching` with semantic evidence (compiled body is
  288 bytes versus 408 original bytes; register allocation and the literal pool
  differ)
- **Role:** Applies the work object's active flag to its two model slots by
  mirroring a "hidden" bit into each model's visual node and forwarding the
  matching volume scale to two audio helpers.

## Contract and Behavior

### Signature and ABI
```c
void script_vm_func_00275ca0(void);   // no arguments, void result
```
- The prologue saves `r4`, `r5`, `r6` and `lr`, then `vpush {d8}`. `r5 = 1` and
  `r6 = 0` supply the visible byte values; `s16 = 1.0f` and `s17 = 0.0f` supply
  the volume arguments (literal pool `0x00275e2c..0x00275e37`). Both `d8` and
  the saved registers are restored on every exit.
- `r0` at return is incidental: it is either the second model pointer or the
  helper's residual value, and all four static callers overwrite `r0`
  immediately. The differential test therefore does not treat `r0` as part of
  the contract (it still records it for diagnostics).

### Pointer chain and fields
| Access | Meaning in this record |
| --- | --- |
| `*(u32*)0x004474d8` | work object (`root`) |
| `root + 0x0a` (`ldrb`) | active byte; non-zero requests visible models |
| `root + 0x0c` (`ldr`) | first model slot (`model_0c`) |
| `root + 0x10` (`ldr`) | second model slot (`model_10`) |

| `visual node + 0x1f6` (`strb`) | visible byte: 1 shown, 0 hidden |

The global pointer at `0x004474d8` and the model/backend fields are re-read
after every helper call. The test exercises this explicitly by having a helper
rewrite the work pointer, a model slot, or a backend between the two calls.

### Branch behavior (per slot, first `+0x0c` then `+0x10`)
1. If the model pointer is null, nothing happens and the next slot is tried.
2. `root->active != 0`:
   - if `flags & 2` is set, clear bit 1, store visible `= 1`, then call
     `0x0029bdb4(backend, 1.0f)` and `0x0028c8d0(backend, 1.0f)`;
   - if the model is already visible, no store and no call.
3. `root->active == 0`:
   - if `flags & 2` is clear, set bit 1, store visible `= 0`, then call both
     helpers with `0.0f`;
   - if the model is already hidden, no store and no call.
4. Only bit 1 of the flags word changes; the remaining 31 bits are preserved.
   The flag store is a 32-bit `str`; the visible store is a single byte.

The only other differences between the two halves are the slot offset and the
second half's final helper call, which the original reaches after `vpop {d8}`
and `pop {r4,r5,r6,lr}` and therefore performs as a tail branch
(`b 0x0028c8d0`).

Both helpers are existing raw-ARM bodies; the volume argument is passed in
`s0` (AAPCS VFP variant). No indirect calls.

  stack, the 0x004474d8 slot page and the full contents of all fourteen data

- Result: 43/43 differential cases passed; all ten mutants were detected.

## Domain Limits
- Both callees are stubbed. Their real bodies (volume notification and volume
  set) are not executed; no audio, persistence or task side effect of those
  helpers is exercised.
- The field roles (`active`, hidden bit, visual node visible byte, backend) are
  inferred from the ARM operand widths and from the same pointer pattern in the
  reviewed H4 player-visibility work (`docs/agent-work/h4-player-transform-contract.md`)
  and the `0x002d5780` volume helper record. The object's remaining fields and
  its exact engine type are not established.
- The test uses synthetic RAM for every object and a synthetic global slot at
  `0x004474d8`. No full game or emulator run was performed, and no canonical
  full build was run.
- `r0` on return is not compared because the routine is `void` and no caller
  observes it.
