# Function Record: func_0013d460 (0x0013d460)

## Summary
- **Address:** `0x0013d460`
- **Size:** 1240 bytes (310 ARM instructions, no literal pool; the next function
  starts at `0x0013d938`)
- **File:** `src/engine/leaf_batch34_c.cpp`
- **Role:** Advance the shared draw-layout cursor past the remaining regions of
  one packed descriptor: a 32-byte-aligned preamble, three header/word-run
  pairs, five count-derived reservations, an optional range span or entry walk,
  and a typed-entry walk that calls two layout helpers.
- **Status:** Semantically equivalent C++ (`non_matching`, 832 bytes versus
  1240). Verified with a 147-case Unicorn ARM differential test plus eight
  detected negative controls. No byte-identity claim.

## Contract and Behavior

### Signature and ABI
- `extern "C" u32 func_0013d460(LayoutStream* stream, PacketWords* packed,
  LayoutRequest* request)` — `r0` = stream, `r1` = packed, `r2` = request.
- `r3` and the incoming `ip` (`r12`) word are never read. The `r4` byte-shuffle
  at `0x0013D480..0x0013D4A8` only re-extracts bits 8..15 of `request+0x00`;
  the clear/orr with the incoming `ip` cannot reach that byte, so `ip` is dead.
  This was confirmed by running the original with `ip = 0xA5A5A5A5`.
- The frame is `push {r4, r5, r6, r7, r8, sb, sl, fp, lr}` plus a 12-byte local
  area; the two stack words are private scratch and are not observable.
- Every exit runs through `0x0013D8E4`, which rebuilds `r0` from the final
  cursor, so `r0` at the `pop {..., pc}` is the stored `stream->cursor` on every
  path. The sole caller, `bl 0x0013d460` at `0x0012B66C` inside the builder at
  `0x0012B638`, discards it. Returning that cursor is therefore faithful but not
  a caller-visible contract.
- Two direct calls, both `bl`:
  - `0x0014B6C0` at `0x0013D760`, arguments `(stream, entry, marker, word_10)`
    with `marker = (word_10 != 0)`. `r3` is live here (the callee tests its low
    bit at `0x0014B73C`).
  - `0x002B43B0` at `0x0013D8AC`, arguments `(stream, entry, s8(1))`. The
    original builds `ip = (stale & ~0xFF) | 1` and passes `sxtb(ip)` in `r2`,
    which is always `1`; its `r3` input is dead (the callee overwrites `r3` with
    `[r1+0x18]` at `0x002B43BC`), so no fourth argument is modelled.
- No indirect calls, no stack arguments, no caller-visible globals.

### Memory layout (offsets only, as evidenced by the ARM)
- `stream+0x00` cursor; `stream+0x04` alignment unit; `stream+0x08`
  high-water alignment mark. All three are read/written with 32-bit accesses.
- `request+0x00` flags word (only the signed byte at bits 8..15 is observed);
  `+0x04` count_04; `+0x08` preamble stride; `+0x0C` per-entry stride for the
  block-C run; `+0x10` word_10; `+0x14` range pointer/word; `+0x18` unused;
  `+0x1C` count_1C.
- `packed+0x28` signed typed-entry count; `+0x2C` self-relative typed-list word;
  `+0xB4` count n; `+0xBC` signed range-list count; `+0xC0` self-relative
  range-list word; `+0xCC` count m.
- `range+0x164` begin word, `range+0x168` end word (only when `range_14 != 0`).

### Reservation primitive
`cursor = (cursor + unit - 1) & ~(unit - 1) + size`, all 32-bit modular. The
original reloads both stream words before every step, so a helper that advances
the cursor is observed. A zero unit makes `~(unit-1)` zero, so every reservation
floors the cursor to zero; this is preserved literally rather than assuming a
power of two.

3. `0x0013D544..0x0013D5B4`: when `selector != 0` (signed byte at bits 8..15),

4. `0x0013D5B8..0x0013D5F8`: the same `0x14` / `4*count_04` pair again.
5. `0x0013D5FC..0x0013D68C`: five unconditional reservations,

### Entry resolution and signedness
- Both walks use the same self-relative rule: `base = owner + field + [owner +
  field]`, with a zero displacement yielding "none"; `entry = base + i*0x10`;
  `target = entry + 0x28 + [entry + 0x28]`, with a zero inner word yielding
  "none".
- The range walk forwards a null target to `0x0014B6C0` (which accepts null).
- The typed walk dereferences the null target at `+0x0C`; the original faults at
  address `0x0C` and this reconstruction reproduces that read. The resolvent and
  type word are handled as integer addresses behind a volatile accessor so the
  compiler cannot exploit the original's null-dereference undefined behaviour to
  delete the zero checks (this was observed with a plain pointer form: the
  zero-entry branch disappeared).
- The lists and both loop bounds are re-read at the places the ARM does: the
  range list owner word is reloaded on every iteration; both entry counts are
  latched once at their loop entry (signed `blt` / `bgt`); `request+0x1C` is
  reloaded for each of the final two reservations.

## Validation
- `python tools/test_leaf_0013d460.py` — 147/147 differential cases plus eight
  detected mutants. `python -m py_compile tools/test_leaf_0013d460.py` passes.
- Two independent Unicorn ARM machines run the pinned original and the relocated
  candidate with identical fixtures. `0x0014B6C0` and `0x002B43B0` are
  deterministic stubs at their real addresses; the first logs `r0`-`r3`
  (including the live `word_10`) and the second logs `r0`-`r2` (its `r3` is
  dead). Both can advance `stream->cursor` or rewrite their list owner between
  iterations.
- Compared: `r0` (final cursor), continuation PC, final SP, callee-saved
  `r4`-`r11`, the ordered call log, the complete stream/packed/request/range
  pages, and all non-stack writes.
- Coverage: selector bytes zero, positive and negative; `count_04` zero and
  non-zero with and without a range; the block-C gate with `count_28` zero,
  positive, negative and `0x80000000`/`0xFFFFFFFF`; both stride words at
  `0`, `1`, `2`, `3`, `0x40000000` and `0xFFFFFFFF`; range spans flat, unaligned,
  negative and wrap-around; both entry walks with null owners, null inner words,
  type words `2`/`3` versus all other values, and cursor/owner mutations by the
  helpers; alignment units `0`, `1`, `2`, `3`, `4`, `8`, `16`, `0x20`, `0x40`
  and `0xFFFFFFFE`; cursors at `0`, small values, `0x7FFFFFFF`, `0xFFFFFFE0`,

## Frame and unresolved limits
- `0x0014B6C0` and `0x002B43B0` are stubbed; their real bodies are separate
  ledger rows (`0x0014B6C0` currently a 1120-byte naked block, `0x002B43B0` a
  164-byte naked block in `src/engine/leaf_batch14_b.cpp`). The stubs model only
  the cursor writes and list-owner rewrites this body can observe.
- The original leaves the final cursor in `r0`; the caller at `0x0012B66C`
  ignores it. A caller that consumed `r0` would be relying on incidental
  register state, not a documented return value.
- A null `packed` faults in both bodies (first at `+0x28` when the selector is
  non-zero, otherwise at `+0xB4`); this invalid-input domain is not part of the
  supported fixture set.
- The original keeps `r8 = request+0x0C` and the `r4` byte shuffle live for the
  block-C multiply; a malformed request whose `+0x0C` aliases `+0x00`/`+0x08`
  would not be distinguishable from the compiler's reordering of these dead
  reads. Disjoint request fields are the supported contract.
- No emulator or whole-game runtime scenario was run; this record covers the
  offline differential contract only.
