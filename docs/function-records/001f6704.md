# Function Record: ui_func_001f6704 (0x001F6704)

## Summary

- **Address:** `0x001F6704`
- **Ledger span:** 420 bytes, `[0x001F6704, 0x001F68A8)` (396 code bytes, 99 ARM
  instructions through the unconditional `pop`, plus the six literal words at
  `0x001F6890..0x001F68A7`).
- **File:** `src/engine/leaf_batch41_c.cpp`
- **Role:** Draws one effect made of a centre point sprite plus a closed
  19-vertex ring, both inside the render-stack push/pop bracket. The colour and
  the two xy endpoints come from a 0x24-byte sub-object owned by an effect
  instance; the ring radius is half the x distance between the endpoints and the
  ring is centred on their midpoint.
- **Status:** Reconstructed as readable C++ and semantically verified against
  the pinned original with a differential Unicorn harness. The ledger row is
  `non_matching`: the compiled candidate is 416 bytes (104 words) and, apart
  from one literal word, every word differs from the pinned encoding, so the
  row keeps the non-matching classification and this record carries the
  semantic evidence.

## Contract and ABI

```c
extern "C" u32 ui_func_001f6704(void* object);
```

- `r0` is the only live argument: a pointer to the 0x24-byte draw-state
  sub-object. `r1..r3` and `s0..s15` are dead on entry (the first instruction
  that touches `r1` is the `ldrb` at `0x001F6718`).
- The sub-object layout read by this routine:

  | Offset | Width | Meaning |
  | --- | --- | --- |
  | `+0x0C..+0x0F` | 4 × `u8` | RGBA quad, in that byte order in memory |
  | `+0x14` / `+0x18` | `f32` | first endpoint x / y |
  | `+0x1C` / `+0x20` | `f32` | second endpoint x / y |

  Nothing else in the object is read and the object is never written.
- **Return:** the render-stack pop result: the new stack top, or the result of
  the node's flush callback when the callback ran. The only caller
  (`0x002C7288`) reaches this routine with a tail branch, so the value becomes
  that caller's return value in `r0`. Callers of *that* function are not
  resolved (see below), so whether the game observes it is unknown.
- Callee-saved `r4-r8` and `s16-s23` (d8-d11) are preserved by the prologue
  `push {r4, r5, r6, r7, r8, sb, sl, lr}` / `vpush {d8, d9, d10, d11}` and
  restored before the `pop {..., pc}`; final `SP` equals entry `SP`. No stack
  arguments. One indirect call type: the render-stack flush callback (`blx r1`),
  which the original never null-checks.

## Execution order

1. **Colour** (before any helper runs):
   - `word = *(u32*)(object + 0x0C)`; `b = *(u8*)(object + 0x0F)`.
   - `color = (bswap32(word) & 0xFFFFFF00) | b`. Because `b` is the byte that
     becomes the low byte after the byte swap, the mask/OR pair is redundant and
     the value is exactly `bswap32(word)`, i.e. `R << 24 | G << 16 | B << 8 | A`
     for the memory bytes `R, G, B, A`.
   - `ring_color = color & 0xFFFFFF00` (`bic r7, r6, #0xff`), the alpha byte
     cleared.
2. `ui_func_002c1d3c(*(u32*)0x0044EA00, 0)` selects render mode 0.
3. **Push**: the base is re-read from `0x0044EA00` *after* the render-mode call
   and before the command-word helper. `pushed = ui_func_002c5f7c(1, 0)`
   (the real helper builds `0x0F10` for `(1, 0)`).
   - `node = base + 0x124C`; `previous = node->slots[node->count]`;
     `node->count += 1`; `node->slots[node->count] = pushed`.
   - If `node->dirty != 0 || previous != pushed`, call the node's `+0x1C`
     callback with `pushed` in `r0` and clear `node->dirty`. The callback result
     is dead (the next instruction overwrites `r0`).
4. **Geometry** (loaded only *after* the push callback):
   `dx = to_x - from_x`, `dy = to_y - from_y`, `mid = from + d * 0.5`,
   `radius = dx * 0.5`. Each step is one rounded VFP operation
   (`vsub`/`vmla`/`vmul`).
5. `func_0025760c()` — queue flush. The wrapper sets `r0 = 2` and tail branches
   to `0x002B03B8`, which builds a 0x34-byte packet (`[0] = 2 << 8`) and
   submits it through `0x002ADE34`. The caller's registers are dead.
6. `ui_func_002575fc(color, mid_x, mid_y, 0.0f)` — centre sprite. The wrapper
   loads `s3 = s4 = 0.0f` and tail branches to `0x002B0208`; `r0` is the
   colour and `s0..s2` the position.
7. **Ring loop**, 19 iterations (`mov r4, #0`; `cmp r4, #0x13`; `blt`, signed):
   ```
   angle  = ((f32)i * 2*pi) * (1/18) * (128/pi)
   sine   = ui_func_002b73a4(angle)     // 0x002B73A4, table sine
   cosine = ui_func_002b740c(angle)     // 0x002B740C, table cosine
   ui_func_002575fc(ring_color, mid_x + radius * sine,
                    mid_y + radius * cosine, 0.0f)
   ```
   `2*pi = 0x40C90FDB`, `1/18 = 0x3D638E39`, `128/pi = 0x4222F983` (literal pool
   at `0x001F689C..0x001F68A7`); `0.5f = 0x3F000000` and `0.0f` are the other
   two float literals. The two table helpers take their argument in units of one
   table step (256 steps per turn), which is why the caller multiplies by
   `128/pi`; `i = 18` closes the ring. The angle product chain is re-evaluated
   before the cosine call in the ARM code; the reconstruction computes it once,
   which is bit-identical because the operation sequence and rounding are the
   same.
8. `ui_func_0025b988()` — second queue flush. Four-byte wrapper, a tail branch
   to `0x002B80D4` inside `ui_func_002b8070`; no live arguments, result
   discarded.
9. **Pop**: `0x0044EA00` is re-read a third time.
   `previous = slots[count]`; `count -= 1`; `new_top = slots[count - 1]` (flat,
   unchecked addressing, so a zero count reads `node + 4`); the same callback
   rule applies. The callback result, or `new_top`, is returned.

The three independent reads of `0x0044EA00` are observable: a helper that
rewrites the global changes the base used by the *next* step only.

## Verification

Tool: `tools/test_leaf_001f6704.py`

Command:

```text
python tools/test_leaf_001f6704.py
```

Result: **41/41 differential cases pass**, plus **11/11 negative controls** are
detected. `python -m py_compile tools/test_leaf_001f6704.py` passes. The test
compiles `src/engine/leaf_batch41_c.cpp` with the pinned ARMv6K flags, extracts
`ui_func_001f6704` (416-byte candidate body), patches its seven `R_ARM_CALL`
relocations to deterministic stubs at the original addresses and its
`R_ARM_ABS32` reference to `g_RenderRegisterBase` back to `0x0044EA00`, then
runs the pinned original (`extracted/exefs/code.bin`) and the candidate on
separate Unicorn machines with identical fixtures.

Compared state per case:

- return `r0`, continuation `PC` (`TRAP`), final `SP`, callee-saved `r4-r11` and
  VFP `d8-d15`;
- the ordered call log: render mode `(base, mode)`, push `(kind, enabled)`, the
  bare `func_0025760c` call, every `ui_func_002575fc` call with the colour in
  `r0` and the x/y/z arguments as raw bit patterns, both table-trigonometry
  inputs, the bare `ui_func_0025b988` call, and each indirect flush callback
  (`target, value`);
- the full 2.0625 MiB data region (render global, both render-stack node pages,
  the parameter object and its fill bytes) and the ordered list of writes
  outside the private stack;
- an independent Python model of the push/draw/ring/pop sequence (including its
  own render-stack bookkeeping) that asserts the original's call log, `r0`, both
  node images, the final render base and the object image.

Coverage: node counts 0..3 (including the flat out-of-bounds slot access at
count 3), dirty cleared/set, no flush, push-only flush, pop-only flush, both
flushes, two indirect callback targets, a callback that switches the render
global, render-mode and push helpers that switch it, a push helper that rewrites
the parameter object (the original reads the colour *before* and the endpoints
*after* the push), push values `0`/`0x1F51`/`0xFFFFFFFF`, every RGBA byte
combination boundary, endpoint payloads including signed zero, smallest normals,
subnormals, `+/-FLT_MAX`, `+/-inf` and NaN, equal endpoints (zero radius),
symmetric deltas `0`, `1e-30`, `+/-1e30`, and junk `r0-r3`/`s0-s15`.

Float log arguments are compared as raw bit patterns with one documented
exception: when an endpoint is NaN, the original's `vmla.f32` (destination
register = addend) and clang's `vmul` + `vadd` sequence select different NaN
payloads. The test canonicalises NaN payloads in the float argument slots only;
NaN-ness, signed zero, subnormals, infinities, every finite value and every
integer argument remain exact.

Negative controls mutate the ring segment count (19 -> 18), the three angle
literals (each to the next representable float), the alpha mask, the render
stack offset, the push kind, the endpoint field selection and the `0.5f` scale,
flip the pop flush condition from `||` to `&&`, and hoist the endpoint loads
above the helper calls; each mutant is detected.

## Known differences from the pinned encoding

- Candidate 416 bytes vs 420: clang allocates 4 bytes of stack and saves
  `d8-d15` instead of the original's `d8-d11`, and schedules the midpoint as
  `vmul` + `vadd` (product first) rather than `vmul` + `vmla` (addend first).
- The loop counter converts with `vcvt.f32.u32` where the original uses
  `vcvt.f32.s32`; the index is always 0..18, so the two conversions agree.
- These are instruction-selection differences; the differential test shows
  identical behaviour for every defined input.

## Unresolved and limits

- The seven direct dependencies (`0x002C1D3C`, `0x002C5F7C`, `0x0025760C` ->
  `0x002B03B8` -> `0x002ADE34`, `0x002575FC` -> `0x002B0208`,
  `0x002B73A4`/`0x002B740C` table trigonometry, `0x0025B988` -> `0x002B80D4`)
  are not reconstructed here. The test stubs them deterministically and logs
  their inputs; the batch packet built by `0x002B03B8`, the sprite submission in
  `0x002B0208` and the table contents behind `0x002B73A4`/`0x002B740C` are
  outside this row. `ui_func_002c1d3c` is itself a `non_matching` reconstruction
  in `leaf_batch31_c.cpp`.
- The table-sine contract (argument in 256-steps-per-turn units) is inferred
  from the callee's `vcvt`/`& 0xff` interpolation, not from a producer.
- The render-stack flush callback target is data-driven and was not traced to
  a real function; the test supplies two deterministic ARM stubs. Whether any
  production node uses a null callback is unknown (the original would branch to
  address 0).
- The caller chain above `0x002C7288` is unresolved: no direct reference exists
  in `code.bin`, only the descriptor literal at `0x004724BC`. Natural caller
  reachability and scheduler parity are therefore not proven.
- Stack arguments: none. Register leftovers passed to the two no-argument
  wrappers (`r0`/`r1..r3`) are dead in the callees and are not compared.
- No emulator launch was performed; the evidence is offline differential
  emulation only. This does not prove whole-game equivalence.
