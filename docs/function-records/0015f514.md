# Function Record: func_0015f514 (0x0015F514)

## Summary
- **Address:** `0x0015F514`
- **Size:** 448 bytes (span `[0x0015F514, 0x0015F6D4)`). The last two words are
  the literal pool: `0x0015F6CC = 0x92492493` (used by the `smlal` at
  `0x0015F5B8`) and `0x0015F6D0 = 0x0000131A` (the base-relative selector
  offset). The last instruction is the `pop` at `0x0015F6C8`.
- **File:** `src/engine/leaf_batch34_c.cpp`
- **Role:** Validates one source record's start address and flag-driven stride,
  computes the resulting end address, and publishes it (plus a six-byte payload
  copy and two status bits) into the per-channel descriptor reached through the
  base object's `+0x1000` table. Returns 1 when the descriptor was filled and 0
  when either address window rejects the record.
- **Status:** Reconstructed as readable C++ and **differentially verified**
  against the pinned original. The candidate body is 436 bytes and is not
  byte-identical, so the ledger row is `non_matching` and this record carries
  the semantic evidence.

## Contract and Behavior

### Signature and ABI
```c
extern "C" u32 func_0015f514(u8* base, u32 index,
                             const ChannelRecord* record, u32 flags);
```
- `r0 = base`: base object pointer. The sole caller passes the literal
  `0x004E6F64` (`0x0015F2B4`); this body reads `u16` at `base + 0x131A` and the
  slot pointer at `base + 0x1000 + ... + 0xB0`.
- `r1 = index`: 32-bit index; used only as `index * 4` inside the table walk
  (`add r3, r3, r7, lsl #2`, `0x0015F5F4`). The caller passes the low byte of its
  own `+0x00` word (`and r1, r0, #0xff`, `0x0015F29C`), but this body never
  narrows it.
- `r2 = record`: source record pointer (caller's node).
- `r3 = flags`: 32-bit word whose **low 16 bits only** are used. The original
  spills it with the register push and reads `[sp+0xC]` three times: `uxth`
  (`0x0015F550`), `ldrh` (`0x0015F614`) and `ldrh` (`0x0015F634`), all of which
  zero-extend.
- **Return value:** `1` on the success path (`mov r0, #1`, `0x0015F6BC`) and `0`
  on every rejection path (`0x0015F694 mov r0,#0`; the helper-equal path keeps
  the helper's zero in `r0`). The caller ignores it; it is compared by the
  differential test because the values are well defined.
- Callee-saved registers are preserved: the body pushes
  `{r0,r1,r2,r3,r4-r8,sb,sl,lr}` (48 bytes), discards the four spilled argument
  words with `add sp, sp, #0x10` and pops `{r4-r8,sb,sl,pc}`. `sb` holds the
  0x92492493 reciprocal and `sl`/`r11` are never touched. Final SP equals entry
  SP.

Details pinned by the ARM encoding:
- The start-address check is unsigned (`add r0,r5,#0xEC000000` then `bhs`), i.e.
  `address` must be in `[0x14000000, 0x1C000000)`.
- The end-address check is **asymmetric**: `bls` against `0x14000000` (low bound
  exclusive) and `bhi` against `0x1C000000` (high bound inclusive). The test
  pins `end == 0x14000000` (rejected), `end == 0x14000001` (accepted),
  `end == 0x1C000000` (accepted) and `end == 0x1C000001` (rejected).
- `family == 0, count == 2` adds **two** strides, not three: the
  `addeq r3, r5, r2` at `0x0015F564` is conditional on `count == 1`, so the
  `count == 2` path starts from `r3 = address` and only executes
  `addeq r3, r3, r2, lsl #1`. (The differential test caught this.)
- The `family == 2 && count == 1` scale is the `smlal ip, r0, sb, r0` idiom at
  `0x0015F5B8`, which is architecturally the sequence
  `acc = (s64)(s32)(stride + 13) * (s64)(s32)0x92492493 + (u64)(stride + 13) << 32`,
  followed by `asr ip, r0, #3` and `sub r0, ip, r0, asr #31`. The effective step
  is four sevenths of `(stride + 13)` rounded down to eight-byte units. The
  reconstruction reproduces the 64-bit arithmetic verbatim; for numerators
  below `0x80000000` it equals `floor((stride + 13) / 14) * 8`.
- `flags` is truncated to 16 bits before both the selector fields and the
  `+0xB4` store.
- The `+0xBC` halfword is a read-modify-write in both places, and the bit-1
  source is `2 & (s8 << 1)`, i.e. bit 0 of the signed byte at `record+0x10`.
- `record+0x08` is loaded twice (`0x0015F644`, `0x0015F67C`) and `record+0x10`
  is loaded at `0x0015F61C`, i.e. **after** the `+0xBE` store. Both loads are
  preserved; the candidate needs a compiler memory barrier because the record
  and the descriptor may overlap (the test's alias fixtures place the
  descriptor at `record-0xAE`, so the six-byte copy overwrites `record+0x08`
  and the `+0xBE` store overwrites `record+0x10`).
- The six-byte copy is a peeled `do/while`: reads `payload+0`, stores `+0xB6`;
  reads `payload+2`, stores `+0xB8`; reads `payload+4`, stores `+0xBA`. It is
  reproduced as a three-iteration halfword loop, so the read/store interleaving
  (observable for overlapping source and destination) is preserved.
- The two ror-16 stores are true 16-bit rotations of the 32-bit values
  (`ror r2, r2, #0x10`, `ror r3, r0, #0x10`), not byte swaps of the halves.
- The descriptor control word is ORed with `0x40000000 | 0x00200000` in two
  steps and stored as one word (`str r0, [r5], #0xa4`), then `0` is stored at
  `descriptor+0xA4` with `lr`, which was set to zero by `mov lr, #0` at
  `0x0015F5A4` (the only other `lr` write is the `bl` return address, which is
  overwritten there).

## Domain Limits
- `0x002BB5B4` is stubbed by address, so the global signed byte it reads
  (`0x0044E459`) is not exercised. The stub models it as "0 rejects, any other
  value proceeds", which is what the branch tests.
- The `smlal ip, r0, sb, r0` at `0x0015F5B8` has `RdHi == Rm == r0` and is
  architecturally UNPREDICTABLE on ARM. The traced semantics (verified against
  the pinned image in Unicorn for positive, negative and boundary numerators)
  is a signed 32x32 product accumulated over the numerator placed in the high
  word, i.e. the 64-bit product of the numerator and `0x92492493`. The
  reconstruction reproduces that arithmetic exactly; real-hardware behaviour for
  the unpredictable case is not independently verified here.
- The `high < 0` branch of the scale (`sub r0, ip, r0, asr #31`) is transcribed
  but has no observable effect: a negative high word always yields units
  `>= 0xF0000001`, so the scaled step is `>= 0x80000000` and the end address
  always falls above `0x1C000000` (the addition cannot wrap back into the
  window). No differential case can distinguish it.
- The record and the descriptor are data-driven pointers, so nothing prevents
  them from overlapping; the alias fixtures cover the two overlaps produced by
  `descriptor == record - 0xAE`, but arbitrary partial overlaps of the
  `+0xAC/+0xB0/+0xB4` stores with the record's `+0x00/+0x04` fields are not
  enumerated.
- `index` is used without narrowing; the caller only supplies a byte, and the
  fixtures stay inside the mapped base page, so an out-of-range index in
  production would read an unrelated slot (as the original does).
- No runtime, staging or production promotion is claimed.
