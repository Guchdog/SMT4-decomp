## Reconstruction

`camp_func_002bf6d0` in [`leaf_batch27_b.cpp`](../../src/engine/leaf_batch27_b.cpp) accepts a group ID and a raw 32-bit node index. It calls the original `ui_func_002b0188(group)`, reads a pointer at manager `+4`, reads the base pointer at that indirect address, interprets the index as signed `s32`, takes its C++ remainder modulo 1000 (truncation toward zero), and returns `base + remainder * 20` with 32-bit address wraparound.

The helper assumes all three pointer levels are readable. It does not validate a null manager, indirect pointer, or base. The tested ABI preserves `r4-r11` and SP and has no non-stack writes. The original spills eight stack bytes while the candidate spills sixteen; the differential filters each function's stack scratch and compares external effects. The body is 64 bytes with one `R_ARM_CALL` relocation to `0x002B0188`. It differs from the original bytes, so the ledger classification is `non_matching`.

## Contract limits

The accepted arithmetic domain is every 32-bit index, but pointer dereferences require a valid readable manager chain and a 32-bit address space consistent with the original game. The tested group IDs are representative fixtures, not an exhaustive group domain. Stack scratch bytes are excluded from memory-effect equality because the original and C++ use different spill sizes. No claim is made for invalid pointers, caller composition, runtime reachability, or the H2 scenario as a whole.
