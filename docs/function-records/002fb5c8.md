## Contract and ABI

```c
extern "C" s32 engine_func_002fb5c8(void* resource);
```

- `r0` (`resource`, held in `sl`) is the model/resource object. `r1..r3` are not
  read. There are no stack arguments. The prologue saves
  `{r4,r5,r6,r7,r8,sb,sl,fp,lr}` and the epilogue restores the same set, so
  `r4-r11` and `sp` survive.
- Return value: `1` on completion, `0` from either global gate. The literal is
  loaded into `r0` by the gate branches, so the returned zero is the loaded
  zero.
- Two entry gates read the process-wide manager at `0x00464AF0`:
  byte `+0x01` must be non-zero and the pointer at `+0x80` must be non-zero.
  The `+0x80` pointer is only tested, never dereferenced in this span.
- No null guard exists for `resource` after the gates. A null resource makes the
  first type match fail (no vtable call), after which the loop reads
  `0x164`/`0x168` through address zero, exactly like the original.

## Behavior

```text
if (manager->flag_01 == 0) return 0;
if (*(u32*)(manager + 0x80) == 0) return 0;

model = type_match(resource, 0x00472180);   // resource or 0
for (s32 index = 0; ; ++index) {
    begin = *(u32*)(model + 0x164);
    end   = *(u32*)(model + 0x168);
    if (!(index < (s32)(end - begin) >> 2)) break;   // signed compare
    element    = ((u32*)begin)[index];
    descriptor = *(u32*)(element + 0x08);
    table      = relptr(descriptor + 0x14);          // zero -> 0
    value      = 0;
    if (table != 0) {
        len      = engine_002c3290("shadow");
        found    = engine_002c31e8(&table, "shadow", len);
        if (found) value = relptr((u8*)found + 0x0C); // zero -> 0
    }
    if (value != 0) {
        tag  = *(u32*)value;
        base = (tag & 0x20000000) ? value : 0;        // tag-clear -> base 0
        kind = *(s32*)(base + 0x10);                  // latent low read
        if (kind <= 0) {
            if (manager->flag_01) engine_002a34a4(element, 1, mgr_float_0x60);
            continue;                                 // no status store
        }
        if (kind == 2) {
            if (manager->flag_01) engine_002a34a4(element, 1, mgr_float_0x64);
        }
        status_object = type_match(resource, 0x00472288);  // resource or 0
        *(u32*)(status_object + 0x21C) = 1;               // 0x21C if no match
    }
}
return 1;
```

Details preserved from the ARM:

- The loop bound and the vector pointers are re-read from memory every
  iteration, so a helper that changes `model+0x164/+0x168` changes termination.
  The count is the arithmetic shift of the raw 32-bit subtraction and the
  comparison is signed (`blt`/`bge`).
- The relative pointers are `field_address + offset` with a zero offset
  resolving to address 0. The value tag check is `tst`/`moveq`, so a clear
  `0x20000000` bit makes the base zero and the kind is read from address
  `0x10`; it is not an empty-property fallback.
- `kind` is signed: `<= 0` uses the `0x00464AF0+0x60` weight and skips the
  status store; `== 2` uses `+0x64` and then stores the status; other positive
  kinds skip the setter and still store the status.
- Manager byte `+0x01` is re-read before each setter call. The status store does
  not consult it.
- The original materialises the status word through a byte stack local; with a
  zeroed stack that word is `0x00000001`. The reconstruction stores `1`.

## Type-chain idiom

Each `type_match` mirrors:

```text
ldr r0,[obj]; ldr r1,[r0,#8]; mov r0,obj; blx r1
loop: cmp r0,type; beq match
      ldr r0,[r0]; cmp r0,#0; bne loop
```

The chain is walked even when the query returns 0 (address 0 is read first and
is only checked afterwards). A matched query returns the object address;
otherwise the result is 0. The first match uses `0x00472180`, the status match
uses `0x00472288`.

## Static data and helpers

- `0x00464AF0` `+0x01` (u8 gate), `+0x80` (u32 gate), `+0x60`/`+0x64` (f32
  weights). The `+0x80` slot is the record produced by `AsdList_Init`
  (`0x0010BBAC` stores it); higher-level naming is not proven by this span.
- `0x00472180`, `0x00472288`: type-info identities compared against the vtable
  chain.
- `0x002C3290`: ARM string length (`"shadow"` -> 6). Return value feeds the
  next call's key length.
- `0x002C31E8`: Patricia name-tree lookup; `r0 = &slot` (the slot holds the
  resolved table node), `r1 = "shadow"`, `r2 = 6`; returns a node or null.
- `0x002A34A4`: mode-1 render initialisation; `r0 = element`, `r1 = 1`,
  `s0 = weight`. Its return value is not observed.
- The only indirect target is the vtable slot at `+0x08` of the receiver's
  vtable.

## Validation

`tools/test_leaf_002fb5c8.py` compiles `src/engine/leaf_batch41_c.cpp`, extracts
the 472-byte candidate body, resolves its three direct calls and its one
`.rodata` reference, and runs the pinned original against the candidate in
identical Unicorn ARM machines. It compares:

- return `r0`, continuation PC (`0x90000000` trap), final `sp` and `r4-r11`
  sentinels;
- the ordered call log: query receiver, `"shadow"` key text, key length, slot
  contents, setter element/mode/`s0` bit pattern and every stack argument;
- every fixture page (low memory, manager/type-info, model, vtable, element,
  descriptor, table, found, value, chain, rodata);
- every non-stack write, including the `+0x21C` status store and the latent
  `0x21C` store when the second type match fails.

Coverage: both gates (zero and non-zero byte forms, zero pointer), empty,
negative and one/two-element vectors, absent descriptor table, null find result,
zero found link, kinds `-0x80000000`, `-1`, `0`, `1`, `2`, `3`, `0x7FFFFFFF`,
tag bit clear with low-read kinds `5`/`-3`/`0`, first-match-only and
status-match-only chains, null-model low-vector paths, a query that returns 0, a
setter that clears the manager gate (suppressing the second setter but not the
status store), and a setter that shrinks the vector after the first element.

Negative controls mutate the tag mask, the kind offset, the status offset, the
setter mode and the `<= 0` weight field; each mutant is detected.

## Limits

- The three direct helpers are stubbed deterministically; their internal
  behaviour (including the exact Patricia layout of `0x002C31E8` and the full
  mode-1 semantics of `0x002A34A4`) is outside this span.
- The vtable query target is an indirect call. The test uses a single
  deterministic stub; real receiver vtables are not exercised.
- The gate pointer `0x00464AF0+0x80` is only tested for non-zero; its consumer
  and the full manager layout are not recovered here.
- A clear `0x20000000` tag bit leads to a read of address `0x10`, matching the
  original. That low read is intentionally reproduced and is only meaningful
  under a test mapping; on hardware it is a latent fault.
- No emulator or whole-game run was performed; evidence is offline Unicorn
  differential testing with deterministic stubs.
