# Function Record: engine_func_002e7e94 (0x002e7e94)

## Summary
- **Address:** `0x002e7e94`
- **Size:** 604 bytes (original span `[0x002e7e94, 0x002e80f0)`; the final
  word at `0x002e80ec` is the only literal, `0x00464110`, the effect-type
  table base).
- **File:** `src/engine/leaf_batch45_a.cpp`
- **Role:** `effParts` child-node destroy. Detaches `node` from the manager's
  doubly linked child list, recursively destroys the remaining alias members
  (flag `0x1` referencing the same particle), re-parents members bound through
  flag `0x2` with `0x0025C888`, releases the node's particle (type-table `+0x10`
  callback, two owned blocks, the particle itself) and finally frees the node
  through `0x002C4360`. The caller at `0x00323B58` (in
  `src/engine/leaf_batch29_c.cpp`) passes the manager from `[r4+0x14]` and the
  node returned by `0x00246A4C(manager)`.
- **Status:** Semantically equivalent C++ (`non_matching`). The compiled body is
  568 bytes versus the 604-byte original. The compiler keeps the manager and
  node in `r7`/`r4`, pushes `r11` instead of `r8`, reads the flag words through
  their low byte (`ldrb`), orders the two stage-2 stores the other way round
  (aux key before flags), and clears both low flag bits instead of only bit 1 at
  the point where the search has already proven bit 0 clear. The ledger row is
  classified `non_matching` with this record.

## Contract and Behavior

### Signature and ABI
```c
extern "C" void engine_func_002e7e94(void* manager, void* node);
```
- `manager = r0`, `node = r1`.
- Returns nothing; the original's exit `r0` is the value left by the tail call
  to `0x002C4360(node)` (`mov r0,r4`, `0x2e80e0..0x2e80e8`). The caller discards
  it. The C++ keeps the tail call, so the register still matches.
- The original saves `r4-r8` and `lr` (24 bytes) although `r8` is never
  written; the C++ compiler saves `r4-r7`, `r11` and `lr`. `r8` is preserved by
  both.

### Control flow (original PCs)
1. `0x2e7ea0..0x2e7ed0`: `next = node+0xAC`, `prev = node+0xB0` (single `ldrd`).
   `prev != null` → `prev->next = next`, else `manager+0x8C = next`.
   `next != null` → `next->prev = node->B0`, else `manager+0x88 = node->B0`.
   Then `manager+0x80 -= 1` (32-bit wrap). No other guards.
2. `0x2e7ed4`: `node+0x98 & 1` → free the node and return.
3. `0x2e7ee0..0x2e7f24`: head-first scan of `manager+0x8C` for the first member

4. `0x2e7f28..0x2e7f2c`: that member is destroyed by a recursive call
   (`bl 0x2e7e94` with `r0 = manager` and `r1` still holding the member). The
   loop then reloads the head and the particle pointer and rescans; each
   recursion removes one member, so the loop terminates.
5. `0x2e7f70`: `node+0x98 & 2` → skip the re-parent stage.
6. `0x2e7f7c..0x2e7fc8`: head-first scan for the first member whose low two

7. `0x2e7fcc..0x2e8068`: rescan; every further match is re-parented onto the

8. `0x2e806c`: `node+0x98 & 1` (reloaded) → skip the particle release.
9. `0x2e8078..0x2e809c`: `particle = node+0x90`; when `particle+0x08` is

10. `0x2e80a0..0x2e80b8`: `particle+0x18` non-null → free it, then clear

### Indirect call
`0x00464110 + type*0x44 + 0x10` is called with `r0 = particle+0x08`
(`instance`); `r1` still holds the resolved slot address and `r2` the table
base in the original, and both are dead. The slot is the destructor counterpart
of the `+0x14` `create_instance` slot: entry 1's `+0x10` word is `0x001F7104`,
which frees the object it receives (and then itself). The C++ models
`void (*)(void*)` and does not null-check it, matching the original.

## Limits
- Fixtures are synthetic: the manager, nodes, particles, contexts, blocks, type
  table and all register inputs are scripted. No real effect graph, allocator,
  scene or render device is exercised.
- `0x0025C888` is stubbed: only its `+0x94` re-parent store is modelled, not its
  list relinking, index comparison or recursive pruning. Consequently the test
  verifies this function's arguments and pre-call mutations, not the helper's
  own effect on list order.
- A bound member that also carries the *destroyed* particle makes the original's
  re-parent rescan non-terminating (the helper restores the same `+0x94`); such
  an input is therefore outside the modelled domain and is not fixtured.
- The original's `manager->count` store precedes its `node+0x98` reload, while
  the compiled candidate reads the flags first. That order is only observable
  if `manager` and `node` alias; all fixtures keep them distinct.
- `0x002C4360` is treated as an opaque block release that does not mutate
  memory; real allocator behaviour and double-release detection are not
  modelled.
- The type table is runtime-populated absolute data; the test installs its own
  35-entry table, so the real entries and the `+0x10` destructor bodies are not
  validated (only the `0x001F7104` shape was inspected for the argument
  contract).
- The C++ does not reproduce the exact byte encoding, register allocation,
  `ldrb`-lane flag tests, the `bic #3`/`bic #2` difference, the store order in
  the stage-2 unbind, or the unused `r8` save.
- No emulator, caller-composition or whole-game equivalence is claimed.
