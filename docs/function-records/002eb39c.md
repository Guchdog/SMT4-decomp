## Behavioral Contract

The global cell `0x00439C60` holds the target-select work object; its first
word (`work + 0x00`) points at the reticle record. The function fills that
record, which must be at least `0xF8` bytes (`+0xF4` is the last field written;
the documented reticle allocation is `0x12C` bytes).

1. `unit = 0x2B087C(unit_id)` — battle-record lookup, resolved once before any
   formatter runs and reused for every subsequent read.
2. `0x2BE7FC(record + 0x04, "%s", 0x2BD25C(unit_id))` — first text buffer.
3. `0x2BE7FC(record + 0x2C, "%s", 0x2BD020(unit_id, 0))` — second text buffer.
4. `record[0x24] = (u8)0x29EC6C(unit_id)` — entity predication byte.
5. `*(u32*)(record + 0x28) = unit[2]` — zero-extended `ldrb`.
6. For `i = 0..7`: `record[0x4C + i] = (u16)(unit[0x24 + 2i]) >> 10`
   (logical shift; each stored byte is in `0x00..0x3F`).
7. `record[0x54..0x59] = b0, b1, b2, b3, b4, b5`.
8. `*(u32*)(record + 0x5C/0x60/0x64) = position[0..2]`.
9. `0x26330C(scratch, 0, 0x27DD78(0), record + 0x5C)` writes 12 bytes to the
   private stack scratch; only its first two words are copied back:
   `*(f32*)(record + 0x68/0x6C)`.
10. Branch on the first projected word, compared as a **signed 32-bit integer**
    against the literal `0x43520000` (also the bit pattern of `210.0f`):
    - `bits > 0x43520000`:
      `record[0xE4] = 0`;
      `*(f32*)(record + 0xF4) = value - *(f32*)(record + 0x78)`.
    - otherwise:
      `record[0xE4] = 1`;
      `*(f32*)(record + 0xF4) =
          (*(f32*)(record + 0x70) + *(f32*)(record + 0xD8)) - value`.

The signed-integer test is intentional and is preserved exactly. It differs
from a float comparison only for positive NaN bit patterns (which take the
`if` path here because their signed bit pattern exceeds `0x43520000`); the
differential suite covers `0x7FC00000`, `+inf`, negative zero, negative NaN and
both boundary words.

Note that `0x26330C` reads its input from `record + 0x5C` (the copy just
written), not from the caller's `position` pointer.

## Domain Limits

- `0x2B087C`'s result is dereferenced unconditionally at `+2` and
  `+0x24..+0x32`; a null result would fault in both the original and the
  candidate. The test keeps it non-null and instead exercises null results for
  the string lookups and for `0x27DD78`, whose results are only forwarded to
  stubs.
- The real behavior of the seven callees is not reconstructed here; the test
  models each as a deterministic stub and checks the call sequence, arguments
  and the memory the function observes/writes.
- The reticle record's initial `+0x70`, `+0x78`, `+0xD8` values are caller
  state; the test seeds them (including negative and extreme floats).
