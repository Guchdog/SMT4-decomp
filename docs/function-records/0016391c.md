# Function Record: func_0016391c (0x0016391c)

## Summary
- **Address:** `0x0016391c`
- **Size:** 1848 bytes (462 ARM instructions plus two literal-pool words read
  from immediately before the body)
- **File:** `src/engine/leaf_batch34_c.cpp`
- **Role:** Packed-byte edge filter over four strided rows of 32-bit words.  For
  every eight-byte group it recomputes one byte of each row's first word and
  one byte of each row's second word from the surrounding byte lanes.
- **Status:** Semantically equivalent C++ (`non_matching`). Verified with a
  Unicorn ARM differential test across 93 cases plus five negative controls.

## Contract and Behavior

### Signature and ABI
- **Signature:** `extern "C" void* func_0016391c(void* config)`
- `r0` points at a six-word config object; `r1`-`r3` are not read.
- **Return:** the config pointer itself.  The original saves `r0` with
  `push {r0, lr}` and restores it with `pop {r0, pc}`.
- **Stack/return:** `SP` is restored to its entry value.  The frame is 20 bytes:
  `[sp+0]` working horizontal counter, `[sp+4]` original `(width - 0x20)`,
  `[sp+8]` vertical counter, `[sp+0xC]` saved `r0`, `[sp+0x10]` saved `lr`.
- **Callee-saved registers:** the original saves only `r0`/`lr`, so it clobbers
  `r4`-`r11` (`r4`-`r7`, `r8`, `sb`/`r9`, `sl`/`r10`, `fp`/`r11`).  This is an
  ABI violation in the pinned image.  The C++ reconstruction is a normal AAPCS
  function and preserves `r4`-`r11`; the test verifies that property and records
  the original's divergence as evidence rather than comparing the two sets.
- No direct or indirect calls and no relocations.

### Config object (all reads are 32-bit `ldr`)
| Offset | Meaning |
|--------|---------|
| `+0x00` | never read |
| `+0x04` | absolute base address of the filtered buffer |
| `+0x08` | horizontal byte counter, consumed as `horizontal - 0x20` |
| `+0x0C` | vertical band counter, consumed in steps of 4 |
| `+0x10` | threshold word A, prefix-OR expanded (`r8`), used by the third compare |
| `+0x14` | threshold word B, prefix-OR expanded (`sb`), used by the first two compares |

Both thresholds are expanded with `orr rX, rX, rX, lsl #8` followed by
`orr rX, rX, rX, lsl #16`.  Because the second instruction consumes the updated
register, the result is a prefix OR per byte (`b0`, `b0|b1`, `b0|b1|b2`,
`b0|b1|b2|b3`), not plain byte replication.

### Memory layout and group
A group is one eight-byte window per row: the word at `+0x04` and the word at
`+0x08`, repeated in four rows spaced `0x100` bytes apart (`+0x000`, `+0x100`,
`+0x200`, `+0x300`).  The eight 32-bit `ldr`s all happen before any store, in
this original order: `+0x104`, `+0x108`, `+0x304`, `+0x308`, `+0x004`, `+0x008`,
`+0x204`, `+0x208` (relative to the group base).  Only these eight bytes are
written per group (all `strb`):

| Row | `+0x04` word | `+0x08` word |
|-----|--------------|--------------|
| `+0x000` | byte 3 at `+0x007` | byte 0 at `+0x008` |
| `+0x100` | byte 3 at `+0x107` | byte 0 at `+0x108` |
| `+0x200` | byte 3 at `+0x207` | byte 0 at `+0x208` |
| `+0x300` | byte 3 at `+0x307` | byte 0 at `+0x308` |

The gather step (`pkhtb`/`pkhbt`/`uxtb16` plus `orr`) resolves to four lane
vectors, one lane per row in row order 0..3:

```
a_low  = byte 2 of each +0x04 word
a_high = byte 3 of each +0x04 word   (replaced by `upper`)
b_low  = byte 0 of each +0x08 word   (replaced by `lower`)
b_high = byte 1 of each +0x08 word
```

Bytes 0 and 1 of the `+0x04` word and bytes 2 and 3 of the `+0x08` word are
never read.

### Packed-byte arithmetic (per byte)
- `uhadd8(a,b) = (a + b) >> 1`
- `uqsub8(a,b) = max(a - b, 0)`
- `uqadd8(a,b) = min(a + b, 255)`
- `uadd8(a,b)  = (a + b) & 0xFF`
- `ssub8` stores `(a - b) & 0xFF` and sets `GE = signed(a_byte) >= signed(b_byte)`
- `sel Rd, Rn, Rm = GE ? Rn : Rm` (GE taken from the preceding `ssub8`)

Per lane:

```
mixed   = uhadd8(uhadd8(uhadd8(~b_high, a_low), 0x01010101), 0x01010101)
average = uhadd8(a_high, b_low)
raise   = uqsub8(mixed, 0x02020202)
drain   = uqsub8(0x02020202, mixed)
upper'  = uqsub8(uqadd8(average, raise), drain)
lower'  = uqadd8(uqsub8(average, raise), drain)
```

Three selection masks are built with `ssub8` and consumed by `sel`:

1. `|a_high - a_low|` versus threshold B (`+0x14`),
2. `|b_high - b_low|` versus threshold B (`+0x14`),
3. `|a_high - b_low|` versus threshold A (`+0x10`).

Each `sel` keeps the current computed byte when its `GE` is clear and restores
`a_high`/`b_low` when it is set.  Because a later clear mask preserves an
earlier restoration, a lane keeps its original input byte if **any** of the
three signed comparisons is non-negative at that byte.  Comparisons are signed
(`ssub8` `GE`), so bytes above `0x7F` behave as negative values.

### Control flow
- **Initial branch (`0x00163958`):** `ble` after `subs r2, r2, #0x20` tests the
  *signed* value of `width - 0x20`.  If `<= 0` the short path is taken.
- **Short path (`0x00163f04..0x00164050`):** the horizontal reset value becomes
  `(width - 0x20) + 0x18`; the body filters one group, advances `0x8`, subtracts
  `0x8`, and repeats while the signed remainder is `> 0` (the body runs at least
  once).  The band advance adds `0x400` and subtracts `reset`; the vertical
  counter drops by 4 per band until it equals zero.
- **Full path (`0x0016395c..0x00163efc`):** a chunk filters four consecutive
  groups at lane offsets `0, 8, 0x10, 0x18` and advances `0x20`.  Starting from
  `width - 0x20`, the counter drops by `0x20`; another chunk runs while the
  signed remainder is `> 0`.  On exit the tail count is `remainder + 0x18`:
  when non-zero, groups are consumed eight bytes at a time (at least one); when
  zero the tail loop is skipped.  The band advance adds `0x400`, subtracts
  `0x18`, subtracts the original `(width - 0x20)`, and re-arms the counter.
- The vertical counter is only compared for equality, so the configured band
  count must be a positive multiple of 4 for termination.

## Unresolved Limits
- There are no helper or indirect calls, so nothing is stubbed.
- The original clobbers `r4`-`r11`; the candidate preserves them.  The test
  therefore checks the candidate's AAPCS preservation rather than comparing two
  undefined post-call register values.
- The fixture layout is synthetic (deterministically generated buffer plus a
  hand-built config), not captured game memory.  Field meaning beyond the
  offsets and access widths above is not claimed.
- Widths in `0x80000000..0x8000001F` make `width - 0x20` a huge positive
  counter under the signed branch; such inputs run far outside any realistic
  buffer and are intentionally not exercised.  The band count must be a positive
  multiple of 4, as with the original.
- The C++ models the packed operations byte by byte rather than emitting ARM
  SIMD instructions, so byte identity is not expected.
- No emulator or whole-game runtime session was run; equivalence is offline
  differential evidence only.
