# Function Record: engine_func_0014cae4 (0x0014CAE4)

## Summary
- **Address:** `0x0014CAE4`
- **Size:** 608 bytes. The ARM instruction stream spans
  `[0x0014CAE4, 0x0014CD28)`; the trailing 28 bytes are the inline literals
  `".cmp"`, `".stex"`, the manager pointer `0x00433130`, and `"STEX"`.
- **File:** `src/engine/leaf_batch45_a.cpp`
- **Role:** Build one texture slot's variant file name (source path + sibling
  name + `.cmp`/`.stex`), request the asset through the global AOC manager,
  optionally upload/decode it through the TMSprite helper, validate the
  `"STEX"` magic, and publish the decoded header into a new AsdTexture object.
- **Status:** Semantically equivalent C++ (`non_matching`). The compiled body
  is 520 bytes versus the 608-byte original because the three string literals
  live in `.rodata.str1.1` instead of inline in `.text`; Clang also folds the
  two suffix `strcat` calls into one address pair plus a conditional move.
  Return values, branch conditions, call order, stack arguments, field
  widths and every observed memory effect match the original.

## Contract and Behavior

### Signature and ABI
```cpp
extern "C" s32 engine_func_0014cae4(const char* base_name,   // r0
                                    EngineTextureSlot* slot, // r1
                                    u32 user);               // r2
```
- The original saves `r4-r8` and `lr`; `r9-r11` are untouched. The C++ build
  saves `r4-r8`, `sb`, `sl` and `lr`, and restores all of them, so the entry
  SP and every callee-saved register are preserved.
- Frame: the original reserves `0x110` bytes. `sp+0x00..0x0F` is the outgoing
  register/stack word area, `sp+0x10..0x8F` is the variant-name buffer and
  `sp+0x90..0x10F` is the base-path buffer (both `0x80` bytes).
- Return value: `0` on every failure path, `1` after the slot is updated.
  `r0` on entry is a NUL-terminated base name, `r1` is the slot record and
  `r2` is forwarded unchanged as the seventh argument of `0x002A4828`.
- No indirect calls and no loops: all transfers are direct `bl`/`blx` or
  straight-line branches.

### Control flow (original PCs)
1. `0x14CAE4..0x14CB04`: save registers, latch `slot->source` and `slot->desc`,
   reserve the frame, copy the inline source path into the variant buffer with
   `0x002BF86C` (`strcpy`).
2. `0x14CB08..0x14CB74`: read `desc->name[0]`.
   - `'-'`: `0x14CB48` sign-extends `name[1]`, computes
     `slot + 0x604 - (s8)name[1]*0x20`, loads the node pointer, reads its
     `+0x08` string and appends it with `0x002B67E0` (`strcat`).
   - otherwise: append `desc->name` itself.
   Then append `".cmp"` when `desc->variant != 0`, else `".stex"`.
3. `0x14CB78..0x14CB90`: `strlen(desc->name)`; a zero length clears
   `slot->texture` and returns `0`. Otherwise `strcpy` the caller's base name
   into the second buffer.
4. `0x14CB9C..0x14CBB4`: load `slot->flags`; if any bit other than `0x10000`
   is set, return `0` (no memory writes). `base_mode = (flags & 0x10000) ? 3 : 1`.
5. `0x14CBB8..0x14CBF8`: `load_mode = variant ? base_mode ^ 2 : base_mode`.
   Call `0x002A4828(manager = *(void**)0x00433130, base_path, variant_name,
   &size, load_mode, 0x80, user)` with its three stack words. A null result
   returns `0` without touching the slot.
6. `0x14CC00..0x14CC24`: when `desc->variant != 0`, replace the asset pointer
   with `0x002A465C(data, base_mode, 0x80)`; the upload receives the
   **untoggled** mode.
7. `0x14CC24..0x14CC44`: `memcmp(data, "STEX", 4)` (`0x002C1A48`); a mismatch
   frees the asset pointer with `0x002C4360` and returns `0`.
8. `0x14CC54..0x14CC60`: if `*(u32*)(data+0x24) != 0`, clear `slot->texture`
   and jump to the common tail.
9. `0x14CC80..0x14CD24`: otherwise allocate the texture through
   `0x002BD940((flags & 0x10000) ? 1 : 0)`, store it at `slot+0x08`, copy
   `data+0x08`→`tex+0x04`, `+0x0C`→`+0x14`, `+0x10`→`+0x18`, `+0x18`→`+0x1C`,
   `+0x14`→`+0x20`, `size - data+0x20`→`+0x28`, OR `0x10` into `tex+0x2C`,
   and when `*(u32*)(data+0x04) == 1` set `tex+0x3C = tex+0x40 = 1`. Then
   `tex+0x24 = data + *(u32*)(data+0x20)`.
10. `0x14CC64..0x14CC7C`: common tail — `slot->loaded = data`,
    `slot->flags |= 2`, return `1`.

### Unresolved or unchecked behavior
- `0x002A465C` returning null is not guarded; the following `memcmp` would
  fault in both the original and the candidate. That fault path is not
  exercised by the test.
- `0x002BD940` returning null is not guarded either; the original stores then
  dereferences the result. That fault path is not exercised by the test.
- The bodies of the eight helper targets are not reconstructed here; the test
  replaces each with a deterministic stub at its original address.
- The sibling table is only described by the observed arithmetic; its owner
  object and the meaning of the node's other fields are not established.

## Differential Verification
`python tools/test_leaf_0014cae4.py` compiles
`src/engine/leaf_batch45_a.cpp`, relocates the candidate's calls (including the
two Thumb `blx` targets) and `.rodata.str1.1` references, and runs the pinned
608-byte original against the candidate in separate Unicorn ARM machines with
identical fixtures.

Compared: return `r0`, continuation PC, final SP, callee-saved `r4-r11`, the
ordered call log (register arguments, the three stack words of `0x002A4828`,
the string bytes actually received/appended, the `out_size` written back),
the full 0x10000-byte slot page (including every sibling entry), the source,
descriptor, string, raw-asset, decoded-asset, texture and manager pages, and
that all writes stay inside the private stack, slot page or texture page.

Coverage (49 cases):
- plain names and the `-<byte>` sibling form with codes `0`, `2`, `3`, `4`,
  `-1`, `+127` and `-128` (the signed-shift boundaries);
- `variant` `0`, `1`, `0xFF`, including the `variant × flags(0x10000)` mode
  combinations and the `.cmp` vs `.stex` suffix;
- every rejected flag form (`0x1`, `0x2`, `0x20000`, `0x10001`, `0x10002`,
  `0xFFFF`, `0xFFFE`) and both accepted forms;
- empty and one-byte descriptor names, the empty `strlen` early exit, and long
  base/descriptor names;
- null and non-null asset loads, `"STEX"` match/mismatch before and after the
  TMSprite upload, and `data+0x24` zero/non-zero;
- `data+0x04 == 1` vs `!= 1` and the texture `+0x2C` OR pattern;
- asset-size boundaries: equal, one-byte, zero, `0xFFFFFFFF` and
  `0x80000000` wrap cases, plus a `size - offset` underflow;
- `user` pass-through `0`, `1`, `0x80000000`, `0xFFFFFFFF`.

Negative controls mutate the `.cmp` suffix, the mode toggle, the sibling
stride and the `+0x28` store offset; each mutant is detected by at least one
case (a mutant that faults where the original completes counts as detected).

Limits: this is an isolated function-level differential test. It does not
prove whole-game runtime equivalence, the helper bodies, the null
upload/texture fault paths, or the ownership/lifetime of the asset buffers.
