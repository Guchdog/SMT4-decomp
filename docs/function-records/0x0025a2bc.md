## Identity and interface

- Original function: `0x0025A2BC`, 92-byte ARM function including its trailing
  global-pointer literal; entry `r0` is not a formal argument.
- Candidate: `h1_preview_gate_candidate` in
  `experiments/semantic_equivalence/h1_preview_gate_candidate.cpp`.
- Pinned original `code.bin` SHA-256:
  `1f98884fe997af22e032a14c51a46c872b05b0e079a0f29e307b0e059cfaa558`.
- Global pointer slot: `0x0043E278`, containing the `FrameTexScene*`.
- The H1 state-5 callback calls the function at `0x001E9D1C` after
  `Script_IsReadyToAdvance` returns nonzero. It passes no formal argument,
  compares returned `r0` with zero, and branches to `0x001EA62C` on zero. A
  nonzero result continues at `0x001E9D2C` before the timer update.

## Recovered gate behavior

Let `scene = *u8**(0x0043E278)`. The function performs these short-circuited
checks and returns an integer 0 or 1:

1. If byte `scene+0xF2B` is zero, return 1 without reading the later fields.
2. Otherwise, if byte `scene+0x1C` is zero, return 1.
3. Otherwise, load a **signed** byte from `scene+0xD6D`; any nonzero value
   returns 0.
4. Otherwise call `0x002BF9F0` once with `r0 = scene+0xD74`. Return 1 if its
   `r0` result is nonzero (positive or negative); return 0 if it is zero.

The helper's recovered call type is `s32 (*)(void*)`: its entry saves
callee-saved registers and consumes the sole object pointer in `r0`. Its body
is not a simple pure predicate. It reads and mutates the pointed animation
object and calls other helpers. On its main return path it obtains `r0` from a
sign-extended byte at object `+0x8A`; early branches can return constant 1. The
caller uses only the zero/nonzero distinction. Existing source declarations
that treat the helper as `void` are not modified by this candidate.

The candidate uses the pinned no-argument gate ABI, fixed global pointer slot,
exact byte widths and offsets, signed `+0xD6D` test, and explicit helper
function-pointer type. It does not accept a synthetic readiness flag.

## Evidence and limits

The focused report is
`build/agent-work/H1-semantic/h1-preview-readiness-candidate/sleep-20261025-preview-gate/checks/final/report.json`.
The compiled C++ matched the original gate with the helper intercepted only at
its entry for 52 cases: all eight boolean branch combinations with four
positive/zero/negative helper responses, zero/nonzero byte boundaries
`0, 1, 0x7F, 0x80, 0xFF` at each tested field, and signed helper-result
boundaries. Wrong helper-object offset, wrong primary-branch polarity, and
wrong helper-result polarity controls were all detected. The check compares
return `r0`, helper entry and pointer argument, untouched scene memory, stack,
callee-saved registers and VFP state.

The report marks compiled and ARM differential evidence `passed`, caller
evidence `partial`, and runtime `not_run`. `FrameTexScene` construction
allocates and zeroes a `0xFEC`-byte scene and writes zero to `+0x1C` and
`+0xF2B`; however, current scene declarations leave the nested `+0xD74` object
untyped, and this experiment does not establish the full runtime lifecycle or
call timing. The gate has no null check for the scene pointer. The helper body,
its callbacks and animation side effects, actual Azahar execution, and whole-H1
behavior were not exercised.
