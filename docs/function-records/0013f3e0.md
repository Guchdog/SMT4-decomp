# Function Record: func_0013f3e0 (0x0013f3e0)

## Summary
- **Address:** `0x0013f3e0`
- **Size:** 684 bytes (171 ARM instructions, no literal pool; the next function
  starts at `0x0013f68c`)
- **File:** `src/engine/leaf_batch34_c.cpp`
- **Role:** Fold six tagged record references into one fingerprint word: walk the
  owner's self-relative table to a record, resolve each of the record's six
  reference slots through a self-relative descriptor chain, and XOR each
  accepted, helper-resolved address (rotated right by a fixed amount) into a
  word seeded from the owner. The result is stored back on the owner.
- **Status:** Semantically equivalent C++ (`non_matching`). The ledger row said
  `matching` only because the previous body was relocatable assembly; the
  readable C++ is 496 bytes versus 684 and makes no byte-identity claim.
  Verified with a Unicorn ARM differential test across 40 cases plus five
  detected negative controls.

## Contract and Behavior

- `r1`, `r2` and `r3` are never read. There are no stack arguments.

### Memory layout (offsets only, as evidenced by the ARM)
- `*self` (`0x0013F3E8`, re-read at `0x0013F40C` and `0x0013F680`): owner word.
- `owner + 0x288`: self-relative slot to the table (`0x0013F3F0`).
- `table + 0x28`: self-relative slot to the record (`0x0013F400`); this chain is

- `owner + 0x2C4`: seed fingerprint (`0x0013F418`).
- `owner + 0x2C0`: fingerprint destination (`0x0013F684`).
- Record slots folded, in listing order: `+0x0C`, `+0x10`, `+0x00`, `+0x04`,
  `+0x08`, `+0x14`. Each word is a self-relative displacement to a descriptor.
- `descriptor + 0x08`: self-relative displacement to a tagged object.
- Tagged object `+0x00`: tag word; bit `0x40000000` must be set for the
  reference to take part.
- Tagged object `+0x0C`: payload slot read by `0x002A7F94`.

### Self-relative slot rule
A slot word is a displacement from its own address:
`target = slot_address + word`, and a zero word selects "none" without
dereferencing anything. All arithmetic is 32-bit modular. This is the same
relative-offset convention used by the neighbouring record walkers.

### Helper 0x002A7F94
`u32 res = helper(slot)` with `slot` pointing at a word that holds the object
address. The helper (48 bytes, `matching` in its own ledger row) does:
`p = *slot; tag = p[0]; if (tag == 0x80000000) return p; if (tag !=
0x40000000) return 0; off = p[3]; return off ? (p + 0x0C + off) : 0;`
Because the caller has already required bit 30, the `0x80000000` case is
unreachable from this function, tags with bit 30 but not exactly `0x40000000`
return 0, and an exact `0x40000000` with a zero `+0x0C` word also returns 0
(the call still happens).

### Control flow
1. `owner = *self`.
2. `table = owner + 0x288 + [owner + 0x288]` (0 when that word is zero).
3. `record = (table + 0x28) + [table + 0x28]` (0 when that word is zero).
4. `fingerprint = [owner + 0x2C4]`.
5. For each of the six slots, in the order above:
   - `a = record + slot + [record + slot]`; skip when 0.
   - `b = a + 0x08 + [a + 0x08]`; skip when 0.
   - skip when `([b] & 0x40000000) == 0`; otherwise store `b` in the stack word
     and call `0x002A7F94` with its address.
   - `fingerprint ^= ror(result, N)` with `N` = `0`, `28`, `24`, `20`, `16`,
     `12` in that order (rotate right, so the effective mix rotates left by
     `4*i`).
6. Re-read `owner = *self` and store `fingerprint` at `owner + 0x2C0`; return
   that re-read owner word.

### Signedness and arithmetic
- There are no signed comparisons and no loops in this function: the only tests
  are `== 0` on resolved addresses and the `0x40000000` bit test. Signed and
  unsigned interpretations therefore coincide for every branch.
- The rotations are ARM register `ror` by constant amounts; `ror #0` is the
  plain value.
- The seed and the XOR are full 32-bit words; no truncation or sign extension
  occurs anywhere in the body.

## Frame and unresolved limits
- The real body of `0x002A7F94` is stubbed; its own ledger row and record cover
  it. No indirect call target exists in this function to exercise.
- The helper is deterministic and never faults in the fixtures; the two fault
  cases are caused by the unguarded owner/record slots and reproduce the
  original's read addresses (`0x28`, `0x0C`). Faults inside partially mapped
  pages are not modelled.
- The original pre-loads the first record slot (`record + 0x0C`) five
  instructions before the seed word, so a fixture in which `record + 0x0C`
  aliases `owner + 0x2C4` would observe a different seed. The candidate reads
  the seed first. Malformed overlapping records are outside the supported
  contract; all tested fixtures use disjoint records.
- The compiler emits the tag test as a byte load at `object + 3` (testing bit
  `0x40`) instead of a word load; the values agree on little-endian ARM, but a
  record straddling a mapped/unmapped page boundary could report a different
  faulting byte offset. Aligned, fully mapped records are covered.
- No emulator or whole-game runtime scenario was run; this record covers the
  offline differential contract only.
