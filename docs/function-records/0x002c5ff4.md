# `0x002C5FF4` — forward byte-copy helper

Status: experimental readable candidate; not integrated or independently
reviewed. The pinned behavior and H1 use are documented in
[`h1-title-message-contract.md`](../agent-work/h1-title-message-contract.md).

Pinned image SHA-256:
`1f98884fe997af22e032a14c51a46c872b05b0e079a0f29e307b0e059cfaa558`.
The 136-byte extent `[0x002C5FF4,0x002C607C)` has hash
`644501596cdc02773609b59f6b01e737be96c516e4546919af3c259c1b64746e`.
Its ABI is `r0=destination`, `r1=source`, `r2=byte count`; the pinned routine
advances `r0` and returns the end pointer. For adjusted word-aligned sources,
it branches to pinned `0x002BCF58` (116 bytes, hash
`d4e075de5405e2393514369688bf643d3d2064f5386b321b2b9f0ee3d511e0fe`).

The readable candidate copies bytes forward and returns `destination+length`.
Its evidence is restricted to valid, non-overlapping source/destination spans
in ordinary memory. This is not `memmove`: overlap, invalid pointers, null
pointer behavior, MMIO ordering, and game-runtime behavior are unsupported.
The original-versus-candidate matrix covers 176 alignment/length combinations
(all source/destination alignments modulo four and lengths 0, 1–4, 7–9, and
31–33), with no mismatch. A deliberate byte-corruption mutant was detected.
See [`h1-title-message-candidate.md`](../agent-work/h1-title-message-candidate.md)
for the report and exact validation evidence.
