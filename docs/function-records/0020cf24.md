## Frame and unresolved limits
- The three callees are stubbed. Their real bodies are separate ledger rows
  (`0x002C5B04`, `0x002C5AB8` and `0x002C1DE4`); the stubs model only the
  return values and the table retarget this body can observe. The stubs do not
  model any allocation or side effect of the real row loader/selector.
- The exact meaning of the two extra row loads in `0x0020d0a4`/`0x0020d0b0`
  (sub-rows `0x00` and `0x01` before fetching `0x0E`) is not recoverable from
  the caller side alone; they are reproduced by argument and order only.
- **Aliasing domain:** within an enabled slot the original publishes the slot
  first and then writes `widget+0x3C`, reloads the slot word and writes
  `widget+0x40`. Clang reorders the two widget writes before the publish and
  reuses the already-loaded widget for the second flag. That is identical for
  disjoint widget/table memory; an input that makes a widget word alias a table
  slot is not distinguishable and is outside the supported contract.
- An enabled slot whose widget lookup returns null faults in both bodies at
  widget `+0x3C`. Unicorn does not expose the faulting address, so this
  invalid-input domain is documented rather than compared. Publish-only slots
  accept null and are covered.
- No indirect calls exist, so there is no unresolved indirect target.
- No emulator or whole-game runtime scenario was run; this record covers the
  offline differential contract only.
