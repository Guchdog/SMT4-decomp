# Function Record: script_vm_func_0028f15c (0x0028f15c)

## Summary
- **Address:** `0x0028f15c` (original span `[0x0028f15c, 0x0028f2ec)`, 400 bytes)
- **File:** `src/engine/leaf_batch33_c.cpp`
- **Role:** Actor-slot release / activation step of the script-VM actor tables.
  It gates on a per-actor flag record, rewrites that record, and then either
  claims one of four 14-byte actor slots or records the id as the shared
  "active id" and clears 32 command bits of the script-VM work block.
- **Status:** Semantically equivalent C++ (`non_matching`). The compiled body
  is 460 bytes versus 400 original bytes (clang hoists the `id >= 0x15e` test
  into a shift/compare, splits the halfword stores into byte stores and
  computes the free-slot offsets; the observable register, memory and call
  behavior matches). The ledger row is classified `non_matching`; this record
  carries the semantic evidence.

## Contract and Behavior

```c
extern "C" s32 script_vm_func_0028f15c(u32 id);
```
- `id = r0`; no other register or stack argument is read.
- Return: `0` from either early gate, otherwise `1`.
- The original saves `r4-r8, lr`, never touches `r9-r11` or VFP, and restores

### Flag record (`[work_a + 0x200 + id*4]`)
`work_a` is the first `0x002ADF14` result. The routine addresses
`work_a + id*4`, then uses the pre-index write-back `ldrb r0,[r4,#0x200]!`.
Only three bytes of the four-byte stride are observed:

| Offset | Use |
| --- | --- |
| `+0` | gate bit 0; bits 2 and 6 are rewritten; bit 7 is cleared |
| `+1` | non-zero copies into bit 6 of byte `+0` |
| `+2` | bits 0 and 2 are cleared |

The address arithmetic is 32-bit modular: ids `0x40000000`, `0x7fffffff`,
`0x80000000` and `0xffffffff` wrap to record offsets `+0x200`, `+0x1fc`,
`+0x200` and `+0x1fc`, and the test covers that wrapping.

### Gate 1
`if ((flag byte 0 & 1) == 0 && id < 0x15e) return 0;`
The comparison is unsigned (`blo`) against the literal `0x15e` at the pool
word `0x0028f2e8` (loaded by `ldr r0,[pc,#0x160]` at `0x0028f180`). Ids
`>= 0x15e` therefore run even when bit 0 is clear; id `0x15e`, `0x15f`,
`0x18f`, `0x40000000`, `0x7fffffff`, `0x80000000` and `0xffffffff` are covered.

### Gate 2
`work_b` is the second `0x002ADF14` result. After
`kind = 0x00287AFC(id)` and `gate = 0x00299224(id)`:
`if (gate == 0 && kind != 0 && u16[work_b+0x840] != 0) return 0;`
The chain is ordered exactly as in the original (`bne` to the continuation,
then `beq` on the kind, then `beq` on the halfword); the halfword load is the
`mov r0,#0x840; ldrh r0,[r0,r5]` pair, i.e. a 16-bit read of `work_b+0x840`
(the two 32-bit register values are added, so this is the same address as
`work_b+0x840`).

### Flag rewrite (every path that passes both gates)
```
follow = byte1                              // loaded before the first store
value  = (byte0 & ~4) | 2;      byte0 = value
value  = follow ? value | 0x40 : value & ~0x40;  byte0 = value
byte0  = reload(byte0) & ~0x80
byte2  = byte2 & ~5
```
The original stores byte 0 twice and reloads it once; the test covers
`00/00/ff`, `ff/01/ff`, `01/00/05` and `24/ff/fa` starting triples.

### Slot registration (`gate != 0` after the rewrite)
1. Only when `kind == 1`; every other kind returns `1` immediately.
2. Scans the four 14-byte slots at `work_b+0x842 + 14*index` for the first
   zero halfword id.
3. On a free slot: stores `(u16)id` in the slot's leading halfword, then calls
   `0x003EB280(slot+2)`, which zeroes the 12-byte payload.
4. If all four slots are occupied, no write and no call happen.
5. Returns `1`.

### Activation (`gate == 0` after the rewrite)
1. Only when `kind != 0`; `kind == 0` returns `1` without touching the work
   block.
2. `u16[work_b+0x840] = (u16)id`.
3. Zeroes the 14-byte tail record at `work_b+0x87a`: three 32-bit stores at
   `+0x87a/+0x87e/+0x882` followed by a 16-bit store at `+0x886`. These three
   word stores are unaligned (the work block is 4-aligned and `0x87a % 4 == 2`)
   exactly as in the original; the test verifies the identical final bytes.
4. For each bit `0x500..0x51f`: calls `0x002ADF14` again, calls
   `0x0023DF18(bit, 0)`, then clears that bit (`work[bit>>3] &= ~(1 << (bit&7))`).
   The byte is read *after* both calls, so a callee that rewrites the block is
   observed; the test covers a getter rewriting byte `+0xa0` and a
   `0x0023DF18` stub rewriting byte `+0xa1`.
5. Returns `1`.

## Domain Limits
- Every direct callee is stubbed. The real bodies of `0x002ADF14`,
  `0x00287AFC`, `0x00299224`, `0x003EB280` and `0x0023DF18` are not executed;
  the record covers the arguments and return values this function observes.
  `0x0023DF18`'s internal state machine and entity lookup (`0x002B6700`) are
  outside this record.
- The work blocks and flag table are synthetic RAM. Field meanings beyond the
  ARM offsets are not established: `+0x840` and the 14-byte records are named
  from their observed roles only, and the four-slot limit is hard-coded from
  the `cmp r0,#4` loop bound.
- The unaligned word stores at `+0x87a/+0x87e/+0x882` are modeled with
  `__builtin_memcpy`; clang emits byte stores, so the identical final bytes
  are verified but the exact store widths are not. The tail record's semantics
  are unknown beyond "zeroed".
- Stack bytes of the dead push frame differ because the candidate saves eight
  registers instead of six; both restore `sp` and every callee-saved register,
  and the stack outside that frame is compared.
- No runtime, caller-composition or whole-game equivalence is claimed. The two
  callers are documented from disassembly but are not executed against a
  patched image.
