# Function Record: ui_func_002247c8 (0x002247c8)

## Summary
- **Address:** `0x002247c8`
- **Size:** 504 bytes (original span `[0x002247c8, 0x002249c0)`): 124 ARM
  instructions `0x002247c8..0x002249b4` plus the two-word literal pool at
  `0x002249b8` (`0x0044ea00`) and `0x002249bc` (`0x00000000` = `+0.0f`).
- **File:** `src/engine/leaf_batch42_b.cpp`
- **Role:** With a looked-up UI object whose `+0x10` byte is non-zero, pushes one
  command word onto each of three render command stacks
  (`*0x0044ea00 + 0x126c`, `+0x124c`, `+0x12ac`), hands the object's `+0x0c`
  state pointer to `engine_func_00281adc`, then pops the three stacks in reverse
  order.  Every path returns 0.
- **Classification:** `non_matching` with semantic evidence.  The compiled body
  is 548 bytes versus the 496 instruction bytes + 8 literal bytes of the
  original: the compiler keeps the render base in callee-saved registers (so it
  saves `r4-r11` instead of `r4-r8`), uses `movw`/`movt` for `0x0044ea00`, and
  inlines the push/pop helpers; the observable calls, stack-node traffic and
  return value are identical (28/28 differential cases).

### Push and pop sequences
Push (identical for the three nodes):
1. `previous = slots[depth]`
2. `depth = depth + 1`
3. `slots[depth] = value`
4. re-read `dirty`; if `dirty != 0 || previous != value`, call
   `flush_cb(value)` and store 0 to `dirty`.

Pop (identical for the three nodes):
1. `previous = slots[depth]`
2. `depth = depth - 1`
3. `new_top = slots[depth]`
4. re-read `dirty`; if `dirty != 0 || previous != new_top`, call
   `flush_cb(new_top)` and store 0 to `dirty`.

A pop always runs after its push, so a node's depth is at least 1 when the pop
executes; the `depth == 0` pop index is unreachable in this routine.

## Domain Limits
- All five direct calls are stubbed deterministically because their real
  behaviour depends on live engine/render state.  `0x00286834`, `0x002c5f7c`
  and `0x002c5fa4` are reproduced faithfully from their ARM bodies (pure bit
  building); `0x002c0ac8` and `0x00281adc` are replaced by fixture-controlled
  stubs, so the object-table traversal and the engine state consumption are not
  exercised here.
- The flush callback is fixture-controlled (two targets per node, one of which
  switches the render base).  Its real identity, arity and return use are not
  recovered beyond "called with the new value in `r0`, result unused".
- Neither `0x0044ea00` nor the flush callback is null-checked by the original;
  the reconstruction keeps that, and the render base is required to be a valid
  mapped pointer.
- The object pointer returned by `0x002c0ac8` is dereferenced without a null
  check, exactly like the ARM `ldrb r0, [r0, #0x10]`; a lookup miss faults in
  both bodies (verified).
- The stack node layout is only backed by the observed byte offsets; ownership,
  capacity, the meaning of the pushed command words and the true slot count are
  not recovered.  Depth 3 is covered; a depth that pushes the slot store onto
  the callback pointer (`depth == 4`) was not exercised because both bodies would
  then `blx` a clobbered pointer.
- The optimizer would otherwise reorder the push's dirty-byte read ahead of the
  out-of-range slot store (legal only if the index is assumed in range).  The
  reconstruction adds an empty `asm volatile("" ::: "memory")` compiler barrier
  between the store and the read to preserve the ARM's `count == 3` observation;
  it emits no instruction.
- Runtime integration (a live render base, the real object-table producer and
  the consumer of the queued command words) was not exercised; this record
  covers offline differential equivalence only.
