# Function Record: ui_func_001084f0 (0x001084f0)

## Summary
- **Address:** `0x001084f0`
- **Size:** 520 bytes (`[0x001084f0, 0x001086F8)`; the last word at
  `0x001086F4` is this function's literal-pool entry `0x0044EA00`)
- **File:** `src/engine/leaf_batch34_c.cpp`
- **Role:** `"HDRCL"` capture-completion callback, the companion to
  `0x00108300`. It resolves the packed widget handle to the FrameTex scene,
  requires capture mode 0 and the same four enable gates, trims the capture
  texture chain and publishes the inverse completion state (`+0xE96 = 1`,
  `+0xE95 = 0`). It always returns 0.
- **Status:** Semantically equivalent C++ (`non_matching`). The compiled body is
  424 B versus 520 B: the candidate keeps only `r4-r6` (plus `lr`), merges the
  redundant `count - 1` clamp into `count - (mode == 0 && count > 1)` and
  folds independent pointer reloads. The ledger row is classified
  `non_matching` with this record.

## Contract and Behavior

- Like `0x00108300`, the callback is an `"HDRCL"` task calculation callback, so

## Differences from the 0x00108300 companion
- It clears `+0xE96` first and requires `0x002C00E8(0) == 0` before the enable
  gates, whereas `0x00108300` clears `+0xE95` first and does not gate on mode.
- The success state is `+0xE96 = 1`, `+0xE95 = 0`, the inverse of
  `0x00108300`.
- Everything from the GPU pass through the trim loops is the same sequence and
  uses the same helpers and field offsets.

## Compiler transformations that preserve observable behavior
- The redundant `count -= 1; count = max(count, 1)` clamp becomes
  `count - ((u32)CaptureMode(0) == 0 && count > 1)`; the candidate implements
  it with `clz`/`lsr`/`and`/`sub`. For `count > 1`, `count - 1 >= 1`, so the
  clamp never triggers and the result is identical.
- Independent pointer loads are merged where the original reloads them after a
  helper; helpers cannot observe the difference unless the scene and a texture
  object overlap in memory (they are separate allocations in the pinned game;
  the tests use distinct pages, and aliasing scenes are exercised separately).
- The success stores `+0xE96 = 1` / `+0xE95 = 0` are emitted in the opposite
  order. They target distinct bytes, so final memory is identical.

## Limits
- All five callees are stubbed; no real widget lookup, GPU pass, texture trim,
  layout-mode query or texture blit is exercised. Their internal contracts are
  inferred only from their register use at this call site.
- Helper side effects are synthetic. The stubs deliberately mutate scene and
  texture memory to prove reload behaviour, but the real helpers may write other
  fields.
- The packed handle encoding, `+0xE8C/+0xE8D/+0xFD8/+0xFE0` meanings and the
  capture-texture chain semantics are not established beyond their role here.
- The test maps the low page so the null-lookup path is observable; on a real
  unmapped page both implementations fault at the `+0xE96` store.
- No caller-composition, emulator-run or whole-game runtime equivalence is
  claimed.
