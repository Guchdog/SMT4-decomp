# Function Record: engine_func_003cf20c (0x003cf20c)

## Summary
- **Address:** `0x003cf20c`
- **Size:** 456 bytes (original span `[0x003cf20c, 0x003cf3d4)`; 113 ARM
  instructions plus the trailing literal word `0x000001c6` at `0x003cf3d0`)
- **File:** `src/engine/leaf_batch41_c.cpp`
- **Role:** Party-member selection gate. Reads a context master word, scans the
  first four actor records for eligible roster values, requires that at least
  one value was collected *and* that at least one record carried a blocking bit,
  then randomly re-arms one collected value: it resolves a per-unit flag record,
  issues a battle-record call, clears/flags one UI row returned by
  `0x00282b94`, and posts action `0x1C`. The 0x10-byte scratch list is released
  through the `0x00250fb4` wrapper, whose result becomes the return value.
- **Status:** Semantically equivalent C++ (`non_matching`). The compiled body is
  912 bytes versus the 456-byte original because the fixed four-iteration scan
  bound (`cmp r7,r4` with `r7 = 4`) is fully unrolled and the compiler merges the
  collected/blocked flags into the count register; the ledger row is classified
  `non_matching` with this semantic record.

## Contract and Behavior

### Signature and ABI
```c
extern "C" u32 engine_func_003cf20c(void** context, void* owner, s32 key);
```
- `context = r0` is a **pointer to a pointer**; every context read re-loads
  `*context`. `owner = r1` and `key = r2` are only forwarded to `0x00246f90`,
  with the first two arguments swapped (`r0 = key`, `r1 = owner`). `r3` is not
  read.
- Return: the `+0x44A0` master word on the early exit (r0 is loaded and never
  cleared), otherwise the forwarded result of the `0x00250fb4` tail call.
- The original preserves `r4-r8, sb, sl, fp`; the candidate preserves the same
  set. Final `sp` equals the entry value on every non-faulting path.

## Contract corrections found during implementation
- **The `+0x1c6` read is an in-record offset, not a constant address.** The
  literal word is `0x000001c6`; the ARM emits
  `ldr r0,=0x1c6` + `ldrh r0,[r0,r5]`, i.e. `*(u16*)(record + 0x1c6)`. This was
  confirmed by the differential test (an absolute `0x1c6` address would fault).
- **`0x0022aaac` takes two arguments.** The stub sees leftover `r2 = 2` and
  `r3 = -1` from the preceding `0x002462a0` call, but those are not architected
  arguments; only `r0`/`r1` are set by the caller.
- **`0x00246f90` receives `r0 = key`, `r1 = owner`** — the reverse of this
  routine's own parameter order — plus stack word `1`.
- **`count` is a signed byte.** `sxtb r8,r1` after each increment, though the
  count can never exceed four.
- **The action cannot run with four collected values.** The blocker bit that is
  required for the action also excludes its record, so the action's reachable
  counts are 1..3; four collected records always release early.
- **The scratch index is unbounded.** The original indexes `[fp, r0, lsl #2]`
  directly with the draw result; a draw outside `[0, count)` reads beyond the
  0x10-byte allocation (the harness exercises `count = 1, draw = 5`).

## Limits
- Fixtures are synthetic: context object, actor records, flag records, row page
  and scripted helper results are not captured game data.
- Every helper is stubbed; no real roster validity check
  (`0x2462a0`/`0x22aaac`), RNG (`0x23ec3c`), battle-record submission
  (`0x246f90`), row lookup (`0x282b94`), action posting (`0x22a76c`) or
  allocator/free (`0x2c684c`/`0x250fb4`) behaviour is exercised.
- The meaning of the probe result bits (`0x170000`), the `+0x1c6` stage bits,
  the `+0x44a0` bit 2 master bit and the `+0x44a8` bit 24 gate is not
  established; they are treated as opaque bit fields at the recovered offsets.
- The faulting cases compare only the fault outcome, the call log and the
  read-only fixtures; the faulting PC differs between the original and the
  recompiled body.
- The candidate's internal frame layout, unrolled loop and register allocation
  differ from the original; only the documented ABI inputs, call arguments,
  saved registers, returned state and observable memory are compared.
- No caller-composition, game-state or whole-game runtime equivalence is
  claimed.
