## Contract corrections found during implementation
- **The `+0x10`/`+0x18` words are command values, not function pointers.**
  `0x00250800` stores its third argument at `[object + 0x2C]` and never calls it.
- **The singleton fetch precedes the not-found test and the switch.** A
  no-match call still invokes `0x00293C98`, and the relative family still reads
  `*(0x004342C8)` before returning `0`; only the dispatch and the `+0x49E4`
  store are skipped.
- **The original reuses the format scratch area for the dispatch stack
  arguments.** At `0x394BCC..0x394BD0` the `0x20`-byte buffer region at `sp` is
  overwritten with `0, sector, 0`; the formatted text is only observable at the
  `0x2AA7F4` call, which is why the harness snapshots the buffer inside the
  format stub.
- **Two absolute thresholds are not the nearest float to their decimal
  spelling.** `-2.965f` rounds to `0xC03DC28F` and `0.965f` to `0x3F770A3D`,
  one ULP below the original `0xC03DC290`/`0x3F770A3E`; the candidate uses
  bit-exact constants.
- **`selector` is tested unsigned.** Values below `2` (including negative
  words) and above `13` take the relative path.

## Limits
- Fixtures are synthetic: the effect table, reference float, requested name and
  singleton are test data, not captured game state.
- Every helper (`0x2C583C`, `0x2BE7FC`, `0x2AA7F4`, `0x293C98`, `0x250800`) is
  stubbed; no real effect lookup, string formatting, singleton state or command
  dispatch is exercised.
- The semantic meaning of the command words, ids, table name suffix and
  `selector` values is not established; the field names describe only their
  role in this function.
- The reference float at `*(*(0x004342C8) + 0x574)` is treated as an opaque
  float bit pattern.
- The candidate's frame layout and register allocation differ from the
  original; only the documented ABI inputs, call arguments, saved registers,
  formatted text and written state are compared.
- No caller-composition, emulator-run or whole-game runtime equivalence is
  claimed.
