# Function Record: script_vm_func_00339d98 (0x00339D98)

## Summary
- **Address:** `0x00339D98`
- **Size:** 604 bytes (original span `[0x00339D98, 0x00339FF4)`; the final two
  words `0x00435D90` and `0x00002244` are the only literals).
- **File:** `src/engine/leaf_batch45_a.cpp`
- **Role:** Battle-main start/resume state machine. Holds the global recursive
  lock at `work+0x4A00`, drives the 14-state dispatch at `work+0x49FE`, copies
  the seven global object pointers from `0x00435D90+0x0C..+0x2C` into the work
  block, creates one script process through `0x002972F8`, lets `0x0023EBC8`,
  `0x00328F60` and `0x003291D8` finish their subsystems, then sets the done
  flag at `work+0x49FC` and releases the lock through `0x002C3A24`.
- **Status:** Semantically equivalent C++ (`non_matching`). The compiled body is
  548 bytes versus the 604-byte original. Clang places the 14-entry dispatch
  table inside the function body at `+0x80` and merges the state-12 and
  state-13 tails, while the original keeps its table at `+0x28` and enters the
  state-13 flag store separately. The observed ABI, call order, pointer copies,
  halfword stores and termination behavior are identical. The ledger row is
  classified `non_matching` with this record.

## Contract and Behavior


- `work = r0` is a pointer to the 0x4A58-byte battle main work object. The
  routine saves and restores `r4-r8` plus `lr` in the original; `r9-r11` are
  untouched. The C++ compiler saves `r4-r8`, `sb`, `sl`, `fp` and `lr`

### Unresolved or unchecked behavior
- `0x002972F8` is assumed to return non-null. The original stores through the
  result at `+0x108` without a guard, so a null result faults in both versions;
  that fault path is not exercised by the test.
- A dispatch value >= 14 with `work+0x49FC` bit 0 clear loops between
  `0x339DB0` and the flag test forever. The original has no other exit; the
  test covers the same default path only with bit 0 already set.
- The internal behavior of the eight helper targets is not reconstructed here;
  the test replaces each with a deterministic stub at its original address.

## Differential Verification
`python tools/test_leaf_00339d98.py` compiles
`src/engine/leaf_batch45_a.cpp`, relocates the candidate's calls and inline
dispatch table, and runs the pinned 604-byte original against the candidate in
separate Unicorn ARM machines with identical fixtures.

Compared: return `r0`, continuation PC, final SP, callee-saved `r4-r11`, the
ordered call log (including the two pointer arguments of `0x002972F8` and the
`0x3E` id), the full 0x10000-byte work page, the full script-process page, the
0x100-byte global window at `0x00435D80`, and any write outside the private
stack/work/process pages.

Coverage (42 cases):
- the full path from state 0 and resume from every state 1..13;
- the state-1 poll returning zero twice and then non-zero, plus its failure
  with the flag already set;
- passing and failing state-2..7 gates, the state-8 gate, and both
  `0x0023EBC8` results;
- dispatch boundaries 14, 15 and 0xFFFF (with the done flag set, so they take
  the same terminating default path);
- null and non-null global/work pointers, distinct pointer values, the
  process-state clear at `+0x108`, and flag values 0, 1, 0xFFFE and 0xFFFF.

Negative controls mutate the process id, one global-pointer copy source, the
argument order of `0x002972F8`, and the identity of the second tail helper;
each mutant is detected by at least one case.

Limits: this is an isolated function-level differential test. It does not
prove whole-game runtime equivalence, the helper bodies, or the behavior of a
null `0x002972F8` result / non-terminating default loop.
