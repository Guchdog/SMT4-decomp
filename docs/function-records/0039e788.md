# Function Record: engine_func_0039e788 (0x0039e788)

## Summary
- **Address:** `0x0039e788`
- **Size:** 844 bytes (original span `[0x0039e788, 0x0039ead4)`)
- **File:** `src/engine/leaf_batch45_b.cpp`
- **Role:** Second-stage placement publisher. For two placement arrays it
  walks every slot, converts each active slot's four stored floats into
  screen-space coordinates, copies a halfword tag, and publishes a
  pairing/mode selector word. The engine-context byte at `+0xD5A` selects
  whether the coordinate origin is derived from the full or the halved work
  extents.
- **Status:** Semantically equivalent C++ (`non_matching`). The compiled body is
  520 B versus the 844 B original. The compiler folds the two layouts into
  shared code, keeps the loop count/indices in different registers, and omits
  the original's duplicated cold tails; the literal-pool gap in the middle of
  the original is not reproduced. The ledger row is classified `non_matching`
  with this semantic record.

### Control flow
```text
ctx = 0x2C2B1C(self)
origin = 0x231F58(self + 0x162)          // two floats at origin[0], origin[1]

for pass = 0, 1:
    count = pass==0 ? (s32)self[0x5A88] : (s32)self[0x61B0]
    full  = ctx[0xD5A] == 12
    ex    = (s32)self[0xB80]
    ey    = (s32)self[0xB84]
    px    = (s32)((f32)(full ? ex : ex/2) - origin[0])
    py    = (s32)((f32)(full ? ey : ey/2) - origin[1])
    for i = 0; i < count; ++i:            // signed loop bound
        e = self + i*0x4C + (pass==0 ? 0xE88 : 0x5A90)
        if (u16)e[0x34] == 0: continue
        (u16)e[0x36] = (u16)e[full ? 8 : 0xA]
        base_off  = full ? 0x0C : 0x1C
        cx = (f32)px - 160.0f; cy = (f32)py - 120.0f
        (u32)e[0x38] = (s32)((f32)e[base_off+0]  - cx)
        (u32)e[0x3C] = (s32)((f32)e[base_off+4]  - cy)
        (u32)e[0x40] = (u32)((f32)e[base_off+8])
        (u32)e[0x44] = (u32)((f32)e[base_off+12])

            || (kind==0x8D && id==0x8E) || (kind==0x8E && id==0x8D)
            || (kind==0x5C && id==0x5D) || (kind==0x5D && id==0x5C)

        (u32)e[0x48] = (mode==0 || mode==4)
            ? (pair ? 0xB4FF83FF : 0xFFFFFF99)
```

and in the candidate, so `count <= 0` only suppresses the slot loop.

The README/docs `address`-style normalization of the `pair_id` comparison is
exact because `ldrb` zero-extends and `cmp ip, r7` is a 32-bit compare; a word
such as `0x0000018D` therefore does **not** pair with kind `0x8D`.

## Contract Corrections / Domain Limits
- **Halving is truncating signed division.** The original sequence
  `add r0,r0,r0,lsr#31; asr r0,#1` is exactly `s32/2`, including negative
  extents (for example `-1 / 2 == 0`, `-3 / 2 == -1`).
- **Two separate layouts, not one.** Full-scale mode (`ctx[0xD5A] == 12`) uses
  the un-halved extents and the slot fields at `+0x0C..+0x18` / copy source
  `+0x8`; the other 255 byte values use halved extents and
  `+0x1C..+0x28` / copy source `+0xA`. Both write `+0x36` and `+0x38..+0x48`.
- **`+0x48` is not always `0xFFFFFFFF`.** When `mode` is 0 or 4 it distinguishes
  the paired (`0xB4FF83FF`) and unpaired (`0xFFFFFF99`) record; any other mode
  ignores pairing.
- **Float-to-integer conversion domain.** `vcvt.s32.f32` / `vcvt.u32.f32` use
  round-toward-zero and VFP saturation for NaN/out-of-range inputs. The C++
  `static_cast` assumes finite in-range values; NaN/overflow inputs are outside
  the verified domain. The differential cases keep converted values in range.
- **Counts and indices are signed.** The loop uses `blt`; negative counts skip
  the pass. Counts larger than the physical array are not clamped and are
  outside the verified domain.
