# Function Record: engine_func_002f7f18 (0x002F7F18)

## Summary

- **Address:** `0x002F7F18`
- **Size:** 432 bytes (`[0x002F7F18, 0x002F80C8)`): 105 ARM instructions through
  the unconditional `pop {r4, r5, r6, r7, r8, sb, sl, fp, pc}` at `0x002F80B8`,
  followed by the three literal words at `0x002F80BC..0x002F80C7`:
  `0x0043427C`, `0x51EB851F` and `0x010001C1`.
- **File:** `src/engine/leaf_batch41_c.cpp`
- **Role:** Sweeps four actor records, filters them by their flag word and
  signed id, scales two signed 16-bit stats into percentages, and emits one
  `0x0027E1A0` + one `0x00250800` call per surviving actor.
- **Status:** Semantically equivalent C++ (`non_matching`). The candidate body is
  436 bytes versus 432 bytes. The eight direct calls, the call order, every
  register and stack argument, the loop bound, the skip conditions, the
  truncating `mul`/`0x51EB851F` division, the clamp and the zero rewrite are
  preserved. Behavioural support is the differential runner below, not byte
  identity.

## Contract and ABI

```cpp
extern "C" u32 engine_func_002f7f18(void);  // r0 = 1 on every path
```

- `r0..r3` are never read. The prologue saves `{r4, r5, r6, r7, r8, sb, sl, fp,
  lr}` and reserves `0x34` bytes; the epilogue restores exactly those, so every
  callee-saved register (`r4-r11`) and `SP` survive. The pinned original never
  touches VFP.
- Frame use: `[sp+0x00..0x20]` are the nine outgoing stack arguments of the
  `0x0027E1A0` call, `[sp+0x24]` caches the `0x0027EB98` result,
  `[sp+0x28]`/`[sp+0x2C]` cache the first two `0x00296F60` results.
- **Return value:** `mov r0, #1` before the final `pop`. No static `bl`/`blx`
  reaches this address (see *Callers*), so the consumer of the return value
  cannot be observed. It is modelled as `u32` to keep the differential exact.
- The two float-shaped helper arguments (`0x0027E1A0` argument 12 and
  `0x00250800` argument 6) are **stack words** in the original: `0x0027E1A0`
  reloads its copy with `vldr s16, [sp, #0x64]` and `0x00250800` with
  `vldr s16, [sp, #0x24]`. The caller writes plain zero words
  (`str fp, [sp, ...]`, `fp = 0`) and never programs `s0`. Because this
  translation unit is built with `-mfloat-abi=hard`, the reconstruction
  declares those two parameters as `u32` carrying the `0.0f` bit pattern
  (`kZeroFloatBits = 0`); declaring them `f32` moved them into `s0` and shrank
  the outgoing frame by one word, which the differential caught.

## Recovered behaviour

### Selector resolution (`0x002F7F20..0x002F7F50`)

1. `scale_a = engine_func_00296f60(0)`
2. `scale_b = engine_func_00296f60(1)`
3. `limit_selector = engine_func_00296f60(2)`; the results of the first two are
   spilled to `[sp+0x28]`/`[sp+0x2C]` before the third call runs.
4. `limit = (s32)limit_selector > 0 ? 0x3E0 : 0`. The comparison is **signed**
   (`cmp r4, #0` / `movgt`), so `0x80000000` selects 0 and `0x7FFFFFFF` selects
   `0x3E0`. `0x3E0` (992) is otherwise unexplained by the ARM; it is only
   forwarded to `0x0027E1A0`.
5. `handle = script_vm_func_0027eb98(*0x0043427C)`. `0x0043427C` is the
   canonical `script::g_ScriptVmContext_43427c` slot; `0x0027EB98` dereferences
   it again and returns 0 for a null context or an out-of-range `[ctx+0x84]`
   field. The result is resolved once and forwarded to both per-actor calls.

### Actor sweep (`0x002F7F70..0x002F80B4`)

`index` runs `0..3` (`cmp r4, #4` / `blt`). At the top of every iteration
`ui_func_00293c98()` (returns `*0x00435D90`) is called; the actor array base is
`*(ui_state + 0x1FC0)` and the entry is `base + index*648` (the ARM builds
`index + index<<4 + index<<6`, then `<<3`, i.e. `index*81*8`).

An entry is skipped when any of:

- bit 0 of the word at `[actor+0x00]` is clear,
- bit 6 of that word is set,
- the `s16` at `[actor+0x08]` is negative (`ldrsh` / `cmp #0` / `blt`).

Any other bit of the flag word is ignored.

### Scaling and clamping (`0x002F7FAC..0x002F801C`)

For a surviving actor:

```
raw_a = (s16)[actor+0x1B6]        // add r0, r5, #0x100 ; ldrsh [r0, #0xb6]
clamp = (u16)[actor+0x1C6]        // ldrh [r0, #0xc6]
raw_b = (s16)[actor+0x1BA]        // ldrsh [r0, #0xba]

v_a = (s32)low32(raw_a * scale_a) / 100;   // mul + smull 0x51EB851F + asr #5
v_b = (s32)low32(raw_b * scale_b) / 100;

if ((clamp & 8) != 0 && v > 1) v = 1;
if (v == 0) v = -1;               // `cmp r7, #0` / `mvneq r7, #0` (MVN -> -1)
```

- `scale_a`/`scale_b` are the raw 32-bit words from `0x00296F60`; the `mul`
  keeps only the low 32 bits, then `smull`/`asr #5` with the sign fixup performs
  a truncating signed division by 100. The reconstruction reproduces the wrap
  explicitly (`wrap_to_s32`) and uses C++ integer division, which truncates
  toward zero the same way.
- The clamp is a one-sided `min(v, 1)` gated by bit 3 of the `u16` at
  `[actor+0x1C6]`; no other bit of that word is examined.
- The zero rewrite uses **MVN**, not MOV: a result of 0 becomes `0xFFFFFFFF`.
  It applies after the clamp on both values.
- Load order is preserved (`raw_a`, `clamp`, `v_a`, `raw_b`, `v_b`).

### Emit (`0x002F8020..0x002F80A0`)

A second `ui_func_00293c98()` call re-derives the array base; the record is
`*(ui_state_2 + 0x1E98) + id*276` (`0x1C00+0x298`, then
`id + id<<2 + id<<6`, `<<2`), where `id` is the actor's `s16` reloaded from
`[actor+0x08]` after that call. With `slot = emitted*5` (`emitted` counts the
survivors):

```
0x0027E1A0(r0=0, r1=handle, r2=record, r3=0,
           [sp+0x00]=v_a, [sp+0x04]=v_b, [sp+0x08]=-1, [sp+0x0C]=limit,
           [sp+0x10]=slot, [sp+0x14]=slot, [sp+0x18]=9,
           [sp+0x1C]=0.0f, [sp+0x20]=0, [sp+0x24]=0);
0x00250800(r0=slot, r1=handle, r2=0x010001C1, r3=0,
           [sp+0x00]=0, [sp+0x04]=0.0f, [sp+0x08]=0);
```

`emitted` starts at 0 and is incremented only after both calls, so the slot
values are 0, 5, 10, 15. `0x010001C1` is a literal constant (not a pointer).
Neither helper's return value is used; both results are dead.

## Differential verification

`tools/test_leaf_002f7f18.py` compiles `src/engine/leaf_batch41_c.cpp`, extracts
the `engine_func_002f7f18` body, resolves its eight `R_ARM_CALL` relocations to
deterministic stubs at the original addresses, and runs the pinned original
against the candidate on separate Unicorn ARM machines with identical fixtures.
CPACR/FPEXC are programmed because the candidate spills `d8` for stack
alignment.

Per case it compares:

- returned `r0` (must be 1), continuation PC (`0x90000000` trap), final SP, and
  callee-saved `r4-r11` plus `d8-d15`;
- the ordered call log with every register argument and the architected stack
  words of each helper (nine for `0x0027E1A0`, three for `0x00250800`), so both
  float-shaped slots are checked as words;
- both actor tables, both UI state pages, both record tables and the
  script-context slot page, byte for byte (all must be unmodified);
- every emulated write outside the private stack (none expected).

Coverage (59 cases):

- every skip condition at every visit slot: bit 0 clear, bit 6 set, flag word
  `0xFFFFFFFF`, negative ids `-1` and `-32768`, zero, one and four emitted
  actors;
- id boundaries `0, 1, 2, 255, 949` and a mixed id set (record pointer is part
  of the call log);
- `s16` value boundaries `0, 1, 99, 100, 101, 32767, -1, -100, -32768` with the
  clamp bit clear and set, plus clamp words `0x0004, 0x0010, 0x8000, 0xFFFF`
  proving only bit 3 matters;
- scale words `0, 1, 100, 0xFFFFFFFF, 0x80000000, 0x7FFFFFFF, 0x01000000` with
  `raw = 32767/-32768/-1/2`, exercising the low-32-bit wrap and negative
  division truncation;
- signed `limit_selector` boundaries `0, 1, 2, -1, 0x80000000, 0x7FFFFFFF`;
- null and non-null `0x0027EB98` results, null and non-null context-slot words;
- a case where `0x00293C98` alternates between two UI state pages (with distinct
  actor and record tables), which detects a wrong actor-vs-record call order;
- a combined case: four emitted actors, clamping, alternating pages, limit 0.

Result: **59/59 cases pass**, plus 17 negative controls that are each detected:
hidden bit, enabled bit, actor stride, record stride, clamp bit, limit constant,
slot stride, row-start constant, `0x010001C1` constant, scale divisor, unused
`-1` argument, `>` vs `>=` limit comparison, id `<=` vs `<`, the zero-to-`-1`
rewrite, both table offsets (`0x1FC0`, `0x1E98`) and the `return 1`.

## Limits / unresolved

- The bodies of `0x00296F60`, `0x0027EB98`, `0x00293C98`, `0x0027E1A0` and
  `0x00250800` are outside this translation unit and are stubbed at their ABI
  boundary. Their internal effects (rendering, log/effect emission, script-table
  interpretation) are not reconstructed here; argument values, access widths and
  call order are.
- The meaning of the `0x3E0` limit and of the `0x010001C1` constant is not
  derivable from this function's ARM; both are forwarded values.
- The record-table consumer is not modelled, so only the computed record
  pointer's identity is verified, not how `0x0027E1A0` later reads it.
- `0x0027EB98`'s table arithmetic (a `0x3C7`-stride selector over
  `[0x00434278+4]`) is not reproduced; the function only consumes its return.
- The actor/record layouts are documented only at the offsets this function
  touches; no wider struct is asserted.
- No static caller exists (the only reference is a data-table entry), so
  caller-side integration cannot be exercised; the test drives the function
  directly.
- No emulator or whole-game run was performed for this function; evidence is
  the offline differential above. The reconstruction is not byte-identical
  (436 B vs 432 B), so `non_matching` is the truthful ledger classification and
  this record carries the semantic evidence.
