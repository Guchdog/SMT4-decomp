# `0x002B1C8C` — preview sequence/track selector

## Identity and ABI

Pinned US image SHA-256:
`1f98884fe997af22e032a14c51a46c872b05b0e079a0f29e307b0e059cfaa558`.
The executable extent is `[0x002B1C8C,0x002B1DFC)` (368 bytes), body SHA-256
`8097eb2315dd6b7f6dd72be434ee38223841c6470bfa3b923b362900572ba092`.
The function has a single object pointer in `r0`, preserves `r4-r7` and SP, and
has no direct calls. Every return restores `{r4-r7}` and branches through LR.
Most paths return the original object in `r0`; paths that write a selected or
restarted track into object words `+4/+8` return `object+4`. The H1 preview
helper calls this entry at `0x002BFC48` after `mov r0,r4`; it ignores the result.

## Direct object and table behavior

- Byte `object+0x89` is an early gate; nonzero returns unchanged. A null word at
  `+0x70` also returns unchanged. The object pointer itself is not null-checked.
- The word at `+0x70` points to 4-byte records. Each inspected record has a
  signed halfword at `+0` and an unsigned halfword duration at `+2`. The signed
  halfword index at object `+0x74` addresses `base + 4*index`; signed halfword
  progress is at `+0x76`.
- If unsigned duration is signed-greater than progress, the function increments
  progress by one as a low halfword, returns object, and performs no other
  stores.
- Otherwise it increments the signed row index with `SXTH`, resets progress,
  and reads the next record's signed halfword. `-1` enters sequence selection;
  `-2` resets the row index to zero and writes the first record's signed value
  to object `+4` and `-1` to `+8`, returning `object+4`. Any other signed value
  (including `-3`) is written to `+4` with `-1` at `+8`, also returning
  `object+4`.

## Sequence and sentinel behavior

The sequence path is entered only when the next row value is `-1`. If feature
byte `+0x84` is zero or sequence pointer `+0x78` is null, it writes `1` to
`+0x89` and returns object. Otherwise, sequence entries use a 28-byte stride;
the signed halfword index is at `+0x82`, and each entry's signed selector word
is read at entry `+8`. Current `-1` completes without incrementing the sequence
index. Other current values increment the index with `SXTH` before reading the
next entry. Next `-1` or `-3` sets `+0x89=1` and returns object. Next `-2` is
not a restart sentinel in this function: it proceeds as a signed lookup selector
and cannot equal the nonnegative empty-entry count, so a valid finite lookup
array misses and clears `+0x70`.

The lookup descriptor pointer is at object `+0x48`. Its unsigned halfword byte
length is at descriptor `+6`; the number of records is `length >> 2`. Its
pointer to 4-byte lookup records is at descriptor `+0x18`. A nonnegative
sequence selector `k` selects the record at index `i` where exactly `k`
preceding records have signed halfword `-1`; the function tests this count
before reading the current record. If no index satisfies it, or the count is
zero, object `+0x70` is cleared and the function returns object. On a match, it
stores the selected record pointer to `+0x70`, clears `+0x74`, `+0x76`, `+0x89`,
and `+0x8A`, writes the selected record's signed halfword to object `+4`, writes
`-1` to `+8`, and returns `object+4`. The lookup record's halfword at `+2`
becomes the duration used on later calls.

All addresses and signed indices are unchecked in the original. The candidate's
defined test domain therefore restricts to valid, non-aliasing object,
descriptor, record, and sequence storage. It does not assign semantics to
invalid pointers or out-of-range memory accesses.

## Differential evidence

The experimental C++ is
`experiments/semantic_equivalence/h1_preview_sequence_track_candidate.cpp`.
The private runner is `tools/h1_preview_sequence_track_experiment.py`; its
run-01 report records a compiled ARMv6K candidate differentially executed
against the pinned ARM body using offline Unicorn ARM11 MPCore. The 24 synthetic
cases cover both early gates, duration/progress comparison, ordinary row
transition, row `-2` restart and row `-3` ordinary behavior, sequence current
`-1`, next `-1/-3/-2`, disabled/null sequence, selector hits/misses, zero and
non-multiple-of-four counts, negative/minimum row indices, negative sequence
index and signed-halfword sequence-index wrap. The comparison checks return
`r0`, callee-saved registers, SP, termination/fault status, caller-owned stack,
and SHA-256 of the full mapped object/descriptor/lookup/sequence region. All
24 cases pass. A deliberate mutation reads the record duration from `+0`
instead of `+2`; it is detected by both `r0` and mapped memory differences.

Focused tests assert the final report and the function-specific `-2/-3`, lookup,
index-wrap, and mutation behavior. Evidence remains partial: only finite
synthetic memory was used. The H1 call at `0x002BFC48` was inspected statically,
not differentially. Actual object construction/lifecycle at scene `+0xD74`,
caller side effects, invalid pointers/indices, aliasing, concurrent mutation,
MMIO, and game runtime are unvalidated. This experimental entry does not alter
the exact `matching` ledger classification and is not integrated.
