| Order | Test | Result |
|---|---|---|
| 1 | `byte[+0x54] != 0` | return that byte |
| 2 | controller `+0x04D != 0` | return the controller pointer |
| 3 | controller `+0x080 == 0` | return `0` |

## Limits
- Fixtures are synthetic pattern-filled pages, not captured game memory.
- Every helper is stubbed. In particular the exact runtime identity of
  `0x002AA504` (unsigned 64-bit divide) and the heap/stream construction inside
  `0x0015C310` are not exercised; only their call arguments, call order and
  returned registers are modelled. `0x002BD448`, `0x00235DBC` and
  `0x003E73FC` are also stubbed with their statically decoded effects.
- The gather buffer in the original is exactly eight words and the original
  does not bound `slot_count_D0`. The candidate uses an eight-word array; the
  differential runner exercises bounds `0..8` only. A larger live bound would
  overwrite the original frame (and the candidate frame differently), and no
  claim is made for that case.
- Field names and object groupings are descriptive, not recovered identifiers.
  The record only claims the offsets, widths and branch/call behavior observed
  in the ARM stream.
- The candidate’s frame, register allocation and the relative order of the two
  independent byte stores at `+0x54`/`+0x56` differ from the original; the final
  memory image is identical for every tested case.
- No caller-composition or whole-game runtime equivalence is claimed; the
  indirect caller/vtable and the two large helpers are not reconstructed.
