### Control flow
1. **Fast window.** With `ys = bits(y) << 1` and `xs = bits(x) << 1`, the test
   `0xE8000000 + ys < 0xE5000000 && 0xE8000000 + xs < 0xE5000000` is true
   exactly when both biased exponents are in `24..252`. Such inputs skip the
   whole special-value prologue and go to step 5. (The compiled candidate folds
   this to a top-byte compare, a compiler-equivalent form of the same test.)
2. **NaN.** `ys > 0xFF000000 || xs > 0xFF000000` means a NaN mantissa (or a
   signalling NaN); the routine returns `y + x` through the ARM VFP default-NaN
   add.
3. **Zero and infinity rewrites** (`0x002820F4..0x0028212C`), all of which jump
   to step 5:
   - `0/0` (`(bits(y) | bits(x)) << 1 == 0`): `x = copysign(inf, x)`.
   - `inf/inf` (both patterns shift to `0xFF000000`): both clear bit 30, so
     `y = copysign(1, y)` and `x = copysign(1, x)`.
   - `inf/finite` (`ys == 0xFF000000`) or `finite/0` (`xs == 0`): the two
     variants share one block, `bits(y) |= 0x7F800000` and `bits(x) &= 0x80000000`.
     For `finite/0` the stored `s1` still holds the original zero; the tail's
     exponent delta always returns before any division in that case.
4. **Prefix rescale** (`0x00282130..0x00282154`). For every remaining input,
   when the two exponent-MSB bits agree
   (`((ys ^ xs) & 0x80000000) == 0`) both operands are multiplied by
   `bit31(xs) ? 2^-32 : 2^32`. The quotient is unchanged, but the exponent window
   selection is not: e.g. a subnormal `/ 1.0` is lifted into the normal range,
   and `1e30 / 1e30` is lowered. The `2^32` constant is only selected when the
   dividend exponent MSB is clear; `2^-32` when it is set. Both bit patterns are
   refreshed from the scaled floats.
5. **Exponent window** (`0x00282158..0x0028218C`). With `yd = ys >> 24`,
   `xd = xs >> 24` (the biased-exponent bytes) and `delta = yd - xd` (signed):
   - `delta > 27`: return `copysign(pi/2, y)`.
   - `delta < -26`:
     - `x >= 0`: compute `q = y / x`, call `0x002A4600(bits(q))`; when the
       returned class equals 4 (subnormal) call `0x002A462C(y)`; return `q`.
     - `x < 0`: return `copysign(pi, y)`.
   - otherwise continue to step 6.
6. **Quadrant reduction** (`0x002821C8..0x00282244`).
   - `ys > xs` (i.e. `|y| > |x|`): offset `copysign(pi/2)` split into
     `1.5703125 + 0.0004838268`; ratio `r = x / -y`.
   - `ys <= xs` (i.e. `|y| <= |x|`, including equal magnitudes): if `x >= 0`
     the offset is `+0.0`; if `x < 0` the offset is `copysign(pi)` split into
     `3.140625 + 0.0009676536`. Ratio `r = y / x`.
   - **Half-angle refinement.** When `(denominator_bits - numerator_bits) << 1`
     is below `0x01000000` (raw patterns within one binade), the quotient is
     computed as `r' = (r - h*den) / (den + h*num)` with
     `h = copysign(0.5, num ^ den)` and the offset is adjusted by
     `-atan(1/2)` (negative quotient) or `+atan(1/2)` (non-negative quotient),
     keeping the fine and coarse halves separate. This is the
     `tan(atan(r) ± atan(1/2))` range reduction; it moves `r` into
     `[-0.5, 0.5]` for the polynomial.
7. **Polynomial** (`0x00282274..0x002822AC`).
   `P(z) = c4 + z*(c3 + z*(c2 + z*(c1 + z*c0)))`, `z = r*r`, and
   `result = ((fine + r^3 * P(z)) + r) + coarse`. The two additions are kept in
   that order, and the coarse/fine offset halves are never pre-summed.

## Limits
- Both direct calls are stubbed rather than executed: the two helper bodies are
  still naked blocks (`0x002A4600` in `src/engine/leaf_batch10_c.cpp`,
  `0x002A462C` in `src/engine/leaf_batch21_b.cpp`). The classifier stub was
  verified against the pinned body for representative patterns, but it is not a
  reconstruction of that helper.
- The FPSCR/exception-status side effect of the `0x002A462C` underflow probe is
  not compared; the test compares the call order and argument, not the raised
  underflow flag.
- The `delta > 27` early exit is numerically immaterial at `delta == 27` (both
  paths round to `±pi/2`), so a threshold mutant at that boundary is
  behaviourally neutral and is not used as a negative control. The constants 27
  and -26 are preserved from the ARM comparison. The `delta < -26` boundary is
  observable through the classifier call at `delta == -26`.
- The `0/0` and `finite/0` bit-pattern rewrites are not observable in the final
  `s0`; they only select which tail exit is used (both yield the same
  `±pi/2`, `±0` or `±pi`). They are preserved because they are part of the
  pinned instruction sequence and can affect FP status flags.
- NaN results rely on the same ARM VFP `VADD` instruction being emitted by the
  compiler for `y + x`; the compared bit pattern includes quieting and payload
  behaviour observed under Unicorn.
- No emulator run and no canonical full-game build were performed for this
  task; callers were inspected for argument/return usage only.
