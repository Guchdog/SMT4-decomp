# Function Record: func_0035b364 (0x0035b364)

## Summary
- **Address:** `0x0035b364`
- **Size:** 616 bytes (original span `[0x0035b364, 0x0035b5cc)`; the last four
  bytes are the literal-pool word `0x00472C80`, the dispatch-table base)
- **File:** `src/engine/leaf_batch45_a.cpp`
- **Role:** Forward UTF-16 message-macro scanner. It appends one 0x10-byte node
  per token to a circular doubly-linked list anchored on the scanner object
  itself, then terminates the list with a `type = 0x12` node. Text between
  `\Q` and `\E` is copied verbatim (one literal character node each);
  whitespace is dropped; every other character is appended and then handed to a
  per-character member-function-pointer table.
- **Status:** Semantically equivalent C++ (`non_matching`). The compiled body is
  1104 B versus the 616 B original: clang lowers the 16-way character switch to
  an `R_ARM_ABS32` jump table inside the body (89 local-label entries), while
  the original indexes a shipped table at `0x00472B80` through `blx`. The
  candidate also keeps a different register allocation and a larger frame. The
  ledger row is classified `non_matching` with this semantic record; the byte
  difference is not a behavioral difference.

## Contract and Behavior

### Signature and ABI
```c
extern "C" s32 func_0035b364(MsgScanner* self, void* allocator,
                             const u16* text, u32 length);
```
- `self = r0`, `allocator = r1`, `text = r2`, `length = r3`.
- Returns `0` after the terminator node is appended, `1` when the node
  allocator returns null, `2` for a `\E` seen outside verbatim mode, otherwise
  the first non-zero handler result (the scan stops at that point).
- Saves and restores `r4-r8` and `sb` (`r9`); the `push {r3, ...}` word is frame
  padding. Final `sp` equals the entry value; `r3` is not an in/out value.
- The only call site in the pinned image is `0x0035EE90`: `r0` is an object
  allocated with `0x00238C44(pool, 2)` and constructed by `0x0035C23C`, `r1` is
  the same pool handle, `r2` the UTF-16 text and `r3` its length. The caller uses
  the return value as a success flag (`cmp r0, #0; bne 0x0035EFA8`).

### Scanner object layout (recovered)
```text
+0x00  Node*  list head (newest node)   \ the object is the circular
+0x04  Node*  list tail (oldest node)   / list's sentinel
+0x08  void*  allocator handle            written at entry
+0x0C  const u16* text                   written at entry
+0x10  u32    cursor                     NOT written at entry (input state)
+0x14  u32    length                     written at entry
+0x18  s32    depth                      written to 0 at entry
```
`0x0035C23C` (the caller's constructor) sets `+0x00 = +0x04 = self` and zeroes
`+0x08..+0x18`, so `cursor` starts at 0 in the shipped flow. It is the only
initializer of `+0x10`; this scanner simply continues from it.

### Node layout (0x10-byte allocator unit)
```text
+0x00  Node*  next
+0x04  Node*  prev
+0x08  u8     type
+0x09  u8     (never written)
+0x0A  u16    character
+0x0C  u16    value      (second number of a "{first,second}" token)
+0x0E  u16    (never written)
```
`0x00238C44(pool, n)` is a 16-byte-unit free-list allocator: it scans the byte
bitmap at `[pool]` for the first run of `n` free bytes (starting at the search
position `[pool + 8]`), marks them used and returns
`[pool + 4] + offset * 16`, or null. The scanner always asks for one unit.

`append_node` reproduces the original's four stores exactly: new node
`next = self->head`, `prev = (Node*)self`, `self->head = node`, old head
`prev = node` (insertion at the head of the circular list).

### Control flow
Entry: store `allocator`, `text`, `length`, `depth = 0`; `verbatim = false`.
If `self->cursor == length`, jump to the terminator. Otherwise loop while
`self->cursor != self->length`, re-reading both words each iteration (handlers
may advance the cursor).

Verbatim state (`r5 != 0`):
1. If `cursor != length - 1` and `text[cursor] == '\'` and
   `text[cursor + 1] == 'E'`: `cursor += 2`, `verbatim = false`.
2. Else if `text[cursor]` is `0x0020` or `0x3000`: `cursor += 1`.
3. Else append a node with `type = 0` and `character = text[cursor]`, then
   `cursor += 1`.

Unquoted state (`r5 == 0`):
1. If `cursor != length - 1` and `text[cursor] == '\'` and
   `text[cursor + 1] == 'Q'`: `cursor += 2`, `verbatim = true`.
2. Else if `cursor != length - 1` and `text[cursor] == '\'` and
   `text[cursor + 1] == 'E'`: return `2` (input is not consumed).
3. Else if `text[cursor]` is `0x0020` or `0x3000`: `cursor += 1`.
4. Else append a node, copy its address into a stack slot, and call
   `dispatch(self, &slot)`; a non-zero result is returned immediately.

Terminator: append a node, set only `type = 0x12`, return `0`.

### Character dispatch
The original loads `r8 = 0x00472C80` from the function's literal pool, then
reads the 8-byte entry `{handler, this-adjust}` at
`0x00472B80 + 8 * character` (so the first live entry, for `' '`, is
`0x00472C80`; the table spans `0x00472C80..0x00472F78`). Out-of-range
characters (`character < 0x20` or `> 0x7E`) skip the table and call
`0x0035BBC4` directly. The call is
`handler(this + (adjust >> 1), &node)`; when `adjust & 1` is set the original
loads the vtable from the adjusted object and calls the virtual slot (the
member-function-pointer virtual path). **Every shipped adjust word is zero**, so
the virtual path never executes and each handler simply receives the scanner and
the address of the new node. The adjustments are documented here but not
reproduced, because the shipped table has no non-zero entry.

## Contract corrections found during implementation
- **`+0x10` is an input, not an output.** The entry writes `+0x08`, `+0x0C`,
  `+0x14` and `+0x18` only; the cursor is read before it is written, so the
  scan resumes from the caller's cursor value. `0x0035C23C` is what zeroes it.
- **The table base is `0x00472C80`, not `0x00472B80`.** The index is the raw
  character (`add r2, r8, r2, lsl #3`, then `[r2, #-0x100]`), so the entry for
  `' '` is `0x00472B80 + 8 * 0x20`.
- **The virtual-dispatch branch is dead code with the shipped data.** All 95
  `this-adjust` words are zero; the candidate therefore calls the handlers
  directly instead of modelling the vtable load.
- **The escape probes read two units.** Both `\Q` and `\E` require
  `cursor != length - 1`; when the backslash is the last unit it is handled as
  an ordinary character node (verbatim) or by the `'\'` handler (unquoted).
  A stray `\E` returns 2 *without* advancing the cursor.
- **Verbatim mode drops whitespace.** `0x0020` and `0x3000` are skipped in both
  states, so verbatim text is not literally byte-preserving for spaces.

## Limits
- Fixtures are synthetic; the UTF-16 strings and scanner/depth state are not
  captured game data.
- Every callee is stubbed: the allocator (`0x00238C44`) and all sixteen
  handlers (`0x0035B254`, `0x0035B294`, `0x0035B2D4`, `0x0035B324`,
  `0x0035BBC4`, `0x0035BBF8`, `0x0035BC38`, `0x0035BC78`, `0x0035BCF8`,
  `0x0035BD64`, `0x0035BF8C`, `0x0035BFCC`, `0x0035C128`, `0x0035C168`,
  `0x0035C1A8`, `0x0035C210`). The stubs model the handlers' documented
  observable effects (type/character/value writes, cursor advance, depth
  change, return codes) but not any real pool allocation, macro validity
  checking, `{...}` numeric formatting or `\`-escape sub-dispatch performed by
  the real bodies.
- The semantic meaning of node types (`0x00`, `0x01`, `0x05`..`0x12`) and of
  the `{first,second}` value pair is not established; they are treated as
  opaque constants.
- Domain limit: `cursor <= length` must hold at entry. A cursor past `length`
  (or `length == 0` with a non-zero cursor) makes the original index outside
  the text; the candidate reproduces the same read/behaviour but no test case
  exercises it because it depends on unmapped memory.
- The candidate's internal frame, register allocation and switch lowering
  differ from the original; only the documented ABI inputs, handler call
  arguments, memory effects and returned status are compared.
- No caller-composition, integration or whole-game runtime equivalence is
  claimed.
