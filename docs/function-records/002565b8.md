# Function Record: script_vm_func_002565b8 (0x002565b8)

## Summary
- **Address:** `0x002565b8` (original span `[0x002565b8, 0x00256750)`, 408 bytes,
  including the single `0x51EB851F` literal at `0x0025674c`)
- **File:** `src/engine/leaf_batch33_c.cpp`
- **Role:** Two-pass decay of signed 16-bit values. Modes 0, 2 and 3 first lower
  the `s16` at `+0x2A` of the shared record returned by `0x002B66EC`; modes 0/1
  then walk a counted signed-byte category list at `+0x90F0`, and modes 2/3
  walk three fixed entries at `+0x9108`, lowering the same `+0x2A` field of the
  indexed record returned by `0x002A89E4`. Every decrement is a truncated
  signed percentage, and every result is saturated at 1 and at the record's
  upper bound.
- **Status:** Semantically equivalent C++ (`non_matching`). The compiled body is
  472 bytes versus 408 original bytes. Clang splits the `u16` record accesses
  into byte pairs (the record base is `u8*`), folds the redundant `sxth` after
  the lower clamp, and expands the division by 100 into the usual
  multiply-high sequence. Register, memory and call behavior match the original
  on the tested domain. The ledger row is classified `non_matching`; this
  record carries the semantic evidence. The body does not fit the original
  408-byte slot, so no in-place integration was attempted.

## Contract and Behavior

### Signature and ABI
```c
extern "C" void script_vm_func_002565b8(u32 mode, u32 bit, s32 scale);
```
- `r0` = `mode`, `r1` = `bit` (mask index), `r2` = `scale` (signed
  percentage multiplier). Incoming `r3` and the stack are never read.
- The original saves `r4-r8`, `r9`, `r10`, `lr` (`sl` is saved but never used),
  uses no VFP, and restores `sp` and every callee-saved register.
- The original has no defined return value. Its final `r0` is whatever the last
  path left in the register (a mask halfword, a record pointer or a computed
  value depending on the branch), and no caller was recovered. The C++ is
  therefore `void`; the test records `r0` for diagnostics but does not use it as
  an equality gate.

### Mask index and record fields (ARM evidence only)
- `bit` is used as an ARM register-shift count: `r7 = 1 << (bit & 0xFF)`; a
  count of 32 or more produces zero.
- Both record masks are read as `u16`. Consequently only shift-bit indices
  0..15 can ever match; indices 16..31 (already excluded by the shift rule for
  counts >= 32) are ANDed with a 16-bit value and cannot match.
- Shared record (`0x002B66EC`, fetched six times):

| Offset | Width | Use |
| --- | --- | --- |
| `+0x72` | u16 | reject when bit 1 (`0x2`) or bit 10 (`0x400`) is set; accept only when the shift bit is set |
| `+0x1C` | s16 | first fetch: multiplier base; sixth fetch: upper bound |
| `+0x2A` | s16 | fifth fetch: current value; sixth fetch: decrement store |

- Indexed record (`0x002A89E4`, one fetch per non-negative list entry):

| Offset | Width | Use |
| --- | --- | --- |
| `+0x44` | u16 | reject when bit 1 (`0x2`), bit 10 (`0x400`) or bit 2 (`0x4`) is set; accept only when the shift bit is set |
| `+0x0E` | s16 | multiplier base and upper bound |
| `+0x2A` | s16 | current value and decrement store |

- List bases are relative to the pointer returned by `0x002A8A08`:
  `+0x90F0` for the counted pass and `+0x9108` for the three fixed entries.
  The counted length comes from `0x002A8A1C`; the fixed count is 3. List
  entries are read with `ldrsb`, so bytes `0x80..0xFF` are negative and skipped.

### Arithmetic (exact operation order)
First and second passes share the same sequence:
```
product = (s32)((u32)base * (u32)scale)      // mul: low 32 bits, modular
amount  = trunc(product / 100)               // signed division toward zero
if (amount <= 0) amount = 1                  // signed
value   = current - amount
if (value <= 0) value = 1                    // signed
value   = (s16)value
if (value > limit) value = limit             // signed; no lower clamp here
else if (value < 1) value = 1                // signed
store u16 value at +0x2A
```
- The original computes the division with `smull` against `0x51EB851F`,
  `asr #5` and a sign correction. That sequence is exactly truncating signed
  division by 100 for every 32-bit input (checked over the full range by
  analysis, not by exhaustive enumeration).
- Because `current` is an `s16` and `amount` is forced to at least 1, the
  `value = (s16)value` step is redundant; the C++ keeps it explicit and Clang
  removes it. The comparisons visible in the compiled candidate therefore use
  the pre-truncation value, which cannot differ.
- The upper-bound branch deliberately skips the floor of 1: a limit of 0 or a
  negative limit is stored unchanged when `value > limit`.

### Control flow
1. Compute the shift mask from `bit`.
2. If `mode` is 0, 2 or 3:
   - fetch the shared record and read `u16[+0x72]`; stop the pass on bit 2.
   - fetch again and read `u16[+0x72]`; stop on bit `0x400`.
   - fetch again and read `u16[+0x72]`; stop when the shift bit is clear.
   - fetch again, read `s16[+0x1C]` and form the modular product.
   - fetch again, read `s16[+0x2A]`, clamp, subtract and clamp.
   - fetch a sixth time, read `s16[+0x1C]`, clamp the value and store `u16` at
     `+0x2A`.
3. If `mode` is 0 or 1: call `0x002A8A1C` for the count, then `0x002A8A08` for
   the base, and use base `+0x90F0`. If `mode` is 2 or 3: use count 3 and base
   `+0x9108` after one `0x002A8A08` call.
4. For `index = 0 .. count-1` (signed comparison; a non-positive count skips
   the loop): read the signed-byte category; skip it when negative; call
   `0x002A89E4(category)`; skip a null result; apply the `+0x44` gates and the
   shift bit; then run the arithmetic above using `+0x0E` and `+0x2A`.
5. Return.

## Domain Limits
- All four direct callees are stubbed. Their real bodies (global-pointer
  dereference, indexed record arithmetic and the 24-entry count loop) are not
  executed; only the arguments and return values observed here are modeled.
  Their contracts above come from disassembling the pinned helpers.
- Null helper results are exercised with address 0 mapped as a zero page. The
  first pass then reads and stores at `0x72`/`0x2A` exactly as the original
  does. In the second pass the original also reads `+0x44`, `+0x0E` and
  `+0x2A` before its `cmp r1,#0`; the C++ returns immediately on a null record,
  which produces the same observable memory under a mapped zero page but avoids
  the fault the original would take when address 0 is unmapped. Fault timing is
  therefore not modeled.
- Clang emits the `u16` loads and stores as two byte accesses, while the
  original uses `ldrh`/`strh`. The two-byte content is identical for the
  aligned synthetic records, but unaligned or page-crossing accesses do not
  reproduce `ldrh`/`strh` fault/rotation semantics.
- Counted lengths above 100 are not exercised; the loop is linear in the
  helper-provided count, so very large counts are a runtime/performance limit,
  not a recovered bound.
- The test covers the function in isolation. No emulator run, staged image,
  caller composition, production integration or whole-game equivalence is
  claimed.
