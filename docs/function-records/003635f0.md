# Function Record: func_003635f0 (0x003635f0)

## Summary
- **Address:** `0x003635f0`
- **Size:** 444 bytes (original span `[0x003635f0, 0x003637ac)`; 110 ARM
  instructions through the unconditional `pop`, then the four-byte descriptor
  address `0x004105AC`)
- **File:** `src/engine/leaf_batch41_c.cpp`
- **Role:** Manager teardown/synchronisation pass. Walks three manager-owned
  pointer vectors (registered objects at `+0xEC`, owners at `+0x0C`, entries at
  `+0x3C`), notifies two direct helpers and three virtual slots, clears and
  re-sets per-entry state flags, then dispatches the registered list through the
  two-word member-function-pointer descriptor at `0x004105AC`.
- **Status:** Semantically equivalent C++ (`non_matching`). The compiled body is
  456 B versus the 444 B original because the compiler materialises the
  descriptor address as a literal-pool word and uses a different register
  allocation; the explicit return of the dead `r0` also costs a few bytes. The
  ledger row is classified `non_matching` with this semantic record.

## Contract and Behavior

### Signature and ABI
```c
extern "C" u32 func_003635f0(void* context, void* manager);
```
- `context = r0`, `manager = r1`; both are non-null in the recovered usage.
- The source-level contract is `void` (the callers ignore `r0`). The candidate
  returns `r0` explicitly because the original leaves the final dispatch result
  in `r0`, and `0x004105AC` when the final vector is empty. This is ABI-neutral
  for callers.
- The original preserves `r4-r8, sb, sl, fp`; `ip` is pushed only as stack
  padding and restored. Final `sp` equals the entry value. No stack arguments
  are consumed.
- All vector elements and object fields listed below are 32-bit little-endian
  loads/stores except the two flag bytes, which use `ldrb`/`strb`.

### Control flow and calls
1. For every `object = *it` in `[manager+0xEC, manager+0xF0)`:
   `func_00361c64(*(u32*)(object+0x28), 0)`.
2. For every `owner = *it` in `[manager+0x0C, manager+0x10)`:
   - `children = *(u32*)(owner+0x34)`;
   - inner vector `[children+0x08, children+0x0C)`; for every
     `child = *inner`, with `vtable = *(void***)child`:
     `vtable[0](child, owner, manager)` (r0=child, r1=owner, r2=manager);
   - `vtable = *(void***)owner`;
     `vtable[8](owner)`, then
     `vtable[3](owner, *(u32*)(context+0x10), manager)`.
3. Repeat step 1 with mode `1`.
4. Entry clear pass over `[manager+0x3C, manager+0x40)`:
   `count = (s32)((u32)end - (u32)begin) >> 2` (arithmetic shift).
   For `index = 0 .. count-1`:
   `state = *(u32*)(entry+0x220)`, then `*(u8*)(state+0x18) = 0`.
   The count form is preserved exactly: a negative difference runs zero
   iterations and a non-multiple-of-four difference floors.
5. Entry notify pass: reload `begin`, keep the `end` loaded before step 4, and
   walk with pointer inequality (`it != end`). For each entry:
   - if `*(u8*)(entry+0x231) != 0`, skip;
   - `state = *(u32*)(entry+0x220)`; if `*(u8*)(state+0x18) != 0`, skip;
   - `func_003e138c(*(u32*)(context+0x08), state, *(u32*)(context+0x10))`;
   - `*(u8*)(state+0x18) = 1`.
   Step 4 has just cleared every state flag, so the state-nonzero branch is not
   reachable for well-formed, non-aliasing fixtures; it is retained because the
   original tests it.
6. Final dispatch over `[manager+0xEC, manager+0xF0)` using the descriptor at
   `0x004105AC = {target, adjustment}` (shipped value `{0x00375CC8, 0}`):
   - `adjusted = entry + ((s32)adjustment >> 1)` in 32-bit arithmetic;
   - if `adjustment & 1`: `vtable = *(void***)adjusted`,
     `target_address = *(u32*)((u8*)vtable + target)`;
     otherwise `target_address = target`;
   - call `target_address(adjusted)`; the last result becomes `r0`.
   With the shipped descriptor the call is the direct `func_00375cc8(entry)`.

## Memory and side effects
- The only direct memory writes are the `u8` state flag at `state+0x18` (zero in
  the clear pass, one in the notify pass).
- Helper and virtual calls can have arbitrary side effects; this function only
  supplies their arguments and ordering.
- The manager vectors and object fields are read, never written, by this
  function.

## Differential test
`tools/test_leaf_003635f0.py` compiles `src/engine/leaf_batch41_c.cpp`, extracts
the candidate body, resolves the two direct call relocations, and runs the
original and candidate in separate Unicorn ARM machines with identical fixtures.
It compares `r0`, continuation PC, final SP, `r4-r11`, the ordered call log
(meaningful register arguments; no helper has stack arguments), every byte of a
1 MiB fixture region, the descriptor, and all writes outside the private stack.

The suite has 45 differential cases: empty and non-empty instances of all three
vectors, loop bounds 0..3, owner child counts `0`, `1`, `3`, and mixed lists,
skip-flag classes `00/01/7F/80/FF`, initial state-flag classes, context and link
boundary values, zero/non-zero helper results, the empty-final-vector return, and
both descriptor branches (even/odd, positive/negative adjustment, alternate
direct target, virtual offsets 0/8/0x10). Four negative controls mutate the
registered-link offset, the bare vtable slot, the context second-word offset and
the skip-flag offset; each mutant is detected.

Command: `python tools/test_leaf_003635f0.py`

## Limits
- Helpers and virtual targets are deterministic stubs, not the real
  implementations; their domains and side effects are not validated here.
- The shipped descriptor is the only real value exercised. Synthetic descriptor
  cases cover the generic member-function-pointer form but do not prove that any
  game object ever uses the virtual form.
- Malformed vectors whose byte difference is not a multiple of four are only
  meaningful for the count-based clear pass; the pointer-inequality passes would
  not terminate, so the test keeps vector bounds well-formed.
- Test vtables are word-aligned. Unaligned ARM loads are not exercised.
- No emulator or whole-game runtime scenario was run; this is a focused
  contract-level differential test.
