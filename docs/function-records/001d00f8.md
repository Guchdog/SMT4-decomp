# Function Record: camp_func_001d00f8 (0x001D00F8)

## Summary
- **Address:** `0x001D00F8`
- **Size:** 684 bytes (span `[0x001D00F8, 0x001D03A4)`, including the three
  literal-pool words at `0x001D0398..0x001D03A0`: `0.0f`, `0.01f`, `1.0f`)
- **File:** `src/engine/leaf_batch45_a.cpp`
- **Role:** Camp roster unit selection. Scores every non-zero candidate unit id
  in a caller-owned state block, keeps the best score, appends the winning id
  to the result list, clears it from the candidate list, and - when the winner
  has a battle object - appends and clears the first partner record that matches
  that object. Returns 1 when a candidate was selected and 0 when the state
  offers none.
- **Status:** Reconstructed as readable C++ and **semantically verified**
  against the pinned original. The candidate body is 712 bytes with 11
  `R_ARM_CALL` relocations and no data relocations; it is not byte-identical
  (different register allocation, larger frame, `vmul`+`vadd` instead of a
  folded `vmla`), so the ledger row is `non_matching` and this record carries
  the semantic evidence.

Notable details preserved in the C++:

- The first `0x0029EC14(id)` call at `0x001D0138` discards its result but is a
  real call (its argument is the freshly loaded id). The second call is the one
  whose pointer is used.
- `0x0026A904(id)` is evaluated once per candidate and its value is reused for
  every selected-entry comparison; the selected-entry loop does *not* recompute
  it for the candidate.
- Every loop bound is a signed `s32` compare (`ble`/`bgt` at `0x001D0114`,
  `0x001D01A0`, `0x001D01E8`, `0x001D01F8`, `0x001D0240`, `0x001D02F4`,
  `0x001D036C`); a negative count therefore skips the loop.
- The tie branch compares 16-bit unsigned ids with `bls`, so a later candidate
  replaces the winner when its id is less than or equal. `bestScore != score`
  uses the non-signalling `vcmp`/`bne` after the signalling `vcmpe`/`bgt`, which
  gives the usual "unordered replaces" IEEE behaviour; unreachable here because
  every score is a finite level expression.
- After the selection the winner id is re-read from the candidate array for the
  `0x002AE3F0` call, and the partner id is re-read from the partner array for
  the append (`0x001D0330..33C`). Both re-reads are kept.
- The result array has no capacity check: the original stores at
  `selectedIds[selectedCount]` unconditionally.

### Floating point
`score = level + level * 0.01f` with `level` in `0..31`. The original emits
`vmul`/`vmla` (`s16 = s0 + s0*0.01f` single-rounded); clang emits `vmul` +
`vadd` for the same expression. All 32 reachable levels were evaluated in
float32 arithmetic: fused and unfused forms are bit-identical for every level,
and the `+/-1.0f` weights are exact at these magnitudes, so the two forms cannot
produce a different ranking.
