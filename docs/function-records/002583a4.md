# Function Record: camp_func_002583a4 (0x002583a4)

## Summary
- **Address:** `0x002583a4`
- **Size:** 664 bytes (original span `[0x002583a4, 0x0025863c)`: 158 ARM
  instructions plus the two literal words at `0x00258634`/`0x00258638`)
- **File:** `src/engine/leaf_batch45_a.cpp`
- **Role:** Camp-scene transform/selection pass. Phase 1 adds the offset pair
  produced by `0x00340C30` to the float pairs of every child element selected
  through the camp manager's first entry table. Phase 2 re-resolves the second
  entry table's selection, notifies `0x002A2DDC`, and clears the `+0x2B0` word
  of the selected group record.
- **Status:** Semantically equivalent C++ (`non_matching`). The compiled body
  is 676 bytes versus the 664-byte original, uses a different register
  allocation and frame layout (saving `d8` and `d9`), and hoists the
  `manager + 0x84` chain reads into explicit pointer locals. No byte-identity
  claim is made. The body was absent from `HEAD` before this reconstruction
  (the ledger still pointed at this file), so the C++ replacement also restores
  the function.

  the observable `r0` identical. Callers ignore the value.

  - `+0x298`: signed 32-bit phase-2 entry count (tested with `ble`).

    table and group-slot selectors.
- Render chain tip `D` exposes a relative-offset table at `D + 0xC8`:
  `word = *(u32*)(D+0xC8)`; zero selects address `0 + idx*4` (the original

  `D + 0xC8 + word + idx*4`. The word at that element address is again a

### Control flow
1. `manager = *[0x0043DD90]`.
2. `camp_func_00340c30(self, sp+0x10, sp+0x08)` fills two float pairs. Only
   the pair at `sp+0x08` is used later; the pair at `sp+0x10` is unused.
3. Phase 1, for `i = 0; i < (s32)manager[0x194]; ++i` (bound re-read after each
   iteration):
   - Resolve the object through the `+0x84` chain and the `+0xC8` relative
     table using the signed `s16` selector at `manager+0x94+4*i`.
   - Skip unless `(object[0] & 0x10000001) == 0x10000001`; other flag bits are
     ignored.
   - For `child_index = 0; child_index < (s32)object[0x38]; ++child_index`,
     resolve the child relative slot. Skip `null` children and children whose
     `[0]` flag lacks bit `0x40000000`.
   - Read `data_offset = child[0x18]`, `element_count = child[0x28]`,
     `data_span = child[0x14]`.
   - For `element_index = 0; element_index < element_count; ++element_index`
     (unsigned), resolve the element relative slot. The original dereferences
     `element + 4` even when the relative offset was zero, so a malformed table
     faults at address 4; the candidate keeps that raw read.
   - On key match, read the signed `element[0x30]` index. Negative indices
     leave the element loop without notifying `0x2C25F0`.
   - `cursor = data_base + index`, `end = data_base + span`; while
     `cursor < end` (unsigned) update the float pair and advance by
     `child[0x24]`. A zero stride therefore hangs the original and the
     candidate alike.
   - After the float loop (including the `index >= span` case) call
     `0x2C25F0(data_base, span)`; `data_base` is `0` when the relative data
     offset is zero.
4. Phase 2, for `i = 0; i < (s32)manager[0x298]; ++i` (bound re-read):
   - Resolve `lookup`, `entry` and `group` as above from the two signed `s16`
     selectors, then resolve the relative group slot.
   - Perform the original's dead `*(u32*)(selected + 8)` load; a null
     selection therefore faults at address 8 in both bodies.
   - Call `camp_func_002a2ddc(&selected, *(u32**)(self + 0x0C))` and store
     `0` at `group + 0x2B0`.
5. Return `*(u32*)(manager + 0x298)`.

### Floating-point details
The original loads the pair, computes `x - 0.5f`, `y - 0.5f`, then
`+ 0.5f`, stores both intermediates, adds `sp+0x08`/`sp+0x0C`, and stores the
final pair. The `-0.5f` / `+0.5f` sequence uses two rounding steps and is kept
verbatim; no `-ffast-math` reassociation is assumed. The second `vadd` for `y`
uses the pair's second word, not the first.

### Signedness and arithmetic
- Both entry counts, the object data index and both loop counters that use
  `ble`/`blt` are signed.
- The child element count and the element-key table index use unsigned
  `bls`/`bhi`.
- `s16` selectors are sign-extended; their scaled table addresses are 32-bit
  wrapping adds (`lsl #2` on the two's-complement value).
- The float cursor and end are compared with unsigned `bhs`/`blo`.

## Frame and unresolved limits
- The three helpers are stubbed; their real bodies (including the callback
  behind the `0x002C25F0` veneer) are not exercised.
- The manager, render chain, object, child and element records are assumed to
  point to mapped memory exactly as the original assumes. Malformed
  relative-offset tables that resolve to null reproduce the original fault
  addresses in the tested cases, but faulting inside a partially mapped page is
  not modelled.
- `data_index` values are signed offsets added to a byte base without scaling;
  only the boundaries above are tested.
- A zero `child+0x24` stride makes the float loop non-terminating in both
  bodies; it is not exercised.
- The `0x00340C30` output pair at `sp+0x10` is never read by the original and
  is therefore only covered indirectly by call-log arguments.
- No emulator or whole-game runtime scenario was run; this record covers the
  offline differential contract only.
