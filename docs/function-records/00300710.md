### Unlisted helper at 0x003008C8

- `u8 guard` at `+0x575D`;

Behavior: a zero guard or a non-positive count returns `-1`. For an odd count,

covers every entry exactly once. The first set flag returns its 32-bit value;
an exhausted scan returns `-1`.

the image contains its address (or the Thumb-tagged `0x003008C9`). It is dead

## Limits
- Fixtures are synthetic: the UI context, slot table, unit table, VM slot and
  helper object are generated pages. The real `0x00296F60`, `0x00293C98`,
  `0x0027EB98`, `0x00250960`, `0x002553EC` and `0x00250800` bodies are not
  exercised; the stubs only model their arguments and return values.
- `0x002553EC` is called with a by-value aggregate; the runner verifies the
  resulting stack words and core registers, not the callee's interpretation of
  them. Its prologue at `0x255410/0x25541C` reads stack words 3/4/19 as
  `f32` bit patterns, which is why the words are preserved verbatim.
- No direct caller exists in the pinned image: no `BL` targets `0x00300710`.
  The address appears once as a data pointer at `0x00407178` in a table of
  `(function pointer, small integer)` pairs (paired with `2`). The indirect
  caller, its register preparation and its continuation are unresolved and were
  not exercised.
- The unlisted `0x003008C8` helper is dead code in this image (no direct or data
  reference). Its C++ copy is tested in isolation; no integrated caller exists
  to exercise it.
- No emulator or whole-game runtime scenario was run. Byte identity is not
  preserved (488 B vs 688 B, the difference being compiler-selected
  instructions and the separately placed helper).
