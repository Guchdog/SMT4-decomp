# Function Record: engine_func_00155fd0 (0x00155FD0)

## Summary

### Cleanup predicate
The original performs `r8 = (s8)[object+0x0E]` and finally `ands r8, r8, r0`
where `r0` is `counters_active | has_work_callback` (0 or 1). The result is used
only as a zero/non-zero test. Because the AND is with a 0/1 value, the effective
predicate is `(selector & 1) != 0 && (counters_active || has_work_callback)`;
sign-extended selector values with bit 0 clear (for example `0xFE` or `0x80`) do
not enable cleanup even though the getter arm still runs.

### 64-bit frame duration
The original computes `ldrd` of the helper interval, then `subs`/`sbc` for
`end_tick - start_tick`, then `adds`/`adc` to add the interval. The candidate
evaluates `measured + (end_tick - start_tick)` with `u64` wrap-around and stores
the low word first, high word second (the original stores high then low with no
observable access in between). If `[object+0x08]` is set at the end of an
iteration but was clear at the start, `start_tick` is zero, exactly like the
original's zeroed `r5:r6`.

## Domain Limits
- `0x002AD630`'s singleton identity (`0x004E8518`) is read from its literal
  pool, but the differential test substitutes a deterministic pointer because
  the real object lives in exheader/private data. The original would fault on a
  null return; the candidate dereferences it identically.
- The original forwards `r1`/`r2`/`r3` to `0x002AD630` unchanged; the C++
  reconstruction only guarantees `r0`. The shipped `0x002AD630` ignores all
  register inputs, so this is unobservable for the real callee.
- The work/second callback targets, the profiler-getter values, the tick values
  and the two `0x00159DC4`/`0x002A232C` sync helpers' internals are unresolved;
  the test substitutes deterministic arguments and results. In particular the
  loop's termination depends on called code clearing `[object+0x0D]`.
- `__sync_synchronize()` is lowered by the pinned compiler to the ARMv6 DMB form
  (`mcr p15,...,c7,c10,5`) while the original emits DSB (`c7,c10,4`). Both are
  full barriers for the single-threaded translated control flow; the difference
  is not observable in the offline model.
- The lock helpers, the two sync helpers and the callbacks were not executed
  against their real implementations; runtime behaviour of the audio/frame loop
  was not exercised. This record covers offline differential equivalence only.
