# Function Record: engine_func_001069bc (0x001069bc)

## Summary

- **Size:** 400 bytes (original span `[0x001069bc, 0x00106b4c)`)
- **File:** `src/engine/leaf_batch28_a.cpp`
- **Role:** One-shot boot configuration of the global render camera block:
  construct the projection block, feed it the current screen dimensions,

6. Basis matrix handed to the camera helper (3x4, row stride `0x10`):
   ```text
   length = sqrt(p0 * p0)              // vsqrt after vmla from 0
   axis   = p0 * (1.0f / length)       // vdiv, then vmul

   row0 = ( axis, 0,    0,    -0.0f )
   row1 = ( 0,    1.0,  0,    -0.0f )
   ```

   The original computes `axis` as `p0 * (1/|p0|)` (division first, then
   multiply); the C++ keeps that order so the sign is bit-exact. The
   Y component (`s1` of the incoming float vector) does not participate.
7. `func_0011cfa4(camera, mtx34)` — 0x0011CFA4 passes the matrix to
   `0x002A84EC` (3x4 inversion), stores the inverted translation at
   `camera+0x4B8..0x4C0`, then copies the normalised basis rows to
   `camera+0x4C4`, `camera+0x4D0`, and `camera+0x4DC` with the third row
   negated.
8. `ui_func_002c1774(camera, p0, p3)` — 0x002C1774 stores `p0` at
   `camera+0x504` and `p3` at `camera+0x500` (clip range; same helper used by
   the effect/scene paths under the `AsdCamera_SetClipRange` spelling).
9. `battle_func_002c1740(camera)` — 0x002C1740 inserts `camera` into the
   first null slot of the 32-entry table at `*(u32*)(0x0044EA58 + 4)`; no

## Limits
- Every helper is stubbed. The real constructor body, the screen accessor
  globals, the 0x002A84EC matrix inversion, and the global camera table are not
  exercised; only the behavior this function observes is modelled.
- The camera block is synthetic memory. Values left in it by the real
  constructor/global state are not reproduced.
- `p0 = 0`, denormal `p0`, `inf`, and `NaN` are outside the supported domain:
  the original normalises `p0` (`1/|p0|` then multiply, `sqrt`), so a zero
  length produces NaN products in the matrix. The finite non-zero domain is
  covered, including negative and extreme magnitudes.
- The candidate's internal frame and register allocation differ from the
  original; only documented ABI inputs, call arguments, written object bytes,
  saved registers, SP, and continuation PC are compared.
- No caller composition or whole-game runtime equivalence is claimed. The
  integrated caller at `0x00101b20` is documented but not executed against the
  patched image in this record.
