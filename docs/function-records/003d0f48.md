- **Role:** refresh the "seen party slot" outputs of the battle work object.
  It marks one byte per battle table record, clears and rebuilds the three

- **Status:** Reconstructed as readable C++ and **differentially verified**
  against the pinned original (45 named cases plus eight negative controls).
  The candidate body is 724 bytes with 66/688 bytes identical, so the ledger row
  is `non_matching` and this record carries the semantic evidence.

## Contract and ABI

```cpp
extern "C" void engine_func_003d0f48(void** context, u8* flags);
```

- `context = r0` (kept in `r4`), `flags = r1`. `r2`/`r3` are not read.
- Prologue `push {r4, r5, r6, r7, r8, sb, sl, fp, ip, lr}`; the epilogue pops
  the same ten registers (`ip` included) and tail-branches to `0x00250FB4`, so
  SP is balanced and `r4-r11` are restored.
- **Return value:** `r0` is whatever the tail-called free wrapper returns. The
  only call site ignores it (`ldr r0, [r5]` immediately afterwards), so this
  reconstruction returns `void` and ends with the tail call.
- `[context]` is reloaded before every group of work accesses, i.e. after each
  helper call; the reconstruction re-reads it at the same points.

| `+0x1FD4` | `u32` | high word of the published mask |

The flag word of each table record (`stride 0x288`, computed as
`i * (17 + 64) * 8`) is the only field read:

- bit `0x02` or bit `0x20` set: the record is skipped entirely
  (`tst r2,#2` / `tsteq r2,#0x20` / `bne`);
- otherwise, bit `0x10` clear: `flags[0x38 + i] = 1`;
- bit `0x10` set: no byte is written.

The candidate load is narrowed to the low byte of the flag word because only
bits `0x02`, `0x10` and `0x20` are tested; the original performs a full word
load. The difference is observable only for a faulting or self-modifying upper
byte and no test relies on it.

`publish` for amount `= entry[0] + 1` (32-bit add, then truncated to a byte for
the store and masked to the low byte for the shift):

```cpp
bit = (amount & 0xFF) < 32 ? 1u << (amount & 0xFF) : 0u;  // LSL by register
work[0x1FD0 .. ] |= bit;                 // low word
work[0x1FD4 .. ] |= (bit & 0x80000000) ? 0xFFFFFFFFu : 0u;  // `asr #31`
work[0x1FE0 + position] = amount & 0xFF;
```

- `count` is at most 3, so the pair loop runs at most once; the odd path
  publishes entry 0 before it.
- The high-word term is the arithmetic sign fill of the shifted bit, **not** a
  64-bit shift: index 30 (amount 31) sets `lo |= 0x80000000` and
  `hi |= 0xFFFFFFFF`. Amounts 32 and above (positions 31..254) shift to zero, so
  the mask is unchanged while the marker byte still receives the amount.
- Equal sort keys keep their collected order (the pinned sort is a stable
  insertion sort), so the published positions for duplicates are deterministic.

## Limits / unresolved

- The comparator `0x0032B580` is invoked **inside** `0x002B7F0A`, not by this
  body. It compares the byte at `+1` first and the byte at `+2` as an unsigned
  tie-breaker; the test stub implements that ordering as a stable insertion sort
  and logs the comparator address, which is how a changed literal is detected.
  The real sort's `count > 10` path (`0x002B7D0C`) is not modelled, but the
  clamp limits this function to `found <= 255` scratch entries and the tested
  found values stay within the stable-insertion range.
- `0x002A8A08`, `0x002A89E4`, `0x0029EE4C`, `0x002B9364`, `0x002C684C`,
  `0x002C4450`, `0x00250FB4` and `0x002B7F0A` are stubbed at their ABI
  boundaries with their decoded behaviour (`0x002A89E4` = `camp + 0x90 +
  index*0x604`, `0x0029EE4C` = `+0x44` bit test, `0x002C4450` = byte fill,
  `0x00250FB4` = null-guarded free). Their internal implementations are not
  re-proved here, and real heap accounting is not exercised.
- The getter's incoming `r0` is dead on entry (`ldr r0,[pc]; ldr r0,[r0,#4];
  add r0,r0,#0x8c; bx lr`), so the reconstruction passes `0` and the test does
  not log that register. Any caller-visible effect of the leftover value would
  require a different `0x002A8A08` implementation.
- A null allocation with a non-zero count faults at address `0` in both bodies;
  the faulting instruction differs because the candidate fills the scratch entry
  bytes in a different order. The test compares fault parity, the pre-fault call
  log and the pre-fault page contents.
- The work object is treated as `[context]` plus bytes threaded through raw
  offsets; the owning structure was not recovered. The table record's leading
  word and the `+0x44` record word are named only by the bits this body tests.
- No emulator run, integrated caller composition or whole-game runtime scenario
  was performed for this function.
