# camp_func_001ce19c (0x001CE19C)

## Summary
- **Address:** `0x001CE19C`
- **Size:** 520 bytes (`[0x001CE19C, 0x001CE3A4)`)
- **File:** `src/engine/leaf_batch34_c.cpp`
- **Role:** One frame of the camp row-menu state machine. Walks the active row
  records, keeps the highlight cursor inside the enabled options, publishes the
  option's lookup value as the current selection, and commits the highlighted
  row into the camp menu (status mode, menu buffer, sound) when the actor's
  state changes.
- **Classification:** `non_matching` with semantic evidence. The compiled body
  is 472 bytes versus 520: the candidate rotates the row loop, folds the mask
  test into `tst r10, r0, lsr r7`, and has a different stack layout, but the
  branches, helper call order, argument values and stored fields are the same.
  Verified by the differential runner below.

## Contract and ABI
```c
void camp_func_001ce19c(u8* work);
```
- `r0` is the camp work block; there is no other argument.
- `void` return. No caller consumes `r0`: the two call sites either overwrite
  `r0` immediately (`0x00217CB8`) or reach `0x0029E2CC`, which reloads `r0` from
  its own literal (`0x00217F2C`). The final `r0` of the listing is the raw row
  count and is dead; the runner therefore does not gate on it.
- Prologue `push {r4,r5,r6,r7,r8,sb,sl,fp,lr}` plus `sub sp,#0xc14`; the epilogue
  restores every callee-saved register and returns to `lr`. No stack arguments
  are passed to any helper.
- `Status_GetSelectedActorPtr()` (0x0029AF4C) is called before the row count is
  inspected, so it runs even when the loop body is skipped.

## Work block layout (`work`, all offsets as listed)
| Offset | Width | Role |
|---|---|---|
| `+0x5758` | s32 | number of 0x2C-byte row records; re-read on every loop iteration |
| `+0x591C` | s32 | shared frame timer; `>= 0x18` recycles the cursor |
| `+0x5920` | u32 | cursor: ordinal of the enabled option currently highlighted |
| `+0x5700 + i*0x2C` | `Row` | row records, `i` from 0 while `count > i` |

### Row record
| Offset | Width | Role |
|---|---|---|
| `+0x60` | u16 | row/option id passed to `0x0026AAC0` |
| `+0x62` | u16 | copied into menu buffer `+0x2A` |
| `+0x64` | u16 | copied into menu buffer `+0x2C` |
| `+0x66` | u16 | enabled-option bit mask; also copied into buffer `+0x44` |
| `+0x88` | u8 | active flag (any non-zero byte) |

Only mask bits 1..10 are visited; bit 0 and bits 11..15 are ignored by the
ordinal loop.

### Selected actor record (`Status_GetSelectedActorPtr()` result)
| Offset | Width | Role |
|---|---|---|
| `+0x00` | s16 | actor id, loaded with `ldrsh` |
| `+0x14` | u16 | actor state mask compared against the row mask |

The id comparison is a 32-bit `cmp` of a sign-extended halfword against a
zero-extended halfword, so an actor id of `0x8000..0xFFFF` can never equal the
same row id.

### Menu buffer
A 0x610-byte scratch object. `0x0026AAC0` clears its first 0x604 bytes and fills
the descriptor; `0x0029DB94` copies fields up to `+0x48` into the camp context.
This routine then patches three halfwords before submitting:

| Buffer offset | Value |
|---|---|
| `+0x2A` | row `+0x62` |
| `+0x2C` | row `+0x64` |
| `+0x44` | row `+0x66` |

The listing keeps two such buffers (`sp+0` and `sp+0x604`) that overlap in their
last twelve bytes. The overlap is never read: `0x0024D9E4`/`0x0029CB94` only
touch fields `<= +0x48`, so the reconstruction uses one scratch object per
submission.

## Control Flow
1. `actor = Status_GetSelectedActorPtr()`.
2. `row = 0`; read `count`; if `count <= 0` return (signed `ble`).
3. Loop while `*(s32*)(work+0x5758) > row` (signed; count reloaded every
   iteration after the body).
   1. `entry = work + 0x5700 + row*0x2C`. If `entry[0x88] == 0`, next row.
   2. `mask = *(u16*)(entry+0x66)`.
   3. If `mask != 0`:
      1. If `(s32)(s16)*(u16*)(actor) != (s32)*(u16*)(entry+0x60)`, next row.
      2. `ordinal = 0`; for `bit = 1; bit < 11; ++bit`:
         - reload the mask; if bit not set, next bit (no ordinal change);
         - if `*(u32*)(work+0x5920) == ordinal`:
           - `0x00317FA4(0x002B0788((s16)bit))`;
           - `Status_SetMode1E71(1)`;
           - if `*(u16*)(entry+0x66) != *(u16*)(actor+0x14)`, submit the row;
         - `++ordinal`.
      3. If `*(s32*)(work+0x591C) >= 0x18` (signed):
         - `next = *(u32*)(work+0x5920) + 1`;
         - `*(u32*)(work+0x5920) = (u32)(ui_func_002c615c(next, ordinal) >> 32)`
           (the remainder in `r1`);
         - `*(s32*)(work+0x591C) = 0`.
      4. If the row mask is still non-zero, next row.
   4. Clear path: `0x00317FA4(0x002B0788(0))`; if
      `*(u16*)(entry+0x66) == *(u16*)(actor+0x14)`, next row; otherwise submit
      the row.
4. Return.

### Row submission (both paths, identical sequence)
1. `0x0026AAC0(*(u16*)(entry+0x60), buffer)`
2. `buffer[0x2A] = entry[0x62]`
3. `buffer[0x2C] = entry[0x64]`
4. `buffer[0x44] = entry[0x66]`
5. `0x0029DB94(buffer, 1, 0)`
6. `Status_SetMode1E71(1)`
7. `0x0029D924(1)`

### Edge cases preserved
- A non-zero mask with no bit in 1..10 (`0x0001`, `0x8000`, `0xF001`, ...)
  leaves `ordinal == 0`; the timer block then calls `0x002C615C(next, 0)`. The
  helper record documents quotient 0 and remainder = numerator for a zero
  divisor; that path is exercised.
- `ui_func_002c615c` is declared `u64`; only the high word (`r1`, the signed
  remainder) is stored back into the cursor.
- The row count is re-read after every iteration, so a helper that changes it
  shortens or extends the walk. This is verified with a stub that shrinks the
  count.
- `Status_SetMode1E71(1)` runs before the actor-mask comparison, so it fires
  even when the row is not submitted.

## Domain Limits
- All eight helpers are deterministic stubs in the runner. Their internal
  tables, global camp context, sound engine and the real `__aeabi_idivmod`
  divide-by-zero path are not executed. Both bodies call the same stub, so the
  comparison is valid for this routine's contract but does not prove the
  helpers' own behaviour.
- The original's two overlapping scratch buffers are modelled as one object per
  submission. The only reader of the buffer (`0x0024D9E4`/`0x0029CB94`) reads
  fields `<= +0x48`, i.e. outside the overlapping twelve bytes, so the
  difference is unobservable; this is argued from disassembly, not exercised
  against the real helpers.
- The final `r0` is dead on return; the runner leaves it out of the comparison
  (it happens to coincide with the row count, the listing's last load).
- The mask/count re-reads are preserved in the source, but LLVM may hoist the
  mask load out of the ordinal loop when it can prove the calls do not alias the
  row record. No helper receives the row pointer, so this is unobservable in
  the reconstructed contract; the count re-read is observable and is tested.
- Runtime integration (real camp menu, rendering and sound) was not exercised;
  this record covers offline differential equivalence only.
