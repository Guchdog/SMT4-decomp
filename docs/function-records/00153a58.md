# Function Record: func_00153a58 (0x00153a58)

## Summary
- **Address:** `0x00153a58`
- **Size:** 400 bytes (original span `[0x00153a58, 0x00153be8)`)
- **File:** `src/engine/leaf_batch44_b.cpp`
- **Role:** Appends the skinning/bone matrix block of one draw entry to the
  dynamic GPU command stream rooted at `g_GpuCommandCursor` (`0x004652a0`),

- **Status:** Semantically equivalent C++ (`non_matching`). The compiled body is

## Contract and Behavior

- **Signature:** `extern "C" void func_00153a58(void* scene, void* unit, void* draw_entry, s32 count)`
- **Arguments:**
  - `scene` (R0): scene object. `[scene+0x08]` is the scene render context
    (`scene_render`); `[scene_render+0x08]` is the render-state block.
  - `unit` (R1): unit/entity object. `[unit+0x220]` is the `RenderModel`.
  - `draw_entry` (R2): draw entry. `[draw_entry+0x04]` is a relative offset from
    `draw_entry+0x04` to an array of `u32` matrix indices; `[draw_entry+0x08]`
    is the entry type.
  - `count` (R3, signed): number of matrix indices to emit.
- **Return value:** none (the original leaves the advanced cursor in R0; the
  only caller at `0x0015075c` ignores it).

### Render-state selection
- `type = [draw_entry+0x08]`.
- `type == 2`: `[render_state+0x14] = (old & ~6) | 2`.
- any other type: `[render_state+0x14] = (old & ~6) | 4`.
- The original performs two word stores to the same address (bit 1 then bit 2);
  no call or read happens between them, so only the final value is observable.

### Matrix source selection
1. `model = [unit+0x220]`, `chain_root = [model+0x08]`.
2. Two model vtable slots are called, in order, with `model` as the only
   argument: `[vtable+0x1c]` then `[vtable+0x24]` (the vtable pointer is
   reloaded before each call). Each returns a `MatrixListView` whose `+0x04`
   word points at the matrix array.
3. For each element index `e`:
   - `record = chain_root + 0x1c + [chain_root+0x1c] + e*16` (a zero
     `[chain_root+0x1c]` skips this lookup).
   - `node_offset = [record+0x28]`; when nonzero `node = record+0x28+node_offset`.
   - `flags = [node+0x04]`. Bit 9 of `flags` selects the second list only when
     `type == 2`; for `type != 2` bit 9 is masked away and the first list always
     wins.
   - Source matrix = `selected_list->matrices_04 + e*48` (`e*3` words shifted by
     4 bytes, wrapping modulo 2^32).

### Command stream emission
- Empty/negative `count`: nothing is copied; the cursor still advances by one
  word (`+4`) at the end.
- First element (`i == 0`), 0x3c bytes:
  - `[cursor+0x00] = 0x80000019`
  - `[cursor+0x04] = 0x000f02c0`
  - `func_002a1ac8(cursor+0x08, source, tag)` writes 12 matrix words plus the
    tag at `cursor+0x0c` (13 words / 52 bytes).
  - `tag = (0xfff00000 + (count*3 << 22)) | 0x000f02c1`, matching the fixed
    `count == 1` constant `0x00bf02c1` used by the neighbouring routines.
- Remaining elements, 0x30 bytes each:
  - `func_002a1a90(cursor, source)` writes 12 matrix words (48 bytes).
- After the loop the cursor is advanced by one more word (`+4`).

### Observed call order
`[vtable+0x1c]`, `[vtable+0x24]`, then (`0x2a1ac8` once and `0x2a1a90`
`count-1` times) when `count > 0`; no helper calls when `count <= 0`.

### Null/zero relative-offset fallback
The original has no null guard when a relative table offset is zero:
- `[draw_entry+0x04] == 0` makes it read the index from address `i*4`.
- `[chain_root+0x1c] == 0`, or a zero `[record+0x28]`, makes it read the node
  flags from address `0x4`.
These paths are latent low-address reads, not empty-table handling. The C++
reproduces them literally through a `noinline` load helper (`LoadUntabled`) so
the compiler cannot fold the fallback away as undefined behaviour.

## Domain Limits
- The matrix-copy helpers are stubbed with their observed memory effect; their
  VFP register side effects are not modelled (no caller reads them).
- The function returns `void`; the original's incidental R0 cursor value is not
  reproduced. No caller consumes it.
- The zero-offset fallback reads address `0x0`/`0x4`, which the differential
  fixture maps explicitly. In the retail game those paths are not expected to
  be reached with zero offsets.
- Runtime behaviour inside the game (command-stream consumption, GPU state) was
  not exercised; this record covers offline differential equivalence only.
