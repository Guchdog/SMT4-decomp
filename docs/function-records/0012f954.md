# Function Record: engine_func_0012f954 (0x0012F954)

## Summary
- **Address:** `0x0012F954`
- **Size:** 672 bytes (`[0x0012F954, 0x0012FBF4)`): 163 ARM instructions
  through the `pop {..., pc}` at `0x0012FBDC`, followed by the five literal
  words `0x00000558`, `0x17F405FD`, `0x75075075`, `0x00002BD4`, `0x175D2EA3`
  at `0x0012FBE0..0x0012FBF0`.
- **File:** `src/engine/leaf_batch34_c.cpp`
- **Role:** Turn the seven size words of one parsed layer plan into four
  consecutive regions of a caller-supplied buffer. Three regions are arrays of
  strided records; the body converts every record through a per-layer builder,
  links the resulting node into a circular list, and publishes the region
  `{base, byte_size}`. A fourth region is only reserved (one object span) and
  then handed to `0x002B5064`. Each region is rejected when its 4-byte-aligned
  end is *signed-greater* than `buffer + length`.
- **Status:** Semantically equivalent C++ (`non_matching`). The candidate body
  is 700 bytes versus the 672-byte original: it spells out the four region
  passes and the seven helper calls instead of sharing the original's register
  layout, but preserves the call order, arguments, arithmetic and exits. The
  ledger row is classified `non_matching` with this semantic record.

Each strided region publishes `base` at `self+0x28/+0x48/+0x68` and `byte_size`
at `+0x04` of that region. The two words are written **after** the region's
node loop, exactly like the original (`0x0012FA3C/40`, `0x0012FAD8/E0`,
`0x0012FB70/7C`). The tail region publishes nothing; only its aligned end is
checked and `0x002B5064` is called.

For every region: `total = word * stride` is a 32-bit wrapping multiply;
`count = total / stride` (the three `umlal`/`lsr` sequences are exact unsigned
division-by-constant for all `u32` totals; the accumulator is seeded with the
magic, so the product is `(total+1) * magic`). `end = (base + total + 3) & ~3`
with 32-bit wrapping. Region bases chain: `base_B = end_A`,
`base_C = end_B`, `tail_base = end_C`.

### Comparisons and termination
- All four boundary checks are signed: `sub rX, end, limit; cmp rX, #0; bgt`
  for A/B/C and `ble` for the tail. A difference whose high bit is set passes
  even when `end > limit` in unsigned terms; the reconstruction keeps
  `static_cast<s32>(end - limit) > 0`.
- Every loop back-edge is unsigned (`cmp count, i; blo`), and `i`/`count` are
  `u32`. A zero count skips the loop but still publishes `{base, total}`.
- The null-record branch (`cmp r4,#0; moveq r2,#0`) skips the builder and still
  links node `0 + 0xD4`; it is modelled as the `record != 0` guard.

## Limits
- All seven direct-call targets are stubbed by address; their real bodies
  (`0x0013FE4C`'s header walk, `0x001419BC`'s resource lookup, the three
  builders, the list append and the `0x002B5064`/`0x002B5070` body) are not
  exercised. The test verifies the arguments and the observable register /
  memory effects of the stub contract, not the callees' internals.
- Fixtures are synthetic mapped pages, not captured game memory. The buffer is
  never dereferenced by this function (only its addresses are compared and
  handed to builders), so its contents are only checked for non-modification.
- A region base at `0` makes the original link node `0xD4`; the harness keeps
  that path memory-safe by making its list stub skip node writes below the
  mapped node page. The original would fault if the node page were unmapped.
- The candidate is 700 bytes and not byte-identical (the original reuses its
  register frame heavily); the ledger row is truthfully `non_matching` with
  this record. The literal-pool constants are not emitted as a data pool by the
  candidate; the same arithmetic is expressed directly.
- `0x002B5064` is a 12-byte entry that falls through into `0x002B5070`; the
  test stubs the entry with `bx lr`, so the fall-through is not exercised.
  The original reaches it with an ARM `bl`.
