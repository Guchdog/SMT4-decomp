# Function Record: ui_func_001a1954 (0x001A1954)

## Summary
- **Address:** `0x001A1954`
- **Size:** 676 bytes (original span `[0x001A1954, 0x001A1BF8)`)
- **File:** `src/engine/leaf_batch45_a.cpp`
- **Role:** Publishes the current camp/UI context into the UI work base held at
  `*(u32*)(0x0043E2A8 + 4)`. It assembles an `0x80`-byte record at the start of
  the work base, fills status bits from four event flags, derives three rotation
  ids from the 0x604-byte record table, and finally copies the record to
  `work_base + 0x24794`.
- **Status:** Semantically equivalent C++ (`non_matching`). The compiled body
  is 612 B versus the 676 B original; Clang chooses a different register
  allocation/instruction selection (e.g. `smlabb` for the record address) and
  places the manager literal in the function's own literal pool. The ledger row

The indexed load expands to `ctx + 0xDA + index*0x604` (`0xDA = 0x90 + 0x4A`),
i.e. record row `0x604` bytes starting at `ctx + 0x90`, field `+0x4A` (u16).
This matches the `0x604`-byte gamedata record layout documented for the
`0x0043E2A8` manager in `include/camp/unite_extras.h`. Negative signed indices
produce `0` rather than an access.

## Contract corrections found during implementation
- **`out[0x4E]` is easy to miss.** The first 16-bit store of `ctx[0x00]` occurs
  before the first memcpy (`0x1A1970`); a version without it leaves that work
  byte at its previous value.
- **The manager handle is re-read.** The original reloads `*(0x0043E2AC)` at
  `0x1A1AEC` and `0x1A1BA8`; the `out` pointer itself is *not* reloaded. The
  candidate reproduces both re-reads, and the differential test mutates the
  handle inside the first memcpy call to prove it.
- **`ctx[0xAFCA]` has an asymmetric load pattern.** `ldrb` performs the zero
  test, `ldrsb` then sign-extends for the `+1000` addition. This is equivalent
  to testing the signed byte, but the candidate keeps the same two-step
  expression.
- **The `0x5A` zero store is real.** When `ctx[0xA83B] == 0`, `out[0x58] == 0x18`
  and `(s8)ctx[0xAFCA] == 0`, the original overwrites the previously copied
  `ctx[0xA83A]` value with zero.
