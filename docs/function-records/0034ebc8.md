## Recovered contract

The callable ABI is `u32 engine_func_0034ebc8()`:

- No argument is read; `r0`-`r3` only carry whatever the caller left.  The
  prologue saves `{r4-r7, lr}` and reserves 0x14 bytes for the six-argument
  0x002C42FC call.  `r8-r11` are untouched and no stack arguments exist for
  this routine.
- `r0` on return is 0 on the early path and the value returned by 0x0010FB9C on
  the normal path.  The literal pool supplies 0x0044D0F8 (device block),
  0x004C40F8 (shared memory lock) and 0x0044D128 (audio thread handle/state).

### Global objects

`0x0044D0F8` matches the `S4AudioDevice` block modelled in
`include/nn/mobiclip.h`:

| Offset | Width | Meaning | Access here |
| --- | --- | --- | --- |
| +0x00 | u8 | lifetime/state byte | cleared (`strb`) |
| +0x04 | u32 | device object (lifetime gate) | read, zeroed |
| +0x08 | u32 | slot array base | read twice per loop, passed to the vtable |
| +0x0C | u32 | heap buffer | freed with 0x002C4360, zeroed |
| +0x10 | u32 | heap object | released, optionally freed, zeroed |
| +0x14 | u32 | slot count | read at each loop entry and latch |

Each slot is 0x70 bytes (`rsb r1, r4, r4, lsl #3` then `lsl #4`).  Only two
words are proven: `+0x00` (released by 0x0015A3F4 and 0x002BD620) and `+0x04`
(released through the device vtable).  The remaining 0x68 bytes are untouched.

`0x0044D128` is an 8-byte sync/thread block: `+0x00` is the kernel handle and
`+0x04` is the state byte written to 1.  `0x004C40F8` is the `AsdMemLock`
object used as `(lock + 0, lock + 4, lock + 8)`; `+0x08` is the final marker
word.

## Behaviour in original order

1. `0x0034EBD4..0x0034EBDC`: `[device+0x04] == 0` returns immediately with
   `r0 = 0`; nothing else is touched.
2. `0x0034EBE0..0x0034EC1C`: 0x002C3AA8(lock); then for each index while
   `index < [device+0x14]` (count reloaded after every iteration) call
   0x0015A3F4(`slot[index]+0x00`, 1) when that word is non-null; then
   0x002C3A24(lock).
3. `0x0034EC2C`: `[device+0x00] = 0` as a single byte.
4. `0x0034EC34..0x0034EC70`: build a one-word handle array from
   `[0x0044D128]` and call 0x002C42FC(&out, &handle, 1, 0, -1, -1).  A negative
   signed Result calls 0x002C5468(Result) and then continues.  Then
   `[0x0044D128+4] = 1` and 0x002C41E8(0x0044D128); because the byte was just
   set, the one-shot wait inside the callee is skipped.
5. `0x0034EC74..0x0034EC88`: reload `[0x0044D128]`; when non-zero close it with
   `svc #0x23` and store 0 back.
6. `0x0034EC8C..0x0034ECC0`: 0x002C4160(`[device+0x10]`); reload the same word
   and, when non-null, call 0x002C4160 again and 0x002B2520; store 0.  Then
   0x002C4360(`[device+0x0C]`) and store 0.
7. `0x0034ECC4..0x0034ED44`: second slot pass.  Entry is skipped when the
   reloaded count is 0.  Each iteration executes the body only when
   `(s32)index >= 0` and `(u32)index < count` (`cmp r4,#0; blt` at
   0x0034ECD8 and `cmp r4,r0; bhs` at 0x0034ECE0).  The body locks, releases
   `slot[index]+0x00` through 0x002BD620 and zeroes it, releases
   `slot[index]+0x04` through vtable slot `+0x04` of `[device+0x04]` (device
   and vtable reloaded per iteration) and zeroes it, then unlocks.  The count
   is reloaded at the latch (0x0034ED38).
8. `0x0034ED48..0x0034ED64`: `[0x004C40F8+0x08] = 0xFFFFFFFF`; reload the
   device object and its vtable, then call vtable slot `+0x04` with
   `(device, [device+0x08])`; store 0 to `[device+0x04]`.
9. `0x0034ED6C..0x0034ED84`: 0x0010FE58, 0x0010FB6C, then a tail branch to
   0x0010FB9C.  Each stage receives the previous stage's `r0` (the real
   routines overwrite `r0` without reading it); the routine returns
   0x0010FB9C's `r0`.

## Calls and data

- `0x002C3AA8` / `0x002C3A24` (ARM `bl`): AsdMemLock acquire/release, one
  argument.
- `0x0015A3F4` (ARM `bl`, conditional): per-slot audio release with mode 1.
- `0x002C42FC` (ARM `bl`): `svc #0x25` trampoline,
  `(out, handles, count, wait_all, timeout_lo, timeout_hi)`; the original
  pushes `-1, -1` as the two stack words and keeps the one-word handle array
  at `sp+8`.
- `0x002C5468` (ARM `bl`, conditional): negative-Result abort path.
- `0x002C41E8` (ARM `bl`): flag-guarded one-shot wait on the same block.
- `0x002C4160` (ARM `bl`, twice): shared-object release.
- `0x002B2520` (ARM `bl`, conditional): free-if-non-null wrapper.
- `0x002C4360` (ARM `bl`): heap free.
- `0x002BD620` (ARM `bl`, conditional): slot object release.
- `0x0010FE58` / `0x0010FB6C` / `0x0010FB9C` (ARM `bl`/tail branch): chained
  shutdown stages.
- Indirect: vtable slot `+0x04` of `[device+0x04]`, called once per slot with
  a non-null `+0x04` word and once for the whole slot array, always as
  `(device_object, object)`.  Vtable slot `+0x00` is not used.
- `svc #0x23` directly at 0x0034EC84 (svcCloseHandle), no `bl`.

## Evidence

`python tools/test_leaf_0034ebc8.py` compiles
`src/engine/leaf_batch41_c.cpp` for ARMv6K, relocates only this function's
fifteen direct calls to deterministic stubs at the pinned addresses, and runs
the original bytes against the candidate in separate Unicorn ARM machines with
identical fixtures.

- 34 differential cases: null and non-null device gate (including a fully
  populated block behind a null gate); count 0/1/2/3 with every
  first/second-field null/non-null combination; null slot buffer with count 0;
  null/non-null heap, heap buffer and thread handle (0, 1, 0xFFFFFFFF); thread
  state bytes 0x00..0xFF; wait Results 0, 1, 0x7FFFFFFF, 0x80000000 and
  0xFFFFFFFF (abort path); and gate bytes 0x00..0xFF with sentinel neighbours.
- Compared: return `r0`, continuation PC, final SP, callee-saved `r4-r11`, the
  ordered call log with every declared register argument and the two stack
  words of 0x002C42FC plus the handle-array contents, the full 0x1000-byte
  device page, the full 0x1000-byte lock page, the full 0x10000-byte slot page,
  the device-object and vtable pages, and any write outside the fixtures and
  private stack.
- Six compiled negative controls are detected: the first-pass release mode,
  the 0x002C42FC handle count, the negative-Result condition, the lock marker
  offset, the second-slot release argument, and the thread state value.
- Result: `All 34/34 differential cases PASSED.`

## Unresolved limits

- All direct callees are deterministic stubs; the real bodies of the lock,
  wait, abort, release, free, slot-release and shutdown-stage routines were not
  executed.  The indirect vtable slot `+0x04` is a stub in the test; the real
  device object and its vtable contents are not established.
- The 0x0015A3F4 mode-1 behaviour, the 0x002C4160 double-release idiom and
  the 0x0010FB9C result are reproduced from the listing and the sibling
  teardown 0x003518D0, not from executing those callees.
- The `(s32)index >= 0` skip path in the second loop is evaluated on each
  iteration but only becomes observable after 2^31 iterations when the count
  has bit 31 set; that branch is not emulated (runtime limit).
- Slot bytes 0x08..0x6F are modelled as padding; no access to them is claimed.
- No caller composition, whole-binary promotion, or runtime/emulator scenario
  was run for this isolated candidate.
