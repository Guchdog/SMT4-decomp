# Function Record: script_vm_func_00296a18 (0x00296A18)

## Summary

- **Address:** `0x00296A18`
- **Size:** 448 bytes (`[0x00296A18, 0x00296BD8)`). The executable body is 110
  ARM instructions ending at the `pop {r4, r5, r6, r7, r8, pc}` at
  `0x00296BCC`. `0x00296BD0`/`0x00296BD4` hold the literal pool
  (`0x00003534`, `0x323232FF`). `0x00296BD8` starts the next function.
- **File:** `src/engine/leaf_batch41_c.cpp`
- **Role:** script-VM state/mode transition dispatcher. It snapshots the old
  state, publishes a new state, drains a signed callback count, requests a
  per-state transition id after clearing the message line, and either returns
  the re-read state word or runs the state-0x14 teardown that either advances
  the script step or finishes it.
- **Status:** Reconstructed as readable C++ and **differentially verified**
  against the pinned original (81 explicit cases + 8 negative controls; all
  pass). The candidate body is 296 bytes plus an 18-byte compiler-generated
  `.rodata` state table and is not byte-identical, so the ledger row is
  `non_matching` and this record carries the semantic evidence.
- **Class:** non-leaf; fourteen distinct direct call targets (fifteen call
  sites), no indirect calls, no stack arguments.

## Contract and ABI

```cpp
extern "C" u32 script_vm_func_00296a18(u8* ctx,  // r0
                                        u32 state); // r1
```

- `ctx` (`r0`) is the script/event work object. Only the fields listed below
  are read or written; the object is not null-checked.
- `state` (`r1`) is the new state word. It is stored before any helper call.
- `r2`, `r3` and the caller stack are never read by the body.
- **Return value:** on the ordinary exit at `0x00296BCC`, `r0` is the state
  word re-read from `ctx+0x352C` after the optional message/transition calls.
  The two terminal arms are tail branches, so their callee's `r0` becomes the
  function result:
  - `0x00296BB4` -> `0x002971E4(slot, 5)`;
  - `0x00296BC8` -> `0x002B85BC(3)`.
- Prologue `push {r4, r5, r6, r7, r8, lr}`; epilogue restores those registers
  (r9-r11 are untouched by the body). `r12` is scratch. No VFP.
- The pinned callers declare the function `void` in several places, but the
  machine-visible `r0` is meaningful and is compared in the differential test.

## Recovered behaviour

1. **Snapshot and reset** (`0x00296A2C..0x00296A58`):
   `previous = ctx[0x352C]`; `ctx[0x3530] = previous`;
   `ctx[0x352C] = state`; then `ctx[0x3534] = ctx[0x353C] = ctx[0x3544] = 0`
   in that order. `ctx[0x3538]` and `ctx[0x3540]` are **not** touched.
2. **Callback drain** (`0x00296A5C..0x00296A84`): `count = (s16)ctx[0x357C]`.
   When the signed count is greater than zero, loop with a zero-based index:
   call `0x002B9008(count)`, re-read the signed halfword, increment the index
   and continue while `count > index` (signed `bgt`). The callback receives the
   value from the previous test; a callback that rewrites `ctx+0x357C` changes
   both the bound and the next argument. After the loop the halfword is set to
   zero unconditionally.
3. **State mapping** (`0x00296A88..0x00296AFC`): equality tests map
   `0x01 -> 0x62`, `0x0A -> 0x9E`, `0x0B -> 0x65`, `0x0D -> 0x66`,
   `0x0E -> 0xDF`, `0x0F -> 0x68`, `0x10 -> 0x6A`, `0x11 -> 0xE1`,
   `0x12 -> 0x64`. The ARM splits the chain with a signed `bgt` after `0x0E`,
   but only equality tests select a value, so every other value (including
   negative and bit-31 values) falls through identically to `0x00296B18`.
4. **Message and transition** (`0x00296B00..0x00296B14`): for a mapped state,
   call `0x0029F10C(NULL, 0x323232FF)` and then
   `0x002B8B78(mapped & 0xFF)`. Both calls occur in that order.
5. **Post-helper state re-read** (`0x00296B18..0x00296B20`):
   `current = ctx[0x352C]`; if `current != 0x14`, return `current`. Helpers may
   have rewritten the state, so the returned value is not necessarily the
   argument and the teardown decision uses the fresh word.
6. **State-0x14 teardown** (`0x00296B24..0x00296B7C`):
   `0x0029A3C4(0)`, `0x00292F44(0)`, `0x0029E260(0)`, `0x0029EB14(0)`,
   `0x0029C768(0)`, then `0x00292EB0(r0 left by 0x0029C768)` and
   `0x00292E94(r0 left by 0x00292EB0)`. The pinned `0x0029C768` stores its
   low byte and leaves `r0` equal to the input, so the dead argument to
   `0x00292EB0` is zero. The last result is kept in `r4`.
7. **Limit test** (`0x00296B7C..0x00296B8C`): when the result is zero, skip the
   limit lookup and finish. Otherwise call `0x002A8A08(result)` (the callee
   ignores the argument), load its first word, and finish when
   `result > limit` **unsigned** (`bhi`).
8. **Finish** (`0x00296BB8..0x00296BC8`): `0x002954B8(0)`, then tail-branch to
   `0x002B85BC(3)`.
9. **Advance** (`0x00296B90..0x00296BB4`): store `ctx[0x352C] = 0x13`, call
   `0x002B8B78(0x90)`, then tail-branch to
   `0x002971E4(ctx[0x3568], 5)`. The slot word is loaded **after** the
   `0x002B8B78` call, so a helper that rewrites `+0x3568` changes the argument.

## Limits

- The fourteen direct callees are not reconstructed here. They are stubbed from
  their observed register contracts. In particular `0x002B9008` is modelled as
  a controllable count mutator, `0x002A8A08` as a manager-pointer provider
  whose first word is the limit, and the rest as deterministic log-and-return
  targets. Their transitive effects outside the fixtures are outside this
  routine.
- `0x00292F44` is the already-reconstructed
  `smt4::ui::StatusDown_SetDisplayMode` in `src/ui/status_down.cpp`; this TU
  declares the same address with C linkage as `func_00292f44`, following the
  existing precedent in `src/engine/leaf_batch31_c.cpp`.
- The pinned `0x0029C768` returns its input in `r0`. This reconstruction passes
  a literal `0` to `0x00292EB0`, which is exact for the pinned callee but would
  not forward a different return if that callee were replaced by an
  implementation with an observable different `r0`.
- The switch is compiled to a bitmask plus an 18-byte `.rodata` table. The test
  relocates the `R_ARM_ABS32` literal to the mapped table, so the table content
  is part of the differential evidence; the original encodes the same mapping
  as an immediate compare chain.
- The exact meaning of the state values and transition ids is not established
  beyond the compare/store evidence and the `0x14` special-case confirmed by
  `0x002B89A0`. No sound/audio semantics are claimed for `0x002B8B78`.
- No emulator or whole-game runtime scenario was run. The evidence is offline
  Unicorn ARM execution of the pinned bytes versus the compiled candidate with
  identical fixtures, plus static caller reading.
