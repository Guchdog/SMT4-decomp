# Function Record: engine_func_00238ed4 (0x00238ed4)

## Summary
- **Address:** `0x00238ed4`
- **Size:** 452 bytes (original span `[0x00238ed4, 0x00239098)`; 107 ARM
  instructions through the unconditional `pop` at `0x0023907c`, then the
  24-byte literal pool at `0x00239080..0x00239098`)
- **File:** `src/engine/leaf_batch45_b.cpp`
- **Role:** One-shot engine setup step serialised by the recursive lock object
  at `0x004E629C`. The three state bytes at `0x004656CA` decide whether the
  call may run, whether setup has already happened, and whether the one-shot
  driver still has to be invoked. On success it returns an engine slot
  (selected by the `kind` argument) or, for `mode == 0`, polls the `svc #0x25`
  wait trampoline up to 62 times and closes the resulting kernel handle.
- **Status:** Semantically equivalent C++ (`non_matching`). The compiled body is
  424 B versus the 452 B original: register allocation and the literal pool
  differ, and clang merges the two `engine_func_002c3a24` call sites. The
  ledger row is `non_matching` with this semantic record.

- Returns a `u32` in `r0`: an engine slot pointer, `0xC8A10BF0`

### Contract details found during implementation
- **`0x00359288` runs before `0x00239BB0`.** The wait-alloc call is at
  `0x238FC8`; the kind-selected slot lookup at `0x238FE4`. The handle therefore
  sees no engine-slot allocation yet.
- **The poll predicate is a 10-bit mask, not a full-word compare.** The
  original encodes `cmp sb, sl, lsl #22` at `0x239034` as `0xE1590B0A`
  (bit 4 clear, `imm5 = 22`). Objdump, capstone and Unicorn all decode it as
  the immediate form, and the disassembly is consistent with `sb` holding
  `0xFF800000`; the candidate keeps `(Result << 22) == 0xFF800000`, which
  ignores the upper 22 bits of the Result. Verified in Unicorn against both
  `0xE1590B0A` and the canonical `0xE1590B1A` encoding.
- **62 poll bodies are possible.** `iteration` starts at 0; the failure value is
  assigned on the body where `iteration == 0x3D`, and the loop exits without
  another trampoline call. Status `1` on that 62nd body still wins over the
  failure value because the status test precedes the bound test.
- **A negative trampoline Result does not stop the loop locally.** The
  non-returning reporter `0x002C5468` is called with `r0 = Result`, then the
  code continues to the poll predicate with whatever `sb`/`sl` hold; only a
  matching predicate keeps polling.
- **The handle close is skipped on the `mode != 0` path.** That path branches
  from `0x238F8C`/`0x238FB4` straight to `0x23906C`, past the `svc`.
- **`0x002C42FC` takes a 64-bit timeout.** `r0 = &key_out`, `r1 = &handle`,
  `r2 = 1`, `r3 = 0`, `[sp] = 0x3B9ACA00`, `[sp+4] = 0`. The trampoline moves
  the two stack words into `r0`/`r4`, executes `svc #0x25`, stores the kernel's
  `r1` into its first argument and returns the Result. Nothing reads that
  output slot afterwards, so the write is unobservable.
- **Three `engine_func_002c3a24` call sites in the original** (`0x238F48`,
  `0x238F94`, `0x239070`); clang merges the two early-exit sites into one block
  and keeps the shared trailing unlock, so the candidate has two.

## Limits
- Fixtures are synthetic: the three state bytes, the probe byte, the lock
  payload, the wait Results/status words and the helper return values are not
  captured game data.
- All ten helpers (`0x00239BEC`, `0x00239BB0`, `0x002C3AA8`, `0x002C3A24`,
  `0x0035B0A4`, `0x002BB490`, `0x002C42FC`, `0x002C5468`, `0x00359288`,
  `0x00359088`) are stubbed; no real lock, engine-slot allocation, kernel wait,
  fatal reporting or timing is exercised.
- `0x002C5468` never returns in the real engine; the test lets the stub return
  a fixed register state so the continuation stays comparable.
- `svc #0x23` is serviced by a Unicorn interrupt hook that only records `r0`;
  the kernel handle lifecycle is not modelled, and `0x002C42FC`'s `svc #0x25`
  is not executed at all (the stub replaces the whole trampoline).
- The meaning of the three state bytes, of `kind` (`0x0B`/`0x0C` slot tables),
  of the `0x00F42400` deadline and of the `0x00359088` status value is not
  established beyond their observed use.
- Caller composition, runtime/emulator validation and whole-game equivalence
  are not claimed.
