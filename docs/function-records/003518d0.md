## Unresolved / limits
- `0x002C42FC` is reproduced by its externally visible contract (writes the
  kernel's `r1` result to `*out`, returns the Result in `r0`, two `-1` stack
  words, seventh word ignored). The exact kernel service behind `svc #0x25` is
  inferred from the project record in `src/engine/asd_file.cpp`
  (`AsdKernel_WaitProcessWideKey`) and was not runtime-verified here; no
  emulator run was performed.
- The roles of `0x002C4160` (queue-node release/wait returning `[+0x14]`),
  `0x0035074C` (owner reset) and `0x0034F260` (single-pointer container free)
  are described only as far as their own bodies and the shared teardown idiom
  show. Their callees (`0x001376C4`, `0x002BBB04`, `0x0023A774`, `0x00351040`,
  `0x003F6228`) were not reconstructed.
- `AsdSync_WaitOnce` (`0x002C41E8`) is a descriptive name; the body is a
  flag-guarded one-shot `0x002C42FC` call. Because the caller sets
  `[self+0x2C] = 1` first, that entry never performs work from this function.
- Object lifetime ownership beyond this routine (who sets `[self+0x14]`, the
  three counts and `[self+0x158]`) is outside this body. `0x00351A88` shows the
  matching initializer, and `0x00351B34` shows the delete-style teardown.
