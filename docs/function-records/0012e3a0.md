# Function Record: func_0012e3a0 (0x0012E3A0)

## Summary

- **Address:** `0x0012E3A0`
- **Size:** 772 bytes (`[0x0012E3A0, 0x0012E6A4)`): 193 ARM instructions ending at
  the shared `add sp,sp,#0xC; pop {r4-r8,sb,sl,fp}; ldr pc,[sp],#0x14` return
  sequence. There is no literal pool inside the range; the next function starts
  exactly at `0x0012E6A4`.
- **File:** `src/engine/leaf_batch34_c.cpp`
- **Role:** A void draw-stream builder. Calls `0x002B4454` to reserve the packet's
  first sub-blocks, then advances the shared byte cursor through five more
  aligned regions and two optional layouts: a byte span read from a range
  argument, or a list of entries forwarded to `0x0014B6C0`. Finally it lays out
  the `count4` tail and, when the flag byte at bits 8..15 is non-zero, walks a
  second entry list and calls `0x002B43B0` for every entry whose type word is 2
  or 3.
- **Status:** Reconstructed as readable C++ and **semantically verified**
  against the pinned original. The candidate body is 560 bytes and is not
  byte-identical, so the ledger row is `non_matching` and this record carries
  the semantic evidence.

## Contract and ABI

```cpp
extern "C" void func_0012e3a0(DrawStreamState* stream, // r0
                              PacketWords* packed,     // r1
                              u32 flags,               // r2
                              u32 count4,              // r3
                              u32 word0,               // [sp+0x00]
                              u32 word1,               // [sp+0x04]
                              u32 word2,               // [sp+0x08]
                              RangeSpan* range);       // [sp+0x0C]
```

- The prologue is `push {r0,r1,r2,r3}` (to preserve the four register arguments
  while reaching the stack arguments), then
  `push {r4,r5,r6,r7,r8,sb,sl,fp,lr}`, then `sub sp,sp,#0xC`. With entry SP = S
  the four stack words live at `[S+0x00..S+0x0C]`, i.e. `[sp+0x40..0x4C]` after
  the frame is built; the saved `r2` copy is at `[sp+0x38]`. Only the four words
  `S..S+0x0C` are read. A fifth word at `S+0x10` is never touched (the `vstmia`
  at the callers writes five words; the fifth is dead here).
- `r7` receives `word2`, `sb` receives `range`. `word0`/`word1` are copied to
  `[sp+0x00]`/`[sp+0x04]` and become the fifth/sixth arguments of `0x002B4454`.
- **Return value:** none. The epilogue restores SP to S and pops the five saved
  words with `ldr pc,[sp],#0x14`; the caller discards its own four stack words.
  `r0` on return is a leftover of the last flag test or helper call (AAPCS
  caller-clobbered) and both recovered callers ignore it. The reconstruction is
  therefore `void`; the differential runner records r0 for diagnostics but does
  not treat it as an observable result.
- The cursor/unit pair is re-read from memory after every helper call because
  the callees (`0x002B4454`, `0x0014B6C0`, `0x002B43B0`) all advance the same
  shared cursor. The candidate keeps the pair in memory, not in a cached local.

## Recovered behaviour

The allocator primitive throughout is
`align_up(value, unit) = (value + unit - 1) & ~(unit - 1)`, exactly the repeated
`add/sub/bic` sequence. `[stream]` is the byte cursor and `[stream+4]` the
alignment unit.

### Initial reservations (`0x0012E3A4..0x0012E464`)

After `0x002B4454(stream, packed, flags, count4, word0, word1)`:

```
n = *(u32*)(packed + 0xB4)
m = *(u32*)(packed + 0xCC)
cursor =      align_up(cursor, unit) + 4*n
cursor =      align_up(cursor, unit) + 0x88*n
cursor =      align_up(cursor, unit) + n
cursor =      align_up(cursor, unit) + 8*m
cursor =      align_up(cursor, unit) + m
*(u32*)stream = cursor
```

All arithmetic is 32-bit wrapping (`lsl`/`add` with no overflow test).

### Range-present path (`0x0012E46C..0x0012E49C`)

When `range != 0`:

```
span = (range->end_168 - range->begin_164) & ~3   // asr #2 then lsl #2
cursor = align_up(cursor, unit) + span
```

The `asr`/`lsl` pair is exactly a signed round-down to a multiple of four, so
the C++ uses `& ~3` instead of a signed shift (identical for every 32-bit input,
including a negative difference).

### Range-absent path (`0x0012E4A0..0x0012E528`)

When `range == 0`:

```
count = *(s32*)(packed + 0xBC)                 // signed loop bound
cursor = align_up(cursor, unit) + (u32)count * 4
for (s32 i = 0; i < count; ++i) {
    entry = resolve(packed, 0xC0, i);
    /* marker = (word2 != 0), value = word2 */
    0x0014B6C0(stream, entry, marker, word2);
}
cursor = *(u32*)stream                          // reload after the helpers
```

`resolve(packed, off, i)` follows the self-relative list exactly:

```
rel  = *(u32*)(packed + off)
base = rel ? packed + off + rel : 0
if (base == 0) return 0
ent  = base + i*0x10
inner = *(u32*)(ent + 0x28)
return inner ? ent + 0x28 + inner : 0
```

A null entry is still forwarded to `0x0014B6C0`. The bound is signed
(`cmp r8,#0; ble` and `blt`), and the `4*count` increment is still added for a
negative count before the loop is skipped.

### Common header and `count4` tail (`0x0012E52C..0x0012E5A4`)

```
cursor = align_up(cursor, unit) + 0x14
*(u32*)stream = cursor
if (count4 != 0) {
    cursor = align_up(cursor, unit) + 4*count4
    *(u32*)stream = cursor
    cursor = align_up(cursor, unit) + 0x14
    *(u32*)stream = cursor
    cursor = align_up(cursor, unit) + 4*count4
} else {
    cursor = align_up(cursor, unit) + 0x14
}
*(u32*)stream = cursor
```

### Type loop (`0x0012E5A8..0x0012E66C`)

The gate is the sign-extended byte at bits 8..15 of `flags`
(`lsl #0x10; asrs #0x18`); only zero/non-zero is observed. When non-zero:

```
count = *(s32*)(packed + 0x28)                  // signed bound
for (s32 i = 0; i < count; ++i) {
    entry = resolve(packed, 0x2C, i);
    type  = *(u32*)(entry + 0x0C);
    if (type == 2 || type == 3) {
        tagged = (type & ~0xFF) | 1;            // always 1 for the tested types
        *(u32*)stream = align_up(*(u32*)stream, unit) + 0x68;
        0x002B43B0(stream, entry, (s8)tagged, tagged);
    }
}
```

The original sets both `r2 = sxtb(tagged)` and `r3 = tagged` before the call;
the declaration keeps both so the architected register pair matches even though
the helper reads only `r2`.

### Tail (`0x0012E670..0x0012E694`)

```
if (range == 0)
    *(u32*)stream = align_up(*(u32*)stream, unit) + 8;
```

Notice the asymmetry: the range-present path still runs the common `count4`
blocks, but never the `0x0014B6C0` loop or the final `+8`.

## Differential verification

`tools/test_leaf_0012e3a0.py` compiles `src/engine/leaf_batch34_c.cpp`, extracts
the `func_0012e3a0` body, resolves the three direct calls to deterministic stubs
at the original addresses, and runs the pinned original against the candidate on
separate Unicorn ARM machines with identical fixtures.

Per case it compares:

- continuation PC, final SP and callee-saved `r4-r11` (`sb`/`sl`/`fp` included);
- the ordered call log with `r0..r3` of every helper and the two architected
  stack words of `0x002B4454`;
- the whole stream page (cursor, unit and the sentinel at `+0x08`), the whole
  packet page (all list owners, entries, type words and sentinels), the range
  page and the opaque `word2` target page;
- any emulated write outside the private stack and the two writable fixture
  pages.

The stubs deliberately advance the shared cursor (`+0x28`, `+0x40`, `+0x30`
cases), rewrite the alignment unit, and rewrite the list owner after the first
iteration; both bodies must observe those changes in the same order. `word2` is
tested both zero and non-zero (so the emitted marker/r3 pair is covered). The
entry resolvents are tested non-null, null-owner and null-inner (null-inner only
for the `0x0014B6C0` loop, which accepts a null entry).

Coverage: range present with aligned, unaligned, zero, negative and 32-bit
wrap-around spans; range absent with signed counts `0..3`, `-1`, `-2`,
`0x80000000`, `0xFFFFFFFF`; `count4` `0,1,2,4,0xFFFFFFFF,0x40000000`; flag byte
`0x00`, `0x01`, `0x7F`, `0x80`, `0xFF` including other-bit noise
(`0xFFFF00FF`, `0xFFFFFFFF`); type lists with matching/non-matching mixtures;
alignment units `0,1,2,3,4,8,16,32` including the non-power-of-two mask; cursor
values at zero, unaligned neighbours and 32-bit wrap boundaries; both stack
argument words varied.

Result: **100/100 cases pass**, plus five negative controls (initial stride
`0x88`, flag-byte shift `8`, type header `0x68`, final tail `8`, entry stride
`0x10`) that are each detected.

## Limits / unresolved

- The three helpers are stubbed at their ABI boundary. Their internal cursor
  bookkeeping is not reimplemented; the test checks the exact arguments, order,
  and the fact that their cursor writes are observed.
- A null type-loop entry is a fault in the original (`ldr r0,[r1,#0xC]` with
  `r1 == 0` at `0x0012E600`). That invalid-input domain is intentionally not
  exercised; the reconstruction dereferences the same null pointer.
- `r0` is not part of the return contract (see above); the ledger status is
  `non_matching` because the candidate is 560 B versus 772 B. Byte identity is
  not claimed.
- No caller-side integrated scenario is run here: the two static callers belong
  to the large `0x002AAD14` dispatcher, which is outside this function's scope.
