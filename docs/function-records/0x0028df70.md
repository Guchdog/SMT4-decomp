# `0x0028DF70` — H2 manager row halfword query

## Contract

The helper accepts a raw unsigned 32-bit index. If `index >= 6`, it returns zero before loading the manager pointer. For indices 0–5, it loads the manager pointer from `0x0043DA2C` and returns the zero-extended halfword at `manager + 0x496 + 4*index`. It does not write memory and preserves SP and `r4-r11`.

The original `0x00286928` calls this helper at `0x00286B60` for row bytes 7, 8, or 9, with `r0=0`. Return 5 triggers the following `P+0xA26` store, `0x002B8CCC` result store at `P+0xA12`, and `0x002B8B78(0xDC)` call.

## Evidence

The typed C++ candidate compiles to exactly 40 bytes in the 40-byte slot with no relocations. A single inline `LDRH` keeps the target halfword load and return in `r0` while the guard, pointer, and address logic remain typed C++. Final-VMA IPS replay was exact and slot-limited.

The fresh run passed 94 direct cases: all indices 0–5 crossed with halfword values `0`, `1`, `4`, `5`, `0x7FFF`, `0x8000`, `0xFFFE`, and `0xFFFF`, plus out-of-range boundary/high-bit/`UINT32_MAX` and seeded indices. Invalid-index cases use an unmapped manager pointer and confirmed no pointer read. Nine compositions ran the original `0x00286928` row 7/8/9 path for getter values 5, 4, and `0xFFFF`; the getter was real and other helper callees were controlled.
