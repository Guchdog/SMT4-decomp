# Function Record: camp_func_0025a0d0 (0x0025a0d0)

## Summary
- **Address:** `0x0025a0d0` (original span `[0x0025a0d0, 0x0025a268)`, 408 bytes)
- **File:** `src/engine/leaf_batch33_c.cpp`
- **Role:** Title-config touch-region refresh. It reads the title-config
  workspace pointer from `g_TitleConfigWork` (`0x0044E2D0`), releases the touch
  regions recorded by the previous invocation, clears the four stored region
  handles, resolves five `0x2F`-group layout records, and registers four new
  rectangles (top, middle, bottom, and cursor/details).
- **Status:** Semantically equivalent C++ (`non_matching`). The compiled body is
  684 bytes versus 408 original bytes; clang splits every halfword load into
  two byte loads, repeats the coordinate arithmetic per record, and keeps the
  literal in a pool. The ledger row is classified `non_matching`; this record
  carries the semantic evidence. The body does not fit the original 408-byte
  slot, so no in-place/staged integration was attempted.

### Control flow
1. `work = *g_TitleConfigWork`.
2. `previous = (s16)u16[work+0x24]`. While `previous > 0`, call
   `0x002B9008()` `previous` times. A zero or negative halfword skips the loop;
   the signed compare covers `0x8000` and `0xFFFF`.
3. `0x0027EDF8(work+0x1C, 0xFFFFFFFF)` fills the eight handle bytes with `0xFF`;
   then `u16[work+0x24] = 0` (`strh`).
4. `selected = 0x0029F248(work+0xE8)`. The anchor node id is the full 32-bit
   modular sum `(u32)selected + 0x1F`, with no 16-bit narrowing (ids wrap for
   `selected = -1`, `0x7FFFFFFF`, `0x80000000`).
5. `anchor = 0x002BF6D0(0x2F, selected+0x1F)`.
6. For node ids `0x1B`, `0x34`, `0x38`, register one rectangle each:
   - `x = sxth(u16(anchor[+8]  + node[+8]))`
   - `y = sxth(u16(anchor[+0xA] + node[+0xA]))`
   - `w = node[+4] & 0x7FFF`, `h = node[+6] & 0x7FFF`
   - the `s16` result is stored at `work+0x1C`, `+0x1E`, `+0x20` respectively.
   Before the `0x34` lookup the count is read, incremented and stored
   (`ldrh/add/strh`), so the sequence is `0 -> 1`.
7. The last record uses node id `0x33`. Its `+0xC` word points at a signed
   halfword pair: `w = s16[ptr+0]`, `h = s16[ptr+2]`. `x`/`y` are the same
   signed sums with the `0x33` record. The result is stored at `work+0x22`.
   No bit-15 masking is applied to this pair.
8. `u16[work+0x24] += 3` (read, add, `strh`), giving 4 for every reachable
   invocation. That 16-bit value is returned.
9. The original re-reads `u16[work+0x24]` for each loop iteration; the C++
   caches the initial signed value. `0x002B9008` has no workspace pointer and
   only touches its manager global, so the bound cannot change under the
   recovered contract.
