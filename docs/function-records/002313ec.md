# Function Record: func_002313ec (0x002313ec)

## Summary
- **Address:** `0x002313ec`
- **Size:** 456 bytes (original span `[0x002313EC, 0x002315B4)`; the last 12
  bytes are the literal pool `320.0f, 240.0f, 0x0044EA00`)
- **File:** `src/engine/leaf_batch41_c.cpp`
- **Role:** Clips a screen-space rectangle to the 320x240 logical screen and
  publishes the result through three pending slots of the overlay stack object
  whose base pointer is stored at `0x0044EA00`. It is the clipping helper called
  by `ui_func_0022d994` (see `docs/function-records/0022d994.md`) and by
  `leaf_batch45_c.cpp`.
- **Status:** semantically equivalent C++ (`non_matching`). The compiled body is
  476 B versus the 456 B original: the text is 468 B versus 444 B, the literal
  pool is 8 B (the two floats) versus 12 B (which also held the
  `0x0044EA00` pointer that the candidate materialises with `mov/orr`), and
  register allocation differs. The ledger row carries this semantic record.

## Contract and Behavior

### Signature and ABI
```c
extern "C" void func_002313ec(s32 x, s32 y, s32 w, s32 h);
```
- `x = r0`, `y = r1`, `w = r2`, `h = r3`, all 32-bit signed. The callers pass
  clipped signed screen coordinates/widths and heights.
- `void` result. The original happens to leave the last packed slot value in
  `r0`; the candidate leaves zero on the tail path where the third flush
  callback fires. `r0` is caller-saved and both callers (`0x0022D994` and the
  `leaf_batch45_c.cpp` site) overwrite it before using it.
- Saves `r4-r8, sb, sl, lr` (the candidate additionally saves `fp`); final `SP`
  equals the entry value and `r4-r11` are preserved.
- The original computes `x + w` and `y + h` with wrapping ARM `add`; the
  candidate performs the same arithmetic through `u32` so signed overflow is
  not undefined, then interprets the result as signed for the comparisons and
  for `vcvt.f32.s32`.

### Control flow (ARM addresses)
1. `0x2313EC..0x2313F0` - save the frame; `w`/`h` are copied to scratch.
2. `0x2313F4..0x23144C` - horizontal clamp:
   - `x + w < 0` -> `x = 0, w = 0`;
   - else `x < 0` -> `w += x, x = 0`;
   - else `x > 0x140` -> `x = 0, w = 0` (this path jumps past the final check);
   - then when `x + w > 0x140`, `w = (s32)(320.0f - (f32)x)`.
3. `0x231450..0x2314A4` - vertical clamp, same shape against `0xF0`:
   - `y + h < 0` -> `y = 0, h = 0`;
   - else `y < 0` -> `h += y, y = 0`;
   - else `y > 0xF0` -> `y = 0, h = 0`;
   - then when `y + h > 0xF0`, `h = (s32)(240.0f - (f32)y)`.
4. `0x2314A8..0x231508` - `end_x = x + w`, `end_y = y + h` (wrapping 32-bit);
   `right = (s32)(320.0f - (f32)end_x)` and
   `bottom = (s32)(240.0f - (f32)end_y)`, both computed once before any callback.
5. `0x2314B8..0x231520` - slot 1 at `overlay + 0x130C`: `depth = *(u32*)slot`,
   `pending = slot + 8 + depth*4`; store `3`; if `slot[0x18] != 0 || old != 3`
   call `*(void**)(slot + 0x1C)` (r0 = 3) and clear `slot[0x18]`.
6. `0x23151C..0x23156C` - reload `*(u32*)0x0044EA00`; slot 2 at
   `overlay + 0x132C`: store `right | (bottom << 16)`; the same dirty/old rule
   calls the callback with that packed value in r0 and clears the dirty byte.
7. `0x231570..0x2315BC` - reload the base pointer again; slot 3 at
   `overlay + 0x134C`: store `w | (h << 16)`; the same rule calls the callback
   with the packed value and clears the dirty byte.
8. `0x2315A4` - restore the frame and return.

### Calls
There are no direct calls. The only callees are the three flush callbacks
loaded from `*(void**)(slot + 0x1C)` for slots `0x130C`, `0x132C`, `0x134C`.
Their targets are unresolved; the reconstruction declares
`typedef void (*OverlayFlushFn)(u32 value)` and passes the value just stored,
which reproduces the original `r0`/`r1` (`r1` holds the callback address at the
`blx`). The original performs no null check, so a null callback faults in both.

### Memory effects
- Writes one `u32` (and possibly one dirty byte) per slot at
  `*(u32*)0x0044EA00 + 0x130C / 0x132C / 0x134C` plus `8 + depth*4`.
- The base pointer is reloaded from `0x0044EA00` before each slot, so a callback
  can redirect the global between slots; the candidate preserves that reload.
- `depth` is used without bounds checking, matching the original.

## Limits
- Fixtures are synthetic: the overlay objects, pending arrays, dirty bytes and
  flush callbacks are not captured game data.
- The three flush callback targets are unresolved; the test substitutes logging
  `bx lr` stubs and a redirecting variant. Real flush behavior, including any
  argument use beyond `r0`/`r1`, is not modeled.
- `0x0044EA00` is treated as a plain pointer to a byte buffer; the surrounding
  overlay-stack object is not modeled beyond the three touched slots.
- `depth` is not bounds-checked; only in-range depths (0-3) are exercised
  because deeper arrays would overlap the next slot's header fields.
- Extreme `x + w` / `y + h` values that would make the float-to-int conversion
  saturate are not exercised, and no runtime, caller-composition or whole-game
  equivalence is claimed.
