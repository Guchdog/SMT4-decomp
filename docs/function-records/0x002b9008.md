# `camp_func_002b9008` — shared manager counter adjustment

## Reconstructed behavior

The function ignores incoming register arguments. It reads the manager pointer
from `0x0043DCB4`, computes the manager base plus `0x600`, and reads the signed
halfword at offset `0x4A` from that address (`manager + 0x64A`). If the value is
greater than 10, it writes the value minus one. Values at or below 10 are left
unchanged. The original returns with `r0 = manager + 0x600`; callers treat the
entry as void and do not consume this caller-saved register value.

## C++ and evidence

`src/engine/leaf_batch23_b.cpp` now expresses the helper in typed C++ and keeps
the same 36-byte span. The compiled body differs from the original instruction
encoding, so the ledger classification is `non_matching`. The replacement
preserves the observed raw `r0` value while keeping the existing void calling
declarations.

`tools/h2_b9008_experiment.py` compares original and staged execution at
`0x002B9008` across 32 fixtures: signed threshold boundaries, four different
incoming `r0` values, randomized unrelated manager bytes and `r1-r3` values.
It compares the complete manager region, global pointer words, ordered writes,
raw `r0`, SP and callee-saved registers. Both the `10`-to-`9` threshold mutation
and the `+0x64A`-to-`+0x648` offset mutation were detected. Exact-slot IPS replay
passed and no bytes outside the 36-byte slot changed. The affected production
TU compiled.

## Callers and limits

The helper is called by the H2 `TitleConfig_Secondary` callback and by other
camp/UI routines. Evidence supports its shared direct side effect over valid,
mapped ordinary memory. It does not establish scheduler behavior, the broader
manager lifecycle, aliasing, faults from invalid pointers, concurrency or
MMIO behavior. See the [production conversion report](../agent-work/h2-002b9008-production-conversion.md)
and [independent review](../agent-work/h2-002b9008-independent-review.md).
