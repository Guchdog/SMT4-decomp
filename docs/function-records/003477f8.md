# Function Record: `ui_func_003477f8` (`0x003477f8`)

## Summary
- **Address:** `0x003477f8`
- **Size:** 904 bytes (original span `[0x003477f8, 0x00347b80)`)
- **Source:** `src/engine/leaf_batch45_b.cpp`
- **Domain:** UI
- **Role:** Advances four animated UV offsets, conditionally advances and wraps a
  rotation angle, rebuilds the 4x4 transform matrix at `self + 0x18` from the
  shared sine/cosine LUT, advances a scale, and rescales the matrix.
- **Status:** Semantically equivalent C++ (`non_matching` in the ledger). The
  compiled body is 692 B versus the 904 B original; the original carries a
  hand-written literal pool (eight words) while the candidate uses different
  register allocation and a smaller inlined LUT. The ledger row was changed
  from `matching` to `non_matching` when the naked block was replaced.

## Contract and Behavior

### Signature and ABI
```c
extern "C" void ui_func_003477f8(u8* self);
```
- `self` is in `r0`; the caller ignores `r0` afterwards.
- The original saves `r4-r8, sb (r9), lr` and `d8` (the `s16`/`s17`
  scratch pair), allocates 12 bytes of stack, and restores the same set. The
  candidate preserves `r4-r11`; final `sp` equals the entry value.
- Float fields are read/written as single-precision words. Integer flag/bits
  comparisons in the original use the raw IEEE-754 bit pattern in a general
  register, so the C++ uses an explicit `f32_bits` helper and signed compares.

### Control flow and calls

1. **vtable flush.** `vobj = *(u8**)(self + 0x14)`;
   `(*(void (***)(u8*))vobj)[2](vobj)` — slot 2 at byte offset 8. The result is
   ignored.
2. **UV advance.** For the four 20-byte elements of the array
   `arr = *(u8**)(self + 4)`:
   `arr[i].f0C += *(f32*)(cfg + 0x20)` and
   `arr[i].f10 += *(f32*)(cfg + 0x24)`, where
   `cfg = *(u8**)(self + 0x60)`. The array pointer and config pointer are
   re-loaded on every iteration in the original (and in the C++).
3. **Angle advance gate.** With `denom = *(u32*)(cfg + 0x30)`:
   - `denom == 0` → advance the angle.
   - otherwise call `ui_func_002c615c(numerator, denom)` where
     `numerator = *(u32*)(*(u8**)(self + 0x14) + 4)` (re-loaded after the
     vtable call). Only the **high word** (`r1`) of the returned `u64` is
     tested: `r1 == 0` advances, `r1 != 0` skips the angle update.
4. **Angle wrap.** On the advance path:
   `ang = *(f32*)(self + 0x58) + *(f32*)(cfg + 0x28)`;
   if `(s32)bits(ang) >= 0x43B40000` (`ang >= 360.0f`) subtract `360.0f`,
   else if `ang < 0.0f` add `360.0f`. The original stores the raw sum before
   the wrap and again after it; only the final value is observable.
5. **Matrix rebuild.** `sin/cos` of `(0, 0, ang * (256/360))` are evaluated with
   the shared 256-entry LUT at `0x00407FC0`; the three results `(sx, cx)`,
   `(sy, cy)`, `(sz, cz)` build `m = (f32*)(self + 0x18)`:
   ```text
   m[0]  = cz*cy                 m[1]  = (sx*cz)*sy - (cx*sz)
   m[2]  = (sx*sz) + (cx*cz)*sy   m[3]  = 0
   m[4]  = sz*cy                 m[5]  = (cx*cz) + (sx*sz)*sy
   m[6]  = (cx*sz)*sy - (sx*cz)   m[7]  = 0
   m[8]  = -sy                   m[9]  = sx*cy
   m[10] = cx*cy                 m[11] = 0
   m[12..14] = 0                 m[15] = 1
   ```
   `sx` and `sy` are `+0.0f`, `cx` and `cy` are `1.0f` because their LUT inputs
   are `0.0f`; `sz` is sign-corrected for a negative scaled angle.
6. **Scale advance.** With `ds = *(f32*)(cfg + 0x2C)`:
   `*(f32*)(self + 0x5C) = (*(f32*)(self + 0x5C) + ds) * (ds + 1.0f)`.
   The config pointer and `ds` are re-loaded before the multiply, matching the
   original's second load. The first store is overwritten and not separately
   observable.
7. **Row scaling.** `func_0023e55c(m, m, v)` with `v = {scale, scale, 1.0f}`;
   that helper multiplies each 4-float matrix row by the corresponding vector
   element (in place here).

### LUT contract
- Table base `0x00407FC0`, 16 bytes per entry:
  `{sin(a), cos(a), sin(a+step)-sin(a), cos(a+step)-cos(a)}`.
- Index: `(u32)value & 0xFF` after reducing `|value|` by 65536 while the raw
  bit pattern is `>= 0x47800000` (`65536.0f`). Fraction:
  `value - (float)(u32)value`; interpolation `s = e0 + frac*e2`,
  `c = e1 + frac*e3`.
- The function's three LUT inputs are `0.0f`, `0.0f`, and
  `ang * 0x3f360b61` (`256.0f / 360.0f`).
- The inlined original contains two dead conditional negations (`cmp ip,#0`
  and `cmp r5,#0` with both registers zero) for the two zero-angle LUTs; the
  C++ omits them because they are provably no-ops.

## Limits
- Fixtures are synthetic: `self`, the four-element array, the config page, the
  `+0x14` object, its vtable and the returned `u64` are test-controlled.
- `func_0023e55c`, `ui_func_002c615c` and the vtable slot-2 target are stubbed;
  the real flush, division and matrix helpers are not exercised. The identity
  and side effects of the vtable slot are unknown.
- The semantic meaning of the `+0x30` divisor and of the `+0x14` object's
  word at `+4` is not established; only their values and the high-word gate are
  reproduced.
- `NaN`, `Inf`, and signaling values are not tested (the 65536 reduction loop
  would not terminate for an infinite magnitude). Aliasing between `self`,
  the array and the config object is not exercised.
- No rendering, UI-state, caller-composition or whole-game runtime equivalence
  is claimed.
