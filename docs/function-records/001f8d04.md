# Function Record: script_vm_func_001f8d04 (0x001F8D04)

## Summary

- **Address:** `0x001F8D04`
- **Size:** 796 bytes (`[0x001F8D04, 0x001F9020)`). The routine body is the 190
  instructions from `0x001F8D04` to the `pop {r4-r8,sb,sl,fp,pc}` at
  `0x001F8FF8`, followed by its three-word literal pool at
  `0x001F8FFC..0x001F9004` (`0x00433158`, `0x000003B7`, `0x0000047E`). The last
  24 bytes of the ledger range (`0x001F9008..0x001F901F`) are a *separate*
  tail stub (`mov r0,#0xA; vldr s4,[pc,#4]; vldr s3,[pc,#4]; b 0x002568F4`
  plus the `20.0f`/`5.0f` constants) that is only reached by the raw `b` at
  `0x0025C058`; it is not part of this function and is preserved verbatim as
  raw words (see Limits).
- **File:** `src/engine/leaf_batch34_c.cpp`
- **Role:** Randomised "draw a group of entries" helper for the event script
  `script_vm_func_001e5448`. It resolves a 24-byte record, turns the record's
  byte pair at `+0x04/+0x05` into a target count and a 0..100 roll value, adds
  the record's three fixed item slots subject to a `mode`/`chance` gate, then
  collects a filtered set of camp rows and picks random rows from it until the
  target count is reached. The item ids, a per-item flag byte and the count are
  published to three caller buffers.
- **Status:** Reconstructed as readable C++ and **semantically verified**
  against the pinned original. The candidate body is 948 bytes and is not
  byte-identical, so the ledger row is `non_matching` and this record carries
  the semantic evidence.

## Contract and ABI

```cpp
extern "C" u32 script_vm_func_001f8d04(s32 id,     // r0
                                       u32* ids,   // r1  (r8)
                                       u8* flags,  // r2  (fp)
                                       u32* count) // r3  (r6)
```

- Four register arguments, no stack words. The prologue is
  `push {r0,r1,r2,r3,r4,r5,r6,r7,r8,sb,sl,fp,lr}` followed by
  `sub sp,sp,#0x1CC`; the argument word for `id` is re-read from
  `[sp+0x1CC]` at `0x001F8D1C`, `0x001F8D28` and `0x001F8E58`. The epilogue
  `add sp,sp,#0x1DC; pop {r4,r5,r6,r7,r8,sb,sl,fp,pc}` skips the four saved
  argument words, so SP is restored exactly.
- **Return value:** `r0` = the roll value described below, or `0` on every
  abort path. Two callers in the event script only forward values, and the sole
  direct caller (`0x001E5840`) ignores the result.
- Register roles: `r8 = ids`, `fp = flags`, `r6 = count` (later reused for the
  slot id), `sl` = resolved record, then the collected-match count, then the
  match array base (`sp`); `sb` = target count; `r5` = slot index / scan index.
- `ids` is written only when non-null (`cmp r8,#0; strne`, twice). `count` is
  written only when non-null (`cmp r6,#0; strne`). `flags` is written with **no
  null test** (`strb` at `0x001F8F7C`/`0x001F8F88`); a null `flags` faults in
  both the original and the reconstruction.
- The record pointer is resolved twice with identical arguments; the second
  resolution is used for the camp scan and is dereferenced without a null test
  (`0x001F8E74` → `0x001F8FB0` → `0x001F8E78`).

## Recovered behaviour

### Record resolution (`0x001F8D18..0x001F8D40`, `0x001F8E54..0x001F8E74`)

```
owner = *(void**)0x00433158                       ; literal at 0x001F8FFC
record = lookup(owner, id)                        ; 0x00389E54
triple = (u32)id * 3                              ; 0x001F8D34
if (record == 0) {                                ; 0x001F8D3C
    table    = Tbb_GetGlobalSubTable(0x21, 0)     ; r0=0x21, r1=0
    payload  = Tbb_GetPayloadData(table)
    rows     = Tbb_GetRowCount(table)
    if ((u32)id >= rows) abort();                 ; 0x001F8DF8..0x001F8E04
    record = payload + triple*8                   ; = payload + id*24
}
if (record == 0) abort();                         ; 0x001F8D40
```

`0x00389E54` returns a pointer into a 26-byte-stride table row after its `s16`
key (row + 2), and the table-0x21 payload has a 24-byte stride, so both sources
produce the same 24-byte record. The fallback compares the id **unsigned**
(`cmp r4,r0; ldrlo/addlo; bhs`), so a negative id can never index the table.
Note that `payload + id*24` is formed even when `payload` is null; only
`id == 0` then yields a null record pointer (caught by `0x001F8D40`) while any
other id would fault.

### Count pair and roll value (`0x001F8D48..0x001F8D94`)

```
min = record[0x04]; max = record[0x05]
if (max < min) swap(min, max)                     ; `cmp sb,r5; movlt` pair
if (min == max) {                                 ; `moveq r0,#0x32`
    roll  = 50;
    target = min;
} else {
    span  = max - min;                            ; uxth before the call
    draw  = Random_Range(span);                   ; 0x002C0BCC, result 0..span
    roll  = (u32)ui_func_002c615c(draw*100, span) ; quotient only (r0)
    target = min + draw;
}
if ((s32)target <= 0) abort();                    ; `cmp sb,#0; ble`
if (count) *count = target;
```

`0x002C0BCC` is the shared LCG (`Random_Range`), whose result is `[0, max]`
inclusive. `0x002C615C` is the 32-bit divmod helper (quotient in `r0`,
remainder in `r1`); both operands here are non-negative, so the roll value is
`100*draw/span` in `0..100`. The value is spilled to `[sp+0x1B8]` and returned
from there at `0x001F8FA4`.

### Fixed item slots (`0x001F8DAC..0x001F8E50`)

Three 4-byte groups at `+0x08`, `+0x0C`, `+0x10`, each
`{u16 id; u8 mode; u8 chance}`:

```
for (slot = 0; slot < 3; ++slot) {                ; `cmp r5,#3; blt`
    id = slots[slot].id
    if (id == 0) continue;                        ; `cmp r6,#0; beq`
    if (slots[slot].chance == 0) continue;        ; `ldrbne +0x0B; cmpne #0`
    if (slots[slot].mode != 0) continue;          ; `ldrb +0x0A; cmp #0`
    roll = Random_Range(99);                      ; `mov r0,#0x63`, result 0..99
    if ((u16)(roll + 1) > slots[slot].chance) continue;  ; `add #1; uxth; bhi`
    add_item(id, 1);                              ; 0x00295CBC
    if (ids) ids[produced] = id;                  ; u16 zero-extended
    if (++produced >= (s32)target) return roll;   ; `cmp r4,sb; bge`
}
```

The 1..100 gate means `chance = 100` always accepts and `chance = 1` accepts
only a zero draw. `id` is stored as a zero-extended 16-bit value here.

### Camp scan (`0x001F8E78..0x001F8F38`)

```

The match array is the 460-byte frame area starting at the frame base
(`str sp,[sp+0x19C]` at `0x001F8E5C` records the base; the store is
`strh` at `sp + 2*i`). 200 entries fit.

### Random pick (`0x001F8F50..0x001F8FA0`)

```
bound = (u16)(s16)count - 1                       ; `sub r6,r0,#1`
do {
    i = Random_Range(bound)                       ; `uxth r6`, same bound each pass
    value = (s16)matches[i]                       ; `ldrsh`
    flags[produced] = (flag_test(value) == 0) ? 1 : 0;   ; 0x0025B920

The flag polarity is inverted relative to the helper: `flags = 1` when
`0x0025B920` reports the bit clear. Ids from this path are sign-extended
(a `u16` value of `0xF7F7` is published as `0xFFFFF7F7`).

## Differential verification

`tools/test_leaf_001f8d04.py` compiles `src/engine/leaf_batch34_c.cpp`, extracts
the `script_vm_func_001f8d04` body, resolves the ten call relocations to
deterministic stubs at the original addresses, and runs the pinned original
against the candidate on separate Unicorn ARM machines with identical fixtures.

Per case it compares:

- return `r0`, continuation PC, final SP and callee-saved `r4-r11`
  (`sb`/`sl`/`fp` included);
- the ordered call log: every helper with its `r0..r3`; the random stub logs
  both the requested bound and the value it hands back, so a bound change is
  visible even when the drawn value would be the same;
- the whole owner page, record page, camp-row page and output page, i.e. the
  `ids`/`flags`/`count` buffers plus every input byte;
- any emulated write outside the private stack and the output page.

Stubs: the two lookups can be null independently; the table-0x21 fallback can
return an in-range or out-of-range row count, a null payload, and a record at
`payload + id*24`; the random draws come from a per-case script (clamped to the
real inclusive `[0, max]` range) so `0`, the top of the range and boundary
rolls are all exercised; the camp stub returns per-index rows (or null) and
logs every index; the flag stub returns per-id bits.

Coverage: primary and fallback record resolution, the second-resolution
fallback, `id` out of range (including negative ids as unsigned), a null
payload with `id == 0`, count pair `min<max` / `min==max` / `min>max`, zero
targets before and after the draw, the draw at `0` and at the top of the span,
roll values `33`/`50`/`75`/`100`, all three slots with `id == 0`, `chance == 0`,
`mode != 0`, chance boundary accept/reject, chance 255, the top roll against
chance 100 and 99, the target reached on the first and second slot, the swapped
scan band, each of the four accepted keys, a non-matching key, null camp rows,
zero matches, a single candidate (pick bound 0) with the array-end index, the
scan window endpoints `0x3B7`/`0x47E` versus `0x3B6`/`0x47F`, sign-extended
`u16` ids, null `ids`, null `count`, and both null.

Result: **33/33 cases pass**, plus seven negative controls (`0x3B7`/`0x47E`
scan bounds, the constant 50, the item roll constant 99, the fallback slot
`0x21`, the `roll+1 > chance` boundary, and the inverted flag polarity) that
are each detected.

## Limits / unresolved

- All ten helpers are stubbed at their ABI boundary. Their internal behaviour
  (`0x00389E54`'s table walk, the TBB loader, the LCG, the divmod helper, the
  item add, the flag bitmap test) is not reimplemented here; the test checks the
  exact arguments, order and return-value use.
- The second-resolution null path (`0x001F8FDC` yielding 0 and `0x001F8E78`
  dereferencing it) is a fault in the original and is therefore not exercised.
  It requires the first lookup to succeed and the second identical lookup to
  fail, which a deterministic table cannot produce; the reconstruction
  dereferences the same null pointer.
- The `target <= produced` guard at `0x001F8F48` is unreachable because the slot
  loop returns as soon as the target is reached. It is kept verbatim.
- The 24 bytes at `0x001F9008` are a separate tail stub inside the ledger range
  (see Summary). They are emitted as raw words so the address `0x001F9008`
  still holds the original encoding that `0x0025C058` branches to; they are not
  part of the reconstructed routine.
- `flags` has no null guard in either body, so a caller passing null faults;
  the test always passes a valid buffer.
- No caller-side integrated scenario is run: the sole caller is the large
  `script_vm_func_001e5448` dispatcher, which is still a raw block.
- Byte identity is not claimed: the candidate body is 948 bytes versus 796 for
  the original range.
