# `0x002A63F8` — `AsdRes_IsLoaded`

## Recovered behavior

The function takes two 32-bit indices, forwards both to `engine_func_002b96f0`, reads the 32-bit word at the resolved address plus `0x10`, and returns `1` when bit 2 is set or `0` otherwise. The resolver can return zero; this function then faults on its unconditional load. The replacement preserves that behavior and does not turn a null result into `false`.

The H2 `TitleConfig_Calc` call at `0x001EA96C` sets `(r0, r1) = (0x2F, 0)` and branches on this function's return value.

## C++ reconstruction

`ui_func_002a63f8(u32 group, u32 subindex)` is implemented in [leaf_batch17_c.cpp](../../src/engine/leaf_batch17_c.cpp). The resolver remains original ARM code. The compiled replacement occupies the original 24-byte span and calls the resolver with an ARM `BL` to even address `0x002B96F0`.

This candidate is **non-matching**: the compiled body differs from the pinned original, and its classification in `config/functions.csv` must remain `non-matching`. The resolver at `0x002B96F0` remains byte-matching assembly; a typed resolver attempt compiled to 40 bytes and did not fit its 24-byte span.

## Evidence

`tools/h2_2a63f8_experiment.py` compares pinned ARM original, temporary compiled C++, final-VMA compiled C++, and the staged image. Eight direct fixtures cover the real `(0x2F, 0)` call, set and clear bit 2, unrelated flag bits, and varied indices. The original null-resolver fault is also compared, including the faulting instruction offset relative to function entry. Two negative controls, changing the mask from 4 to 8 and reversing the predicate, are detected. The actual call slice at `0x001EA964–0x001EA978` was composed with original and candidate code for clear, set, and all-bits-set words; the returned value and caller zero flag matched.

The candidate was staged as a one-slot IPS overlay on H2 run-013. The resulting image SHA-256 is `818f8a104e1761860d3967789994990570838cfc2751d21ddca32caeb8c9cf8d`; the IPS SHA-256 is `652f61bfb85c751bc26a5abb12a22ebbd4b50d17f1fa85acc0bbf474c6e80de0`. The replacement spans only `0x002A63F8–0x002A640F`, with 12 bytes changed from the base image. Offline direct and caller-slice differential passed against this staged image. Independent review confirmed hashes, slot scope, ledger classification and the staged null-fault instruction offset.

The ARMv6K project build completed 204/204 translation units, and all 11 affected consumer/source translation units compiled in focused checks.

## Limits

This is offline Unicorn evidence on controlled, valid table/object fixtures plus one deliberate null-resolver fault. It does not establish resource-table bounds, malformed address behavior, concurrency, natural scheduler reachability, or a full runtime `titleConfig` cycle. Azahar was not launched. Independent review is required before treating the staged integration as reviewed.
