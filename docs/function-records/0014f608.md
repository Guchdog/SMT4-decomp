# Function Record: func_0014f608 (0x0014f608)

## Summary
- **Address:** `0x0014f608`
- **Size:** 484 bytes (original span `[0x0014f608, 0x0014f7ec)`). The body ends
  with `bx lr` at `0x0014f7e0`; `0x0014f7e4`/`0x0014f7e8` hold the literal pool
  (`0x00004652`, `0x00005544`). `0x0014f7ec` starts the next function.
- **File:** `src/engine/leaf_batch34_c.cpp`
- **Role:** expanded-heap split. Given one free block already selected by
  `0x00146ad8`, carve a used block for an aligned payload out of it, return up

- **Class:** leaf on the semantic ledger (category `unknown` retained). There

## Contract and Behavior

### Signature and ABI
```c
struct HeapBlock {              // 16-byte header, payload at +0x10
    u16 signature;              // +0x00: 0x4652 "FR" free, 0x5544 "UD" used
    u16 attribute;              // +0x02: bit15 direction flag, bits 8..14 preamble
    u32 size;                   // +0x04: payload bytes
    HeapBlock* prev;            // +0x08: toward the free-list head
    HeapBlock* next;            // +0x0C: toward the free-list tail
};
struct BlockList {              // passed in r0 (heapBase + 0x24)
    HeapBlock* free_head;       // +0x00
    HeapBlock* free_tail;       // +0x04
    HeapBlock* used_head;       // +0x08
    HeapBlock* used_tail;       // +0x0C
    u16 attribute_source;       // +0x10: low byte copied into a new used block
    u8  split_padding;          // +0x14: non-zero preserves padding remnants
};

extern "C" u8* func_0014f608(BlockList* list, HeapBlock* block,
                             u8* payload, u32 size, u32 direction);
```
- `list = r0`: block list. The zero-fill option word is read from `list - 4`
  (`ldr r3,[r0,#-4]`, then `and r3,r3,#1`). In the heap object this is
  `heapBase + 0x20`, the same `optFlag` used by `0x0011bf0c`; the block list is
  `heapBase + 0x24`.
- `block = r1`: the free block chosen by the caller. Only `+0x02`, `+0x04`,
  `+0x08` and `+0x0C` are read; the signature word is never read.
- `payload = r2`: aligned payload address. It is only read, and it is the
  return value.
- `size = r3`: payload byte count; it is added to `payload` without rounding.
- `direction = [sp]` (fifth argument, stack): `0` from the upward-alignment
  caller and `1` from the downward-alignment caller. Odd/even forms of the
  full word are used, not a signed test: `cmp r7,#0` and `cmp r7,#1` are
  equality tests, and `orr r1,r1,r7,lsl #15` moves only bit 0 into attribute
  bit 15.
- **Return value:** `r2` unchanged (`mov r0,r2` at `0x0014f7dc`).
- Prologue `push {r4,r5,r6,r7,r8,sb,sl,fp}` = r4-r11; epilogue restores them.
  `lr` is not saved because the routine makes no call. `r12` is caller-saved
  and holds the new header address (`ip`).
- The candidate pushes six registers, so its fifth argument load is
  `[sp,#0x18]` instead of `[sp,#0x20]`; both address the caller's `[sp]`.

### Block attribute encoding
- Bits 8..14 of `attribute` hold the number of bytes that lie before the block
  header but still belong to the block (alignment preamble). The free-block
  region start is therefore `block - ((attribute >> 8) & 0x7F)`.
- **The shift pair drops bit 15:** `lsl ip,ip,#0x11` moves bit 15 out of the
  32-bit register, so the following `lsr #25` yields bits 8..14 only. The
  candidate writes the equivalent `>> 8 & 0x7F`.
- Bit 15 is set on the used header from bit 0 of `direction`
  (`orr r1,r1,r7,lsl #15`).
- Bits 0..7 of a new used header come from the low byte of the halfword at
  `list + 0x10` (`ldrh r3,[r0,#0x10]` / `and r3,r3,#0xff`).
- Free remnants created here always get `attribute = 0`.

### Control flow
1. `0x0014f60c..0x0014f634`: snapshot the selected block:
   `free_payload = block + 0x10`, `free_end = free_payload + block->size`,
   `free_region = block - ((attribute >> 8) & 0x7F)`, `free_prev = block->prev`
   (+0x08), `free_next = block->next` (+0x0C).
2. `0x0014f638..0x0014f654`: unlink the block from the free list.
   `free_prev->next = free_next` otherwise `list->free_head = free_next`;
   `free_next->prev = free_prev` otherwise `list->free_tail = free_prev`.
3. `0x0014f658..0x0014f6b8`: leading remnant.
   - Entered when `header - free_region >= 0x14` **unsigned** (`cmp sl,#0x14` /
     `blo`) and (`direction != 0` or `list->+0x14 != 0`). The second test is the
     `cmp r7,#0` / `ldrbeq` / `cmpeq` chain; `direction` other than 0 always
     splits.
   - Writes a free header at `free_region`: signature `0x4652`, attribute 0,
     `size = (header - free_region) - 0x10`, then links it after `free_prev`
     (`free_prev` null -> at the head; a null successor -> tail).
   - When taken, the used block's preamble starts at `header` (attribute
     preamble field 0). When skipped, the used block's region start is
     `free_region`, so the too-small preamble (0..0x13 bytes) is owned by the
     used block and encoded in its attribute.
4. `0x0014f6c0..0x0014f718`: trailing remnant, anchored after the leading
   remnant (or after `free_prev` when there is none).
   - Entered when `free_end - requested_end >= 0x14` **unsigned** and
     (`direction != 1` or `list->+0x14 != 0`). Note the asymmetry with step 3:
     direction 1 alone preserves the leading padding but absorbs the trailing
     padding, while direction 0 does the reverse.
   - Writes a free header at `requested_end` with size
     `(free_end - requested_end) - 0x10`; the used block then ends at
     `requested_end`. When skipped the used block absorbs everything up to
     `free_end`.
5. `0x0014f720..0x0014f760`: zero fill. When `(options & 1) != 0` and
   `used_end - region_start > 3` (unsigned), store zero words starting at the
   region start for `(used_end - region_start) >> 2` words, i.e. the span is
   rounded **down** to a multiple of four. `0x0014f73c` tests bit 2 of the
   length with `lsl #0x1d` and then loops over `lsr #3` pairs; bit 1 of the
   length is ignored. The zeroing happens before the used header is written.
6. `0x0014f764..0x0014f7a8`: used header at `payload - 0x10`:
   signature `0x5544`; `prev = 0`; `next = 0`;
   `size = used_end - header - 0x10` (= `size` when the trailing remnant was
   split, otherwise payload + all absorbed padding); attribute =
   `(direction & 1) << 15 | ((header - region_start) & 0x7F) << 8 |
   (list->+0x10 & 0xFF)`.
7. `0x0014f7ac..0x0014f7d4`: append the used block to the used list. With a
   non-null tail: `used->prev = tail`, `used->next = tail->next`,
   `tail->next = used`, and the old successor's `prev` (or the tail when the
   old successor is null) is updated. With a null tail: `used->prev = 0`,
   `used->head = used`, `used->next = old head`, old head's `prev = used`, or
   the tail when the head was null. The code tolerates a tail whose `next` is
   non-null and a head with a null tail; both are covered by tests.
8. `0x0014f7d8..0x0014f7e0`: restore r4-r11 and return `r2`.

## Contract corrections found during implementation
- **The preamble offset is seven bits, not eight.** The `lsl #0x11` discards
  attribute bit 15, so `block - (attribute >> 8 & 0x7F)` is the region start.
  Treating it as eight bits would move the free region 128 bytes too far back
  for direction 1 blocks.
- **Both remnant thresholds are unsigned.** `free_region` above the header or
  `requested_end` above the free end wrap to a huge `sl`/`r4` and create a
  remnant with a huge size instead of taking the small-remainder path. The
  tests include both wrap directions.
- **The split conditions are asymmetric.** Direction 0 needs a non-zero
  list->+0x14 to split the *leading* padding; direction 1 needs it to split
  the *trailing* padding. Any other direction splits both unconditionally.
- **The zero fill rounds down, not up,** and is skipped for spans below four
  bytes. A four-byte span only covers the used signature/attribute words,
  which are rewritten afterwards, so a length-4 test with a wrapped used end
  is used to make that threshold observable.
- **The used list is appended, not address-sorted.** Free remnants preserve
  address order; used blocks go to the tail.
- **The used header's low attribute byte comes from a halfword load** at
  `list + 0x10` whose high byte is discarded.
- **The selected block's signature is not validated**, and no size or list
  invariant is checked.
- **The candidate narrows two loads.** Clang reads the free attribute's high
  byte as `ldrb [block,#3]` and the list attribute source as
  `ldrb [list,#0x10]`; the original loads a halfword and masks. Both read the
  same bytes and the high bytes are unused, so the observable value is
  identical; no `volatile` was added.

## Limits
- The routine was verified offline with Unicorn against synthetic heap fixtures
  in one mapped page. The game's real heap invariants (address-ordered free
  list, magic signatures, `optFlag` semantics) are inferred from the callers
  and sibling allocator functions (`0x00146ad8`, `0x0014699c`, `0x0011bf0c`),
  which were read statically, not reconstructed or runtime-captured here.
- `0x00146ad8` and the heap free/resize paths are not part of this record. No
  caller-composition test was run: the caller's free-list search and alignment
  arithmetic are outside this function.
- The zero fill uses 32-bit stores at `region_start`, which may be unaligned
  when the 7-bit preamble offset is not a multiple of four. The pinned ARM and
  the candidate both issue unaligned word stores, and the test includes
  unaligned starts; the candidate relies on the same ARMv6 unaligned-access
  behaviour rather than adding alignment handling.
- The candidate reads a newly carved remnant as `HeapBlock*` (four-byte
  aligned in all realistic fixtures). Payload addresses and sizes are used
  exactly as passed; units are bytes, and the caller's rounded size is assumed
  but not required.
- No emulator or whole-game runtime scenario was run; this record's evidence is
  the differential test above.
