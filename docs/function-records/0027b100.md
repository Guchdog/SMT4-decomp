# Function Record: script_vm_func_0027b100 (0x0027b100)

## Summary
- **Address:** `0x0027b100`
- **Size:** 804 bytes (original span `[0x0027b100, 0x0027b424)`)
- **File:** `src/engine/leaf_batch45_b.cpp`
- **Role:** Per-frame submission of the placed/streamed object columns. Walks the
  24-slot placement table behind the singleton at `0x00447E70` and, for every
  slot whose enabled byte is set, forwards a billboard-column draw
  (`0x00267420`) built from the slot position, angle and a per-selector
  dimension set. Selectors `2` and `10` additionally bob the column along X/Z
  and are skipped while the shared screen state is `4` / `1`.
- **Status:** Semantically equivalent C++ (`non_matching`). The compiled body is
  864 B versus the 804 B original: the candidate reloads the slot selector
  between tests and keeps its own register allocation, while the original uses
  `r4` as a write-back slot pointer and keeps every literal in a tail pool. The
  ledger row is classified `non_matching` with this semantic record.

## Contract and Behavior

### Signature and ABI
```c
extern "C" void script_vm_func_0027b100(void);
```
- No parameters and no computed return value. The original saves
  `r4-r8, lr` plus `d8-d15`; the candidate preserves the same callee-saved
  integer set (floating-point state is caller-saved under the AAPCS-VFP and is
  not live across the routine). Final `sp` equals the entry value in both.
- `r0` is always set to `0` immediately before each `0x00267420` call, so it is
  only observable as the callee's return value (the call is `void`). The
  differential runner sets a fixed sentinel in the stub and compares `r0` only
  for cases whose last executed slot ends in a draw.

### Data
- `0x00447E70` holds `ObjectLoadContext*`. Slots begin at context `+0x14` and
  are `0x48` bytes apart, 24 of them (the same layout used by
  `ObjectLoadContext`/`ObjectLoadSlot` in `leaf_batch45_a.cpp`). This function
  reads:
  - `slot + 0x00`: `enabled_00` (`ldrb`); `0` skips the slot.
  - `slot + 0x04/0x08/0x0C`: `position_04/08/0C` (`f32` X/Y/Z).
  - `slot + 0x1C`: `angle_1C` (`f32`, degrees).
  - `slot + 0x24`: `object_id_24` (`u32` behaviour selector).
- `0x0049F91C`: shared screen/script word block. Only `+0x00` and `+0x04` are
  read, as the near/far suppression gate.
- The routine performs no memory writes; every draw is its only effect.

### Control flow and calls
For each slot index `0..23`:
1. If `enabled_00 == 0`, continue.
2. `suppress = *(u32*)0x0049F91C == 4 && *(u32*)0x0049F920 == 1`.
3. Re-read the selector before each independent test (as the original does; a
   draw callee could in principle rewrite the shared slot table):
   - `2`, if `!suppress`: `rad = angle * pi/180`;
     `draw(0, x + sin(rad)*20, y - 400, z + cos(rad)*20, angle, 80, 350, 50)`.
   - `10`, if `!suppress`: same bob; `y - 550`, `80, 500, 50`.
   - `7`: `draw(0, x + sin(rad)*-17.5, y, z + cos(rad)*-17.5, angle, 200, 300, 50)`.
   - `9`: same as `7` with width `150`.
   - `11`: same as `7` with width `200` (it is a distinct comparison in the
     original, not a fallthrough).
   - `15`, `16`: `draw(0, x, y, z, angle, 50, 50, 50)`.
   - `17`: `draw(0, x, y, z, angle, 100, 50, 60)`.
   - any other value: no call.
4. `index += 1`; loop while `index < 24` (`cmp r5, #0x18` / `blt`).

Call order per slot is exactly `sin`, `cos`, then the draw; the sine result is
consumed before the cosine call. The two radians values are the same product
computed twice in the original (the angle is reloaded between the calls); the
candidate computes it once per branch, which is bit-identical because each is a
single `f32` multiply.

### Draw-call argument map (all in registers)
```text
r0 = 0 (id)
s0 = X            s1 = Y          s2 = Z          s3 = angle (degrees)
s4 = width        s5 = height     s6 = depth
```

## Contract corrections found during implementation
- **Independent comparisons, not `switch`/`else-if`.** The original reloads
  `[slot+0x24]` before every test, including after a draw. The candidate keeps
  that reload order.
- **Suppression is checked once per iteration, before the `2` and `10` tests.**
  It does not gate `7/9/11/15/16/17`.
- **`7` and `11` share dimensions but are separate source comparisons.** They
  were kept separate so a future change to one cannot silently alter the other.
- **`15` and `16` are byte-identical blocks in the original.** They are written
  as two tests with the same arguments (no fallthrough) to match the separate
  selector reads.

## Limits
- Fixtures are synthetic: the slot table and the `0x0049F91C` page are built by
  the harness, not captured game data.
- All three callees are stubbed. `0x0028277C`/`0x00282600` are the pinned
  single-precision libm sine/cosine (implemented elsewhere in the same
  translation unit), and `0x00267420` is a 2,888-byte billboard/column
  submitter. Their real maths, clipping, sorting and GPU submission are not
  exercised, and no claim is made about the drawn geometry.
- The non-finite angle/position cases only verify that the candidate forwards the
  same bit patterns as the original into the stubs; the real transcendental
  result for `nan`/`inf` is a property of the stubbed helpers.
- `*0x00447E70` is dereferenced unconditionally (the original does the same); a
  null context faults in both, and no null guard is added.
- Frame layout and register allocation differ from the original; only the
  documented ABI effects, call arguments, saved registers and memory
  (un)modified state are compared.
- No emulator launch and no whole-game/caller-composition runtime equivalence is
  claimed.
