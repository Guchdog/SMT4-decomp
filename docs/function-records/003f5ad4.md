## Contract and ABI

```c
extern "C" u32 ui_func_003f5ad4(void* object, void* row_array, u32 total);
```

- `r0` is the owning structure, `r1` the base of the caller's row records, `r2`
  the byte total divided by the row count. There are no stack arguments at the
  entry. The prologue saves `{r4,r5,r6,r7,r8,sb,sl,fp,lr}` and the epilogue
  restores the same set, so `r4-r11` and `sp` survive.
- Object fields (all 32-bit, re-read on use):
  - `+0x00` output buffer base
  - `+0x04` output byte capacity
  - `+0x08` bytes made valid by the decode (cleared first, then written)
  - `+0x0C` scratch buffer (`2*width` bytes)
  - `+0x10` scratch halfword capacity
  - `+0x18` row count, also the divmod divisor
- Return value: `1` on the normal/zero-width/zero-row paths, `0` only when one
  of the two allocator calls returns null.

## Behavior

```text
row_count = *(u32*)(object + 0x18);
*(u32*)(object + 0x08) = 0;

q     = udivmod(total, row_count);           // 0x002C6C10, quotient only
width = width_helper(q - 0x26, 2, 1);        // 0x00360270
if (width == 0) return 1;

if (row_count > 1 && width > *(u32*)(object + 0x10)) {
    if (*(u32*)(object + 0x0C) != 0) release(*(u32*)(object + 0x0C));
    *(u32*)(object + 0x10) = 0;
    scratch = allocate(width << 1);
    *(u32*)(object + 0x0C) = scratch;
    if (scratch == 0) return 0;
    *(u32*)(object + 0x10) = width;
}

transposed = ((width - 0x20) * row_count) << 1;          // 32-bit wrap
required   = row_count == 1 ? (width << 1) : transposed;
if (*(u32*)(object + 0x04) < required) {
    if (*(u32*)(object + 0x00) != 0) release(*(u32*)(object + 0x00));
    *(u32*)(object + 0x04) = 0;
    output = allocate(required);
    *(u32*)(object + 0x00) = output;
    if (output == 0) return 0;
    *(u32*)(object + 0x04) = required;
}
*(u32*)(object + 0x08) = transposed;

if (row_count == 1) {
    copy6(stack_state, rows + 0x20);                     // 0x002BD9EC
    decode(rows + 0x26, *(u32*)(object + 0x00), rows,
           stack_state, width);                          // 0x0036014C
    return 1;
}
if (row_count == 0) return 1;

for (row = 0; row < row_count; ++row) {                  // unsigned bound
    copy6(stack_state, rows + 0x20);
    decode(rows + 0x26, *(u32*)(object + 0x0C), rows,
           stack_state, width);

        output  = *(u32*)(object + 0x00);

            *(u16*)(output + 2*row + 2*row_count*k) =
                *(u16*)(scratch + 0x20 + 2*k);

    rows += q;                                           // unsigned wrap
```

Details preserved from the ARM:

- `0x002C6C10` is the unsigned divmod service. Only `r0` (the quotient) is
  consumed; the remainder in `r1` is overwritten by the next instruction. A zero
  divisor yields quotient `0xFFFFFFFF`, which flows into the width helper.
- `0x00360270` mode 2 doubles the input (`lsl #1`), splits it into the low nibble
  and the upper bits, and returns `14*(shifted >> 4) + (nibble >= 2 ? nibble-2 : 0)`
  with 32-bit wrap. All values it can produce are even, so the original's
  parity-split copy always follows the odd path; the reconstructed ascending loop
  performs the identical source/destination sequence for both parities.
- `required` is `2*width` only for exactly one row; otherwise it is
  `2*(width-0x20)*row_count`, including 32-bit wrap for `width < 0x20`. The
  comparison against `+0x04` is unsigned `bhs`.
- The single-row arm passes `*(u32*)(object + 0x00)` to `0x0036014C`, not the
  scratch buffer, and performs no transposition. The multi-row arm passes
  `*(u32*)(object + 0x0C)` and re-reads both `+0x00` and `+0x0C` after the call,
  so a helper that rewrites those fields changes the transposition source and the
  next row's destination.
- The transposition is guarded by a signed `> 0` test of `width - 0x20`; widths
  0x1E and 0x20 skip it even though `+0x08` is still written.
- The row loop is `row < row_count` with unsigned `blo`; the row record advances
  by the divmod quotient each iteration and may wrap.
- The allocator slot `0x0044E918[0]` and release slot `0x0044E918[1]` are read
  immediately before each call. The release is skipped when the old pointer is
  zero; the new pointer is published even when it is zero, but the capacity field
  is only published on success.
- The 6-byte per-row state at `row+0x20` is copied to the stack by `0x002BD9EC`
  (u32 at `+0`, u16 at `+4`); `0x0036014C` receives that state, the packed nibble
  stream at `row+0x26`, the row record base, the output buffer and the width, with
  the width as the only stack argument.

## Helpers and indirect targets

- `0x002C6C10` — unsigned divmod, reconstructed in `src/engine/leaf_batch40_c.cpp`.
  Returns quotient in `r0` and remainder in `r1`; zero divisor returns
  `0xFFFFFFFF`/dividend.
- `0x00360270` — width helper (148 bytes) in `src/engine/leaf_batch33_a.cpp`.
  Modes 0/1 tail-call the signed divmod at `0x002C615C`; mode 2 is the arithmetic
  above.
- `0x002BD9EC` — 20-byte 6-byte structure copy in `src/engine/leaf_matching.cpp`.
- `0x0036014C` — 292-byte nibble-stream filter in `src/engine/leaf_batch36_b.cpp`.
  Its filter arithmetic (signed halfword coefficients, bilinear term, clamping)
  is outside this span and is not recovered here; only its ABI is declared.
- `0x0044E918[0]` / `[1]` — allocator/release function pointers. Their concrete
  targets are not recovered; the reconstruction reads each slot at the call site.

## Validation

`tools/test_leaf_003f5ad4.py` compiles `src/engine/leaf_batch41_c.cpp`, extracts
the `ui_func_003f5ad4` body, resolves its four `R_ARM_CALL` relocations to stubs at
the pinned target addresses, and runs the pinned original against the candidate in
identical Unicorn ARM machines. The stubs implement the real divmod, the real
mode-2 width arithmetic, a deterministic 6-byte copy, a deterministic 0x0036014C
filter that writes `count` halfwords and rewrites the descriptor state, and a
bump allocator with injectable failure. It compares:

- return `r0`, continuation PC (`0x90000000` trap), final `sp`, and the `r4-r11`
  sentinels;
- the ordered call log with every register argument, the descriptor words and the
  stack count;
- the full row page, object page, scratch page, output page, allocator pool and
  the `0x0044E918` slot page;
- every emulated write outside the private stack.

Coverage: width zero (one and three rows), width 0x1E below the narrow limit,
width 0x20 exactly, widths 0x22/0x2A/0x40/0x46 that run the transposition, one
row (allocating/preallocated, including the 0x08 = `2*(width-0x20)` boundary),
three and five rows, capacity exactly equal to the requirement, division
remainders, zero/nonzero old scratch and output pointers (release skipped or
performed), allocation failure at the first and second allocator call, zero rows
(divmod by zero), and filter stubs that reassign `+0x00`/`+0x0C` mid-run.

## Limits

- `0x0036014C` and the two indirect allocator slots are deterministic stubs; the
  real filter arithmetic and the real allocator are not recovered. The stub's
  writes are arbitrary but identical for both machines, so the wrapper's argument
  forwarding, call order, buffer publication and transposition are what is
  validated.
- The original's parity-split copy is exercised only through the reachable
  (even) widths produced by `0x00360270`; odd widths cannot come from the pinned
  helper. The reconstruction's unified loop still matches both sequences.
- All fixtures use mapped, aligned ordinary RAM. Null/misaligned/unmapped buffer
  pointers, MMIO, concurrency, live caller composition and whole-game runtime
  behaviour are not covered.
- This is offline Unicorn differential evidence, not formal equivalence and not
  an emulator or whole-game run.
