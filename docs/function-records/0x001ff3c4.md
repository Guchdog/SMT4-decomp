# `0x001FF3C4` — cursor-axis mover

The complete ARM body is expressed as typed C++ in `src/engine/leaf_batch43_a.cpp`. It retains all ten eager calls to `ui_func_00254ca8`, statuses 0..4, the ordered flags/axis writes, and signed or wrapped branches. The main symbol is 580 bytes; Clang outlines two local movement helpers of 152 and 148 bytes. The integrated 880-byte sequence fits the original 1,104-byte slot. Its ten `R_ARM_CALL` relocations target the pinned query helper; the outlined helpers have no relocations.

Run006 compared the pinned original against the compiled replacement over 162 direct fixtures. All passed, including signed/high-bit boundaries, simultaneous-query priority, `C2/C1` with counts 0 and 1 and width greater than count, and `SUBS`/N behavior at `0x80000000`. Four `TitleConfig_Calc` compositions also passed: stable cursor, active cursor without input, logical input bits, and the statically initialized H2 cursor. The runner executes the original query-service chain and models the unrelated outer Calc services. A deliberately wrong first query target was detected. The ARMv6K build passed 204/204 translation units.

Independent review reran the suite as run007 with a distinct seed and 121 seeded cases: 171/171 direct cases, all four compositions, and the negative control passed. The reviewer separately checked the two corrected ARM conditions and confirmed that all local branches stay in the contiguous 880-byte placement. The ledger classification is `non_matching`.

An in-place IPS was also applied to the accumulated H2 image that already includes the reviewed `0x0029F278` updater. Roundtrip succeeded, the remaining slot suffix stayed unchanged, and the patched accumulated image passed four `TitleConfig_Calc` compositions. Independent review reproduced the artifact hashes, confirmed changes were confined to this slot and passed all four compositions. The hashes and limits are recorded in the [slot integration report](../agent-work/h2-001ff3c4-slot-integration.md).

The pinned-ARM contract was corrected before differential testing: `C2/C1` has no `count <= 1` gate; its comparisons use original width while reset values use `min_signed(width,count)`. `B0/B2` checks N after wrapped `SUBS offset,#1`, which differs from an ordinary signed-positive test at overflow. These are covered by the direct cases.
