## Behaviour

- Seed phase: copies four rows verbatim at `source`/`destination` and four rows
  at `source + (height_rows - 4) * 0x400` / destination likewise. Each row is
  `width_bytes` long but copied in whole `0x20`-byte chunks, so it always copies
  at least one chunk and rounds up to the next multiple of 0x20. The signed
  remainder rewinds the pointers to the exact row end before the next stride.
- Filter phase: starts at `source + 0x2000` / `destination + 0x2000`. Each band
  is eight rows and advances `0x2000` bytes; the vertical counter is
  `height_rows - 8` and drops by 8 (`subs`/`bne`), so it repeats while non-zero.
- Per 4-byte lane the routine loads the eight rows at
  `source{-4,-3,-2,-1,0,+1,+2,+3} * 0x400`, copies the four outer rows
  (`-4,-3,+2,+3`) to the destination unchanged, and rewrites the four middle
  rows with the shared `filter_four_centre_rows` kernel (identical to the
  0x001602dc / 0x00164054 family):
  `pair = uhadd8(C, D)`; `B_out = uhadd8(pair, A)`, `E_out = uhadd8(pair, F)`,
  each replaced by `B`/`F` when `|A-C|` / `|F-D|` reaches `threshold_b`; the two
  centre outputs are `pair` sharpened by
  `m = uhadd8(uhadd8(uhadd8(~E, B), 1), 1)` split around the `0x20` bias; then
  all four outputs are replaced by the original `B`, `C`, `D`, `E` per byte
  where `|B-C| >= threshold_b`, `|D-E| >= threshold_b` or
  `|C-D| >= threshold_a`.
- Packed arithmetic: `uhadd8`, `uqsub8`, `uqadd8`, `uadd8`, unsigned `usub8`
  (GE = unsigned `a >= b`, **not** `ssub8`), `mvn` and `sel`.
- Horizontal walk: eight lanes (0x20 bytes) per chunk; counter `width_bytes -
  0x10` drops by 0x20 with a signed `> 0` repeat. Exactly zero filters four
  trailing lanes (0x10 bytes); negative skips them after the unconditional
  first chunk.
- Band wrap: `address += 0x2000 - 0x10`, counter `-= 8`; while non-zero,
  `address -= (width_bytes - 0x10)` and the horizontal counter re-arms.
- ABI: the original saves only `{r0, lr}` and therefore clobbers callee-saved
  `r4-r11` (same deviation as `0x001602dc` / `0x0015f7bc`). The C++ candidate is
  a normal AAPCS function and preserves them.

## Limits

- Byte identity is intentionally not preserved (`non_matching`).
- No real caller or whole-game runtime scenario was exercised; the caller set
  and the semantic meaning of the two thresholds remain inferred from the
  kernel only.
- Heights where `height_rows - 8` is not a positive multiple of 8 do not
  terminate in the original (`subs`/`bne`) and are documented, not executed.
  Widths whose `width_bytes - 0x10` wraps to a huge positive value are likewise
  out of domain.
- The duplicated kernel at `0x00165ac8` was left untouched.
- The original's `pld` hints are omitted (non-semantic).
