# Function Record: battle_func_00137730 (0x00137730)

## Summary
- **Address:** `0x00137730`
- **Size:** 680 bytes (original span `[0x00137730, 0x001379D8)`; 180 ARM
  instructions through the final tail branch at `0x001379CC`, followed by the
  two literal words `0x00008057` and `0x004C6290` at `0x001379D0`)
- **File:** `src/engine/leaf_batch45_a.cpp`
- **Role:** Appends one 28-byte replay entry of kind 3 to the active render
  node's entry array, describing a texture rectangle (two 16-bit coordinate
  pairs, two opaque words and a parameter word). While holding the engine lock
  at `0x004E6C5C` it bumps the node's entry count and, when the node is the
  active owner, requests a one-shot flush of the pending list. The lock is
  released as a tail branch.
- **Status:** Semantically equivalent C++ (`non_matching`). The compiled body is
  816 B versus the 680 B original: the candidate reloads the eight stack
  arguments into a larger private frame, folds the two intermediate flag-word
  stores and the two `blx`-free selector chains differently, and keeps the
  flags word in registers. The ledger row is classified `non_matching` with this
  semantic record.

### Flag word
Bits 0..11 are recomputed; bits 12..31 keep the previous entry value.
```text
bits 0..2   primary field (`a4` mapping, & 7)
bits 3..5   secondary field (`a8` mapping, & 7)
bit  6      a10 != 0
bits 7..8   (a9 - 0x500) & 3
bit  9      a11 == 0x20
bits 10..11 cleared
bits 12..31 preserved from the old word
```
The original performs three stores to `+0x14` (`0x001378C0`, `0x00137968`,
`0x0013797C`). Only the final value is architecturally observable; the
candidate emits one effective store (the compiler folds the others).

### Blend adjustment of entry+0x08
Only when `a10 != 0`. Let `x1 = entry[0x10]`, `x0 = entry[0x0C]`,
`y1 = entry[0x12]`, `y0 = entry[0x0E]` (all zero-extended `u16`):
- If `x1 >= x0 && y1 >= y0`, `entry+0x08` stays `a5` (`bhs 0x00137950`).
- Else with `multiplier_lo == 2` (`a9` `0x501/0x502`, branch `cmp r0,#2`):
  ```text
  delta  = (x0 - x1)                    32-bit wrap
  align  = (scale == 3) ? 0x10 : 0x08
  if (delta & align) delta -= align
  value  = delta * (a7 - 1) * scale     32-bit wrap
  value += value >> 31                  logical: +1 when bit 31 set
  entry+0x08 = a5 - ((s32)value >> 1)   arithmetic shift
  ```
- Else (`multiplier_lo == 1`, i.e. `a9 == 0x500`):
  ```text
  value = (x0 - x1) * (y1 - 1) * scale  32-bit wrap, no rounding
  entry+0x08 = a5 - value
  ```

## Limits
- Fixtures are synthetic: the node, entry array and `0x004C6290` state are
  pattern-filled pages, not captured game memory.
- Every helper (`0x0013AF78`, `0x002BA5F8`, `0x0013AF88`) is stubbed. No real
  lock, pending-list flush, command-stream submission or GPU state is exercised.
- `0x002BA5F8` is not reconstructed here; only its call site, `r0` argument and
  return value are modelled. Its case-3 decoding of this entry (documented above)
  is static evidence, not part of the compared runtime.
- The exact semantics of the two command-id sets and of the flag-word bit fields
  are not recovered; they are treated as opaque selectors whose observed
  mappings are preserved. The field names `pair0_*`/`pair1_*` are descriptive.
- The original writes the flag word to `+0x14` three times; the candidate's
  compiler folds them into one effective store. Final memory is identical. Only
  a fixture where the entry aliases the node or the state page could observe the
  intermediate values; no such aliasing is exercised or claimed.
- The candidate's frame and register allocation differ from the original;
  only the documented ABI inputs, call arguments, returned state, saved
  registers and observable memory are compared.
- No caller-composition, rendering or whole-game runtime equivalence is
  claimed.
