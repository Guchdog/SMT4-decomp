# Function Record: ui_func_0033b3e0 (0x0033b3e0)

## Summary
- **Address:** `0x0033b3e0`
- **Size:** 400 bytes (original span `[0x0033b3e0, 0x0033b570)`; 98 ARM
  instructions plus the 8-byte literal pool `0x00002f1e`, `0x00439ca8`)
- **File:** `src/engine/leaf_batch41_c.cpp`
- **Role:** Unit-slot insertion for the UI context. The function gates on a
  per-unit flag word, copies one s16 out of a unit actor record into the
  twelve-entry ordered unit list of the UI context, re-orders the list with an
  exchange pass, and tail-calls `0x0025508c` with the shared UI buffer.
- **Status:** Semantically equivalent C++ (`non_matching`). The compiled body is
  448 bytes versus 400 original bytes (register allocation, loop shape and the
  literal/load layout differ); the ledger row is classified `non_matching` and
  this record carries the semantic evidence.

## Contract and Behavior

### Signature and ABI
```c
u32 ui_func_0033b3e0(void* context, s32 id);   // r0 = context, r1 = id
```
- `context` is the UI object; `id` is a battle-unit index into the 0x114-byte
  record table reached from `context+0x1E98`.
- Return: the flag word on the early exit, otherwise the R0 value of the tail
  call to `0x0025508c`.
- The original saves `r3`-`r11` and `lr` (40 bytes) and uses the first saved
  slot as scratch for `context+0x1FC0`; `sp` is restored on both exits. The
  non-early exit pops the saved registers and then `b 0x0025508c`, so `lr` is
  still the caller's return address when the callee runs.

### Flag record (0x114-byte stride, field `+0x50`)
`flags = *(u32*)(flag_table + 0x50 + (u32)id * 0x114)`. The index is formed by
`add r3,r1,r1,lsl #2` + `add r3,r3,r1,lsl #6` + `lsl #2` and is added to the
base without any bound check. The function continues only when **both** bit
`0x01` and bit `0x80` are set (`tst r0,#1` at 0x0033B408 followed by the
conditional `tstne r0,#0x80` at 0x0033B40C); otherwise it returns the flag word
unchanged. The caller at `0x003BD2EC` raises exactly `0x81` in this word before
calling.

### Behavior
1. **Flag gate.** Load the flag word as above. If `(flags & 1) == 0` or
   `(flags & 0x80) == 0`, return `flags`.
2. **Helper.** `actor = ui_func_00282b94(context, id)`; the inserted value is
   `*(s16*)(actor + 0x6E)`. The result is dereferenced unconditionally, exactly
   like `ldrsh r0,[r0,#0x6e]` at 0x0033B420 — a null or invalid helper result
   faults at `0x6E` rather than being skipped.
3. **Cursor.** `start = *(s16*)(context+0x2F1E) + 1` (0x0033B428). If
   `start >= 12`, the slot list is left untouched and the function goes to the
   tail call.
4. **Free-slot scan.** Walk `index = start, start+1, ... < 12` and stop at the
   first slot whose value is **negative** (0x0033B438..0x0033B460). If no such
   slot exists the list is left untouched. This is a presence scan, not an
   ordering scan: occupied means "value >= 0" (0 counts as occupied), and the
   scan starts at `start`, not at slot 0.
5. **Insertion.** `*(s16*)(slot_array + found) = (s16)value`.
6. **Ordering.** Only when `start <= 10`, run an exchange pass over
   `j = start..10`, `i = j+1..11`:
   - skip `j` when `slot[j] < 0`, skip `i` when `slot[i] < 0`;
   - `slot[j]` is reloaded on every inner iteration (0x0033B49C), so a swap is
     observed by the next comparison;
   - `primary(index) = (s16)(u16 @ actor+0x1C2 + u16 @ actor+0x254)`: both
     fields are zero-extended, summed modulo 2^32 and truncated to s16
     (`ldrh`/`ldrh`/`add`/`sxth`, 0x0033B4D4..0x0033B4F0);
   - swap when `primary(slot[j]) < primary(slot[i])`; on equal primary keys
     swap when `secondary(slot[j]) > secondary(slot[i])`, where
     `secondary(index) = *(s16*)(actor+0x008)`.
   - The net order is descending by primary key with ascending tie-break.
   Note the pass begins at `start` (the original `mov r2,r1` at 0x0033B430),
   not at the slot the value was written to; an occupied prefix between the two
   indices is therefore re-examined by the pass.
7. **Tail.** Return `0x0025508c(*(void**)0x00439CA8)`. `0x00439CA8` is
   `g_BtlUIManager.buffer` (`*(void**)(0x00439C88 + 0x20)`).

## Domain Limits
- Both callees are stubbed. The body of `0x00282b94` (record search) is not
  executed; the record it returns is synthetic RAM. `0x0025508c` is stubbed to
  return `r0 ^ 0x5A5A5A5A`; its real body and the `0x002ADB34` tail are not
  exercised.
- Field meanings beyond the observed offsets are **not** established. The flag
  word, cursor, slot array, primary/secondary keys and the `+0x6E` value are
  named by role only. `ScriptActor` in `include/script/script_blocks.h` shares
  the `0x288` stride, the `0x6D` count and the `+0x6E` s16, but the search array
  the original helper scans at `+0x08` is not the `group` array documented
  there, so the record is not claimed to be that type.
- No range checks exist in the original: `id` is used as a flag-table index and
  slot values are used as actor indices. Out-of-domain values read outside the
  fixtures (the test only exercises mapped ranges). A cursor below `-1` writes
  and reads before `context+0x2F06` — behaviour preserved and tested for
  `-5` — and a sufficiently negative cursor would read far below the context.
- The inserted value is loaded by the original with `ldrsh` and by the
  reconstruction with a `volatile` s16 load; only its low 16 bits reach the
  slot store, so the width difference is not observable, while the `volatile`
  keeps the access unconditional after the helper call (fault behaviour and
  access ordering of the original).
- The outer sort bound (`j < 11`) is preserved but not independently
  observable: a `j == 11` iteration would have no inner iterations.
- The flag page, actor page and UI context are synthetic RAM. No allocation
  extent, lifecycle, runtime, caller-composition or whole-game equivalence is
  claimed; the two callers are documented from disassembly only.
