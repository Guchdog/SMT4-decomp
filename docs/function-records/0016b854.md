# Function Record: func_0016b854 (0x0016b854)

## Summary
- **Address:** `0x0016b854`
- **Ledger size:** 476 bytes. Only `0x0016B854..0x0016BA1F` (460 bytes, 115
  ARM instructions) is executable; the final 16 bytes (`0x0016BA20..0x0016BA2F`)
  are a literal pool read by the **next** function, `func_0016ba30`, through
  negative PC-relative loads.
- **File:** `src/engine/leaf_batch45_b.cpp`
- **Role:** Strided 16-bit row writer. It consumes 21 source indices, looks up
  one 32-bit table word per index, and writes the low halfword into a
  caller-supplied halfword cursor at a fixed 3-halfword pitch, filling the
  remaining 43 positions of a 64-halfword row with a caller-supplied fill
  value.
- **Status:** Semantically equivalent C++ (`non_matching`). Verified with a
  Unicorn ARM differential test over 30 cases plus five negative controls.

## Contract and Behavior

### Signature and ABI
This is a hand-written internal entry with a private register contract, not
AAPCS. The only call sites are the four `bl 0x0016b854` instructions inside
`func_0016ba30` at `0x0016BA64`, `0x0016BA74`, `0x0016BA84` and `0x0016BA94`.

| Register | Meaning |
|----------|---------|
| `r3` | Destination cursor, `u16*`. Advanced by `sl` after every halfword store; the advanced value is returned to the caller in `r3`. |
| `r4` | Source-index cursor, `const u32*`. Incremented by 4 after every index read (21 reads, +84 bytes total); the advanced value is returned in `r4`. |
| `r6` | Fill value, `u16`, written to the non-value positions. The four call sites pass zero. |
| `r7` | Lookup-table base, `const u32*`, already offset by the caller to the selected 32-byte row. |
| `r8` | Number of leading fill halfwords; the call sites use 0..3. |
| `sl` (`r10`) | Byte stride added to the destination cursor after each store. |
| `r0`, `r5`, `r11` | Never read or written. |
| `r9` (`sb`), `r12` (`ip`), `lr` | Scratch in the original (`r9` holds the last table word, `r12` the loop counter). `lr` is only used for the return. |

- **Return:** `mov pc, lr` at `0x0016BA1C`; no value in `r0` is produced.
- **Stack:** the original does not touch the stack. `SP` at return equals the
  entry value.
- **Callee-saved registers:** the original is an ABI violation: it consumes and
  returns `r4`, and clobbers `r9`, without saving either. `r6`, `r7`, `r8` and
  `r10` are preserved.
- No direct calls, no indirect calls, no relocations in the executable body.

### Call-site setup (`func_0016ba30`)
- `r3` is `r1` after the preceding `bl 0x0016b2a8` (`0x0016BA48`); the same
  helper also yields `r2`, the record used below.
- `r4 = r2 + 0x40`, the first source-index word.
- `r6 = 0`.
- `sl` comes from `[r0 + 0x1CC]`.
- The table base is `pc + 0x178` = `0x0016BBD0`. The first 32-byte row contains
  `-28, -20, -12, -4, 4, 12, 20, 28`; the writer reads individual words, so no
  row meaning is asserted.
- Call *n* (1..4) uses table row `[r2 + 0x2C + 4*n]` and leading count
  `[r2 + 0x1C + 4*n]`. The four calls advance the shared source cursor from
  `r2+0x40` through 84 words and advance the destination cursor by 256 strided
  halfword stores in total.

### Exact algorithm
```
src = *r4
cursor = (u8*)r3

repeat r8 times:            // leading fill; skipped entirely when r8 == 0
    *(u16*)cursor = fill
    cursor += stride

repeat 20 times:            // unrolled as 20 value/fill/fill triplets
    *(u16*)cursor = (u16)table[*src++]
    cursor += stride
    *(u16*)cursor = fill
    cursor += stride
    *(u16*)cursor = fill
    cursor += stride

*(u16*)cursor = (u16)table[*src++]     // 21st and final table value
cursor += stride

tail = 3u - r8              // `rsbs ip, r8, #3`
while tail != 0:            // skipped exactly when r8 == 3
    *(u16*)cursor = fill
    cursor += stride
    --tail

*r4 = src
*r3 = cursor
return
```

Consequences:
- Exactly 21 table words are read and exactly 64 halfwords are stored per call.
- A table word is narrowed to its low 16 bits (`strh`), so high bits and the
  sign of the 32-bit word do not matter.
- The table value positions are `r8 + 3*k`, `k = 0..20`; all other positions
  receive `fill`.
- `stride` is a raw 32-bit byte offset added to the cursor, so zero, odd,
  large and negative (two's-complement) strides all behave as byte
  displacements. With a zero stride every store aliases the same halfword.
- The tail count is unsigned. The call sites use `r8 = 0..3`; `r8 > 3` makes
  `3u - r8` wrap to a near-`2^32` count, exactly as the original `rsbs` plus
  `subs/bne` loop does. This domain limit is not exercised at runtime.

### Trailing literal pool
`0x0016BA20..0x0016BA2F` holds `0x00006E14`, `0x00004000`, `0xFFFF8000`,
`0x00007FFF`. They are loaded by `func_0016ba30` with `ldr ..., [pc, #-0x80]`
and friends, not by this helper. The C++ reconstruction does not emit these
bytes; an integrated patch of `func_0016ba30` must supply its own constants.

## Implementation
- `engine_stride_row_writer(...)` is a normal AAPCS C++ function with no calls;
  it holds the whole algorithm above.
- `func_0016b854` is a 68-byte naked shim that maps the private registers to
  the C++ arguments, calls the body, then restores the advanced `r3`/`r4`, the
  untouched `r0`, and the caller's `lr`.
- The shim preserves `r6`-`r11` indirectly through the AAPCS body, which saves
  and restores every callee-saved register it uses.

## Unresolved Limits
- No helper or indirect targets exist, so nothing is stubbed.
- `r9` is scratch in the original but untouched by the candidate; the caller
  reloads `sb` after the four calls. `r12` is caller-saved in both.
- `r8 > 3` is a documented catastrophic domain in the original; it is not
  executed by the test because it would spin about `2^32` iterations.
- The lookup table is synthetic in the test; only the access width, the
  16-bit narrowing and the caller-provided row offset are claimed.
- Integration of `func_0016ba30` still has to provide that function's literal
  pool, because those 16 bytes are no longer emitted by this block.
- No emulator or whole-game runtime session was run; this is offline
  differential evidence only.
