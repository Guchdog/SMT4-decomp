# Function Record: battle_func_003aa014 (0x003aa014)

## Summary
- **Address:** `0x003aa014`
- **Size:** 592 bytes (original span `[0x003aa014, 0x003aa264)`)
- **File:** `src/engine/leaf_batch45_a.cpp`
- **Role:** Battle-screen value labels. Resolves one screen anchor record in the
  battle layout table, notifies three per-id draw helpers, formats a record word
  as `"%4d"` and issues a positioned draw call, then repeats with a second
  record word and a second (or alternate) label. `flag` selects the
  selected/detail layout, label set, coordinate set and forwarded draw constant.
- **Status:** Semantically equivalent C++ (`non_matching`). The compiled body is
  540 B versus the 592 B original; the compiler uses a different register
  allocation, folds the two `mvn #0` constant paths into conditional moves and
  places the `"%4d"` literal in `.rodata.str1.1` instead of the function's
  literal pool. The ledger row is classified `non_matching` with this semantic
  record.

## Contract and Behavior

### Signature and ABI
```c
extern "C" void battle_func_003aa014(void* ctx, void* work, int flag, int id);
```
- `ctx = r0`, `work = r1`, `flag = r2`, `id = r3`.
- No computed return value: the tail is the second draw call, then frame
  teardown (`add sp,#0x4C` / `pop {r4-r8,sb,sl,fp,pc}`). The caller ignores
  `r0`.
- The original preserves `r4-r8, sb, sl, fp`; the candidate preserves the same
  set. Final `sp` equals the entry value.
- `id` is masked with `uxth` at every record lookup (`r0 = id & 0xFFFF`).
- `0x2BE7FC` is **Thumb** code in the pinned binary: the original reaches it

## Contract corrections found during implementation
- **Draw constant is not `r1`.** The contract lists
  `0x230C80(r0=ctx+0xC8, r1=(flag ? 0xFBEB39FF : 0), r2=..., r3=...)`. The
  binary sets `r1 = 0` for both draw calls (`mov r1, sb` after `sb` is zeroed at
  `0x3AA16C`, and `mov r1, #0` at `0x3AA204`, `0x3AA208`). The opaque word is
  the **third stack argument** at `[sp + 0x08]`
  (`stm r3,{r1,r5}` at `0x3AA180`; `stm r7,{r0,r6}` at `0x3AA1FC`).
- **Flag-0 constant is `0xFFFFFFFF`, not `0`.** The `flag == 0` paths execute
  `mvn sb,#0` (`0x3AA224`) and `mvn r6,#0` (`0x3AA23C`), so the forwarded word
  is all ones, not zero.
- **`0x00643425` is data, not a pointer argument.** The format calls use
  `add r1, pc, #0xF4` / `add r1, pc, #0x74`, which compute `0x3AA250` — the
  address of the literal-pool word. That word's bytes are `25 34 64 00`,
  i.e. the string `"%4d"`. The actual `r1` argument is `0x3AA250`; the
  `0x00643425` value is the word stored there. The semantic format is therefore
  `"%4d"` (the contract's "format pointer `0x00643425`" is misleading).
- **`0x2BE7FC` interworking.** It is Thumb code reached with `blx`; all other
  callees are ARM reached with `bl`. The harness models this explicitly.
- **`0x22DB5C` record byte.** Contract wording "`record[2]`" is correct but the
  load is a zero-extending `ldrbne`; a value of `0xFF` is forwarded as `255`,
  not `-1`.

## Limits
- Fixtures are synthetic: `ctx`, `work`, layout anchor records, id records and
  the scripted format output are not captured game data.
- Every helper (`0x2BF6C8`, `0x22D994`, `0x22DE40`, `0x22DD28`, `0x22DC40`,
  `0x2B087C`, `0x22DB5C`, `0x2BE7FC`, `0x230C80`) is stubbed; no real layout
  lookup, record resolution, text formatting, GPU submission, or battle UI
  state is exercised.
- The semantic meaning of the two forwarded constants
  (`0xFBEB39FF`, `0x6BBB2CFF`) is not established; they are treated as opaque
  32-bit words. They are not claimed to be float bit patterns.
- The `0x2C`-byte text buffer size is inferred from the original's frame
  (`sp+0x20..sp+0x4C`); `0x2BE7FC`'s real width/overflow contract is not
  modeled, and the harness writes only a short deterministic payload.
- The candidate's internal frame layout and register allocation differ from the
  original; only the documented ABI inputs, call arguments, saved registers,
  format output and returned state are compared.
- No rendering, text-layout, battle-state, caller-composition or whole-game
  runtime equivalence is claimed.
