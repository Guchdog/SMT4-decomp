# `0x0029EDFC` — cursor range update wrapper

## Recovered contract

`camp_func_0029edfc(void* object, u32 index)` reads the byte at `object+0x62`. A nonzero byte returns its raw value in `r0` without writing the object or calling another function. Otherwise, it adds the words at `+0x24` then `+0x20` modulo 32 bits. If that sum differs from the original index, it stores byte `1` at `+0x60`; if equal, it preserves the existing byte. It then tail-branches to the original ARM helper `0x002892C0(object,index)` and propagates the return unchanged. There is no null check. The typed tail helper prototype reports its pinned return value; the original `0x002892C0` body remains in place.

The helper updates cursor words `+0x20/+0x24` according to the signed ARM index/count conditions and returns `1` on its normal paths. The caller and data layout do not establish that arbitrary counts, visibility values or malformed objects are valid. See the [static contract](../agent-work/h2-0029edfc-contract.md).

## TitleConfig caller

`TitleConfig_Calc` calls this helper at `0x001EAEA4` after the selected-row query and after a non-selected work halfword handle returns touch state `6`. It passes the cursor object at `work+0xE8` and the handled row index. The caller ignores `r0`, reloads the work pointer and refreshes the row display. The offline caller cases use the pinned original Calc and demonstrate rows 0, 1 and 2, plus the selected-row skip. They use scripted touch returns and do not prove physical input timing.

## C++ reconstruction and offline evidence

The readable implementation is in [leaf_batch34_b.cpp](../../src/engine/leaf_batch34_b.cpp). The body is 44 bytes within the original 80-byte slot. It uses one `R_ARM_JUMP24` relocation to the even ARM entry `0x002892C0`; the final body matches the experimental candidate exactly. The helper declaration now has its actual `(object,index)->u32` ABI.

`tools/h2_29edfc_experiment.py` passed 14 direct cases against the pinned wrapper and original helper, including raw disabled-byte returns `1`, `0x80` and `0xFF`, retained flag values, modulo addition, zero and positive counts, signed-index boundaries, and visible count above the configured count. Returns, object bytes, helper arguments/order, callee-saved registers, stack pointer and VFP callee-saved registers match. The original wrapper writes temporary saved registers to the caller's stack; the C++ leaf does not use stack storage. The comparison treats that stack area as caller-owned temporary space and validates final SP and preserved registers instead.

Four actual `TitleConfig_Calc` touch scenarios reached the original or candidate wrapper and original helper with identical caller state, service trace and ABI, covering `handled` indices 0, 1 and 2 and a selected-row skip. Three compiled negative controls detect a normalized disabled return, inverted flag comparison and changed helper index. The cumulative IPS changes 76 bytes within the declared slot and round-trips; staged image SHA-256 is `a865c64d96785558c1d204b6aa89a3f97369b2b1f27f76d8beb5e3b543c9e25b`; IPS SHA-256 is `f5d6024ae155316ae795a6621ef4bf5a348c23d873a386f985347322f6a8da6c`. The full ARMv6K build passed 204/204 translation units, and independent review accepted this bounded evidence in [run001](../agent-work/h2-0029edfc-independent-review-run001.md). Runtime was not run.

## Limits

The direct cases use deterministic mapped objects and execute original `0x002892C0`; the caller cases use scripted touch service results and other controlled services. They do not establish object validity for arbitrary pointers, concurrency, physical input, natural scheduler behavior or whole-game equivalence. Runtime remains unverified.
