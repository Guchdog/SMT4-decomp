### Nibble-map addressing
The two nibble maps use different strides in the original:
- `type+0x10`: byte address `base + (index & ~7)` (one word every eight
  entries, i.e. words `+0x10, +0x18, +0x20, ...`).
- `type+0x28`: word address `base + (index >> 3) * 4`.
Both OR the value shifted by `(index & 7) * 4`, so a value wider than four
bits spills into the following nibble and, at the top of the word, is
truncated by the 32-bit shift.

### Element encoding
For each element word `w`:
- `sign = (w & 0x80000000) ? 0x00800000 : 0`;
- `fraction = (w << 9) >> 9` (low 23 bits), then `>>= 7` in every path;
- `exponent = (w >> 23) & 0xFF`;
- if `w & 0x7FFFFFFF == 0`: result `sign | fraction`;
- else if `exponent < 0x40`: result `sign`;
- else if `exponent - 0x40 > 0x7F` (signed): result `0x007F0000`;
- else result `sign | fraction | ((exponent - 0x40) << 16)`.

## Limits
- `0x002C39A4` and `0x002BC300` are modelled by deterministic stubs; their
  bodies are not reconstructed here. The stubs return fixed/derived addresses
  and log their arguments.
- The original writes the four element sink words into a four-word stack
  scratch. A record byte at `+0x08` greater than 4 overruns that scratch and
  corrupts the original's own locals/saved registers; this is a domain limit,
  not reproduced. All cases use at most four elements.
- The optional-state resolution dereferences `*(u32*)(optional+8)` and can
  read address `0x44` or address `0` when the state word is null or its
  `+0x44` displacement is zero. The test maps a zero page to model those
  reads; a real runtime would fault on absent data.
- Fixtures are synthetic. No real render descriptor, allocator, GPU command
  consumer or engine context is exercised, and no emulator, caller
  composition or whole-game equivalence is claimed.
- Byte identity is not claimed (1792 versus 1660 bytes). The compiler folds
  the tag-selector chain into `.rodata` byte/word tables and selects them with
  `clz`/table loads.
