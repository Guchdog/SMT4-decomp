returned by `0x002A0FAC` (`*(u32*)(0x0043E2A8+4) + 0x1EC18`).

   `work+0xF92` / `0x3EA`. The routine takes two arguments; the original's
   leftover `r2` is not consumed.
2. Candidate scan, `0x4B1` slots (`u16` index `i`, `i <= 0x4B0` inclusive,
   unsigned bound):
   - skip when `0x0029ED44(*work, (u16)i)` is zero. Its first argument is the
     word at `work+0` and is ignored by that callee.
   - `entry = 0x002B9364(i)` is dereferenced unconditionally (`*(u16*)entry`
     is the id).
   - skip when `0x0029ED08(id) == 0` **and** `0x0029EC6C(id) == 0`.
   - read the signed 16-bit word at `config+0x24` (fresh each iteration). When
     it is zero or equals the zero-extended byte `entry[2]`, append `id` (`u16`)
     at `work+0x5C0 + 2*count_a` and increment `count_a`.
   - when `0x0029D080(work+0xF22, (s32)count_b, entry[2]) == 0`, append the
     zero-extended byte `entry[2]` (as `u16`) at `work+0xF22 + 2*count_b` and
     increment `count_b`. The helper scans the current array contents, so it
     suppresses duplicate category bytes.
3. `0x002B7F08(work+0x5C0, (s32)count_a, 2, 0x001F643C)` sorts the candidate
   ids in place (Thumb qsort-shaped entry at `0x002B7F0A`; the original uses
   `blx`).
4. Skill scan, `0x1F5` slots (`u16` index `i`, `i <= 0x1F4` inclusive,

inclusive, so the loops run `0x4B1` and `0x1F5` times respectively. The unique
byte array is declared with room for `0x38` entries but no explicit capacity
check exists; when more than 56 distinct category bytes occur, the original (and
the replacement) continue storing past that region into the following skill
array, which is still observable behaviour reproduced by the test.
