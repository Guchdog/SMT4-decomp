# Function Record: func_00150654 (0x00150654)

## Summary

- **Address:** `0x00150654`
- **Size:** 440 bytes (`[0x00150654, 0x0015080C)`): 105 ARM instructions through
  the unconditional `pop {r4, r5, r6, r7, r8, sb, sl, fp, ip, pc}` at
  `0x001507F4`, followed by the five literal words at
  `0x001507F8..0x0015080B` (`0x804F02C0`, `0x004652A0`, `0x00472288`,
  `0x000F02C0`, `0x00BF02C1`).
- **File:** `src/engine/leaf_batch41_c.cpp`
- **Role:** Appends one draw unit's position record and then, for every entry of
  a draw group, the entry's matrix block (from the unit's skinning data or from
  the unit's own 3x4 matrix) plus one item submission, all on the GPU command
  stream rooted at `g_GpuCommandCursor` (`0x004652A0`). It also binds the unit
  into the scene context when the context records a different unit.
- **Status:** Semantically equivalent C++ (`non_matching`). The candidate body is
  488 bytes versus 440 bytes. Control flow, every branch, the loop bound and its
  wraparound, call order, arguments, access widths, the relative-pointer
  fallbacks and the full memory effect are preserved. Behavioural support is the
  differential runner below, not byte identity.

## Contract and Behavior

### Signature and ABI

```c
extern "C" u32 func_00150654(void* scene,   // r0
                             void* unit,    // r1
                             void* group,   // r2
                             u32 index);    // r3
```

- The prologue is `push {r4, r5, r6, r7, r8, sb, sl, fp, ip, lr}`; the epilogue
  restores the same ten registers. `r4-r11` are preserved, `SP` is unchanged and
  no local frame exists.
- No stack arguments: the largest argument list is four registers, and the only
  stack slots a callee can see are the caller's spilled callee-saved registers.
- The routine is effectively `void`. Residual `r0` is `scene` on the null-group
  exit, the slot count on the empty-table exit and the last `0x00153C74` result
  otherwise; the only direct caller (`BL` at `0x00148748` inside
  `ui_func_00148660`) discards it. The reconstruction returns those values so
  register-level differential tests stay exact.
- The only argument guard is `movs r7, r2; beq`: a null `group` returns before
  touching anything. No other pointer is checked; a null `scene`, `context`,
  render-state block, entry or vtable faults exactly as in the original.

### Scene / unit layout read by the original

| Expression | Width | Meaning |
| --- | --- | --- |
| `[scene+0x08]` | pointer | scene context (`context`) |
| `[context+0x1C]` | pointer | unit currently bound in the context; written by `0x00153D64` / `0x00153E50` |
| `[context+0x08]` | pointer | render-state block |
| `[render_state+0x14]` | word | render-state flags; bits 1..2 are cleared here |
| `[unit+0x00]` | pointer | vtable; slot `+0x08` returns the first type-info node |
| `[unit+0x8C]` | 3x4 matrix | source for the single-matrix variant (when `unit` is null the address becomes `0x8C`) |
| `0x00472288` | constant | type-info identity the draw path accepts (compared, never dereferenced) |

### Draw-group record (`r2`)

| Expression | Width | Meaning |
| --- | --- | --- |
| `[group+0x20..0x28]` | three words | copied into the position record |
| `[group+0x2C]` | word | entry-slot count (raw 32-bit add) |
| `[group+0x30]` | word | relative offset from that word to the slot array |

A zero relative offset resolves to address `0` (the original has no
empty-table fallback); the end pointer is `slots + count*4` computed modulo
`2^32`, and the loop is bottom-tested on pointer equality. A count whose `*4`
wraps to zero (`0x40000000`, `0x80000000`, ...) therefore exits before the first
iteration.

Each slot holds another relative offset to a draw entry:

| Expression | Width | Meaning |
| --- | --- | --- |
| `[entry+0x00]` | word | matrix count consumed by `0x00153A58` |
| `[entry+0x04]` | word | relative offset to the matrix index array (`0x00153A58`) |
| `[entry+0x08]` | word | entry type (`0x00153A58`) |
| `[entry+0x10]` | word | relative offset to the item-slot table, indexed by `r3` |

Every slot word and entry is re-read for each use, so a callee that rewrites the
slot changes the tail lookup (exercised by the `slot_rewrite` case).

### Command emission

1. Position record at `g_GpuCommandCursor`, 0x18 bytes:
   `{0x80000006, 0x804F02C0, 0, z, y, x}` where `x/y/z` are
   `group+0x20/0x24/0x28` re-ordered by `0x002A1B98` as `{0, src[2], src[1],
   src[0]}`. The global is **reloaded after the helper** and then advanced by
   `0x18`.
2. Single-matrix variant, 0x40 bytes (0x3C written, one word reserved), emitted
   when the type match failed or `entry[0] == 0`: bits 1..2 of
   `[render_state+0x14]` are cleared, then `{0x80000019, 0x000F02C0,
   0x002A1AC8(cursor+8, unit+0x8C, 0x00BF02C1)}` is appended and the cursor is
   reloaded and advanced by `0x40`. This is exactly the `count == 1` shape of
   `0x00153A58`, which the neighbouring `0x00153E50` also emits.
3. Skinning variant: the draw entry is handed to
   `0x00153A58(scene, component, entry, entry[0])`, which emits its own block and
   one trailing reserved word.

### Call order

1. `0x002A1B98(cursor+2, group+0x20)` — position copy.
2. `vtable[2](unit)` then the type-info chain walk (only when `unit != 0`).
3. `0x00153E50(context, component)` when the type match succeeded and
   `[context+0x1C] != unit`; otherwise `0x00153D64(context, unit)`.
4. Per slot: `0x00153A58` **or** `0x002A1AC8`, then always
   `0x00153C74([scene+0x08], item)`.

## Domain Limits

- The indirect target `vtable[2]` of the unit and the helper routines
  `0x00153A58`, `0x00153D64`, `0x00153E50`, `0x00153C74`, `0x002A1B98` and
  `0x002A1AC8` are replaced by deterministic stubs; their own contracts are
  covered by their separate records/tests. A helper that actively rewrites the
  scene, context or command buffer beyond the modelled effects is out of the
  fixture domain.
- The compiled candidate may hoist the `g_GpuCommandCursor` load above the
  `[render_state+0x14]` update; the original loads it after that store. The two
  objects are distinct in the shipped layout, so this is observable only for a
  fixture that aliases them.
- A slot count with a non-zero `count*4` such as `0x20000000` makes the original
  walk upward until it faults; no guard exists and none was added.
- Zero relative offsets read the low addresses (`0x0`, `0x4`, `0x10`, `0x8C`);
  the differential fixture maps those addresses explicitly. In the retail game
  those paths are not expected with zero offsets.
- Runtime consumption of the command stream and in-game behaviour were not
  exercised; this record covers offline differential equivalence only.
