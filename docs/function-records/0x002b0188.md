# `0x002B0188` — group manager resolver

## Reconstruction

`ui_func_002b0188(group, node_index)` reads the table pointer stored at `0x0044EA28`, loads the manager-entry pointer at `table + group * 24`, then tail-calls `0x00138B90(manager_entry, node_index)`. The second input is implicit in the original assembly ABI: `r1` must remain the node index through the tail branch.

`0x00138B90` returns null for a null manager-entry pointer. Otherwise it reads the entry's first word as a base and returns `base + trunc_signed(node_index / 1000) * 32`. The compiled C++ uses one `R_ARM_JUMP24` to this original helper and fits the 24-byte span. After resolving that relocation at `0x002B0188`, the body is byte-identical to the pinned original, so the ledger remains truthfully `matching`.
