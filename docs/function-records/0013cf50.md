## Contract and ABI

```cpp
extern "C" u8* engine_func_0013cf50(void* allocator,  // r0
                                    const char* name); // r1
```

- `r0` (`allocator`) is a context object whose first word is a vtable pointer.
  Slot `+0x08` (index 2) is called as
  `allocator->vtable[2](allocator, size, flags)`. The vtable pointer and the
  slot are re-loaded from `[allocator]` before each request
  (`0x0013CF6C/0x0013CF70` and `0x0013CFD0/0x0013CFDC`), so a call may replace
  the allocation entry point used by the next request.
- `r1` (`name`) is an optional NUL-terminated string. It is not read before the
  first allocation; only its null test at `0x0013CFAC` precedes the block
  header stores.
- **Return value:** the allocated block pointer (`r0 = r4` at `0x0013D0DC`).
  A null first allocation is returned as null if the byte-zeroing loop does not
  fault first.
- No stack arguments. `r2`, `r3`, `r12` are never read. The prologue pushes
  `{r4, r5, r6, r7, r8, sb, sl, lr}` and `vpush {d8}`; `sl` is saved and
  restored but never used; `r9` (`sb`) holds `name`, `r4` the block, `r5`
  zero/the copy during the name path, `r6` the block `/ block+0x0C` pointer,
  `r7` the capped length, `r8` the allocator `/ copy`.
- The only caller in the image is `0x0012AB08`, which always passes `r1 = 0`;
  the non-null name path is recovered from the instruction stream and exercised
  only by the differential test.

## Recovered behaviour

1. **First request** (`0x0013CF68..0x0013CF78`):
   `block = allocator->vtable[2](allocator, 0x100, 4)`.
2. **Zero fill** (`0x0013CF80..0x0013CF88`): a `strb` post-increment loop stores
   zero to `block[0..0xFF]`. The loop is driven by a down-counter and never
   tests the allocation result, so a null block stores through address 0.
3. **Header stores** (`0x0013CF8C..0x0013CFA0`), in store order:
   `block[8] = 0x07010000`, `block[4] = 0x4E465443`,
   `block[0] = 0x40000222`.
4. **Cleared words and name test** (`0x0013CFA8..0x0013CFBC`):
   `block[0x10] = block[0x14] = 0`; `name == 0` branches to `0x0013D05C`,
   which stores `block[0x0C] = 0` and rejoins at `0x0013D00C`.
5. **Name copy** (`0x0013CFC0..0x0013D008`):
   - `length = strlen(name)` (`0x002C3290`, ARM).
   - `kept = length < 0x100 ? length : 0x100`; the comparison is unsigned
     (`cmp` + `movlo` at `0x0013CFC8/0x0013CFCC`), so lengths above `0x100`
     are truncated but never clamped oddly for bit-31 values.
   - `copy = allocator->vtable[2](allocator, kept + 1, 4)`; the slot and
     vtable pointer are re-loaded from `[allocator]` for this request.
   - `memcpy(copy, name, kept)` (`0x002C5FF4`, ARM).
   - `copy[kept] = 0` is stored **before** the null test
     (`strb r5,[r8,r7]` at `0x0013D000`). A null copy therefore faults at
     address `kept` unless that page is writable.
   - The link is stored conditionally (`strne` at `0x0013D004`):
     `block[0x0C] = copy - (block + 0x0C)` when `copy != 0`, else 0 through
     the `0x0013D05C` arm. The subtraction is a plain 32-bit difference of
     addresses; the caller resolves it as `block + 0x0C + link`.
6. **Fixed image** (`0x0013D00C..0x0013D050`): `block[0x20..0x2C] = 0`,
   `block[0x30..0x38] = 1.0f`, `block[0x3C..0x50] = 0.0f`.
7. **Guard** (`0x0013D04C..0x0013D0AC`): if `([0x00476634] & 1) == 0`, call the
   Thumb one-shot helper `0x002C00D4` (via `blx`) with the word's address. The
   helper returns 1 only when it observed a zero word and stored 1; only then
   is the identity image rebuilt. A non-zero word returns 0 and leaves the
   image untouched. A bit-0-set guard skips the helper entirely.
8. **Image copy** (`0x0013D0B4..0x0013D0D8`): the twelve words at `0x004EFD6C`
   become `block[0x84..0xB3]`. The original emits one eight-word `ldm`/`stm`
   pair for `+0x00..+0x1C`, then `+0x2C`, then `+0x20..+0x28`; the
   reconstruction copies in ascending word order (see Limits).
9. **Trailer** (`0x0013D0DC..0x0013D0E8`): `block[0x18] |= 1`; return `block`.

## Limits

- `0x002C3290`, `0x002C5FF4` and `0x002C00D4` are not reconstructed here. They
  are stubbed from their observed contracts (byte length, byte copy, one-shot
  zero-word guard returning 0/1). Their internals and any side effects outside
  the provided name/word pages are outside this routine.
- The two indirect allocation targets live in the caller's vtable and are
  unresolved in the image; the test installs deterministic stubs at
  `0x002E0000`/`0x002E0020` and can replace the vtable pointer between calls.
  Nothing here proves any particular allocator implementation.
- The reconstruction copies the shared image into `+0x84..+0xB3` in ascending
  word order, whereas the original schedules an eight-word pair plus the
  `+0x2C` and `+0x20..+0x28` groups. The final memory is identical; the only
  observable difference would require the block to overlap `0x004EFD6C`,
  which the allocation contract excludes and the test does not exercise.
- The dead literal reload of `0x00476634` into `r0` at `0x0013D0AC..0x0013D0B0`
  has no memory access and its result is overwritten at `0x0013D0B4`; it is
  omitted rather than reproduced as an unused local.
- The terminator store is kept in a `noinline` helper so the compiler cannot
  assume the copy pointer non-null and delete the zero-link arm. The
  observable contract (fault at `kept` when unmapped, zero link when the page
  is writable) matches the original and is tested both ways. The helper costs
  one extra call/reference compared with the original inline `strb`; it is a
  local symbol with no other effect.
- The candidate stores the `1.0f`/`0.0f` image as integer immediates instead of
  `vldr`/`vstr`; the byte pattern and final memory are identical.
- No emulator/runtime scenario was run: the evidence is offline Unicorn ARM
  execution of the pinned bytes versus the compiled candidate with identical
  fixtures, plus static caller reading at `0x0012AB08`.
