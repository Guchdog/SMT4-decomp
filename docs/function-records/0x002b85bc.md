# `ui_func_002b85bc` — profile selector side-effect transition

`0x002B85BC` now has typed C++ in
[`leaf_batch44_c.cpp`](../../src/engine/leaf_batch44_c.cpp). It accepts a full
32-bit request in r0, looks up the current and requested profiles in order,
processes six manager slots according to the old/new profile byte at +0x0C,
optionally processes two additional slots, then reloads the manager object for
the final stores. The raw return is either the second lookup's result on a null
profile pair or the final object's +0x0C address after storing words 0 and 3 at
+0x0C/+0x10. The caller `0x002B8B78` ignores that return.

The original has three status-loop variants: old profile active, new profile
active (which clears nonzero status bytes and then calls one of two helpers for
two additional slots), and both profile flags zero. The status path first calls
`0x002BF030` with `object+0x34+0x8C*i` and selector 1. A nonzero status of 7 or
9 calls `0x002A8A8C`, then the status is reloaded. If that reload is 8, the
original executes three more calls to `0x002A8A8C`; otherwise it executes one
call. Thus an unchanged 7/9 status produces two total calls, unchanged 8
produces three, and an ordinary nonzero value produces one. A 7/9 status changed
to 8 by the first helper takes the three-call block after that first call.

The compiled body is 372 bytes in the original 472-byte slot, with 11 ARM
`BL` relocations to five distinct even ARM targets. The staged IPS changes only
the slot. The independently reviewed candidate is recorded as `non_matching`
in the production ledger because its final body differs from the original.

`tools/h2_profile_selector_experiment.py` passed nine direct fixtures, the two
instruction-pinned `0x002B8B78` caller slices (request `0x99` and conditional
`0xDC`), and five detected mutation controls. These compare full mapped memory,
ordered writes and dependency calls/arguments; normal returns also compare r0,
SP and callee-saved registers. The null-object fixture faults at read address
`0x4C9` in both versions. Caller runs use deterministic hooks for the selector's
five service dependencies and the wrapper's remaining helpers. They do not
validate those callees' transitive effects, natural callback reachability,
profile/TBB lifecycle, persistence, or audio output.

The original static contract's status-8 service multiplicity has been corrected
to three calls, including the status-reload case. See the
[production-conversion evidence](../agent-work/h2-profile-selector-production-conversion-002b85bc.md)
and its final report under
`build/agent-work/H2-semantic/h2-profile-selector-002b85bc-convert/run002/checks/final5/`.
