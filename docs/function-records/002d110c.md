# Function Record: func_002d110c (0x002D110C)

## Summary
- **Address:** `0x002D110C`
- **Size:** 444 bytes (`[0x002D110C, 0x002D12C8)`): 103 ARM instructions
  through `pop {r4, r5, r6, r7, r8, sb, sl, pc}` at `0x002D12A4`, followed by
  the eight literal words at `0x002D12A8..0x002D12C4`.
- **File:** `src/engine/leaf_batch41_c.cpp`
- **Role:** Refresh one display/geometry record at `state + 0xC0`. The routine
  optionally re-installs four default bounds and the state's value word, then
  either exits early on a signed `count < frame` test or blends two packed
  colours through the shared block at `0x004EA91C`/`0x004EA92C` and samples two
  curves for the record's two remaining floats.
- **Status:** Semantically equivalent C++ (`non_matching`). The candidate body
  is 636 bytes versus 444 bytes (clang expands the four float constants into
  byte stores and reloads the colour block base once); call order, arguments,
  signed branches, access widths, packed-byte order, and memory effects are
  preserved. The ledger row is classified `non_matching` with this record.

### Status and evidence notes
- The ledger row is `non_matching` because the compiled candidate differs in
  size and instruction selection from the original. Behavioural support is the
  semantic record plus the differential runner, not byte identity.
- Colour products are expected in `[0, 1]` because both inputs come from
  `0x00257614`, which normalizes byte components by 1/255. In that domain the
  C++ `static_cast<u32>` and ARM `vcvt.u32.f32` agree (both truncate). Values
  beyond the unsigned 32-bit range would diverge: ARM VCVT saturates while a
  C++ float-to-unsigned conversion is undefined; the real callers cannot
  produce them.
- No indirect targets exist. The helper bodies above, the absolute colour
  block, and runtime timing/one-frame behaviour of the callers are the only
  unresolved areas.
